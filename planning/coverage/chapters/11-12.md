## Checklist of Concepts, Numbers, and Patterns to Cover
1. **Why the Traditional Device Plugin Model Hit an Architectural Wall (`GAK Ch 3`, `volume-03/01` §8):**
   - Device Plugin limitations:
     1. **Scalar integer counts only (`nvidia.com/gpu: 4`):** Cannot express attributes (`minMemory: "40Gi"` / `40 GB` $\approx$ `37.25 GiB`, `80 GB` $\approx$ `74.5 GiB`, `migMode: "disabled"`, compute capability, or NVLink domain) inside the resource request.
     2. **No cross-Pod device sharing or dynamic attachment:** A traditional device plugin allocates exclusively to a single container at Pod startup; it cannot share one GPU across multiple Pods in a structured claim or dynamically slice MIG on demand.
     3. **No cross-device relational constraints:** Cannot express *"allocate a GPU and an RDMA NIC VF that sit on the same PCIe switch (`PIX`) or NUMA node"* at the scheduler level (relying instead on post-scheduling `kubelet` Topology Manager rejections `TopologyAffinityError`).
2. **Dynamic Resource Allocation (`DRA`) Architecture (`resource.k8s.io/v1` in Kubernetes `1.34`, `v1beta1`/`v1beta2` in earlier releases, `GAK Ch 3` & `volume-03/01` §8):**
   - Inspired by the Kubernetes **CSI (`StorageClass` -> `PVC` -> `PV`)** dynamic provisioning model (`volume-03/02` §5).
   - Four core DRA API objects:
     1. **`ResourceSlice`:** Published by the node-local DRA kubelet plugin (`gpu.nvidia.com`) to `kube-apiserver`, advertising every physical GPU, MIG capability, memory size, and PCIe/NUMA topology attribute on the node.
     2. **`DeviceClass` (e.g., `gpu.nvidia.com` or `gpu.nvidia.com/a100`):** Cluster-scoped class (analogous to `StorageClass`) defined by platform admins with default CEL (Common Expression Language) attribute selectors and driver parameters.
     3. **`ResourceClaim`:** Namespace-scoped lifecycle object (analogous to `PersistentVolumeClaim`) representing an actual request for device(s) (`exactly`, `allocationMode: ExactCount`, `count: 4` or `1`, CEL `selectors`, `parameters`: `minMemory: "40Gi"`, `migMode: "disabled"`).
     4. **`ResourceClaimTemplate`:** Workload template (`a100-claim-template` in `GAK` Example 3-8, or `gpu-claim` in `volume-03/01` §8.2) referenced in `Pod.spec.resourceClaims` and `Container.resources.claims` (`GAK` Example 3-9) so each Pod replica in a `Deployment`, `StatefulSet`, or `JobSet` gets its own dynamically bound `ResourceClaim`.
   - Evolution from `v1alpha2` ("classic" DRA with `ResourceClass` and `parametersRef`, which was removed) to **Structured Parameters** in `v1beta1`/`v1beta2` and stable **`resource.k8s.io/v1` in Kubernetes `1.34`** (where `kube-scheduler` evaluates `ResourceSlice` objects and CEL selectors directly in memory without external driver RPC round-trips during scheduling).
   - Production maturity caveats (`GAK Ch 3`): Core DRA APIs are GA and enabled by default since Kubernetes `1.34`, while the NVIDIA GPU DRA driver (`gpu.nvidia.com`) and ecosystem integration (cluster autoscalers, quota controllers) are maturing toward full production parity.
3. **Kubelet Node Mechanics, PLEG, QoS (`oom_score_adj`), and CSI Parallels (`volume-03/01`, `volume-03/02`, `volume-03/03`):**

   - **Kubelet Sync Loop, PLEG (`3m0s` threshold), and Eviction/QoS (`volume-03/02` §2–§4):**
