## Checklist of Concepts, Numbers, and Patterns to Cover
1. **Why scheduling a GPU is not giving a process a GPU:**
   - The split between extended-resource scheduling (`nvidia.com/gpu` count), kubelet device allocation (`Allocate` gRPC), and CRI sandbox device injection (`containerd` / `CRI-O` + NVIDIA Container Toolkit / CDI).
   - Host kernel-mode driver (`nvidia.ko`, `nvidia-modeset.ko`, `nvidia-uvm.ko`, `nvidia-peermem.ko`) and character device nodes (`/dev/nvidia0` major `195` minor `0`, `/dev/nvidiactl` major `195` minor `255`, `/dev/nvidia-uvm` dynamic major `238` minor `0`) vs container user-mode libraries (`libcuda.so.1`, `libcudart.so`, `/usr/bin/nvidia-smi`).
   - CUDA Forward Compatibility (`/usr/local/cuda/compat/libcuda.so.1`, `libcuda.so.535.104.05`, `LD_LIBRARY_PATH` ordering).
2. **Evolution of GPU containerization (4 generations):**
   - Gen 1 (`nvidia-docker` wrapper), Gen 2 (`nvidia-docker2` custom daemon runtime), Gen 3 (`nvidia-container-toolkit` pre-start OCI hook + `libnvidia-container`), Gen 4 (`CDI` — Container Device Interface `cdiVersion: 0.5.0`, `kind: nvidia.com/gpu`, `nvidia-ctk cdi generate --output=/var/run/cdi/nvidia.yaml`).
   - Three mechanisms and three questions: NVIDIA Container Toolkit config (node runtime), `RuntimeClass` (Pod handler selection), and CDI (device specification JSON/YAML).
3. **Kubernetes Device Plugin Framework and Kubelet gRPC Contract:**
   - Core functions (discovery, allocation, health monitoring, scheduler integration) and vendor plugins (`nvidia-device-plugin`, `amd-device-plugin`, `intel-gpu-plugin`, `google-cloud-tpu-device-plugin`, `aws.amazon.com/neuroncore`).
   - Socket handshake (`/var/lib/kubelet/device-plugins/nvidia-gpu.sock` / `nvidia.sock`), `Register()`, `ListAndWatch` stream (`Health: "Healthy"` vs `"Unhealthy"`), `Capacity` vs `Allocatable` vs `Allocated resources` (`8` capacity, `8` allocatable, `6` allocated; or `8` capacity vs `5` allocatable when `3` devices fail; or `8` capacity with absent allocatable when plugin crashes).
   - Why bare `nvidia.com/gpu: 1` is a capacity contract, not placement quality (`40` nodes: `25` newer NVLink + `15` older PCIe = `37.5%` chance of landing on older pool without affinity labels).
   - Device plugin flags (`--fail-on-init-error=true`, `--pass-device-specs=true`, `--device-discovery-strategy=auto|nvml|tegra`, `DEVICE_LIST_STRATEGY=cdi-annotations`).
   - PID namespace visibility (`2051234` on host vs empty or PID `1` inside container `nvidia-smi`).
4. **Hands-on Python Simulation & Lab (`code/part11/device_plugin_toolkit_cdi.py` & `device_plugin_toolkit_cdi_lab.py`):**
   - Simulate kubelet `Register` / `ListAndWatch` / `Allocate` state machine, CDI YAML spec generation (`cdiVersion: 0.5.0`, major `195`/`238`), `containerd` `config.toml` handler resolution, and dependency-ordered missing-GPU / failed-injection triage (`Lab 03` flow).
