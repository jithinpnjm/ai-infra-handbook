## Key topics, numbers, and formulas extracted

1. **The `nvidia-smi` Utilization Lie, MFU, HFU, and Goodput (`V13` Ch. 11, `ASP` Ch. 1, `DAI` Ch. 10):**
   - `nvidia-smi` `utilization.gpu` only measures the percentage of sampling windows in which *at least one* kernel was resident on the GPU (`98–100%` utilization can still yield `15%–22%` MFU if running small, unfused memory-bound kernels or spinning in `ncclDevKernel_AllReduce` wait loops).
   - **Model FLOPs Utilization (MFU):** `C_step_flops = 6 * N_params * tokens_per_step` (`2N` forward + `4N` backward); `Achieved_FLOPs_per_sec = 6 * N_params * tokens_per_sec`; `MFU = Achieved_FLOPs_per_sec / (num_gpus * Peak_GPU_FLOPs_per_sec)`. Target for LLM training: **`40%–50%` MFU** (`< 20%` indicates a severe bottleneck).
   - **Worked 70B on 8x H100 SXM Example (`V13` Ch. 11):** Peak dense `BF16` = `989 TFLOPS/GPU * 8 = 7,912 TFLOPS`.
     - *Before DataLoader fix (`30%` GPU util):* `3,200 tok/s` aggregate -> `6 * 70e9 * 3,200 = 1.344e15 FLOPs/s = 1,344 TFLOPS` -> `MFU = 1,344 / 7,912 = 16.99%` (`~17%`).
     - *After DataLoader fix (`num_workers`, GPU augmentations):* `9,000 tok/s` aggregate -> `6 * 70e9 * 9,000 = 3.78e15 FLOPs/s = 3,780 TFLOPS` -> `MFU = 3,780 / 7,912 = 47.78%` (`~48%`, a `2.8125x` throughput gain).
   - **Hardware FLOPs Utilization (HFU):** With full activation recomputation (`+2N` extra forward pass in backward, total `8 * N_params * tokens_per_sec`), `HFU = (8 / 6) * MFU = 1.3333 * MFU` (`47.78%` MFU corresponds to `63.70%` HFU / `5,040 TFLOPS`).
   - **Goodput & Effective Training Time Ratio (`ASP` Ch. 1 & `DAI` Ch. 10):** `100,000` tokens in `10 s` = `10,000 tok/s` vs `8 * 1,500 = 12,000 tok/s` peak -> `83.33%` (`83.3%`) efficiency; `300 / 1,000 samples/s = 30.0%` goodput (`70%–75%` lost compute in Meta's *Revisiting Reliability* analysis). On a `64`-GPU cluster running at `52%` scaling efficiency (`33.28` effective GPUs, `30.72` wasted GPUs) over a `2`-week (`336`-hour) run, `10,321.92` GPU-hours are wasted—costing **`$41,288` to `$51,610`** at `$4–$5/GPU-hr`.
2. **Step-Time Phase Decomposition, Scaling Efficiency, and Amdahl's Law (`DAI` Ch. 10, `ASP` Ch. 13):**
   - **Iteration scaling vs communication tax (`DAI` Ch. 10 Fig. 10.1):** `1` GPU = `155.0 ms` (`0%` comm overhead) -> `16` GPUs = `33.0 ms` (`55.0%` comm overhead = `18.15 ms` comm + `14.85 ms` compute; speedup = `155 / 33 = 4.697x`, scaling efficiency = `4.697 / 16 = 29.36%`).
   - **MLPerf Logging 24.0 ms step breakdown (`ASP` Ch. 13 Table 13-6):** `forward = 10.5 ms` (`43.75%` / `43.8%`), `backward = 9.0 ms` (`37.50%` / `37.5%`), total compute = `19.5 ms` (`81.25%` / `81.3%`), `allreduce = 4.0 ms` (`16.67%` / `16.7%` = `1/6`), `other = 0.5 ms` (`2.08%` / `2.1%`).
   - **64-Expert MoE 138.0 ms step profile (`ASP` Ch. 13 Tables 13-2 & 13-3):** `forward = 60.5 ms` (`43.84%`), `backward = 58.3 ms` (`42.25%`), `optimizer_step = 19.2 ms` (`13.91%`, `64` `aten::add_` kernels). Top operators: `aten::matmul` `43.00 ms` (`31.16%`, `128` calls) + `aten::linear` `35.50 ms` (`25.72%`, `64` calls) = `78.50 ms` (`56.88%` GEMM); `dispatch` `18.70 ms` (`13.55%`) + `combine` `12.10 ms` (`8.77%`) = `30.80 ms` (`22.32%` routing); remaining 6 ops (`layer_norm` `10.20 ms`, `softmax` `5.70 ms`, `scatter` `4.10 ms`, `gather` `3.60 ms`, `to` `2.90 ms`, `add_` `2.20 ms`) = `28.70 ms` (`20.80%`).
   - **Amdahl's Law (`DAI` Ch. 10):** `Speedup(N) = 1 / (s + (1 - s) / N)`; for serial fraction `s = 0.10` (`10%`), `lim_{N->inf} Speedup(N) = 10.0x` (`Speedup(64) = 5.43x`, `8.49%` efficiency).
3. **Top-Down Bottleneck Hunt: Host/DataLoader vs Kernel Roofline vs Memory Allocator (`V13` Ch. 11, `ASP` Ch. 13):**
   - **Host & DataLoader:** `iostat -x 1`, Linux `perf stat`/`perf report` (`1.58` IPC vs `8.0` max IPC on Grace Neoverse V2; `45.0%` `py::forward`, `20.5%` `aten::matmul`, `10.2%` `dataloader_iter_next`, `8.7%` `ncclAllReduce`, `5.3%` `read` = `89.7%` top-5). Fix with `num_workers=4` per GPU, `pin_memory=True`, `persistent_workers=True`, `prefetch_factor=4`, and `torch.compile(mode="max-autotune")` (`248.0 ms -> 173.0 ms`, `75.0 ms` / `30.24%` saved, `1.43x` speedup).
   - **Kernel Roofline (`ncu` Table 13-4):** Baseline unfused/small-tile kernel (`50%` peak FLOPS, `70%` peak HBM BW, `60%` occupancy -> `Memory bound`, causing the `100%` `nvidia-smi` util / `22%` MFU trap) -> Optimized fused/tiled kernel (`85%` peak FLOPS, `40%` peak HBM BW, `80%` occupancy -> `Compute bound`).
   - **Allocator Fragmentation & CUDA Graph Pools (`ASP` Ch. 13):** `roundup_power2_divisions:[256:1,512:2,1024:4,>:8]` rounds a `600 MB` request up to `768 MB` (`256 MB` step in `[512, 1024]`), whereas `PYTORCH_ALLOC_CONF=expandable_segments:True,max_split_size_mb:128,garbage_collection_threshold:0.8` lowers reserved VRAM from `768 MB` to `600 MB` (`168 MB` / `21.88%` saved). FireworksAI shared CUDA Graph pool captures batch sizes in decreasing order `[8, 4, 2, 1]` to reuse the high-water-mark buffer.
4. **Network, NCCL Collectives, Straggler Detection, and Production Failure Modes (`V13` Ch. 1, 8, 11, 12, Labs 01–04; `ASP` Ch. 4 & 13):**
   - **NCCL communicator lifecycle (`ASP` Ch. 4 Table 4-3):** Recreating a communicator every step costs `48.0 ms` init + `0.5 ms` AllReduce = `48.5 ms` vs `0.5 ms` when initialized once (`98.97%` reduction, `97.0x` speedup).
   - **Ring vs Tree & SHARP (`V13` Ch. 8, `ASP` Ch. 4):** For `28 GB` `FP32` gradients, an `8`-GPU Ring on `900 GB/s` NVLink moves `49.0 GB` in `54.4 ms` (`8` hops), whereas a `512`-GPU Ring on `25 GB/s` IB moves `55.89 GB` in `2.24 s` (`512` ring hops vs `9` tree hops). In-network SHARP reduces per-GPU receive volume from `B*(N-1)/N` to `B/N` (`1/(N-1)` factor, `2x–5x` AllReduce speedup).
   - **Straggler Identification (`V13` Ch. 11 & `ASP` Ch. 13 HTA):** In synchronous collectives, 63 fast nodes show a `200 ms` `ncclKernel_AllReduce` wait while the 1 straggler node (`node-14-straggler`) shows **zero wait** and extended compute/transfer time.    - **Thermal Throttling & Silent Fallback Runbooks (`V13` Ch. 8, 11, 12):** MFU decay from `45%` to `28%` over 24 hours (`37.78%` relative drop, mirroring SM clock throttling from `1,800 MHz` to `1,120 MHz` under `>83–85°C` thermal limits); stopped `nvidia-fabricmanager` after reboot dropping throughput from `950 tok/s` to `310 tok/s` (`67.37%` loss) and `nccl-tests` `busbw` from `800 GB/s` to `90 GB/s` (or `400 GB/s` to `20 GB/s` on a broken NVLink bridge showing `PIX` instead of `NV#`); MoE `AllToAll` router collapse dropping throughput to `25%` at uniform `40–50%` GPU util.
