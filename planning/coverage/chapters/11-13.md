## Checklist of Concepts, Numbers, and Patterns to Cover
1. **Six Reasons Default `kube-scheduler` Breaks Down on Shared GPU Clusters (`GAK Ch 7`, `volume-23/chapter-07`, `volume-23/chapter-12`):**
   1. **Per-Pod Scheduling vs Atomic Gang Placement:** Default `kube-scheduler` schedules Pods one by one, leading to `7`-of-`8` partial-allocation rendezvous deadlocks (`56` GPUs idle).
   2. **Static Hard `ResourceQuota` Silos vs Dynamic Borrowing / Fair-Share (`60%` vs `85%` utilization):** In `volume-23/chapter-07`, a `32`-GPU (`4`-node) cluster supports `3` teams (`research`: `16` GPUs / `50%`, `data-eng`: `12` GPUs / `37.5%`, `interns`: `4` GPUs / `12.5%`). Giving each team dedicated nodes or rigid non-borrowable quotas leaves utilization at **`60%`**, whereas dynamic fair-share borrowing raises cluster-wide utilization to **`85%`** (`93%` in the `700 / 750` GPU-hour Professor A/B example).
   3. **Bimodal Research Workload Contention ("Alice's `5`-minute notebook vs Bob's `3`-month `64`-GPU LLaMA run"):** In `volume-23/chapter-12` (`50` teams on `200` GPUs across `25` nodes; `60%` short `< 1` hr, `30%` medium `1–8` hr, `10%` long `> 24` hr up to `72` hr), FIFO queues let long jobs starve interactive notebooks unless the scheduler tracks historical usage deficits (`deficit = (current_usage - quota) / quota`) and supports graceful checkpoint-aware preemption.
   4. **Whole-Integer GPU Allocation vs Native Fractional / Time-Sliced GPU Sharing:** Default `kube-scheduler` only understands whole integers (`nvidia.com/gpu: 1`); it cannot natively bin-pack `0.25` or `0.5` of a GPU or reserve fractional GPU memory (`gpu-memory`) per container without external scheduler intelligence.
   5. **Blindness to GPU Interconnect Topology (`NVLink`, `NVSwitch`, `InfiniBand`):** Default `kube-scheduler` treats `8` GPUs scattered across `8` Ethernet nodes the same as `8` GPUs on `1` NVSwitch node (`900 GB/s`), whereas KAI Scheduler natively integrates with the NVIDIA GPU Operator to place multi-GPU jobs on optimal NVLink/InfiniBand domains.
   6. **Lack of Hierarchical Department -> Project Quotas:** Default Kubernetes `ResourceQuota` is flat (namespace-only) and cannot model multi-level organizational trees (`Department -> Project / Team`) where unused quota flows first to sibling teams in the same department before being lent to other departments.
2. **What is NVIDIA KAI Scheduler (`kai.run.ai/v1`, `schedulerName: kai-scheduler`) (`GAK Ch 7`):**
   - Open-sourced core scheduling engine originally developed by **Run:ai** (acquired by NVIDIA).
   - How KAI Scheduler centralizes **four** capabilities in a single GPU-native scheduler (`Table 7-2`, `Table 7-3`, `Table 7-4` in `GAK Ch 7`):
     1. **Project-based hierarchical quotas & fair-share algorithms** (`apiVersion: kai.run.ai/v1`, `kind: Project`, `gpuQuota: 8`, bound via annotation `kai.run.ai/project: ml-team-a` and `schedulerName: kai-scheduler` in `GAK` Example 7-5).
     2. **Integrated gang scheduling** (co-scheduling aggregated workload APIs such as `PyTorchJob`, `TrainJob` / `JobSet`, `LeaderWorkerSet`, and `RayJob`).
     3. **Native NVIDIA GPU topology-aware placement** (understanding NVLink, NVSwitch, MIG, and InfiniBand without manual affinity rules).
     4. **Dynamic fractional GPU and time-sliced allocation** (consolidating lightweight inference and interactive Jupyter notebooks onto shared GPUs).
3. **Fair-Share Deficit Math & Graceful Preemption Timeline (`volume-23/chapter-07` & `chapter-12`):**
   - Deficit formula: `deficit = (current_usage - quota) / quota` and `priority = -deficit + (0.1 if gpu_count < 4 else 0)`.
   - Worked Professor A (`$100K` -> `500` GPU-hr/month quota, uses `600` -> `deficit = +0.20` / `-100` hr balance) vs Professor B (`$50K` -> `250` GPU-hr/month quota, uses `100` -> `deficit = -0.60` / `+150` hr surplus; `700 / 750 = 93.33%` / `~93%` utilization).
   - Graceful `30`-second `SIGTERM` preemption timeline (`0s` `SIGTERM` -> `5–10s` save checkpoint to `/local_nvme` or `/nfs/checkpoints` / `gs://` -> `30s` `SIGKILL` deadline -> `45s` new job starts -> `90s` preempted job resumes on next available GPU, losing only `~2` minutes of wall-clock time and `0` training steps).
4. **When to Choose KAI Scheduler vs Kueue vs Volcano (`GAK Ch 7`):**
   - Standalone KAI Scheduler vs **Layered Kueue + KAI Scheduler** (where Kueue handles multi-cluster/ResourceFlavor admission and KAI handles GPU-aware placement).
