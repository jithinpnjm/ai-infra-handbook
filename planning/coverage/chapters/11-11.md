## Checklist of Concepts, Numbers, and Patterns to Cover
1. **Why Kubernetes Needs a Separate NVIDIA Network Operator (`volume-06/01`, `volume-06/02`, `volume-10/chapter-06`, `bcm11-containerization`):**
   - Straggler amplification in synchronous collectives (`AllReduce`, `AllGather`, `ReduceScatter`, `Send/Recv`): `1` dropped packet stalls thousands of GPUs at the barrier, tanking Model Flops Utilization (`MFU`).
   - InfiniBand (`NDR`/`XDR`, `200` Gbps HDR at `~25 GB/s` / `400` Gbps NDR at `~50 GB/s`, credit-based flow control, Adaptive Routing, Subnet Manager `OpenSM`/`UFM`, `LRH 8B`, `GRH 40B`, `BTH 12B`, `ICRC 4B`, `VCRC 2B`) vs RoCEv2 (`Spectrum-X` Spectrum-4 + BlueField-3 SuperNICs, UDP destination port `4791`, `PFC` IEEE 802.1Qbb on Priority `3` / DSCP `24` or `26`, `ECN` `minimum-absolute 150` / `maximum-absolute 1500`, `DCQCN`, `CNP` BTH opcode `0x81`, `PFC Watchdog` `50ms` deadlock breaker).
   - Three physically separated AI Factory fabrics: **Compute Fabric (Backend)**, **Storage Fabric (Frontend)**, and **Management Fabric**.
   - Division of labor between **NVIDIA GPU Operator** (`ClusterPolicy`, `nvidia.ko`, `nvidia.com/gpu`) and **NVIDIA Network Operator** (`NicClusterPolicy`, version `26.1.1` in BCM 11 on Kubernetes `1.35`, `ofedDriver`, `nvPeerDriver` / `nvidia-peermem`, `rdmaSharedDevicePlugin` vendor `15b3`, `sriovNetworkOperator`, `secondaryNetwork` with Multus + CNI plugins + Whereabouts IPAM).
2. **NVIDIA Network Operator Architecture, Operands, and Helm / `NicClusterPolicy` Configuration (`volume-06/02` §5, `bcm11-containerization` §6.8 & §6.9):**
   - Five core operands reconciled by Network Operator:
     1. **`ofedDriver` (MOFED / DOCA-OFED DaemonSet):** Compiles/loads `mlx5_core`, `ib_core`, `ib_uverbs` into the host kernel.
     2. **`nvPeerDriver` (`nvidia-peermem` DaemonSet):** Bridges `ib_core` and the NVIDIA GPU driver for GPUDirect RDMA (or coordinated via DOCA-driver / GPU Operator `driver.rdma.enabled: true`).
     3. **`rdmaSharedDevicePlugin`:** Exposes `rdma/rdma_shared_device_a` (or `rdma/hca`) for Mellanox/NVIDIA NICs (`vendors: ["15b3"]`).
     4. **`sriovNetworkOperator` / SR-IOV Network Device Plugin:** Reconciles `SriovNetworkNodePolicy` (`priority: 99`, `mtu: 9000`, `numVfs: 8`, `pfNames: ["enp1s0f0"]`, `isRdma: true`) and `SriovNetwork` (`vlan: 100`, `10.10.100.0/24`).
     5. **`secondaryNetwork`:** Deploys Multus CNI, CNI plugins (`macvlan`, `ipoib`, `sriov`, `ib-sriov`), and Whereabouts IPAM.
   - **NVIDIA NetQ Operator (`bcm11-containerization` §6.9):** Fabric telemetry and validation (`NetQ 4.15+` on Ubuntu `24.04`, `1` or `3` compute nodes with `>= 250 GiB` disk and `>= 64 GiB` RAM, shifting BCM `cmd` ports from `8081` to `--http 8083 --https 8084`, NodePort `30029` or cluster VIP `10.141.255.253`).
3. **Validating RDMA Fabrics (`ibstat`, `ibv_devinfo`, `ib_write_bw`, `ibdiagnet`, `tcpdump` port `4791`):**
   - `ibstat` on InfiniBand (`CA 'mlx5_0'`, `MT4123`, `fw_ver: 20.31.1014` or `20.36.1010`, `State: Active` / `PORT_ACTIVE (4)`, `Physical state: LinkUp`, `Rate: 200 (HDR)`, `Base lid: 32`, `SM lid: 1`, `Link layer: InfiniBand`) vs RoCEv2 (`CA 'mlx5_1'`, `Rate: 400`, `Base lid: 0`, `SM lid: 0`, `Link layer: Ethernet`).
   - `ib_write_bw -d mlx5_0 -i 1` (`65536` bytes, `5000` iterations, `TX depth: 128`, `Mtu: 4096[B]`, `BW peak: 23500.2 MB/sec`, `BW average: 23450.5 MB/sec`, `MsgRate: 0.375208 Mpps`).
   - `ibdiagnet -c 1000` (`ibdiagnet2.pm` symbol errors / flapping port heavy sweeps) and `tcpdump -i <netdev> -nn -e -v udp port 4791` (`ibdump` / SPAN for BTH opcode `0x81` CNPs).
4. **Storage Fabric Integration, GPUDirect Storage (`GDS`), and CSI (`volume-06/03`):**
   - Four storage tiers: **Tier 0 HBM** (`40GB`/`80GB` A100 `1.5-2.0 TB/s`, `80GB` H100 `~3.35 TB/s`, `141GB` H200 `~4.8 TB/s`, `192GB` B200 `~8 TB/s`), **Tier 1 Host NVMe** (`8x 3.84TB` RAID 0 on DGX H100), **Tier 2 Parallel File System** (`WEKA`, `Lustre`, `GPFS`, `VAST`), **Tier 3 Object Store** (`S3`, `MinIO`, `Ceph`).
   - **GPUDirect Storage (`GDS`):** `nvidia-fs.ko` (`nvidia_fs 217088`), `libcufile.so`, `/usr/local/cuda/gds/tools/gdscheck -p`, `/etc/cufile.json` (`max_device_pinned_mem_size_kb: 33554432`, `poll_mode_max_size_kb: 4`, `allow_compat_mode: true`/`false`), WEKA CSI (`csi.weka.io`, `/dev/shm` `sizeLimit: 400Gi`), `fio` (`bs=2M`, `size=500G`, `numjobs=32`, `iodepth=128` for dataset reads; `bs=8M`, `size=100G`, `numjobs=8`, `iodepth=64`, `fsync=1000` for checkpoint writes), `mdtest` (`mpirun -np 128 mdtest -i 5 -b 10 -z 3 -L -I 100000`), and troubleshooting cascading `D`-state hangs (`rpc_wait_bit_killable` > `120`s, load average `500+`, `symbol_error_counter > 1000`) and MDS small-file saturation (`14` million `20KB` `.png` files, `85.12%` time in `stat` vs `0.81%` in `read` -> `50,000`-image `1GB` `WebDataset` tarballs).
