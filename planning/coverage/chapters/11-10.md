## Checklist of Concepts, Numbers, and Patterns to Cover
1. **Kubernetes Pod Networking Foundations & Why Default CNI Overlays Bottleneck AI (`PK Ch 5`, `volume-03/03`, `GAK Ch 7`):**
   - IP-per-Pod model and IPAM (`kubeadm init --pod-network-cidr 10.30.0.0/16` = `65,534` usable IPs out of `65,536`, `--node-cidr-mask-size-ipv4` `/24` = `254` usable IPs from `10.30.0.0 - 10.30.0.255`, default `110` max Pods per node, dual-stack `2002:1:1::/96`).
   - Routing vs Encapsulation (`PK Ch 5`): BGP native routing (`Calico` `BIRD` + `Felix`, `IPPool` `blockSize: 29`, `ipipMode: Always` vs `CrossSubnet`, `BGPPeer` `192.23.11.100` `asNumber: 64567`) vs VXLAN/Geneve overlays (UDP encapsulation overhead, MTU reduction, kernel context switches) vs AWS VPC CNI secondary ENI IPs.
   - `kube-proxy` `iptables` $O(N)$ linear rule evaluation vs **Cilium eBPF** (`XDP` / `tc` hooks, `KubeProxyReplacement: strict`, $O(1)$ hash-table service lookups, `CiliumNode` `cluster-pool-ipv4-mask-size: "24"`, `05-cilium.conf` in `/etc/cni/net.d/`, binaries in `/opt/cni/bin/`, CNI operations `ADD`, `DELETE`, `CHECK`, `VERSION`, and `CiliumNetworkPolicy` DNS/FQDN egress filtering on port `53` / `443`).
   - North-South vs East-West traffic inversion in AI (`GAK Ch 7` Table 7-5: `10–25 Gbps` / `100 Gbps` TCP Ethernet at tens-to-hundreds of $\mu$s vs `100–400 Gbps` RoCEv2 at low $\mu$s vs `200–400 Gbps` InfiniBand at sub-$\mu$s with `40%–60%` GPUDirect RDMA latency reduction; `<15%` vs `20%–25%` communication step-time threshold).
2. **Multus CNI Meta-Plugin & `NetworkAttachmentDefinition` (`PK Ch 5`, `GAK Ch 7`, `volume-03/03`, `volume-06/02`):**
   - How Multus preserves `eth0` on the primary CNI (`Calico`/`Cilium`) for Kubernetes control-plane/service traffic while attaching `net1`, `net2`..`net8` from `NetworkAttachmentDefinition` (`k8s.cni.cncf.io/v1`) CRDs via Pod annotation `k8s.v1.cni.cncf.io/networks`.
   - Three secondary CNI data-plane modes:
     1. **IPoIB (`type: ipoib` / `master: ib0`, `GAK` Example 7-10):** `cniVersion: 0.3.1`, `whereabouts` IPAM (`10.0.0.0/24`, `exclude: ["10.0.0.1/32"]`, InfiniBand `MTU 4,096`).
     2. **Macvlan (`type: macvlan`, `volume-06/02` §5.3):** `master: eth1`, `mode: bridge`, `whereabouts` (`192.168.100.0/24`) paired with `rdma/rdma_shared_device_a: 1` (shares the physical function PF; single-tenant friendly, lacks hardware QoS/rate-limiting isolation).
     3. **SR-IOV (`type: sriov` / `ib-sriov`, `volume-03/03` §2.3 & `volume-06/02` §6.2):** Hardware-isolated Virtual Functions (`VFs`) with `k8s.v1.cni.cncf.io/resourceName: nvidia.com/hostdev` (or `sriovnetwork.openshift.io/rdma_vf`), `vlan: 100`, `mtu: 9000`, `whereabouts` (`192.168.10.0/24` excluding `.1/32` and `.254/32`, or `10.10.100.0/24`).
3. **RDMA Shared Device Plugin vs SR-IOV Network Device Plugin (`volume-06/02`, `GAK Ch 7`):**
   - PCIe Vendor ID `15b3` (Mellanox / NVIDIA ConnectX) vs `10de` (NVIDIA GPU).
   - **RDMA Shared Device Plugin (`rdmaSharedDevicePlugin`):** Allows multiple Pods to share a physical HCA (`rdma/hca: 2` or `rdma/rdma_shared_device_a: 1`), exposing `/dev/infiniband/` (`uverbs0`, `rdma_cm`) into the container.
   - **SR-IOV Network Device Plugin (`SriovNetworkNodePolicy` & `SriovNetwork`):** Carves `1` Physical Function (`PF`, `pfNames: ["enp1s0f0"]`) into `numVfs: 8` PCIe Virtual Functions (`deviceType: netdevice`, `isRdma: true`, `priority: 99`, `mtu: 9000`, `vlan: 100`), reporting each VF's NUMA node to `kubelet` Topology Manager so GPU, CPU, and VF align on the same PCIe switch (`PIX`) and rail (`Rail 1..8`).
4. **End-to-End Pod Wiring (`IPC_LOCK`, `NCCL_*`) and Verification (`GAK` Examples 7-11 & 7-12, `volume-06/02` §4.3 & §7):**
   - `securityContext.capabilities.add: ["IPC_LOCK"]` for pinning RDMA memory buffers.
   - `NCCL_DEBUG=INFO`, `NCCL_IB_HCA="mlx5_0,mlx5_1"`, `NCCL_IB_GID_INDEX="3"` (RoCEv2 IPv4 GID), `NCCL_IB_TC="106"`, `NCCL_IB_QPS_PER_CONNECTION="4"`, `NCCL_NET_GDR_LEVEL="5"`, `NCCL_SOCKET_IFNAME="net1"`.
   - 3-command verification (`ip addr show net1`, `ls /dev/infiniband/`, `kubectl logs ... | grep "NCCL INFO"` confirming `Using network IB` and `NET/IB/GDRDMA` rather than `NET/Socket : Using [0]eth0`).
