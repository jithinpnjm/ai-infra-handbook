## 4. One-Line Expected Exercise Solutions

1. **Exercise 1 (Occupancy & `__launch_bounds__`):** (a) `0.30 * 64 = 19.2` (`~19` active warps/SM); (b) `256 * 80 = 20,480` regs/block fits `65,536 // 20,480 = 3` blocks (`24` warps = `37.5%` theoretical occupancy, `LIMITED_BY_REGISTERS_PER_THREAD`); (c) `__launch_bounds__(256, 8)` targets `8 * 256 = 2,048` threads (`64` warps = `100.0%` occupancy) and caps registers at `65,536 // 2,048 = 32` registers/thread.
2. **Exercise 2 (4 execution regimes):** (a) `UNDERUTILIZED` (increase grid/batch size or use CUDA Graphs); (b) `MEMORY_BOUND` (apply shared-memory tiling, kernel fusion, coalescing/vectorizing, or FP8/FP4); (c) `LATENCY_BOUND` on `EXEC_DEPENDENCY` with `1.4 < 4` eligible warps/cycle (break dependency chains, expose `2–4x` ILP with `#pragma unroll`, or raise occupancy); (d) `COMPUTE_BOUND` on `MATH_PIPE_THROTTLE` (use lower-precision Tensor Cores `FP16`/`FP8`/`NVFP4` or 2:4 sparsity).
3. **Exercise 3 (Predication Table 8-3):** In `threshold_naive`, a 50/50 split executes both `if` and `else` paths serially (`50%` active lanes per pass); replacing with `float val = (x > threshold) ? x : 0.0f;` (or `@torch.compile def f(X): return torch.maximum(X, torch.zeros_like(X))`) cuts runtime `30 → 15 ms` (`-50%`), dynamic instructions `600M → 300M` (`-50%`), branch stall latency `200 → 100` cycles (`-50%`), lifts warp execution efficiency `50% → 99%`, and drops predicated-off threads `50% → 0%`.
4. **Exercise 4 (Warp-unanimous branching):** `threadIdx.x % 2 == 0` splits even and odd lanes inside *every* warp (`16` vs `16` lanes = `50%` warp execution efficiency), whereas `int warpId = threadIdx.x / 32; if (warpId % 2 == 0)` is identical across all 32 lanes of any given warp, so even warps run `Task A` at `100%` efficiency and odd warps run `Task B` at `100%` efficiency (`0` divergence).
5. **Exercise 5 (ILP Table 8-4 & dependency reordering):** Saturation requires `ILP 1: 1,536` threads (`48` warps, `75%`), `ILP 2: 1,024` threads (`32` warps, `50%`), `ILP 3: 768` threads (`24` warps, `37.5%`), and `ILP 4: 512` threads (`16` warps, `25%`); reorder to `float u = x * x; float v = y * y; float temp = u + 1.0f;` so `v = y * y` issues immediately while `u = x * x` is in flight.
6. **Exercise 6 (Blackwell unified `INT32`/`FP32` cores):** On Blackwell (`sm_100`), `INT32` and `FP32` execution units are unified into a single core per lane that executes either `FP32` or `INT32` in a given cycle (never both on the same core in the same cycle); each of the 4 warp schedulers can instead dual-issue one arithmetic instruction (`FP32`, `INT32`, or Tensor Core) paired with one memory (`LD/ST`) instruction from the same warp.
