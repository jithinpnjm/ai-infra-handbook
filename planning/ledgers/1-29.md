## 4. One-Line Expected Exercise Solutions

1. **Exercise 1 (The 7-Step SSH Session Sequence, Host Keys, and RFC 4716 Conversion):** (a) The 7 steps are: (1) establish an encrypted symmetric channel via Diffie-Hellman key exchange, (2) authenticate the **server's host key** against `~/.ssh/known_hosts`, (3) send the target username, (4) offer client public keys one by one, (5) server checks `~/.ssh/authorized_keys`, (6) server sends a challenge signed by the client's private key (which never leaves the client), and (7) start the shell/command; (b) preserve `/etc/ssh/ssh_host_*` across node reinstalls, always append (`>>`) to `authorized_keys` (`700` `~/.ssh`, `600` `authorized_keys`), and convert multi-line RFC `4716` keys with `ssh-keygen -i -f rfc-key.pub >> ~/.ssh/authorized_keys`.
2. **Exercise 2 (`sshd_config` Access Evaluation Order, `Match` Blocks, and Key Restrictions):** (a) OpenSSH evaluates access rules in the strict order `DenyUsers -> AllowUsers -> DenyGroups -> AllowGroups` (`evaluate_sshd_access_rules()`), so a `DenyUsers` match rejects immediately and a non-empty `AllowUsers` rejects anyone not listed even if their group is in `AllowGroups`; (b) use `Match Group sftponly` (`ForceCommand internal-sftp`, `AllowTcpForwarding no`, `X11Forwarding no`) for SFTP-only accounts and prefix monitoring keys in `authorized_keys` with `from="10.0.0.0/8",command="/usr/local/bin/status-only",no-port-forwarding,no-pty`.
3. **Exercise 3 (Host-Based Authentication vs. SSH Keys):** Host-based authentication (`HostbasedAuthentication yes` in a `Match Address` block, `/etc/shosts.equiv`, `/etc/ssh/ssh_known_hosts` populated via `ssh-keyscan`, and `EnableSSHKeysign yes` on the client) lets trusted cluster nodes log in without per-user keys, but compromising any single trusted host compromises all others.
4. **Exercise 4 (Parallel Fan-Out with `pdsh` and ClusterShell `clush` / `cluset`):** A sequential `for h in ...; do ssh ...; done` loop interleaves unlabelled output and hangs indefinitely on one dead node; `pdsh` (`pdsh -w node-[01-64] -x node-13 -f 32 -u 10 uptime | dshbak -c`) and `clush` (`clush -b --diff -w @sp:main` or `@st:idle`) execute in parallel with fan-out caps, timeouts, output folding/diffing, and Slurm state integration.
5. **Exercise 5 (`screen` vs. `tmux` Multiplexers and Nested Escape Sequences):** Attach/create idempotently with `screen -xRR` (prefix `Ctrl-a`) or `tmux new -A -s 0` (prefix `Ctrl-b`), never put slow external commands in the status bar, and when connected to an IPMI Serial-over-LAN (`sol activate`) console inside an SSH session, type `<Enter>~~.` (`compute_ssh_nested_escape(2, ".")`) so the outer SSH passes `~.` through to close SOL rather than dropping your outer SSH connection.
6. **Exercise 6 (Out-of-Band BMC/IPMI Pre-Configuration, `ipmitool`, `conman`/`powerman`, and `iKVM`):** Enable BMC network access, DHCP/MAC inventory, and non-default passwords *before* deploying nodes; use `ipmitool -I lanplus -H 10.0.1.2 -U admin -f /root/.ipmipass` (never `-P` on the command line, and prefer `power off` + sleep + `power on` over `power cycle`), pair with `conman` (always-on logged serial consoles) and `powerman` (IPMI/PDU power control), and isolate all BMCs on a dedicated management VLAN.
