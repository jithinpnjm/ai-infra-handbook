## 4. One-Line Expected Exercise Solutions

1. **Exercise 1:** (a) Llama-3-70B GQA (`H_kv = 8`) uses **`327,680 bytes = 320 KiB/token`**, **`1.25 GiB`** at `S = 4,096`, and **`39.06 GiB`** (`39.0625 GiB`) at `S = 128,000`—an **`87.5%` (`8x`) reduction** compared to MHA (`2,621,440 bytes = 2.50 MiB/token` binary / `2.56 MB` decimal, `312.5 GiB` at `128K`); (b) at `S_actual = 500, B = 16, S_max = 4,096`, PagedAttention allocates **`32` physical blocks (`512` slots, `12` unused slots = `2.40%` internal fragmentation, bounded by `< 16 / 500 = 3.20%`)** versus **`87.79%` contiguous waste** (`3,596 / 4,096`), and on batch lengths `[4, 7, 3]` contiguous padding computes `21` positions for `14` real tokens (**`33.33%` wasted padding FLOPs**) versus **`14` positions (`0%` waste)** in PagedAttention.
2. **Exercise 2:** (a) A `35`-token prompt at `block_size = 16` allocates **`3` physical blocks** (`2` full blocks for tokens `0..31` + `1` partial tail block with `3` tokens `32..34`), all shared with **`ref_count = 4`** across branches `10..13`; appending token `36` on branch `11` triggers Copy-on-Write **only on the 3rd (tail) block**, leaving the first `2` full blocks at **`ref_count = 4`**, the original 3rd block at **`ref_count = 3`**, and the newly allocated tail block for branch `11` at **`ref_count = 1`**; (b) RAG processes **`5,500` uncached prefill tokens** (`5.0 s` TTFT, **`$0.007` per request**) whereas Long-Context CAG caches `100,500` tokens and processes only **`500` uncached tokens** (`11x` fewer), cutting TTFT `10x` to **`0.5 seconds`** at **`$0.013` per request**.
3. **Exercise 3:** (a) With `45` active decode tokens and `long_prefill_token_threshold = 512`, each step schedules **`45 + 512 = 557` tokens** (`<= 2,048` budget), completing the `12,288`-token prompt across **`24` iteration steps** (`12,288 / 512`) while keeping p99 ITL at `21.4 ms` (`< 25 ms`); (b) transferring `4 GB` across `64 GB/s` PCIe takes **`62.5 ms` one-way (`125.0 ms` round-trip)**; at `S = 4,096` on H100 (`989 TFLOPS`), **`t_recompute = 29.01 ms < t_swap = 167.77 ms` (select `recompute` and `--swap-space 0`)**, whereas at ultra-long `S = 65,536`, quadratic `O(S^2)` prefill makes **`t_recompute = 3,661.07 ms > t_swap = 2,684.35 ms` (select `swap` / LMCache offloading)**.
4. **Exercise 4:** (a) For Llama-3-70B (`140 GB` weights, `8 GB` workspace, `0.90` util), `4x 80 GB` (`TP=4`, `320 GB` total) leaves a **`140.0 GB` KV pool** supporting **`C_max = 218` (`S=2048`), `54` (`S=8192`), and `13` (`S=32768`)** requests, while `8x 80 GB` (`TP=8`, `640 GB` total) leaves a **`428.0 GB` KV pool** supporting **`C_max = 668` (`S=2048`), `167` (`S=8192`), and `41` (`S=32768`)** requests with **`160` synchronous AllReduces per token** (`2 * 80` layers); (b) DeepSeek-R1 (`671B`, `256` experts, `D = 8,192`) at `TP=4, PP=8` uses **`32` GPUs**, holds **`~83.9B` (`~84B`) parameters per stage**, and transfers **`2,048` elements per token** (`8,192 / 4`) across stage boundaries; with `--enable-expert-parallel` on `8` GPUs (`EP_SIZE = 8`), each GPU holds **`32` complete experts** (`256 / 8`), using **`all_reduce`** under `TP=8, DP=1` and **`all_to_all`** (with DP Attention partitioned KV cache) under `TP=1, DP=8`.
5. **Exercise 5:** (a) One rank-`16` LoRA adapter across `4` projections/layer on a `32`-layer `8B` model (`d = 4,096`) contains **`16,777,216` parameters (`32.0 MB` in BF16, `0.2097% < 1%` of base weights)**; co-locating `8` active adapters with the `16.0 GB` base model requires **`16.2684 GB` total HBM** and **saves `7` GPUs** (`1` GPU instead of `8`); (b) in Lab 03, `14,258` blocks of `16` tokens (`228,128` tokens) divided by `4,096` yields **`55.69x` maximum concurrency** (`55.695x`), while `120` blocks at `0.25` utilization hold only **`1,920` tokens** (`120 * 16`), causing a `1,500`-repetition prompt + `2,048` max output tokens to fail with `BadRequestError` while `vllm:gpu_cache_usage_perc` approaches `1.0` and `vllm:num_preemptions_total` increments.
