## 4. One-Line Expected Exercise Solutions

1. **Exercise 1 (Kubernetes Release Cadence, Version Skew Policy, and Detecting Deprecated APIs):** `validate_k8s_version_skew()` verifies HA `kube-apiserver` skew $\le 1$ minor, controllers $\in [n-1, n]$, `kubelet`/`kube-proxy` $\in [n-3, n]$, and `kubectl` $\in [n-1, n+1]$; deprecated APIs are caught before upgrades via `apiserver_requested_deprecated_apis`, audit log `k8s.io/deprecated: "true"`, `pluto`, and `kubent`.
2. **Exercise 2 (Executing a 3-Control-Plane `kubeadm` Upgrade and Avoiding Static-Pod / `etcd` Pitfalls, `PK` Ch. 2 & `bcm11-containerization` App. C):** Run `kubeadm upgrade apply` on `cp1` and `kubeadm upgrade node` on `cp2`/`cp3` and workers, persist custom manifest changes in `ClusterConfiguration` (`extraArgs`/`--patches`), and use `evaluate_etcd_upgrade_quorum_safety()` to avoid subtractive `3 -> 2 -> 3` dedicated `etcd` replacement (which drops fault tolerance to `0` during replacement).
3. **Exercise 3 (Upgrading the NVIDIA GPU Operator and Driver Stack Without Killing Training Jobs):** Upgrade compatible operators/CRDs first, then Kubernetes, and use `ClusterPolicy.spec.driver.upgradePolicy` (`maxParallelUpgrades`, `drain`, `waitForCompletion`) to cordon, checkpoint-and-drain, reload drivers, and validate with `nvidia-smi` / `dcgmi` / `nccl-tests` batch by batch.
4. **Exercise 4 (`etcd` Backup Automation, Single-Member Replacement, and Full Multi-Member Snapshot Restore):** When 1 of 3 members dies (quorum intact), run `etcdctl member remove` followed by `kubeadm join --control-plane` (no snapshot restore); when quorum is lost, stop `kube-apiserver` and `etcd` on all 3 nodes and run `etcdutl snapshot restore` on all 3 nodes from the same snapshot with `--initial-cluster-token=etcd-cluster-restored-1`, backed by `/etc/kubernetes/pki` CA keys and KMS encryption keys.
5. **Exercise 5 (Workload and Volume Backups with `Velero`):** Velero exports API resources to S3/GCS and backs up PVCs via CSI `VolumeSnapshot`s or `Kopia`/`Restic` filesystem backups (using `pre`/`post` hooks to quiesce databases), and DR test restores must isolate cloud controllers/`external-dns` so test clusters never hijack production DNS or LoadBalancers.
6. **Exercise 6 (Designing Disaster Recovery Tiers `RPO`/`RTO` and Game-Day Runbooks):** `evaluate_dr_rpo_rto()` verifies `checkpoint_interval + offsite_sync_lag <= target_rpo` and `cluster_restore + job_reload <= target_rto`; stateless inference uses multi-zone/region active/active or warm standby (`RPO=0, RTO=minutes`), while 1,000-GPU training uses async cross-region checkpoint replication and resume (`RPO=15-30m, RTO=hours`).
