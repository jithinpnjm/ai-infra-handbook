## 4. One-Line Expected Exercise Solutions

1. **Exercise 1 (Verifying Slinky's Drain-and-Cordon Ownership State Machine):** `reconcile_slinky_node_drain()` transitions an `ALLOCATED` pod selected for scale-in to `DRAINING` (`can_delete_pod=False`), permits deletion once `DRAINED` (`can_delete_pod=True`), preserves external admin drains lacking the `slurm-operator:` prefix on uncordon, and auto-resumes `slurm-operator:` drains to `IDLE`.
2. **Exercise 2 (Designing Slinky CRDs for an HA GPU Cluster):** Deploy `Controller` (with `controller.ha.enabled: true` and an RWX `existingClaim` PVC for `StateSaveLocation`), `NodeSet` (`StatefulSet` for elastic ordinal workers or `DaemonSet` for 1:1 node mapping), `LoginSet`, `Accounting`, `RestApi`, and `Token`.
3. **Exercise 3 (Evaluating Nebius Soperator's Shared `jail` Root Filesystem):** Soperator mounts a shared RWX PersistentVolume as `/` (`chroot` jail) across all `Login` and `Worker` pods to eliminate node-to-node software drift, requiring high-IOPS shared storage to handle `/usr` and Python `import` loads and careful backup against rootfs corruption.
4. **Exercise 4 (Designing `ActiveCheck` Health Probes in Soperator):** Use `k8sJob` `ActiveCheck` CRs for host-level storage/NVMe checks and `slurmJob` `ActiveCheck` CRs for multi-node `nccl-tests` / DCGM checks that automatically drain and replace degraded workers.
5. **Exercise 5 (Configuring Pod QoS, CPU Pinning, and Host RDMA for `slurmd` Worker Pods):** Request integer CPUs and memory (`requests == limits`, `Guaranteed` QoS) with kubelet `static` CPU Manager, Topology Manager alignment, NVIDIA GPU Operator devices, and Network Operator SR-IOV / `hostNetwork` RDMA access.
6. **Exercise 6 (Platform Architecture Decision Matrix):** Choose bare-metal Slurm for a pure MPI/Slurm HPC lab, Slurm-on-Kubernetes (Slinky/Soperator/SUNK) for a neocloud shifting GPU capacity between Slurm training and K8s inference, and native `Kueue` + `JobSet` for a cloud-native Ray/Kubeflow platform.
