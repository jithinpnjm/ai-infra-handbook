## 4. One-Line Expected Exercise Solutions

1. **Exercise 1 (Kernel Module Mechanics, `vermagic`, `depmod`, and `insmod` vs. `modprobe`):** (a) Modules for the running kernel live under `/lib/modules/$(uname -r)/` and contain an embedded `vermagic` string that must match the running kernel (`Invalid module format` on mismatch); (b) `insmod` loads a single `.ko` path without resolving dependencies, whereas `modprobe` reads `modules.dep` (built by `depmod -a`) and `/etc/modprobe.d/*.conf` to load dependencies and apply `options`/`blacklist` rules.
2. **Exercise 2 (Unloading `nvidia.ko`, Blacklisting `nouveau`, and `Driver/library version mismatch`):** (a) To fix `rmmod: ERROR: Module nvidia is in use`, find open `/dev/nvidia*` descriptors (`sudo lsof /dev/nvidia*`, `fuser -v /dev/nvidia*`), stop GPU services (`dcgm`, `nvidia-fabricmanager`, `nvidia-persistenced`), and unload dependent modules in reverse order (`nvidia_drm`, `nvidia_modeset`, `nvidia_peermem`, `nvidia_uvm`, then `nvidia`); (b) after adding `blacklist nouveau` in `/etc/modprobe.d/`, rebuild the `initramfs` (`update-initramfs -u` / `dracut -f`) so early boot does not load `nouveau`, and reload/reboot after a driver package upgrade to clear `Driver/library version mismatch`.
3. **Exercise 3 (DKMS Failure Modes vs. Precompiled `kABI` / Golden Images at Fleet Scale):** DKMS builds fail on nodes due to missing/mismatched `linux-headers-$(uname -r)`, compiler version drift, kernel API changes, unsigned modules under Secure Boot, or fleet-wide compile boot storms; production GPU fleets compile once in CI and ship precompiled `kmod` packages (RHEL `kABI` or Ubuntu `linux-modules-nvidia-*`) or immutable golden images with `apt-mark hold` / `dnf versionlock`.
4. **Exercise 4 (The NVIDIA Driver Stack, Open vs. Proprietary Modules, and CUDA Compatibility):** `nvidia_uvm` provides CUDA Unified Virtual Memory (`/dev/nvidia-uvm`), `nvidia_peermem` enables GPUDirect RDMA with `ib_core`/`mlx5_ib`, `nvidia-fs` enables GPUDirect Storage, `nvidia-fabricmanager` configures NVSwitch routing on HGX/DGX nodes, and `nvidia-persistenced` keeps the driver initialized (`1–2 s` saved); CUDA `12.x` requires host driver `R525+` and CUDA `13.x` requires `R580+` (unless `cuda-compat` forward compatibility is installed).
5. **Exercise 5 (UEFI Secure Boot, Kernel Lockdown, and Signing Out-of-Tree `.ko` Modules):** Under UEFI Secure Boot, kernel lockdown rejects unsigned `.ko` modules with `Required key not available`; generate an X.509 keypair (`MOK.priv` / `MOK.der`), enroll `MOK.der` via `sudo mokutil --import MOK.der`, sign the module with `/usr/src/linux-headers-$(uname -r)/scripts/sign-file sha256 MOK.priv MOK.der nvidia.ko`, and verify with `modinfo -F signer nvidia`.
6. **Exercise 6 (GPU Node `sysctl` Tuning, `DefaultLimitMEMLOCK=infinity`, and Safe Rollout):** Set `vm.swappiness=1`, `vm.max_map_count=1048576`, `vm.dirty_background_bytes` / `vm.dirty_bytes`, and `kernel.numa_balancing=0` in `/etc/sysctl.d/90-gpu-node.conf` (and `DefaultLimitNOFILE=1048576`, `DefaultLimitMEMLOCK=infinity` in `/etc/systemd/system.conf.d/limits.conf`), noting that `net.core.rmem_max` affects only kernel TCP/UDP sockets and not hardware RDMA verbs.
