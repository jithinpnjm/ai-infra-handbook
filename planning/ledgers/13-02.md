## 4. One-Line Expected Exercise Solutions

1. **Exercise 1:** (a) `DGX H100/H200` has `1.92 TB` usable OS (`2 x 1.92 TB` M.2 `RAID 1`) and `30.72 TB` usable `/raid` scratch (`8 x 3.84 TB` U.2 `RAID 0`), while a `GB200/GB300` compute tray has `1.92 TB` OS (`1 x 1.92 TB` M.2) and `15.36 TB` `/raid` (`4 x 3.84 TB` E1.S `RAID 0`, `18 x 15.36 = 276.48 TB` per rack); `/raid` uses `RAID 0` for `100%` capacity/bandwidth on ephemeral data while OS uses `RAID 1` to survive a boot-drive failure; (b) `8 x 512 KB` = `4096 KB` (`4.0 MB`) full stripe, `sunit = 128`, `swidth = 1024` (`64 KB` read activates `1/8 = 12.5%` of drives vs `4 MB` activating `8/8 = 100%`); `4 x 256 KB` = `1024 KB` (`1.0 MB`) full stripe, `sunit = 64`, `swidth = 256`.
2. **Exercise 2:** (a) Inline staging takes `245 + 9 * 200 = 2,045 s` vs `10 * 245 = 2,450 s` uncached, saving **`405 s`** (**`16.53%` speedup**); (b) explicit pre-staging copy takes `500 / 2.0 = 250 s`, break-even is `250 / (245 - 200) = 5.5556` epochs (**`6` integer epochs**), losing **`115 s`** on a `3`-epoch run (`850 s` vs `735 s`) and saving **`20 s`** on a `6`-epoch run (`1,450 s` vs `1,470 s`).
3. **Exercise 3:** (a) Synchronous Lustre write takes `500 / 1.2 = 416.67 s` (`~417 s`), local NVMe write takes `500 / 3.5 = 142.86 s` (`~143 s`), and `1.0 s` async handoff yields a **`416.67x` (`~417x`) critical-path speedup**; (b) minimum checkpoint interval without double-buffering is `>= 416.67 s` (`~417 s` background flush duration, or `142.86 + 416.67 = 559.53 s` if sequential).
4. **Exercise 4:** (a) Remediate the `5` issues via `echo none > /sys/block/nvme0n1/queue/scheduler`, `echo 1023 > /sys/block/nvme0n1/queue/nr_requests`, `blockdev --setra 8192 /dev/nvme0n1` (`read_ahead_kb=4096`), `mount -o remount,noatime /raid`, and `numactl --cpunodebind=0 --membind=0 python3 train.py`; (b) for pure random `O_DIRECT` (`GDS`/`3FS`), keep `read_ahead_kb=128` (or lower) since page cache is bypassed; `gdsio` `-x 0` improves throughput by **`+20%`** (`8.0 -> 9.6 GB/s`) and cuts latency by **`-20%`** (`1.25 -> 1.00 ms`).
5. **Exercise 5:** (a) Single `3.84 TB` `1.0 DWPD` `5`-yr drive has **`7,008.0 TBW`** (`56,064 TB` across `8` drives), and `2.5 TB/day` at `WAF 1.2` = **`3.0 TB/day`** NAND (**`0.7812 DWPD`**, **`6.40` years** lifespan); (b) `15.0 TB/day` across `8` drives = **`1.875 TB/day`** host/drive, **`2.25 TB/day`** NAND at `WAF 1.2` (**`0.5859 DWPD`**, **`8.53` years** lifespan); alert/drain at `percentage_used >= 90%`, `available_spare <= 10%`, `temperature >= 70 C`, or `media_errors > 0`.
6. **Exercise 6:** (a) Safe `85%` ceiling is `30,720 * 0.85 = 26,112.0 GB`; without `Epilog`, `job_1001` leaks `12,000 GB` (`39.06%`), so `job_1002` (`16,000 GB`) projects `28,000 GB` (**`91.15% > 85%`**) and fails admission; (b) `Prolog` orphan sweep reclaims `12,000 GB` so `job_1002` is admitted at **`52.08%`** fill (`16,000 / 30,720`), and `Epilog` `rm -rf /raid/job_1002` returns usage to **`0.0%`**.
