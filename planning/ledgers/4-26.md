## 4. One-Line Expected Exercise Solutions

1. **Exercise 1 (The Four OpenGitOps Principles, Pull vs. Push Architecture, and the Two-Repository Pattern):** GitOps systems are Declarative, Versioned/Immutable, Pulled Automatically, and Continuously Reconciled; pull-based agents keep `cluster-admin` credentials inside the cluster and self-heal drift, while separating the App Repo (source/Dockerfile/CI build) from the Config Repo (Kustomize overlays/Helm values) isolates permissions and makes every deploy an auditable Git commit.
2. **Exercise 2 (Argo CD Architecture, `Application` Spec, and `ApplicationSet` Matrix Generators):** Argo CD separates `argocd-server`, `repo-server`, `application-controller`, `applicationset-controller`, and `redis`; `evaluate_gitops_reconciliation()` models `ignoreDifferences` on HPA-managed `/spec/replicas` and `Prune=false` protection on stateful PVCs, while `expand_applicationset_matrix()` crosses matched clusters with Git directories.
3. **Exercise 3 (Flux Architecture `GitRepository`/`Kustomization`/`HelmRelease`, Native SOPS, and Argo CD vs. Flux):** Flux composes `source-controller`, `kustomize-controller` (with native SOPS `age`/KMS decryption and `dependsOn`), `helm-controller` (managing real Helm releases with `crds: CreateReplace`), and `notification-controller`; Argo CD provides a rich UI and renders Helm via `helm template`, whereas Flux is CRD-first and uses native Helm releases.
4. **Exercise 4 (Bootstrapping a GPU Kubernetes Platform in 6 Waves and Platform Operators, `PK` Ch. 11):** `plan_argocd_sync_waves()` sequences `PreSync` -> Wave 0 (namespaces/CRDs) -> Wave 1 (`cert-manager`/CSI/Prometheus CRDs) -> Wave 2 (GPU Operator/Network Operator) -> Wave 3 (Kueue/Volcano/KubeRay) -> Wave 4 (Kyverno/tenancy) -> Wave 5 (apps) -> `PostSync`; `PK` Ch. 11's `AcmeNamespace` operator reconciles child resources with `ownerReferences` and `status.phase`.
5. **Exercise 5 (Config Repository Layout and Progressive Delivery `Argo Rollouts` / `Flagger`):** Represent environments as directories (`clusters/`, `infrastructure/{base,overlays}`, `apps/{base,overlays}`) validated in CI with `kustomize build | kubeconform`, and use Argo Rollouts / Flagger to gate model-server canaries on Prometheus TTFT, latency, and GPU error metrics.
6. **Exercise 6 (Troubleshooting `OutOfSync`/`Progressing`, Multi-Tenant Security, and Break-Glass Incidents):** Resolve `OutOfSync` loops with `ignoreDifferences` and `ServerSideApply=true` (for >256 KiB CRDs); restrict tenants with Argo `AppProject`s or Flux `serviceAccountName` impersonation; and pause reconciliation (`argocd app set --sync-policy none` / `flux suspend`) before applying emergency break-glass fixes.
