## 4. One-Line Expected Exercise Solutions

1. **Exercise 1:** On a `16 GB` T4 with `replicas: 10`, all `10` pods mount `/dev/nvidia0` and share a single unprotected `16 GB` VRAM pool (`0 GB` remaining when `Pod 1` leaks `16 GB`), causing `Pods 2..10` (`9` pods) to crash with `CUDA OOM` because Linux `memory` cgroups only govern host system RAM, not GPU VRAM.
2. **Exercise 2:** The `5` phases are `Single tenant`, `Concurrent active`, `Burst`, `Failure/recovery`, and `Upgrade repeat`; on an `80 GB` A100, `1` replica = `(25%, 12 GB, 8 ms)`, `2` = `(40%, 24 GB, 25 ms)`, `4` = `(55%, 48 GB, 120 ms, 32 GB >= 20 GB headroom)`, and `8` = `(65%, 96 GB > 80 GB OOM, 500 ms)` -> maximum safe setting is **`replicas: 4`**.
3. **Exercise 3:** Export `CUDA_VISIBLE_DEVICES=0`, `CUDA_MPS_PIPE_DIRECTORY=/tmp/nvidia-mps`, `CUDA_MPS_LOG_DIRECTORY=/tmp/nvidia-log`, run `sudo nvidia-smi -i 0 -c EXCLUSIVE_PROCESS`, `nvidia-cuda-mps-control -d`, and `echo set_default_active_thread_percentage 20 | nvidia-cuda-mps-control`; `Client A` crashed during its `12 GB` burst because `CUDA_MPS_PINNED_DEVICE_MEM_LIMIT` capped it at `8 GB` even though `30 GB` of the `40 GB` A100 was free (`10 GB` used in `nvidia-smi`).
4. **Exercise 4:** Set `renameByDefault: true` and `failRequestsGreaterThanOne: true` in the device-plugin ConfigMap (`nvidia.com/gpu.shared`) and apply a `ResourceQuota` in production namespaces with `hard: {"nvidia.com/gpu.shared": "0", "nvidia.com/gpu": "unlimited"}`.
5. **Exercise 5:** The `10` fields are `1. Shared-pool purpose`, `2. Eligible/excluded workloads`, `3. Advertised shared resource name`, `4. Tested replica envelope and date`, `5. Memory and latency assumptions`, `6. Quota scope and admission behavior`, `7. Overload action`, `8. Escalation owner`, `9. Protected-service escape path`, and `10. Rollback action for configuration change`.
6. **Exercise 6:** The `8` items are `Workload version & request rate`, `p50/p95/p99 latency & queue depth`, `Pod allocation & placement history`, `Active-process & memory evidence`, `Device health/power/thermal/error events`, `Node/device-plugin config & events`, `Quota/admission decisions`, and `Actions taken & time to recovery`; joining scheduler allocation records with application latency and host `nvidia-smi --query-processes` overcomes the `dcgm-exporter` container-attribution limitation.
