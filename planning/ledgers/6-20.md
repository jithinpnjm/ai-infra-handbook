## 4. One-Line Expected Exercise Solutions

1. **Exercise 1 (Comparing Erasure Coding Usable Efficiency Across Parallel Filesystems):** `erasure_coding_efficiency(d, p)` computes $D / (D + P)$: `1+1 = 50.0%` (buddy mirror / RAID-1), `8+2 = 80.0%`, `16+2 = 88.89%`, and `146+4 = 97.33%`, trading wider failure domains and rebuild fan-in for higher flash capacity efficiency.
2. **Exercise 2 (Quantifying GPUDirect Storage `GDS` vs Host Page-Cache Bounce Buffering):** Reading `100.0 GB` via legacy buffered POSIX I/O writes `100.0 GB` into the Linux page cache and copies `100.0 GB` (`200.0 GB` total host DRAM traffic, `2` PCIe crossings), whereas `cuFileRead` (`nvidia-fs.ko`) performs `1` direct P2P DMA transfer into GPU `BAR1` memory with `0.0 GB` host DRAM bounce traffic.
3. **Exercise 3 (Configuring BeeGFS Striping, RDMA Transport, and `BeeOND` Ephemeral Scratch):** `beegfs-ctl --setpattern --chunksize=1m --numtargets=4 /mnt/beegfs/dir` stripes across 4 targets; `connUseRDMA = true` enables RDMA; and `BeeOND` aggregates compute-node local NVMe drives into a job-private parallel scratch filesystem for the duration of a Slurm allocation.
4. **Exercise 4 (Contrasting IBM Storage Scale (GPFS) and Lustre Metadata and HA Models):** GPFS distributes metadata across all cluster nodes (`NSD`s, indexed directories, token lock manager, quorum surviving split subnets, online disk rebalance, per-server and per-client licensing), whereas Lustre separates dedicated `MGS` and `MDS`/`MDT` servers (`DNE`) from `OSS`/`OST` data servers using open-source kernel modules.
5. **Exercise 5 (Evaluating PanFS (VDURA), WEKA, and VAST Data Architectures):** PanFS pairs Director blades with object storage nodes and offloads RAID-1/RAID-5 checksums to the Linux client driver; WEKA runs user-space DPDK/SPDK threads distributing metadata and data across NVMe nodes with active-file-first rebuilds and S3 tiering; and VAST DASE disaggregates stateless `CNodes` over NVMe-oF from shared-everything QLC/SCM `DBoxes` exposed via multipath NFS-RDMA and S3.
6. **Exercise 6 (Designing a Storage Acceptance Benchmark Suite):** Validate candidate filesystems at target client scale using `IOR` (`N-to-1` and `N-to-N` checkpoint bursts), `mdtest` (sharded vs single-directory metadata rates), `fio` (random/sequential IOPS), `gdsio` + `gdscheck -p` (GPUDirect Storage DMA), and degraded-mode throughput during a live server/drive kill.
