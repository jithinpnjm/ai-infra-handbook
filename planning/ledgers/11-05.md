1. **Exercise 1:** Only Criterion 7 (`7_drain_reboot_return_verified`) fails (`failed_gates == ["7_drain_reboot_return_verified"]`), so `pool_accepted` is `False`.

3. **Exercise 3:** When `post_rollback_allocatable=0`, `rollback_recheck_gate="fail_host_state_diverged"` (`keep_node_cordoned_revert_host_driver_or_node_image_and_escalate`); when `post_rollback_allocatable=8` and workload passes, `rollback_recheck_gate="pass"`.
4. **Exercise 4:** The `open /run/nvidia/driver/dev/nvidia0` OCI error is a **Pod start / runtime injection** failure before the entrypoint runs (`boundary="pod_start_runtime_injection"`), whereas `CUDA error: no CUDA-capable device is detected` occurs inside a `Running` container's user space.
5. **Exercise 5:** An exporter Pod can stay `1/1 Running` while returning `0` metric series after losing its driver socket; you must verify both `DCGM_FI_DEV_GPU_UTIL` series count `> 0` and that the `UUID` label matches the validation Pod's GPU `UUID` (`GPU-3a91...`).
6. **Exercise 6:** `--ignore-daemonsets` prevents evicting the platform's own node DaemonSets (`nvidia-driver-ds-7z4kd`); adding `--force` casually can destroy an un-checkpointed distributed training run (`ml-training/resnet-worker-3`) or violate a `PodDisruptionBudget`.
