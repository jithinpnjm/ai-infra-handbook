## 4. One-Line Expected Exercise Solutions

1. **Exercise 1 (Layer Classification):** `connectx_hca` = `hardware`; `nvidia.ko`, `nvidia_uvm.ko`, `mlx5_core.ko` = `kernel`; `libcuda.so`, `libibverbs.so`, `systemd`, `slurmd` = `user_space`.
2. **Exercise 2 (Root UID 0 vs Kernel Mode Ring 0):** (a) In user space, a `root` (`UID 0`) Python loop runs in `ring 3` (`user_mode`) and **cannot** execute privileged CPU instructions directly without a system call; (b) during `read()`, an ordinary user (`UID 1000`) traps into `ring 0` (`kernel_mode`) while the kernel executes the system call.
3. **Exercise 3 (`fork`/`clone` and `execve` PIDs):** Immediately before `execve("/usr/bin/ls")`, the child has `PID 101` and program image `/bin/bash`; immediately after `execve("/usr/bin/ls")`, the child still has `PID 101` and program image `/usr/bin/ls`.
4. **Exercise 4 (`4 KiB` Page Table Translation):** (a) Virtual address `8,320` = virtual page `2`, offset `128`, mapped to physical frame `15` -> physical address `15 * 4096 + 128 = 61,568`; (b) virtual address `28,736` = virtual page `7` (unmapped), so the MMU raises a hardware page fault (`page_fault = 1`) and traps into the kernel.
5. **Exercise 5 (Process States `D` and `Z`):** Process A (`STAT = D`) is inside an uninterruptible kernel I/O path and ignores `SIGKILL` until the underlying NFS/storage device recovers or times out; Process B (`STAT = Z`) is already terminated and requires its parent process to call `wait4()` (or be killed/signaled so `PID 1` adopts and reaps the zombie).
6. **Exercise 6 (Distributions and Container Kernel Sharing):** (a) Inside the Rocky Linux 9 container on an Ubuntu host, `uname -r` prints the host kernel `6.8.0-1020-gcp`, while the container uses `dnf` (`.rpm`) from its own user-space image; (b) **No**—without `nvidia.ko` loaded in the host's `6.8.0-1021-gcp` kernel, `/usr/local/cuda` user-space libraries inside the container cannot talk to the GPU.
