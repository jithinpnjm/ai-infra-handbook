## 4. One-Line Expected Exercise Solutions

1. **Exercise 1 (Level-Triggered vs. Edge-Triggered Reconciliation):** Level-triggered controllers compare the current observed cluster state against `spec` (`Reconcile(namespace/name)`), so missed events or controller restarts are harmless because the next reconcile pass computes the exact difference and converges.
2. **Exercise 2 (Inside `client-go` Controller Machinery: `Reflector`, `SharedInformer`, `Lister`, and `WorkQueue`, `KPG` Ch. 6):** `Reflector` lists and watches into `DeltaFIFO`, `SharedInformer` updates the local `Indexer` cache (`O(1)` reads via `Lister`) and fires handlers that enqueue `namespace/name` keys into `DeduplicatingWorkQueue`, whose `dirty` and `processing` sets collapse rapid events and guarantee at-most-one active worker per key with exponential backoff on errors.
3. **Exercise 3 (Built-In Workload Controllers, `KUR` Ch. 9–12):** `Deployment` manages `ReplicaSet`s for rolling updates, `StatefulSet` provides stable ordinal names/DNS/PVCs, `DaemonSet` schedules one pod per matching node (`ssd=true` / `nvidia.com/gpu`), and `Job` supports One-shot, Parallel fixed completions, Work-queue consumers, and `Indexed` distributed training (`JOB_COMPLETION_INDEX`, `podFailurePolicy`, `suspend`).
4. **Exercise 4 (`ownerReferences`, Label Quarantining vs. Adoption, `finalizers`, and `status.conditions`):** `reconcile_replicaset()` shows removing a Pod's selector label (`kubectl label pod ... app-`) causes the `ReplicaSet` to orphan the Pod (for live debugging) and create a replacement, whereas an ownerless matching Pod is adopted via `ownerReferences` (`controller: true`); `/status` subresource writes update `conditions` and `observedGeneration` without incrementing `metadata.generation`.
5. **Exercise 5 (Node Lifecycle Taint Eviction, `StatefulSet` Split-Brain Prevention, and `Lease` Leader Election):** After `40s` without heartbeats, `node-lifecycle-controller` taints the node `unreachable:NoExecute` and evicts pods after `300s`; `StatefulSet` waits for old pods to terminate (or the `node.kubernetes.io/out-of-service` fencing taint) to avoid split-brain; and `Lease` leader election (`15s`/`10s`/`2s`) ensures only one active controller manager or scheduler runs at a time.
6. **Exercise 6 (Diagnosing Reconcile Hot Loops, Stuck `Terminating` Namespaces, and Budget-Bounded GPU Health Remediation):** Prevent hot loops by avoiding wall-clock writes when state hasn't changed and filtering status-only updates (`GenerationChangedPredicate`); unstick `Terminating` namespaces by checking remaining finalizers and broken `APIService`s; and use `reconcile_gpu_node_remediation()` (`max_concurrent_cordons`) so fleet-wide false alarms never drain the entire GPU cluster.
