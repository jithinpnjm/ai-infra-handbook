## 4. One-Line Expected Exercise Solutions

1. **Exercise 1 (Dynamic Linker Search Order and `/etc/ld.so.conf` vs. Modules):** The dynamic linker searches `DT_RPATH` -> `LD_LIBRARY_PATH` -> `DT_RUNPATH` -> `/etc/ld.so.cache` (`ldconfig`) -> `/lib64`; using `/etc/ld.so.conf` requires updating the file and running `ldconfig` on every node in the cluster after every compiler upgrade and cannot isolate conflicting versions per job.
2. **Exercise 2 (Tcl Modulefiles `#%Module1.0`, `stderr` Rule, and Tcl vs. Lmod Version Sorting):** A Tcl modulefile starts with `#%Module1.0` and writes help text via `puts stderr` because `stdout` is evaluated by the shell (`eval`); `compare_module_versions_tcl_vs_lmod(["mkl/4.0", "mkl/11.0"])` shows Tcl string sorting picks `mkl/4.0` (`'4' > '1'`) whereas Lmod numeric sorting picks `mkl/11.0` (`11 > 4`).
3. **Exercise 3 (Lmod Dynamic `MODULEPATH` Hierarchies, `inactive` Modules, and `module spider`):** `simulate_lmod_compiler_swap()` shows that unloading `gcc/15.1.0` removes its `MODULEPATH` and marks `openmpi/5.0.7` as `inactive`, loading `intel/2025.0` automatically reloads the Intel-compiled `openmpi/5.0.7`, and `module spider openmpi/5.0.7` lists the prerequisite compilers (`gcc/10.4.0` or `gcc/15.1.0`) needed to make a hidden hierarchical module visible.
4. **Exercise 4 (EasyBuild Bootstrap and Toolchain Workflows):** Create a Python `venv` (`python3 -m venv easybuild && source easybuild/bin/activate && pip3 install easybuild`), install EasyBuild as a module (`eb --install-latest-eb-release --prefix /opt/easybuild && module use /opt/easybuild/modules/all && module load EasyBuild`), inspect paths (`eb --show-config`), and build with `eb HPL-2.3-foss-2024a.eb --robot`.
5. **Exercise 5 (Spack Specs, Concretization Hashes, Environments, Externals, and Module Refresh):** `parse_spack_spec()` parses `@3.21` (version), `+cuda` (boolean variant), `%gcc@13.3.0` (compiler), `cuda_arch=90` (key-value variant), and `^openmpi@5.0.7` (dependency); `spack install hpl` bootstraps `clingo` and compiles the hashed DAG; and `spack module lmod refresh` generates Lmod modulefiles.
6. **Exercise 6 (Designing a Multi-Architecture Shared Software Tree and Avoiding Conda Metadata Storms):** Organize read-only subtrees per CPU microarchitecture (`/opt/apps/x86-64-v3`, `/opt/apps/x86-64-v4`) selected dynamically into `MODULEPATH` at login, and package Python environments into `Enroot` `.sqsh` squashfs containers or stage them to local `/tmp` RAID-1 disks so 500 ranks never hammer Lustre/NFS metadata servers.
