## 4. One-Line Expected Exercise Solutions

1. **Exercise 1 (Network Namespaces, `veth` Pairs, Linux Bridges, and `br_netfilter`):** A network namespace (`ip netns` / `/proc/<pid>/ns/net`) isolates interfaces, IPs, routes, ARP/ND tables, `netfilter`/`conntrack`, sockets/ports, and `net.*` sysctls; a **`veth` pair** acts as a virtual patch cable whose two ends sit in different namespaces, and `net.bridge.bridge-nf-call-iptables = 1` (`br_netfilter`) allows host `iptables`/`kube-proxy` rules to inspect L2-bridged pod-to-pod frames on `cni0`/`docker0`.
2. **Exercise 2 (`macvlan` vs. `ipvlan` L2/L3 vs. Routed `veth`):** Using `evaluate_macvlan_ipvlan_properties()`: **`macvlan`** gives each container its own distinct MAC address on the physical LAN (fast, no NAT, but switches may hit port-security MAC limits and the parent host cannot talk directly to its own `macvlan` children without a host `macvlan` sub-interface), **`ipvlan` (`L2`/`L3`)** shares the parent NIC's MAC address across all containers (avoiding switch MAC table exhaustion), and **routed `veth`** (Calico) uses per-pod `/32` host routes and `proxy_arp` (`169.254.1.1`) without an L2 bridge.
3. **Exercise 3 (Docker CNM Modes vs. the CNCF `CNI` Specification `ADD`/`DEL`/`CHECK`):** Docker's `CNM` (`sandbox`, `endpoint`, `network`) provides `bridge`, `host`, `none`, `container:<name>` (how Kubernetes pods share a `pause` container's netns), `macvlan`/`ipvlan`, and Swarm `overlay`; Kubernetes uses CNCF **`CNI`**, where `containerd`/`CRI-O` creates the pod netns and invokes stateless binaries in `/opt/cni/bin/` with JSON config from `/etc/cni/net.d/` and `CNI_COMMAND = ADD | DEL | CHECK | VERSION` (`run_cni_ipam_action()`).
4. **Exercise 4 (Kubernetes Pod-to-Pod Networking: Overlay vs. Native BGP Routed vs. Cloud-Native ENI):** Kubernetes requires all pods to reach all other pods without NAT; **overlay CNIs** (`Flannel`, `Calico`/`Cilium` VXLAN/Geneve on UDP `8472`/`4789` or IPIP `proto 4`) encapsulate cross-node packets at an MTU/CPU tax, **native routed CNIs** (`Calico` BGP, `Cilium` native routing) advertise node `/24` Pod CIDRs to the switch fabric with zero encapsulation, and **cloud VPC CNIs** (`AWS VPC CNI`, GKE Alias IPs) allocate first-class VPC IPs directly to pods.
5. **Exercise 5 (Designing Multi-NIC GPU Pods: `Multus`, `SR-IOV` / `macvlan` RDMA, `IPC_LOCK`, and `NCCL` Selection):** Using `audit_gpu_pod_rdma_spec()`: keep `eth0` on the primary CNI for Kubernetes control/API traffic and attach secondary `MTU 9000` RDMA interfaces (`net1..net8`) via **Multus (`NetworkAttachmentDefinition`)** + **NVIDIA Network Operator** (`SR-IOV` VF or `macvlan` + `rdma/hca_shared_devices_a`), grant `securityContext.capabilities.add: ["IPC_LOCK"]` so `ibverbs`/`NCCL` can pin memory, align NUMA via the kubelet **Topology Manager** (`single-numa-node`), and set `NCCL_SOCKET_IFNAME=net1` and `NCCL_IB_HCA=mlx5_0,mlx5_1` so `NCCL` never uses the `eth0` overlay.
6. **Exercise 6 (Debugging Pod Networking with `crictl`, `nsenter`, and `peer_ifindex` Pairing):** Find the pod sandbox PID on the node with `crictl inspectp <pod-id> | jq .info.pid`, enter the pod's network namespace from the host using **`sudo nsenter -t <pid> -n`** to run host tools (`ip addr`, `ip route`, `ss -tulpn`, `tcpdump`), and map the pod's `eth0` to its host-side `veth` via `sudo nsenter -t <pid> -n ethtool -S eth0 | grep peer_ifindex` (`resolve_veth_host_peer()`).
