## 4. One-Line Expected Exercise Solutions

1. **Exercise 1 (Pod Design `KUR` Ch. 5, Init Containers vs. Native Sidecars, and Effective Scheduling Requests):** Co-locate containers in a single Pod only if they cannot function on separate machines; `compute_pod_qos_and_effective_requests()` computes $\max(\max(\text{init}), \sum(\text{app}))$ for scheduling, and native sidecars (`initContainers` with `restartPolicy: Always`) start before app containers and automatically terminate when `Job` app containers finish.
2. **Exercise 2 (Labels, Annotations, and Selector Queries, `KUR` Ch. 6):** `validate_k8s_label()` checks the optional $\le 253$-char DNS subdomain prefix + `/` + $\le 63$-char alphanumeric-bounded name and $\le 63$-char value; labels identify and group objects for selectors (`-l 'ver=2,!canary'`, `-l 'ver in (1, 2)'`) whereas annotations store non-identifying tool metadata.
3. **Exercise 3 (Resource Requests, Limits, Extended Resources, QoS Classes, and `/dev/shm`):** `compute_pod_qos_and_effective_requests()` derives `Guaranteed` (`-997`, all containers have `requests == limits` for CPU and memory), `Burstable` (`2..999`), and `BestEffort` (`1000`); `emptyDir: { medium: Memory, sizeLimit: 64Gi }` at `/dev/shm` is charged to the container's memory cgroup limit so `limits.memory` must cover process RSS + `/dev/shm`.
4. **Exercise 4 (Pod Termination Sequence, `EndpointSlice` vs. `SIGTERM` Race, and Slow-Start LLM Probes, `PK` Ch. 14):** Because `EndpointSlice` removal and `kubelet` termination run concurrently, a `preStop` `sleep 10–15` lets load balancers drain before `SIGTERM` closes the listening socket; a `startupProbe` (`periodSeconds: 10, failureThreshold: 180` = 30 min) protects slow 140 GB model loads from `livenessProbe` restarts.
5. **Exercise 5 (Production Workload Manifests: `Deployment` + `PDB`, `StatefulSet`, `DaemonSet`, and `Indexed` `Job`):** Use `Deployment` + `PodDisruptionBudget` (`minAvailable < replicas`, `maxSurge: 0, maxUnavailable: 1` when no spare GPUs exist) for inference, `StatefulSet` (`volumeClaimTemplates`) for stateful stores, `DaemonSet` (`operator: Exists` toleration) for GPU node agents, and `Indexed` `Job` (`podFailurePolicy`, `suspend: true` with Kueue/JobSet) for batch/training.
6. **Exercise 6 (Controlling Rollouts `KUR` Ch. 10, `kubectl debug`, and Organizing Multi-Region Releases `KUR` Ch. 22):** Manage rollouts with `kubectl rollout status/pause/resume/history/undo --to-revision=3`, inspect distroless pods/nodes with `kubectl debug -it --target=...`, and keep manifests in Git with code review and staged promotion (`Development -> Staging -> Canary -> Production` across regions).
