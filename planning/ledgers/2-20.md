## 4. One-Line Expected Exercise Solutions

1. **Exercise 1 (Load Balancer Families, Proxy/NAT vs. Direct Server Return `DSR`, and Preserving Client Identity):** (a) Classify DNS/GSLB, L3 ECMP/Anycast, L4 transport (`IPVS`, `Maglev`, `Katran`), L7 application proxies (`Envoy`, `HAProxy`, `nginx`), and client-side xDS balancers across the 5 LB design questions; (b) in **Direct Server Return (`DSR` / IPVS `-g`)**, the LB forwards requests by rewriting only the destination MAC (or tunneling) while the backend holds the VIP on `lo` (`arp_ignore=1`, `arp_announce=2`) and sends large responses directly to the client—bypassing the LB on return and preserving the client IP (whereas L4/L7 proxies use the **PROXY protocol** or `X-Forwarded-For`).
2. **Exercise 2 (Load-Balancing Algorithms: `Round Robin`, `Least Connections`, `P2C`, and Consistent Hashing / `Maglev`):** Round-robin ignores request duration and least-connections suffers herding across multiple LB nodes; **Power of Two Choices (`P2C`, `select_backend_p2c()`)** picks two random backends and chooses the less loaded one, while **Consistent Hashing** (`Ring Hash`, `Rendezvous HRW`, `Maglev`) moves only **`~1 / N`** of keys when a node is added or removed (`select_backend_rendezvous_bounded()`).
3. **Exercise 3 (Scaling the L4 Tier Horizontally Behind `ECMP` Anycast VIPs):** Multiple L4 LB nodes (e.g., `IPVS` / `Katran` / `Maglev`) announce the same `/32` VIP to leaf routers via **eBGP + BFD**; to prevent existing TCP connections from breaking when an LB node drains or fails, pair router **resilient ECMP hashing** with 5-tuple **Maglev consistent hashing** across the L4 nodes so any surviving L4 node maps an existing connection to its original backend without shared state.
4. **Exercise 4 (The `gRPC` / `HTTP/2` L4 Connection-Pinning Trap and Fixes):** Because `HTTP/2` and `gRPC` multiplex all RPC streams over a single long-lived TCP connection, an L4 load balancer (`kube-proxy` `iptables`/`IPVS`, `nginx stream`, AWS NLB) pins 100% of RPCs from that connection onto **a single backend replica** (`simulate_grpc_l4_vs_l7_distribution(4, 1, 100)` -> `[100, 0, 0, 0]`); fix by balancing per request at **L7** (`Envoy`, `HAProxy proto h2`, `nginx grpc_pass` -> `[25, 25, 25, 25]`), using client-side `round_robin` (`xDS`), or setting server `MAX_CONNECTION_AGE`.
5. **Exercise 5 (Health Checks, Outlier Detection, Circuit Breaking, and Zero-Downtime Streaming Drains):** Combine active **readiness** probes (`/v2/health/ready` checking model load and GPU health, where `inter 2s fall 3` detects failure in `6.0 s`, `compute_health_check_detection_sec()`) with passive **outlier detection** (`consecutive_5xx: 5`), **slow start** (`30 s` ramp for cold GPU caches), **circuit breakers**, and **dynamic endpoint updates (`Envoy xDS` / HAProxy socket)** so deploys drain multi-minute token streams without `nginx -s reload` cutting or leaking old workers.
6. **Exercise 6 (Designing an LLM Inference Router: Queue/KV-Cache Signals, Prefix-Cache Affinity with Bounded Load, and Prefill/Decode Disaggregation):** Route LLM requests at L7 using backend-reported **running/waiting queue depth and KV-cache occupancy** (via `P2C`), apply **bounded-load consistent hashing** on prompt prefixes (`select_backend_rendezvous_bounded()`) to maximize KV-cache prefix hits without hot-spotting a single GPU replica, disable proxy buffering (`proxy_buffering off`), and set stream timeouts (`600 s`) above maximum generation time.
