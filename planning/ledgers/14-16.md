## 4. One-Line Expected Exercise Solutions

1. **Exercise 1:** (a) `llama2-7b-hf` requires **`14.0 GB` for `BF16` weights** and **`54.0 GB` total active HBM per GPU** (`14.0 GB + 40.0 GB` activations < `80 GB`), processing **`256` global sequences (`524,288` tokens/step)** on `8` GPUs versus **`128` global sequences (`262,144` tokens/step)** on the `4`-GPU Kubernetes Job in Lab 03; (b) retaining `save_total_limit = 3` checkpoints at `15.0 GB` each consumes **`45.0 GB`** (fitting inside the `50.0 GB` checkpoint budget and `100.0 GB` persistent storage floor), and a healthy `8`-GPU DGX A100 (`600 GB/s` bidirectional NVLink/GPU, `4.8 TB/s` bisection) achieves **`480.0–540.0 GB/s` per-GPU `busbw` (`80%–90%` efficiency)**.
2. **Exercise 2:** (a) The `175B` model requires **`2,800.0 GB`** of mixed-precision Adam state (`2.73 GB/GPU` under ZeRO-3), or **`1.37B` parameters and `21.875 GB` (`~22 GB`) of state per GPU** under `TP=8, PP=16, DP=8` (`6` layers/stage across `1,024` GPUs), with a `1F1B` pipeline bubble of **`15 / 271 = 5.54%` (`~5.5%`)** at `M = 256` micro-batches versus **`15 / 55 = 27.27%` (`~27.3%`)** at `M = 40`; (b) the `50,000 x 12,288` `BF16` vocabulary table occupies **`1.23 GB` (`~1.2 GB`)**, causing Stages `0` and `15` to run **`~40%` slower**, which is resolved by assigning fewer layers (`5` layers) to Stages `0`/`15` or enabling interleaved virtual pipeline stages (`--num-layers-per-virtual-pipeline-stage`).
3. **Exercise 3:** (a) GPU utilization oscillating **`95% -> 15% -> 8% -> 88%`** alongside DataLoader throughput of **`0.35 < 0.5 batches/sec`** confirms CPU data-loading starvation; cutting I/O wait from `30%` to `5%` yields a **`6.0x` training step speedup**, and `NVIDIA DALI` reduces CPU usage **`4.0x` from `800%` (`8` cores) to `200%` (`2` cores)**; (b) halving the batch size keeps gradient `AllReduce` byte volume constant while halving GPU compute—if NIC throughput stays at **`60 GB/s`** the job is **communication-bound**, whereas if it drops to **`40 GB/s`** the GPUs are starving the NIC and the job is **compute-bound**.
4. **Exercise 4:** (a) Rank-`16` (`alpha = 32`, scale = `2.0`) LoRA across `4` linear projections in `32` layers (`hidden = 4096`) trains **`16,777,216` parameters (`0.2089% < 1%` of `8.03B`)** and produces a **`33.55 MB` `BF16` adapter**; (b) the full `8.03B` Megatron/NeMo checkpoint is **`80.30 GB` theoretical** (`16.06 GB` `BF16` weights + `64.24 GB` `FP32` Adam) and **`108.0 GB` actual** across **`4 x 27.0 GB` `.distcp` shards**, and a `45-minute` (`2,700 s`) single-file checkpoint stall on `1,024` GPUs is **`6,000.0x` slower** than a `450 ms` step.
5. **Exercise 5:** (a) Fine-tuning improves accuracy by **`+2.5` percentage points (`92.0% -> 94.5%`)**, training loss by **`12.8%` (`2.15 -> 1.87`, `1.92` eval loss)**, perplexity by **`18.7%` (`18.7 -> 15.2`)**, `ROUGE-1` by **`+12.9%` (`0.31 -> 0.35`)**, and `BLEU` by **`+16.7%` (`0.24 -> 0.28`)**; (b) the synchronous 5-rail NeMo Guardrails pipeline sums to **`250.0 ms`** (`45 + 15 + 30 + 100 + 50 + 10 ms`, **`+205.0 ms` overhead**, **`5.56x` / `~5.5x` slower**), which is kept within production SLOs by keeping fast regex/embedding rails synchronous and moving heavy `LLM-as-a-Judge` checks to **`1%–10%` asynchronous sampling**.
