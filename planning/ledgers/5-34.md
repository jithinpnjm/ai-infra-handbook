## 4. One-Line Expected Exercise Solutions

1. **Exercise 1 (GKE `Standard` vs. `Autopilot` and Multi-Pool Cluster Architecture):** Use GKE `Standard` with a small CPU-only default pool (`e2-standard-4`), `--enable-dataplane-v2` (Cilium), `--workload-pool`, and `--enable-managed-prometheus --monitoring SYSTEM,DCGM`, adding dedicated GPU pools separately so GPU pools can scale to `0` when idle.
2. **Exercise 2 (Creating a GPU Node Pool `--accelerator`, `gpu-driver-version`, and Taints/Tolerations):** `evaluate_gke_gpu_node_pool_config()` enforces that `gpu-driver-version=latest` requires `COS`, `gpu-driver-version=disabled` is required when the NVIDIA GPU Operator manages drivers, and GKE taints GPU nodes with `nvidia.com/gpu=present:NoSchedule` (injecting the matching toleration automatically when a Pod requests `nvidia.com/gpu`).
3. **Exercise 3 (Triaging Capacity Errors `QUOTA_EXCEEDED` vs. `ZONE_RESOURCE_POOL_EXHAUSTED` and Choosing Consumption Models):** `classify_gke_gpu_capacity_error()` separates project quota limits (`QUOTA_EXCEEDED`) from physical zone stockouts (`ZONE_RESOURCE_POOL_EXHAUSTED`); use `Specific Reservations` for long multi-node training, `Flex-start` (DWS) for bounded multi-node jobs without a reservation, and `Spot` for stateless/checkpointed batch work.
4. **Exercise 4 (Sub-GPU Sharing `Time-Sharing` vs. `MPS` vs. `MIG` and Dynamic Resource Allocation `DRA`, `GAK` Ch. 3):** Time-sharing and MPS share HBM memory and fault fate whereas MIG provides hardware-isolated SMs and memory (`single` exposing e.g. `14` `nvidia.com/gpu` units vs `mixed` exposing `nvidia.com/mig-1g.5gb`); `DRA` (`ResourceClaimTemplate`) replaces integer Device Plugin counters with CEL-filtered device claims.
5. **Exercise 5 (High-Performance Multi-Node GPU Networking on GKE):** Combine `--enable-gvnic`, `--enable-multi-networking` + `--additional-node-network` ($\le 7$) or `--accelerator-network-profile=auto`, GPUDirect-TCPXO / RoCE RDMA NCCL plugins, and `--placement-type COMPACT`, validated with `all_reduce_perf`.
6. **Exercise 6 (Zero-Spare-Capacity GPU Node Pool Upgrades and Terraform IaC Structure):** `validate_gpu_pool_upgrade_surge()` shows `max-surge-upgrade=1` stalls when spare quota/reservation capacity is `0`, requiring `--max-surge-upgrade=0 --max-unavailable-upgrade=1` and decoupled `google_container_node_pool` Terraform resources (`remove_default_node_pool = true`).
