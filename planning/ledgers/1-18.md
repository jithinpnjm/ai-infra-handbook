## 4. One-Line Expected Exercise Solutions

1. **Exercise 1 (CPU Topology, IPC Stall vs. Instruction-Bound Regimes, and `perf stat` / `pmcarch`):** (a) A socket contains physical cores, each core may expose multiple SMT hardware threads sharing execution units and L1/L2 caches, and the OS schedules onto logical CPUs; (b) `IPC < 0.5` (`0.30`) indicates the CPU is mostly stalled waiting on memory/caches/TLB (`memory_stall_bound`), whereas `IPC >= 1.0` (`1.80`) indicates `instruction_execution_bound` execution (`pmcarch` `87,166,313 / 96,163,187 = 0.91`).
2. **Exercise 2 (Scheduling Classes, `SCHED_FIFO` Starvation, and CFS `vruntime` vs. EEVDF):** (a) The 5 classes from highest to lowest priority are `stop` > `deadline` (`SCHED_DEADLINE`) > `realtime` (`SCHED_FIFO`, `SCHED_RR`, priorities `1`–`99`) > `fair` (`CFS`/`EEVDF`: `SCHED_NORMAL`, `SCHED_BATCH`, `SCHED_IDLE`) > `idle`, with `kernel.sched_rt_runtime_us = 950000` (`95%` of `1,000,000 µs`) preventing a runaway RT thread from starving the CPU 100%; (b) in CFS, `vruntime` advances as `actual_runtime * (1024 / weight)` so a `nice -5` task (`weight 3121`) advances `vruntime` `~3x` slower than `nice 0` (`weight 1024`) and stays leftmost in the red-black tree, whereas EEVDF (Linux `6.6+`) picks the eligible task with the earliest virtual deadline.
3. **Exercise 3 (CFS Bandwidth Quota Throttling `cpu.max` vs. Relative `cpu.weight`):** (a) Sibling cgroups with `cpu.weight` `100` and `300` receive `25.0%` and `75.0%` of contended CPU cycles and can burst to `100%` when the sibling is idle; (b) with `cpu.max = "200000 100000"` (`200 ms` quota per `100 ms` period = `2.0` cores) and `16` active threads running in parallel, the `200 ms` quota is exhausted in `200 / 16 = 12.5 ms` of wall time, pausing all `16` threads for the remaining `87.5 ms` (`nr_throttled` rises in `cpu.stat`).
4. **Exercise 4 (cgroup v1 vs. v2 Architecture and the No-Internal-Processes Rule):** (a) cgroup v1 mounts a separate hierarchy per controller (`/sys/fs/cgroup/cpu`, `/memory`), whereas cgroup v2 mounts a single unified tree (`/sys/fs/cgroup`, `cgroup2fs`) with unified memory/writeback accounting, per-cgroup PSI (`*.pressure`), and eBPF device control; (b) in cgroup v2, enabling `+cpu +memory` in a non-root cgroup's `cgroup.subtree_control` while that cgroup directly contains processes fails with `EBUSY` (`Device or resource busy`) because processes may reside only in leaf cgroups (or the root).
5. **Exercise 5 (CPU Affinity, Core Isolation `isolcpus`/`nohz_full`, and IRQ Pinning):** To isolate GPU feeding threads from jitter, set the `performance` governor (`cpupower frequency-set -g performance`), restrict C-states (`max_cstate=1`), route NIC/NVMe interrupts to housekeeping cores (`/proc/irq/N/smp_affinity_list` or `IRQBALANCE_BANNED_CPUS`), and bind each training rank's CPUs and memory to its GPU's local NUMA cores (`numactl --cpunodebind=$node --membind=$node` or exclusive `cpuset.cpus.partition=isolated`).
6. **Exercise 6 (Kubernetes QoS Classes, CPU Manager `static`, and Cgroup Driver Alignment):** (a) Kubernetes maps `requests.cpu: 500m` to `cpu.shares = 512` (v1) / `cpu.weight` (v2) and `limits.cpu: 2` to `cpu.max = 200000 100000`, and assigns `oom_score_adj = -997` to `Guaranteed` pods (requests == limits) and `1000` to `BestEffort` pods; (b) `kubelet` `--cpu-manager-policy=static` + Topology Manager allocates exclusive `cpuset` cores aligned with the GPU's NUMA node, and `kubelet` and `containerd` (`SystemdCgroup = true`) must share the `systemd` cgroup driver to respect the single-writer rule.
