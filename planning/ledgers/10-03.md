| `ASP Ch 6` (pp. 193–201): **Blackwell Memory Hierarchy Table (Table 6-5)**: (1) **Registers**: per thread on SM, `64K` 32-bit registers (`256 KB`) per SM, max `255` per thread, ~1 cycle, tens of TB/s per SM; (2) **Shared Memory & L1 Data Cache**: per SM, `256 KB` combined SRAM (`up to 228 KB shared/SM`, `227 KB` max dynamic shared/block + `1 KB` CUDA reserved, configured via `cudaFuncSetAttribute(..., cudaFuncAttributePreferredSharedMemoryCarveout, ...)`), `~20–30 cycles`, TB/s per SM; (3) **Tensor Memory (`TMEM`)**: per SM on Blackwell, dedicated `256 KB` SRAM per SM for 5th-gen Tensor Cores (`tcgen05.mma` / `UMMA`), `~10 cycles`, TB/s-scale, not pointer-addressable in C++ (orchestrated via **TMA** `global <-> SMEM` and `tcgen05` `SMEM <-> TMEM` descriptors); (4) **Constant Memory Cache**: per SM, `~8 KB` cache fronting `64 KB` `__constant__` space, `~1 cycle` on warp-uniform broadcast (for RoPE tables, ALiBi slopes, LayerNorm $\gamma/\beta$, quantization scales); (5) **L2 Cache**: GPU-wide, `126 MB` on Blackwell B200 (`50 MB` on H100), `~200 cycles`, multi-TB/s; (6) **Local Memory**: per-thread logical spill space backed by off-chip HBM DRAM, `100s -> 1,000 cycles`, `~8 TB/s`; (7) **Global Memory (`HBM3e`)**: device-wide off-chip DRAM, up to `180–192 GB` on B200 (`~288 GB` on B300) across 2 reticle dies (`4` HBM3e stacks/die = `8` stacks total linked by `10 TB/s` chip-to-chip link), `100s -> 1,000 cycles`, `~8 TB/s` (`16 TB/s` across 2 GPUs on GB200/GB300); **Points of Coherency (`PoC`, Fig. 6-15)**: thread, thread-block (`CTA`), thread-block cluster (`CTA cluster`), device, system; **Stream-Ordered Memory Pools**: `cudaMallocAsync` / `cudaFreeAsync` on `cudaStreamNonBlocking` streams (avoiding synchronous `cudaMalloc` `mmap`/`ioctl` OS context switches), `cudaMemPoolAttrReleaseThreshold`, `cudaMemPoolTrimTo`, and PyTorch's caching allocator (`PYTORCH_ALLOC_CONF`, formerly `PYTORCH_CUDA_ALLOC_CONF`); **Unified Memory (`cudaMallocManaged`)**: on-demand page faulting over PCIe vs `~900 GB/s` NVLink-C2C on Grace Hopper/Blackwell, proactive prefetching with `cudaMemPrefetchAsync`, memory hints with `cudaMemAdvise` (`cudaMemAdviseSetPreferredLocation`, `cudaMemAdviseSetReadMostly`, `cudaMemAdviseSetAccessedBy`), and `cudaStreamAttachMemAsync(..., cudaMemAttachSingle)` | `used in sections 1–4` and `gpu_memory_hierarchy.py` |
| `ASP Ch 7` (pp. 216–253): **128-byte cache lines = four 32-byte sectors**: aligned coalesced warp load of 32 floats (`128 B`) touches `4` sectors (`1` cache line), whereas a misaligned contiguous 128B warp load straddles two lines and touches `5` to `8` sectors, and `stride = 2` (`uncoalescedCopy`) touches `8` sectors (`25%` DRAM peak, `23%` Load Efficiency, `4.8 ms` vs `coalescedCopy` `4.0` sectors, `90%` DRAM peak = `3.6x`, `99%` Load Efficiency, `1.3 ms` = `3.7x` faster; Table 7-1); **Vectorized memory access**: `cudaMalloc` guarantees `>= 256-byte` base alignment; `float4` (`16 bytes`/thread = `512 B`/warp = `4 x 128 B` lines = `16` sectors) on Hopper/Ampere vs `32-byte` (`256-bit`, `8 floats` `alignas(32)` / `double4` = `1,024 B`/warp = `8 x 128 B` lines = `32` sectors) single instruction on Blackwell (`CUDA 13+`); **Shared-memory tiling (`32x32` tile)**: reduces global memory reads by `32x` per tile (`8x` overall per thread), dropping DRAM throughput from `90%` to `25%` (`3.6x` less), cutting global load sectors from `9,800` to `1,200`, raising occupancy from `42%` to `89%`, and lifting GFLOPS from `15` to `170` (`11.3x` gain, arithmetic intensity from `1.5` to `8.0` FLOPs/byte; Table 7-4); `64x64` tile resource budget (`16 KB` per `A`/`B` tile, `1,024` threads, `12` to `22` regs/thread = `22,528` regs/block -> capped at `2` blocks/SM = `2,048` threads); `CUTLASS`, `cuBLAS`, `cuDNN`, and Python `cuTile` / `TileIR`; **Shared-memory 32 banks (`4-byte` bank width, repeats every `128 bytes`)**: column-wise read (`tile[threadIdx.x][threadIdx.y]` or `arr[threadIdx.x * 32]`) hits `threadIdx.x * 128 mod 128 == 0` -> **32-way bank conflict** (`4.8M` conflicts, `52%` SMEM util, `38%` warp stall, `4.0 ms`), except when all 32 threads read the **exact same address** (**1-cycle hardware broadcast/multicast**); **Padding (`__shared__ float tile[32][33]`, `+1` float = `~3.1%` / `1 KB` overhead)** or **XOR index swizzling** eliminates conflicts (`0` conflicts, `100%` SMEM util, `0.5%` stall, `1.3 ms` = `3x` faster; Table 7-5); **Warp Shuffle Intrinsics (`__shfl_sync`, `__shfl_down_sync`)**: intra-warp register-to-register butterfly reduction in 5 steps (`offset = 16, 8, 4, 2, 1`) with zero shared memory and zero bank conflicts; **Read-Only Data Cache (`const __restrict__` / `__ldg()`)**: routes immutable lookup/embedding tables through the L1 read-only cache (`2.5 ms` -> `1.0 ms` = `2.5x` faster, DRAM `600` -> `200 GB/s`, L2 `1,500` -> `1,800 GB/s`, Load Efficiency `52%` -> `97%`; Table 7-6); **Tensor Memory Accelerator (`TMA`) & `cuda::memcpy_async` double-buffering**: hardware DMA engine for 1D–5D bulk global-to-shared copies (`cp.async.bulk`), hiding ~800-cycle HBM latency via ping-pong `tile0`/`tile1` buffers (`18 ms` -> `7 ms` = `2.6x` faster, Load Efficiency `23%` -> `99%`, sectors/req `6.4` -> `4.0`; Table 7-7) | `used in sections 1–5` and `gpu_memory_hierarchy.py` (deep kernel tuning code also expanded in `10.13`) |
