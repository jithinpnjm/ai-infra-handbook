## 4. One-Line Expected Exercise Solutions

1. **Exercise 1 (Linux Kernel Primitives Behind a Container, `KUR` Ch. 2 & `PK` Ch. 3):** A container is a normal host process isolated by 7 namespaces (`pid`, `mnt`, `net`, `uts`, `ipc`, `user`, `cgroup`), resource-bounded by cgroups v2 (`--cpus` sets a hard CFS quota while `--cpu-shares 1024` sets relative weight under contention; `--memory 200m` sets physical RAM limit and `--memory-swap 1G` sets RAM+swap), rooted in `overlayfs`, and restricted by capabilities, seccomp, and AppArmor/SELinux.
2. **Exercise 2 (OCI Image Specification, Content Addressing, and the Whiteout Trap, `KUR` Ch. 2 & `PK` Ch. 3):** An OCI Image Index maps `(os, arch)` platforms to Manifests, which reference a Config JSON and Layer tarballs by immutable SHA-256 digest (`@sha256:...`); `simulate_oci_layer_sizes()` proves that deleting a 500 MB file in a later layer writes a `.wh.` whiteout file that hides it in `overlayfs` while all 500 MB still ship in the earlier layer tarball.
3. **Exercise 3 (Writing Fast, Small, Secure Dockerfiles, `KUR` Ch. 2):** `simulate_dockerfile_cache_hits()` shows ordering `COPY requirements.lock` + `pip install` before `COPY src/` preserves build cache on code edits; multi-stage builds (`kuard` and Python wheels) leave compilers out of the runtime stage; and BuildKit `--mount=type=cache` and `--mount=type=secret` prevent caches and secrets from entering layers.
4. **Exercise 4 (Choosing Base Images and Exec-Form Signal Handling `PID 1`):** Avoid `Alpine` (`musl` libc) for Python/CUDA workloads because `manylinux` wheels and NVIDIA libraries link against `glibc`; use exec-form `ENTRYPOINT ["python", ...]` so `SIGTERM` reaches your process as PID 1 instead of being swallowed by `/bin/sh -c`.
5. **Exercise 5 (Operating Registries at GPU Cluster Scale):** Prevent 500-node pull storms on 25 GB images by combining local pull-through caches (`Harbor` + containerd `hosts.toml`), P2P distribution (`Spegel` / `Dragonfly`), shared base layers (`IfNotPresent` + digest pinning), pre-pulling DaemonSets, and lazy-pulling snapshotters (`SOCI` / `eStargz`).
6. **Exercise 6 (GPU Containers Under the Hood: `libcuda.so` vs. `libcudart.so`, CDI, and `/dev/shm`):** The host provides `nvidia.ko` and `libcuda.so` while the container image provides `libcudart.so`, cuDNN, and NCCL (`check_cuda_driver_compatibility()` verifies host driver $\ge$ image CUDA minimum or `cuda-compat`); `nvidia-ctk cdi generate` creates `/etc/cdi/nvidia.yaml` for `--device nvidia.com/gpu=all`, and `/dev/shm` must be enlarged beyond 64 MB (`--shm-size=16g` or `emptyDir: { medium: Memory }`) for PyTorch DataLoaders and NCCL.
