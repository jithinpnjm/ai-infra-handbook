## 4. One-Line Expected Exercise Solutions

1. **Exercise 1 (5-Layer Failure Classification and Verbosity Ladder `-v` to `-vvvvv`, `AUR` Ch. 8):** Using `classify_ansible_failure_layer()`, errors map cleanly to Parse/Syntax, Connection (`UNREACHABLE`), Data/Template, Privilege/Module, or Application Command; `-v` adds module return data, `-vv` adds file/line locations and `false_condition`, `-vvv` adds SSH command lines, remote temp paths, and module args, and `-vvvv` adds raw `ssh -vvv` protocol debug logs.
2. **Exercise 2 (Proactive Verification with `debug`, `assert`, `type_debug`, and `stat` Return Values, `AUR` Ch. 8 Table 8-3):** `stat` returns `exists`, `isreg`, `isdir`, `islnk`, `pw_name`, `mode`, `size`, and `checksum` verified by `assert` (`quiet: true`); `verbosity: 1` hides `debug` tasks during normal runs, and `{{ var | type_debug }}` prints the exact runtime Python type.
3. **Exercise 3 (Interactive Task Debugger `strategy: debug` / `debugger: on_failed`, `AUR` Ch. 8 Table 8-2):** Using `InteractiveTaskDebuggerSession`, modifying `task.args[k]` edits the already-rendered module argument directly whereas modifying `task_vars[k]` requires running `update_task` (`u`) to re-render the template before `redo` (`r`); the five triggers are `always`, `never`, `on_failed`, `on_unreachable`, and `on_skipped`.
4. **Exercise 4 (Diagnosing SSH, Bastion, Host-Key, and Agent-Forwarding Failures, `AUR` Ch. 8):** Resolve changed lab/re-imaged host keys via `ssh-keygen -R <ip>` + `ssh-keyscan -H <ip> >> ~/.ssh/known_hosts`, restrict automation keys with `key_options: 'no-port-forwarding,from="..."'` and `exclusive: true`, and keep `become: false` on `git` tasks using SSH agent forwarding because `sudo` strips `SSH_AUTH_SOCK`.
5. **Exercise 5 (Reproducing a Module Execution Manually with `ANSIBLE_KEEP_REMOTE_FILES=1` and `AnsiballZ`):** Run with `ANSIBLE_KEEP_REMOTE_FILES=1` and `-vvv`, SSH to the target, `cd` to `~/.ansible/tmp/ansible-tmp-.../`, run `python3 AnsiballZ_<mod>.py explode` to unpack the Python script and `args` JSON into `./debug_dir`, and run `python3 AnsiballZ_<mod>.py execute` to debug locally.
6. **Exercise 6 (Performance Profiling `profile_tasks`/`profile_roles` and Fleet Error Triage):** Enable `callbacks_enabled = timer, profile_tasks, profile_roles` and optimize with `pipelining = True`, `ControlPersist=120s`, `forks = 50`, `gathering = smart` + `fact_caching`, and list-based package calls; triage fleet failures by grouping `fatal:`/`FAILED` messages with `sort | uniq -c | sort -rn` and correlating with rack/OS groups.
