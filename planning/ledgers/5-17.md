## 4. One-Line Expected Exercise Solutions

1. **Exercise 1 (`PersistentVolume`, `PersistentVolumeClaim`, `StorageClass`, and `Immediate` vs. `WaitForFirstConsumer`, `PK` Ch. 4):** `evaluate_zonal_pvc_binding()` shows `Immediate` provisions a zonal block volume before scheduling (causing a `volume node affinity conflict` if that zone lacks GPUs), whereas `WaitForFirstConsumer` waits until `kube-scheduler` selects a GPU node (`volume.kubernetes.io/selected-node`) and provisions the disk in the matching zone.
2. **Exercise 2 (Access Modes `RWO`/`ROX`/`RWX`/`RWOP`, Reclaim Policies `Delete`/`Retain`, and `Multi-Attach error`):** `check_csi_volume_attachment()` shows `RWO` allows multiple pods on the *same* node but rejects a second node (`Multi-Attach error`), whereas `RWOP` restricts to a single pod; `Retain` moves released PVs to `Released` until `spec.claimRef` is cleared.
3. **Exercise 3 (Inside the CSI Architecture and the 7-Step Lifecycle, `PK` Ch. 4):** Controller sidecars (`external-provisioner`, `external-attacher`, `external-resizer`, `external-snapshotter`) call `CreateVolume`, `ControllerPublishVolume`, `ControllerExpandVolume`, and `CreateSnapshot`, while the node DaemonSet (`node-driver-registrar`) executes `NodeStageVolume` (`blkid` + `mkfs` + global mount) and `NodePublishVolume` (per-pod bind-mount).
4. **Exercise 4 (Linux Kernel Mount Mechanics, `Bidirectional` Propagation, FUSE vs. Kernel Clients, and Online Expansion):** CSI node containers require `mountPropagation: Bidirectional` so mounts appear on the host; `ResizeFS` runs `resize2fs`/`xfs_growfs` during `NodeExpandVolume`; and a crashed FUSE daemon leaves containers with `Transport endpoint is not connected`.
5. **Exercise 5 (Integrating External and Replicated Stateful Storage, `KUR` Ch. 16):** External storage is imported via `ExternalName` or selector-less `Service` + `Endpoints`, while replicated stateful stores (`MongoDB` `rs0`) combine a Headless Service (`mongo-0.mongo..mongo-2.mongo`), a `StatefulSet` with `volumeClaimTemplates`, and an ordered `initContainer` bootstrap script.
6. **Exercise 6 (Storage Architecture and Throughput Sizing for AI Workloads):** `compute_checkpoint_and_weight_timings()` calculates $\text{checkpoint\_size} / \text{write\_bw}$ and $\text{weights\_size} / \text{read\_bw}$, motivating two-tier async checkpointing (local NVMe -> parallel FS / object store) and pre-warmed node-local NVMe / parallel FS / P2P OCI `image` volumes for 140 GB model weights.
