## 4. One-Line Expected Exercise Solutions

1. **Exercise 1:** **Coscheduling** is a low-complexity `kube-scheduler` plugin (`PodGroup` only); **Kueue** is a job-level `Workload`/`ClusterQueue`/`Cohort` admission controller with TAS; **Volcano** is a standalone DRF/Proportion/`NetworkTopology` batch scheduler; **KAI Scheduler** is a `7`-microservice GPU-native scheduler with `Department -> Project` `Queues`, `SubGroup` topology, and native fractional GPUs (`gpu-fraction`/`gpu-memory`); **YuniKorn** unifies `Spark`/`Flink` and AI/ML with placeholder gang pods and `Fair`/`BinPacking` sorting; and **Slurm** is a bare-metal HPC manager (`topology/tree`, `cons_tres`, `Enroot`/`Pyxis`).
2. **Exercise 2:** (a) **Slurm + Enroot/Pyxis** (with `cm-scale` Auto Scaler coexistence), (b) **NVIDIA KAI Scheduler**, (c) **Apache YuniKorn**, (d) **Kueue** (optionally composed with KAI/Volcano), and (e) **Coscheduling plugin**.
3. **Exercise 3:** Enroot leaves `--net` off (`ENROOT_UNSHARE_NET=no`) so NCCL accesses host InfiniBand/Ethernet NICs directly without overlay overhead; the three `/etc/enroot` directories are `environ.d/*.env`, `mounts.d/*.fstab`, and `hooks.d/*.sh`; `98-nvidia.sh` and `99-mellanox.sh` inject GPUs and host `MLNX_OFED`; and `.credentials` requires both `nvcr.io` and `authn.nvidia.com` with `$oauthtoken`.
4. **Exercise 4:** Cluster MTBF = `1,000 / 512 = 1.95 days`; the `Prolog` checks `8` GPUs enumerated, `0` volatile uncorrectable ECC errors, `0` thermal/hardware slowdowns, `8` active `400G` NDR IB ports, `0` inactive NVLinks, orphan PID cleanup, and `dcgmi diag -r 1 -j`; and `GPUStragglerDetected` alerts when `DCGM_FI_PROF_PIPE_TENSOR_ACTIVE` lags the node average by `> 0.15` for `5m` while `DCGM_FI_DEV_GPU_UTIL > 80`.
5. **Exercise 5:** `Xid 13/31/94 -> RESTART_APP`, `Xid 44/63 -> IGNORE`, `Xid 48 -> WORKFLOW_XID_48`, `Xid 62/64/95/109/119/120 -> RESET_GPU`, `Xid 74 -> WORKFLOW_NVLINK_ERR`, and `Xid 79 -> RESTART_BM`; draining a node on `Xid 31` (user OOM/page fault) or `Xid 44` (`IGNORE`) needlessly depletes healthy cluster capacity.
6. **Exercise 6:** `4` SUs of `32` nodes is `128` nodes (`1,024` GPUs) nominally, but removing `1` DGX node for UFM connectivity leaves `127` nodes (`1,016` GPUs) and `31` nodes in a `1`-SU compute table; a `30 kW` rack holds `floor(30 / 10.2) = 2` DGX H100 nodes (`20.4 kW`); and `BCM Auto Scaler` (`cm-scale`) dynamically repurposes free nodes between Slurm and Kubernetes using configuration overlays.
