## 4. One-Line Expected Exercise Solutions

1. **Exercise 1:** (a) On an `A100-80GB` (`79.14 GiB`) at `gpu_memory_utilization = 0.90`, usable VRAM is **`71.22 GiB`**, and subtracting `14.99 GiB` weights, `0.12 GiB` non-PyTorch memory, and `1.19 GiB` peak activations (`16.30 GiB` total) leaves **`54.93 GiB` for the KV cache**; (b) on an `L40S` (`46,068 MiB`), 4-bit `Qwen3-14B-AWQ` saves **`18.1566 GiB`** of weight memory (`27.5185 -> 9.3619 GiB`), expands KV cache by **`+18.15 GiB`** (`11.00 -> 29.15 GiB`) and KV tokens by **`2.65x`** (`72,064 -> 191,056` tokens, `1.76x -> 4.66x` concurrency), boosts ShareGPT throughput by **`2.70x`** (`474.38 -> 1,280.0 tok/s`), and cuts mean TTFT by **`42.78%`** (`103.61 -> 59.29 ms`).
2. **Exercise 2:** (a) Loading a `28.0 GB` checkpoint takes **`448.0 s`** (`7.47 min`) over a `500 Mbps` (`0.0625 GB/s`) link, **`11.20 s`** from a GKE `gcsfuse` + NVMe PVC (`2.5 GB/s`), and **`4.67 s`** from a Nebius Shared Filesystem / NVMe volume with `--load-format runai_streamer` (`6.0 GB/s`, **`95.93x` faster** than uncached download); (b) a `30.0 s` (`30,000 ms`) cold start versus a `100.0 ms` warm request is a **`300.0x` latency penalty**, requiring KEDA `minReplicas: 1` (or higher) so user requests never block on cold pod initialization.
3. **Exercise 3:** (a) Under `Score = 20 * I(prefix_hit) - 3 * waiting_queue - 10 * kv_cache_util`, `Replica 0` scores **`-29.8`**, `Replica 1` scores **`+12.8`**, and `Replica 2` is excluded (**`-999.0`**, missing LoRA adapter), so the `EndpointPicker` selects **`vllm-replica-1`**; (b) transferring a `512 MB` (`4,096 Mb`) KV cache block takes **`409.6 ms`** on `10 Gbps` pod Ethernet versus **`6.83 ms`** on `600 Gbps` RoCEv2 (**`60.0x` faster**) and **`5.12 ms`** on `800 Gbps` NDR InfiniBand, and with `(6, 5, 7)` running requests (`18` total) at target `4`, KEDA computes `ceil(18 / 4) = 5` and scales to **`5` replicas**.
4. **Exercise 4:** (a) For `output_tokens = 128`, `TTFT = 104.64 ms`, and `ITL = 43.95 ms`, `e2e_latency = 104.64 + 127 * 43.95 = 104.64 + 5,581.65 =` **`5,686.29 ms` (`5.69 s`)**; (b) at `52%` scaling efficiency (`45%` GPU utilization), `64` GPUs provide **`33` effective GPUs** (`33.28` rounded) and waste **`31` GPU-equivalents**, burning **`10,416` wasted GPU-hours** (`31 * 336`) or **`$50,000`** (`$49,996.80` at `$4.80/GPU-hr`) over a 14-day run.
