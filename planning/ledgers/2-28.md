## 4. One-Line Expected Exercise Solutions

1. **Exercise 1 (Why Automate, Automation Outage Lessons, and Interface Evolution `SNMP` -> `CLI` -> `NETCONF` -> `RESTCONF` -> `gNMI`, `NPA` Chapter 2):** (a) Automating a snowflake network relocates complexity and can push a bug to 500 switches simultaneously—prevent fleet-wide outages using **canary/staged rollouts**, **pre/post-checks**, **confirmed commits (`commit confirmed 120`)**, **per-failure-domain blast-radius caps**, and **out-of-band management**; (b) model-driven APIs (`NETCONF`, `RESTCONF`, `gNMI`) return and accept schema-validated data with transactional semantics, replacing brittle version-dependent CLI regex screen scraping.
2. **Exercise 2 (Structured Data Formats `YAML`, `JSON`, `XML`, `Protocol Buffers` and `YANG` / `JSON Schema` Validation, `NPA` Chapter 8):** Use `YAML` (`yaml.safe_load`, quoting strings against the \"Norway problem\" where `no` parses as `False` and `010` as octal) for human-edited Git intent, `JSON` for REST/RESTCONF APIs, `XML` for NETCONF, and **Protocol Buffers** for high-rate binary gRPC/gNMI streaming telemetry; validate intent data in CI with **JSON Schema** / Pydantic (`validate_switch_inventory_schema()`) and device models with **YANG (`RFC 7950`)** (`IETF` vs `OpenConfig` vs native models).
3. **Exercise 3 (Jinja2 Templating with `StrictUndefined`, Custom Filters, and Inheritance, `NPA` Chapter 9):** Render role templates (`leaf.j2`, `spine.j2`) from validated intent data using **`StrictUndefined`** (`render_leaf_config_strict()`) so any typo or missing variable fails immediately at render time instead of producing an empty line in a switch config, keeping complex address math in Python filters rather than inside Jinja templates.
4. **Exercise 4 (Comparing `NETCONF` `RFC 6241`, `RESTCONF` `RFC 8040`, and `gNMI` / Streaming Telemetry, `NPA` Chapter 10):** **NETCONF** (`SSH port 830`, XML) provides multi-step stateful transactions across `candidate` and `running` datastores (`lock`, `edit-config`, `validate`, `commit confirmed`, `simulate_netconf_confirmed_commit()`); **RESTCONF** (`HTTPS`, JSON/XML) provides stateless single-shot HTTP CRUD (`GET`/`POST`/`PUT`/`PATCH`/`DELETE` + `YANG Patch` `RFC 8072`); and **gNMI** (`gRPC/HTTP2`, protobuf/JSON) provides `Capabilities`, `Get`, atomic per-request `Set`, and native **`Subscribe` streaming telemetry** (`sample` and `on-change`, dial-in vs dial-out).
5. **Exercise 5 (Python Network Automation Libraries and Safe Execution Patterns):** Use `ncclient` for NETCONF, `pygnmi` for gNMI, `requests`/`httpx` for RESTCONF, `netmiko`/`scrapli` (+ `TextFSM`/`ntc-templates`) for CLI-only devices, and `napalm` for multi-vendor config compare/commit/rollback, enforcing **idempotency**, `--dry-run` diffs, timeouts, per-device error isolation, and Vault-backed secrets.
6. **Exercise 6 (SDN and Centralized Control Planes: Four Interaction Models, Fibbing/PCEP/OpenFlow, `CAP`, and Subsidiarity, `CN` Chapter 18):** Classify SDN architectures into **Distributed** (`OSPF`/`BGP`), **Augmented** (controller injects paths into the distributed control plane: `BGP` route injection, **Fibbing** fake LSAs, **PCEP**, `I2RS`), **Hybrid**, and **Replace** (`OpenFlow`, `P4Runtime`); by the **CAP theorem** and **subsidiarity principle**, keep fast failure detection and ECMP fast-reroute local in the distributed layer while centralizing global traffic-engineering policy (failing static if the controller is unreachable).
