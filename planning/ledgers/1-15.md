## 4. One-Line Expected Exercise Solutions

1. **Exercise 1 (Unit Search Path Precedence and Drop-In `ExecStart=` Reset):** (a) Among `/usr/lib/systemd/system`, `/run/systemd/system`, `/etc/systemd/system`, and `/etc/systemd/system.control`, `/etc/systemd/system.control` (`systemctl set-property`) wins first and `/etc/systemd/system` (admin units/drop-ins) overrides `/usr/lib/systemd/system` (vendor packages); (b) in a drop-in `/etc/systemd/system/containerd.service.d/override.conf`, you must write an empty `ExecStart=` line before the new `ExecStart=/usr/bin/containerd ...` line so `systemd` clears the vendor list instead of complaining about two `ExecStart=` commands on a `Type=simple` unit.
2. **Exercise 2 (Requirement vs. Ordering Directives `Wants`, `Requires`, `Requisite` vs `After`):** (a) `Wants=b.service` or `Requires=b.service` alone starts `a.service` and `b.service` **in parallel**; to start `a` after `b` finishes starting, you must specify **both** `Wants=b.service` (or `Requires=b.service`) **and** `After=b.service`; (b) `Wants=` keeps `a` running if `b` fails, `Requires=` aborts/stops `a` if `b` fails, and `Requisite=` fails `a` immediately without even attempting to start `b` if `b` is not already active.
3. **Exercise 3 (Template Specifiers `%p`, `%i`, `%I`, `%n` and Socket Activation):** (a) Instantiating `getty@.service` with `/dev/ttyUSB0` sets `%p = "getty"`, `%i = "-dev-ttyUSB0"` (escaped path), `%I = "/dev/ttyUSB0"` (unescaped path), and `%n = "getty@-dev-ttyUSB0.service"`; (b) in `echo.socket` (`ListenStream=22222`), `Accept=true` makes `systemd` accept each TCP connection and spawn a fresh `echo@<conn>.service` instance with the socket wired to `StandardInput=socket`, whereas `Accept=false` passes the listening socket (`$LISTEN_FDS`) to a single long-running daemon.
4. **Exercise 4 (Protecting `system.slice` and Per-User Login Slices `user-.slice.d`):** (a) Never set `MemoryMax=` on `system.slice` because capping `system.slice` throttles or OOM-kills critical host daemons (`sshd`, `kubelet`, `containerd`); instead set `MemoryLow=2G` and `CPUWeight=200` on `system.slice` (and `OOMScoreAdjust=-900` on `sshd`/`kubelet`) while capping workload slices (`kubepods.slice`, `user-.slice`); (b) `/etc/systemd/system/user-.slice.d/10-defaults.conf` (`TasksMax=1250`, `CPUQuota=800%`, `MemoryMax=64G`) caps every login user's aggregate session resources, and `KillUserProcesses=no` in `logind.conf` prevents `tmux`/`screen` sessions from being killed on logout.
5. **Exercise 5 (Ordering GPU Daemons and Health-Gate `oneshot` Units):** Because `nvidia-fabricmanager.service` (`Type=forking`/`simple`) may mark itself started before NVSwitch fabric training completes, ordering `kubelet.service` with `After=nvidia-fabricmanager.service` plus a `Type=oneshot` (`RemainAfterExit=yes`) health-gate unit that verifies `nvidia-smi -L` count and `nvidia-smi nvlink -s` state prevents `kubelet` from advertising broken GPUs.
6. **Exercise 6 (`journald` Persistence, Rate Limiting, and Diagnosing `203/EXEC` / `217/USER`):** (a) With `Storage=auto`, `journald` writes to RAM (`/run/log/journal`) unless `/var/log/journal` exists (or `Storage=persistent` is set in `/etc/systemd/journald.conf.d/`); (b) `status=203/EXEC` means `ExecStart=` failed `execve()` (missing binary, missing `+x` bit, `noexec` mount, or bad `#!` shebang), and `status=217/USER` means the `User=` account does not exist in NSS.
