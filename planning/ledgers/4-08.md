## 4. One-Line Expected Exercise Solutions

1. **Exercise 1 (Handlers, `listen:` Topics, and Lost-Handler-After-Failure Trap, `AUR` Ch. 11):** Using `simulate_handler_listen_and_failure_loss()`, `listen:` allows multiple handlers across roles to subscribe to a single topic and run in handler definition order; if a task after a config change fails before handler flush, the handler is skipped on Run 1 and also skipped on Run 2 (because the file on disk is already updated and reports `changed=False`), requiring `force_handlers: true` or `meta: flush_handlers`.
2. **Exercise 2 (Conditionals `when:`, Boolean-vs-String Traps `-e flag=false`, and Skipped `register` Variables):** `when:` list items are ANDed, `-e flag=false` arrives as the non-empty truthy string `"false"` (requiring `when: flag | bool`), and a skipped task binds its registered variable without `stdout`/`rc` (requiring `when: res is not skipped`).
3. **Exercise 3 (Loops, Nested `loop_var`, and Custom Filter Plugins `FilterModule`, `AUR` Ch. 10):** `FilterModule.surround_by_quotes()` in `filter_plugins/` registers custom Jinja2 filters; `register` on a looped task populates a `results` list; and setting `loop_control: { loop_var: vhost }` on an outer `include_tasks` loop prevents an inner loop from overwriting `item`.
4. **Exercise 4 (Error Handling `failed_when`/`changed_when` and `block`/`rescue`/`always` Rollbacks, `AUR` Ch. 10):** Using `simulate_block_rescue_always_maintenance()`, `rescue:` inspects `ansible_failed_task` and `ansible_failed_result`, rolls back the driver, and calls `fail` so the failure is not silently swallowed as `rescued=1, failed=0`; `always:` collects `journalctl -k` logs, while `scontrol State=RESUME` runs only after `block` succeeds so failed GPU nodes remain `DRAIN`ed.
5. **Exercise 5 (Static `import_*` vs. Dynamic `include_*`, `AUR` Ch. 10 & 11):** `import_tasks`/`import_role` are pre-processed statically at parse time (exposing tasks to `--list-tasks` and `--start-at-task` and copying `when:`/`tags:` to every child task), whereas `include_tasks`/`include_role` execute dynamically at runtime (supporting `loop:` and fact-derived filenames, and using `apply: { tags: [...] }` to propagate tags).
6. **Exercise 6 (Delegation Patterns `delegate_to` + `run_once` and Rolling GPU Node Maintenance, `AUR` Ch. 11):** Section 6 drains each batch on the Slurm controller via `delegate_to`, polls `squeue` with `until: jobs.stdout == ""`, applies and validates changes inside `block`/`rescue`, and resumes healthy nodes; `delegate_to: localhost` with `run_once: true` downloads external artifacts once onto the controller before copying them to isolated cluster nodes.
