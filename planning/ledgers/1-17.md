## 4. One-Line Expected Exercise Solutions

1. **Exercise 1 (Page Tables, TLB Reach, and Huge Pages `4 KiB` vs `2 MiB` vs `1 GiB`):** A `256 GiB` working set requires `67,108,864` (`~67M`) `4 KiB` PTEs; a `64`-entry data TLB covers only `0.25 MiB` (`262,144` B) with `4 KiB` pages, versus `128 MiB` (`512x` larger) with `2 MiB` huge pages and `64 GiB` (`65,536 MiB`) with `1 GiB` huge pages, eliminating most multi-level page walks (`CR3 -> PGD -> P4D -> PUD -> PMD -> PTE`).
2. **Exercise 2 (`VSZ`, `RSS`, `PSS`, `USS` Accounting and `free -h` `MemAvailable`):** For `4` processes each holding `100 MiB` private memory and sharing one `400 MiB` dataset mapping, each process has `USS = 100 MiB`, `PSS = 200 MiB`, and `RSS = 500 MiB` (summing `RSS` gives `2,000 MiB`, whereas summing `PSS` gives the true `800 MiB` physical footprint); in `free -h`, `MemAvailable` counts free memory plus reclaimable page cache and `SReclaimable` slab (`free` is unused RAM).
3. **Exercise 3 (Page Reclaim Watermarks `min`/`low`/`high`, `kswapd` vs Direct Reclaim, and `OOM` Scoring):** With `100,000,000 KiB` (`~100 GB`) RAM and `min_free_kbytes = 90,000`, raising `vm.watermark_scale_factor` from `10` (`0.1%`, step `100,000 KiB`) to `100` (`1.0%`, step `1,000,000 KiB`) wakes `kswapd` at `low = 1,090,000 KiB` instead of `190,000 KiB` so background reclaim prevents synchronous direct-reclaim stalls (`pgscand/s`, `allocstall`); setting `oom_score_adj = -1000` gives `oom_score = 0` (immune), while `+500` on a process using `40%` of RAM raises its score from `400` to `900`.
4. **Exercise 4 (The NUMA GPU Trap, First-Touch Placement, and `numactl`):** Under default local first-touch placement, a data loader running on NUMA node `0` allocates host buffers in node `0`'s DRAM; if it feeds a GPU attached to node `1`'s PCIe root complex, every DMA transfer crosses the UPI/xGMI socket interconnect (`numastat` `other_node` rises); fix by launching with `numactl --cpunodebind=$node --membind=$node` matching `/sys/bus/pci/devices/<BDF>/numa_node` and disabling `kernel.numa_balancing=0`.
5. **Exercise 5 (Allocators, CPython `256 KiB` Arenas, and Copy-on-Write Refcount Breakage):** CPython's `pymalloc` retains `256 KiB` arenas as long as a single object survives inside them, and `fork()`ed `DataLoader` workers break copy-on-write sharing when they read Python lists/dicts because incrementing Python reference counts dirties the shared memory pages; store datasets in NumPy/Arrow/`mmap` arrays and preload `libjemalloc.so.2`.
6. **Exercise 6 (Pinned Host Memory, `RLIMIT_MEMLOCK`, and Training Node RAM Budgeting):** (a) Pinned (`mlock`ed / `cudaMallocHost`) memory cannot be swapped or migrated so GPUs and RDMA NICs can DMA directly without a pageable bounce buffer (`2x`–`3x` faster), and requires `ulimit -l unlimited` (`LimitMEMLOCK=infinity`); (b) `8` GPUs x `16` workers x `2 GiB` (`256 GiB`) + `32 GiB` pinned + `16 GiB` OS = `304 GiB`, which exceeds a `256 GiB` host (`fits_in_ram = False`), triggering cgroup or host OOM kills (`exit 137`).
