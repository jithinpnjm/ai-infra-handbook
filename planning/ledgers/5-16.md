## 4. One-Line Expected Exercise Solutions

1. **Exercise 1 (`ConfigMap` and `Secret` Consumption Patterns, Key Naming Rules `KUR` Ch. 13 Table 13-1, Live Updates, and `immutable: true`):** `validate_configmap_or_secret_key()` enforces `^\.?[A-Za-z0-9]([-._A-Za-z0-9]*[A-Za-z0-9])?$` (no `..` or spaces); `$(VAR)` expands env vars in `command`/`args`; directory mounts update via `..data` symlink swap whereas env vars and `subPath` mounts do not; and `immutable: true` stops kubelet watches.
2. **Exercise 2 (Securing Kubernetes `Secret`s at Rest and Safe Key Rotation, `PK` Ch. 7):** `simulate_etcd_encryption_key_rotation()` shows `EncryptionConfiguration` uses the first key (`secret-key-2`) for new writes and keeps `secret-key-1` in second position so existing Secrets can still be decrypted during `kubectl get secrets -A -o json | kubectl replace -f -`.
3. **Exercise 3 (External Secret Stores and Vault Kubernetes Auth, `PK` Ch. 7):** ESO syncs external secrets into native Secrets, `secrets-store-csi-driver` mounts secrets via CSI without `etcd` storage, and Vault Agent Injector uses `vault.hashicorp.com/agent-inject-*` annotations and `auth/kubernetes` (`TokenReview` API) to render secrets to `/vault/secrets/` in memory.
4. **Exercise 4 (Projected Volumes, Bound `ServiceAccount` Tokens 1.22+/1.24+, and Cloud Workload Identity):** Projected volumes mount short-lived (~1h), audience-bound, Pod-UID-bound JWT tokens from the `TokenRequest` API (never stored in `etcd`), enabling keyless OIDC federation to AWS IRSA / GKE Workload Identity / Vault.
5. **Exercise 5 (Designing Multi-Tenant RBAC, Aggregation, and `autoupdate: "false"`, `KUR` Ch. 14):** A `RoleBinding` referencing a `ClusterRole` scopes permissions to that single namespace, `aggregationRule` (`aggregate-to-edit: "true"`) extends built-in roles with CRDs, `kubectl auth reconcile -f` syncs RBAC declaratively, and `rbac.authorization.kubernetes.io/autoupdate: "false"` prevents `kube-apiserver` from overwriting customized built-in roles on restart.
6. **Exercise 6 (Auditing RBAC Escalation Paths and `sudo`-Style Impersonation, `PK` Ch. 10):** `evaluate_rbac_and_audit_escalations()` flags `cluster-admin` bindings to `system:authenticated`, `nodes/proxy`, and wildcard rules, and verifies the `PK` Chapter 10 `impersonate` pattern where `ops-team` gets `view` by default and must pass `--as=cluster-admin` for writes.
