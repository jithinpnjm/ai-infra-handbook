## 4. One-Line Expected Exercise Solutions

1. **Exercise 1 (Reading the Routing Table, Longest-Prefix Match `LPM`, and Metric Tie-Breaking):** (a) In `ip route show`, `proto kernel scope link src ...` is an on-link connected subnet route (ARP directly for destination), whereas `via <gw>` is an indirect route (ARP for `<gw>`); (b) using `select_best_route_lpm()`, `10.200.5.42` matches `10.200.5.0/24` (`metric 500`) over `10.200.0.0/16` (`metric 50`) and `0.0.0.0/0` (`metric 100`) because **prefix length always wins before metric**, while two `/0` default routes break ties by the lowest `metric` (`100` beats `200`).
2. **Exercise 2 (Special Route Types, `onlink`, and IPv6 Link-Local Gateways):** `local` delivers to the host itself (table `255`), `blackhole` drops silently, `unreachable` drops and returns ICMP Host/Net Unreachable (`EHOSTUNREACH`/`ENETUNREACH`), and `prohibit` returns Administratively Prohibited; `onlink` tells the kernel to ARP for a gateway even when its IP is not covered by a connected prefix (common on cloud `/32` VMs), and IPv6 default routes (`default via fe80::1 dev ens4`) require `dev <iface>` because `fe80::/64` is valid on every interface.
3. **Exercise 3 (The Multiple-Default-Gateway Trap and Policy-Based Routing `ip rule`):** Adding a second default gateway in `main` steals or asymmetrically splits traffic; on a multi-NIC GPU server, keep a single default route in `main` on the management NIC and create per-rail tables (`100 rail0`, `101 rail1` in `/etc/iproute2/rt_tables`) selected by source-IP `ip rule` entries (`ip rule add from 10.100.1.0/24 table rail1 priority 101`, verified via `evaluate_policy_routing()` and `ip route get 10.100.5.20 from 10.100.1.15`).
4. **Exercise 4 (Reverse-Path Filtering `rp_filter` Modes `0`/`1`/`2` and the `max(all, iface)` Trap):** Mode `0` disables `rp_filter`, mode `1` (*strict*) drops packets unless the best return route to the source IP exits the exact interface the packet arrived on, and mode `2` (*loose*) accepts packets if the source IP is reachable via *any* interface; because the kernel computes `effective = max(net.ipv4.conf.all.rp_filter, net.ipv4.conf.<if>.rp_filter)` (`evaluate_rp_filter()`), setting `eth1.rp_filter=0` while `all.rp_filter=1` leaves `eth1` in strict mode (`1`) and silently drops asymmetric packets (incrementing `IPStatsInAddrErrors` in `nstat -az`).
5. **Exercise 5 (Linux as a Router `ip_forward=1`, NAT `MASQUERADE`, and ECMP `fib_multipath_hash_policy=1`):** Turning a Linux host into a router requires `net.ipv4.ip_forward=1` (`net.ipv6.conf.all.forwarding=1`), `FORWARD` chain rules, and return routes (or `POSTROUTING` `MASQUERADE` NAT); for host ECMP multipath routes (`nexthop via ... weight 1`), set `net.ipv4.fib_multipath_hash_policy=1` so the kernel hashes on the **L4 5-tuple** (`src IP, dst IP, proto, src port, dst port`) rather than L3 (`src IP, dst IP` only) and `fib_multipath_use_neigh=1` to skip dead neighbours.
6. **Exercise 6 (Host Routing in Kubernetes Nodes and Rail-Optimized GPU Clusters):** Every Kubernetes node sets `ip_forward=1`, routes local Pods via per-Pod `/32` `veth` routes (`10.244.1.5 dev cali1234 scope link`), and routes remote Pods via direct L3/BGP node routes (`10.244.2.0/24 via 10.0.0.16`) or VXLAN/Geneve tunnels (`flannel.1` / `cilium_vxlan`), while an 8-GPU server pairs per-rail `ip rule` tables with `rp_filter=2`, `arp_ignore=1`, and `arp_announce=2`.
