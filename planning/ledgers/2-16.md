## 4. One-Line Expected Exercise Solutions

1. **Exercise 1 (RFC 7938 eBGP Clos Design, Same-Spine-ASN Valley Prevention, and `multipath-relax`):** (a) Assigning a unique ASN per leaf rack (`65101..65104`) and the **exact same ASN (`65001`) across all spines in a tier** ensures that if Leaf 1 loses its direct link to Spine 2, Spine 2 automatically rejects the valley/hairpin path `Leaf 1 -> Spine 1 -> Leaf 2 -> Spine 2` because Spine 2 sees its own ASN `65001` in `AS_PATH` (`check_clos_valley_path_rejection()`); (b) to make eBGP act like an ECMP fabric protocol, enable `bgp bestpath as-path multipath-relax`, `maximum-paths 64`, `neighbor ... advertisement-interval 0`, `bgp fast-external-failover`, and `bfd` (`100–300 ms`), and never advertise point-to-point link subnets.
2. **Exercise 2 (BGP Unnumbered `RFC 5549` / `RFC 8950` Extended Next Hop):** BGP unnumbered eliminates assigning `/31` IPv4 subnets to hundreds of leaf-spine links by discovering the neighbor's `fe80::` IPv6 link-local address and MAC via **ICMPv6 Router Advertisements (`RA`)** and negotiating **Extended Next Hop Encoding (capability code `5`, RFC 8950)** in `OPEN` so IPv4 prefixes are advertised with an IPv6 link-local `NEXT_HOP` (`via inet6 fe80::... dev swp1 onlink`).
3. **Exercise 3 (Failure Domains, Positive Feedback Loops, and Clos Spine Summarization Black Holes, `CN` Chapter 19):** (a) A **failure domain** is the set of routers that must recompute when state changes, and a **positive feedback loop** occurs when a `3`-flap/s link (`6` events/s) is multiplied across parallel paths to `12` events/s, exceeding a downstream router's `10` event/s capacity and causing a cascading reboot storm; (b) if Spine 2 loses its link to Leaf 3 (`10.10.3.0/24`) while continuing to advertise an unconditional `10.10.0.0/16` summary upward, traffic hashed to Spine 2 for Leaf 3 is **blackholed** (`evaluate_spine_summary_and_min_peers()`).
4. **Exercise 4 (Advanced AI-Fabric BGP: `ADD-PATH`, Link-Bandwidth Weighted ECMP, Minimum Peers, and `BGP DPF`):** `ADD-PATH` (`RFC 7911`) advertises multiple paths per prefix; the **Link Bandwidth Extended Community** enables weighted ECMP (`compute_weighted_ecmp_shares_pct([400, 800, 100, 400])`) proportional to link capacity; the **minimum-peers rule** withdraws a prefix from a spine if fewer than `N` ECMP next hops remain healthy; and **BGP Deterministic Path Forwarding (`DPF`)** tags sessions and routes with **colors** (`filter_dpf_colored_route()`) to partition a physical Clos into isolated logical fabrics for high-priority RoCE tenants.
5. **Exercise 5 (Comparing `eBGP`, `IS-IS` Flood Reduction / `Flex Algo`, and `RIFT` for 32k-GPU Fabrics and Dragonfly):** While eBGP dominates front-end and Clos fabrics, back-end AI fabrics scaling to 32k GPUs or **dragonfly** topologies evaluate **IS-IS with optimized flooding** (`draft-white-lsr-distoptflood`) and **Flex Algo (`RFC 9350`/`9502`)** (computing separate constrained SPF planes per algorithm) or **RIFT (`RFC 9692`)** (link-state northbound, distance-vector default route southbound, with **automatic disaggregation** on link failure to prevent black holes).
6. **Exercise 6 (AI Cluster Multi-Tenancy, BGP to the Server / Anycast, and `SRv6` `uSID` Traffic Engineering):** Isolate tenants via dedicated rail ports, **EVPN-VXLAN** (`MAC-VRF` + `Route Type 5 IP-VRF`, e.g., `8` leaves x `8` spines `64x800G` = `512` GPUs/rail or `7` VRFs per server for `7` NVIDIA **MIG** instances), or VXLAN **GBP** tags; run FRR on GPU hosts/DPUs for MLAG-free ECMP and health-checked **anycast** VIPs; and use controller-driven **SRv6 `16`-bit micro-SIDs (`uSID`s)** for deterministic congestion-free path steering.
