## 4. One-Line Expected Exercise Solutions

1. **Exercise 1:** `Layer 1 Hardware/driver` (`nvidia-smi -L/-q`, `dmesg`), `Layer 2 Sharing state` (`mig.mode.current`, `nvidia-smi mig -lgi`), `Layer 3 Registration` (`status.allocatable`, `nvidia-device-plugin` logs), `Layer 4 Scheduling policy` (`ResourceQuota`, `PodGroup`, `Queue`, MIG fragmentation), `Layer 5 Runtime` (`BindRequest`, reservation pod, `DIAGNOSTIC_GPU_OK`), and `Layer 6 Service & Telemetry` (`p99` latency, `p95` queue wait, `dcgm_exporter_scrape_age_seconds <= 120s`).
2. **Exercise 2:** (a) `0` host instances (`Layer 2` broken) means a host reboot or driver reset wiped the MIG layout -> cordon the node and reapply the approved MIG configuration during maintenance; (b) host instances present (`Layer 2` OK) but `status.allocatable = 0` (`Layer 3` broken) means `nvidia-device-plugin` lost discovery -> restart the device-plugin pod on that node and wait `30 s`.
3. **Exercise 3:** A `ResourceQuota` `"0"` denial rejects `kubectl apply` at API admission before any Pod is created in etcd; a `kai-pod-grouper` failure leaves the Pod `Pending` in etcd with no `PodGroup` CR created; and a `kai-binder` failure shows a scheduled `PodGroup` whose `BindRequest` CR or integer reservation pod is stuck on the target node.
4. **Exercise 4:** `sli_mig_inference_request_success > 99.5%`, `sli_mig_inference_p99_latency < 100 ms` (breach at `> 120 ms`), `timeslice_queue_time_p95 < 30 s`, `timeslice_memory_utilization > 90%`, and `dcgm_exporter_scrape_age_seconds > 120 s` (`UNKNOWN_STALE_TELEMETRY`).
5. **Exercise 5:** (a) `dcgmi test --inject` for `XID 48` Double-Bit ECC; (b) `ibportstate ... disable` on the InfiniBand switch port; host `iptables` cannot block RDMA traffic because RDMA bypasses the Linux kernel TCP/IP stack.
6. **Exercise 6:** Powering off `1` of `3` master nodes caused a brief API server leader-election pause; aggressive liveness probes on the worker-node `nvidia-device-plugin` DaemonSet failed and restarted the plugin, unregistering `nvidia.com/gpu` and causing `kubelet` to kill all Triton pods (`PDBs` only govern voluntary Eviction API calls, not `kubelet` resource-loss terminations); fix by increasing liveness probe timeouts/backoffs in the GPU Operator Helm chart.
