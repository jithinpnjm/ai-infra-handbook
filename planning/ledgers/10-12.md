## 4. One-Line Expected Exercise Solutions

1. **Exercise 1 (`256 MiB` pageable vs pinned vs remote NUMA):** (a) Pageable = `0.268435456 GB / 0.074318 s = 3.61 GB/s`, local-NUMA pinned = `0.268435456 GB / 0.016902 s = 15.88 GB/s`; (b) speedup = `74.318 / 16.902 = 4.40x`; (c) remote-NUMA pinned = `15.88 / 1.75 = 9.08 GB/s`.
2. **Exercise 2 (`nsys` trace verification):** `Stream 14`'s `D2H` finishes at `2,292,900 + 471,200 = 2,764,100 ns`, and `Stream 15` starts at `2,764,300 ns` (`200 ns` later, zero overlap); caused by (1) pageable host memory staging, (2) legacy default stream `0` barrier, or (3) `cudaDeviceSynchronize()` in the loop.
3. **Exercise 3 (`overlap_pipeline.cu` sizing & sync slowdown):** (a) `67,108,864 / 4,194,304 = 16` chunks, `4,194,304 * 4 B = 16.0 MiB` per slot buffer, `67,108,864 * 4 B * 2 = 512.0 MiB` total transfer; (b) `512.0 MiB / 0.8124 s = 630.2 MiB/s`; (c) `1,934.7 ms / 812.4 ms = 2.38x` (`~2.4x`) slowdown.
4. **Exercise 4 (Index `4,194,304` vs `4,194,305` corruption):** Moving `Collect` after `Refill` deterministically overwrites slot 0/1 before chunk 0's output is saved, failing at the start of chunk 1 (`index 4,194,304 = chunkElements`); omitting `cudaEventSynchronize(complete[slot])` creates a timing race where the host begins overwriting the slot while the DMA engine is still finishing the previous chunk, failing intermittently at `index 4,194,305`.
5. **Exercise 5 (LLM stream-ordered scratch & event wait):** Create streams with `cudaStreamCreateWithFlags(&s, cudaStreamNonBlocking)` (and `--default-stream per-thread`), allocate the `16 MB` scratch buffer with `cudaMallocAsync(&d_scratch, bytes, stream)` / `cudaFreeAsync(d_scratch, stream)` (or `export PYTORCH_ALLOC_CONF=backend:cudaMallocAsync`), and link layers `0–5` (`stream0`) to `6–11` (`stream1`) via `cudaEventRecord(ev, stream0)` + `cudaStreamWaitEvent(stream1, ev, 0)`.
6. **Exercise 6 (Bounded pinned pool vs `500 GB` OOM):** Pinning `500 GB` on a `512 GB` host leaves only `12 GB` of pageable RAM, starving the OS and waking the Linux OOM Killer; a bounded 2-slot double-buffered pool of `16 MiB` input + `16 MiB` output per slot (`32 MiB`/slot × `2` slots × `8` GPUs = `512 MiB` total, or `256 MiB` for 1-slot-pair per GPU) achieves full DMA overlap while leaving `> 511 GB` of pageable RAM free.

## 5. Self-Assessment (What I Am Least Sure About)

1. **Binary MiB/s vs decimal GB/s in `V3 Ch 8`:** In `V3 Ch 8` (lines 303–308), `268,435,456` bytes (`256 MiB`) divided by `74.318 ms` is `3.612 × 10^9 B/s` (`3.61 GB/s` decimal), and divided by `16.902 ms` is `15.882 × 10^9 B/s` (`15.88 GB/s` decimal). Our model uses `transfer_bytes / 1e9` so the exact `3.61 GB/s` and `15.88 GB/s` figures match the source text to two decimal places.
2. **Effective MiB/s in `V3 Lab 03` (`~630 MiB/s`):** `67,108,864 * 4 * 2 bytes = 512 MiB` divided by `0.8124 s = 630.23 MiB/s` (`~630 MiB/s` in `V3 Lab 03` line 303); both the exact `630.2 MiB/s` and the rounded `~630 MiB/s` are noted.
3. **PyTorch `PYTORCH_ALLOC_CONF=backend:cudaMallocAsync`:** Taken directly from *AI Systems Performance Engineering* Chapter 11 (p. 361); older PyTorch 2.x versions also accept `PYTORCH_CUDA_ALLOC_CONF=backend:cudaMallocAsync`.
