## 4. One-Line Expected Exercise Solutions

1. **Exercise 1 (Device-Mapper Linear Table Translation and Hyphen Doubling):** (a) In `myvg-mylv2: 0 10960896 linear 8:17 2048` and `10960896 10010624 linear 8:33 20973568`, logical sector `0` maps to device `8:17` sector `2048`, and logical sector `10,960,996` (`10960896 + 100`) maps to device `8:33` sector `20,973,668`; (b) VG `ubuntu-vg` and LV `root` become `/dev/mapper/ubuntu--vg-root` because `udev`/LVM doubles internal hyphens so a single `-` unambiguously separates VG and LV.
2. **Exercise 2 (LVM Online Cloud Resize vs Offline `ext4` Shrink):** (a) To grow an online cloud disk: rescan the block device (`echo 1 > .../rescan` or `nvme ns-rescan`), run `sudo growpart /dev/sdb 1`, `sudo pvresize /dev/sdb1`, and `sudo lvextend -r -l +100%FREE /dev/myvg/mylv1`; (b) to shrink an `ext4` LV, you must `umount`, run `e2fsck -f`, shrink the filesystem *first* (`resize2fs`), and only then `lvreduce` (or use `lvreduce -r`), whereas `XFS` cannot be shrunk at all.
3. **Exercise 3 (RAID Geometry `0`, `1`, `5`, `6`, `10` and the Parity Read-Modify-Write Penalty):** Across `8` drives of `4 TB` each: `RAID 0` = `32 TB` (`0` fault tolerance, `1` I/O per write), `RAID 10` = `16 TB` (`1` per mirror pair, `2` I/Os per write), `RAID 5` = `28 TB` (`1` drive tolerance, `4` I/Os per small write: read old data + read old parity + write new data + write new parity), and `RAID 6` = `24 TB` (`2` drive tolerance, `6` I/Os per small write).
4. **Exercise 4 (NVMe Architecture, `nvme smart-log` Alerts, and NVMe-oF):** (a) NVMe attaches directly to PCIe and provides up to `64,000` per-CPU submission/completion queue pairs (`blk-mq`, MSI-X interrupts, no shared lock) vs SATA's single `32`-deep queue; (b) alert on `critical_warning != 0`, `media_errors > 0`, `percentage_used >= 90%`, `available_spare <= threshold`, and rising `unsafe_shutdowns` / temperatures.
5. **Exercise 5 (Disk Capacity Scaling at `50%` Target Utilization and `qd=1` vs `qd=64`):** (a) Sizing for `200,000` IOPS using drives rated at `100,000` max IOPS at a `50%` target utilization (`50,000` usable IOPS/drive) requires `4` drives rather than `2` so bursts do not queue; (b) `fio` at `--iodepth=1` measures unloaded single-thread latency (`~80,000` IOPS), whereas `--iodepth=64 --numjobs=4` measures saturated parallel throughput (`~1,000,000` IOPS).
6. **Exercise 6 (The 8-Layer Storage-to-GPU Path and Local NVMe Epoch Staging):** (a) The 8 layers are (1) storage media, (2) storage server/controller queue, (3) network fabric, (4) client filesystem, (5) page cache, (6) CPU memory/NUMA, (7) PCIe bus, and (8) GPU `HBM`; (b) local NVMe staging reads from shared storage in Epoch 1 (`~0%` hit rate) and serves Epochs `2..N` locally (`> 95%` hit rate), eliminating shared-fabric congestion when the dataset fits on local NVMe and runs for multiple epochs.
