## 4. One-Line Expected Exercise Solutions

1. **Exercise 1 (`chroot` vs. `pivot_root` and `enter.sh` Preconditions):** (a) Plain `chroot base /bin/sh` changes only pathname resolution while leaving host processes, networking, hostname, and mounts shared (and is escapable by root); (b) in `enter.sh`, `pivot_root . oldroot` requires `mount --make-rprivate /` (so systemd's shared `/` does not reject `pivot_root` with `EINVAL`) and `mount --bind /lab/merged /lab/merged` (so the new root is an independent mount point).
2. **Exercise 2 (Minimal `/dev` Device Nodes and Read-Only `/sys`):** In Step 4, `enter.sh` mounts a `64m` `tmpfs` at `/dev` and creates four character devices with `mknod -m 666`: `dev/null` (`c 1 3`), `dev/zero` (`c 1 5`), `dev/urandom` (`c 1 9`), and `dev/tty` (`c 5 0`), and mounts `sysfs` read-only (`-o ro`) so container processes cannot write to host hardware/driver knobs in `/sys`.
3. **Exercise 3 (OverlayFS Layer Sharing, `upperdir` Inspection, and Whiteouts):** Mounting `/lab/merged` with `lowerdir=/lab/base,upperdir=/lab/upper,workdir=/lab/work` keeps `/lab/base` read-only so multiple containers can share one `base` while each gets its own `upper` and `work`; creating `/newfile` writes into `/lab/upper/newfile`, and `rm /etc/hostname` creates a `0, 0` character-device whiteout at `/lab/upper/etc/hostname`.
4. **Exercise 4 (Placing the Container into `/sys/fs/cgroup/lab-ctr` Before `exec unshare`):** Writing the starter shell's `$$` into `/sys/fs/cgroup/lab-ctr/cgroup.procs` *before* `exec unshare ... /lab/enter.sh` ensures the container's PID 1 and all its descendants inherit membership in `lab-ctr` (`cpu.max = "50000 100000"` = `0.5` CPU, `memory.max = 128M`, `pids.max = 64`), stopping the `:(){ :|:& };:` fork bomb at `64` processes and OOM-killing the `300M` allocation (`oom_kill` in `memory.events`).
5. **Exercise 5 (`veth` Pair, Bridge `br-lab`, `ip_forward`, and `MASQUERADE` NAT):** `vethh0` attaches to host bridge `br-lab` (`10.77.0.1/24`) and peer `vethc0` moves into the container's network namespace (`ip link set vethc0 netns $PID`) as `eth0` (`10.77.0.2/24`) with `default via 10.77.0.1`; reaching `8.8.8.8` requires both `sysctl net.ipv4.ip_forward=1` and `iptables -t nat -A POSTROUTING -s 10.77.0.0/24 ! -o br-lab -j MASQUERADE`.
6. **Exercise 6 (Dropping Capabilities with `capsh`/`setpriv` and Comparing with `docker run`):** `capsh --drop=cap_sys_admin,cap_net_raw,cap_sys_module` and `setpriv --no-new-privs` strip dangerous kernel privileges; compared with `enter.sh`, `docker run` additionally applies a default `seccomp` syscall filter (~44 syscalls blocked), drops capabilities to a narrow default bounding set, masks sensitive `/proc` and `/sys` paths (`/proc/kcore`, `/sys/firmware`), and provides embedded DNS and image lifecycle management.
