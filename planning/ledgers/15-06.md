## 4. One-Line Expected Exercise Solutions

1. **Exercise 1:** (a) Conservative dynamic batching (`dense_net_conservative`) delivers a **`5.48x` throughput speedup** (`2,850 / 520 RPS`) and a **`13.65x` reduction in `p99` latency** (`121.5 ms -> 8.9 ms` at `C = 64`), and at `C = 1` (`1,950 us` server latency), GPU compute input (`1,600 us`) accounts for **`82.05%`** of server processing time; (b) in `dense_net_misconfigured`, `C = 2` never reaches `preferred_batch_size: [64]` so every pair of requests waits the full `500,000 us` (`500 ms`) timeout (`2 requests / 0.5 s = 4.0 RPS`), whereas a `20 ms` SLA requires setting `max_queue_delay_microseconds` to **`2,000–4,000 us` (`2–4 ms`, `10%–20%` of SLA)**.
2. **Exercise 2:** (a) Setting `count: 8` consumes **`76.0 GB` VRAM** (`8 * 9.5 GB`), leaving only **`4.0 GB` free** on an `80.0 GB` A100 (below the `5.0 GB` workspace requirement, causing `1,024 MB` allocator failures) while `8` concurrent unbatched streams stall **`84 ms`** on the CUDA driver stream mutex (`25 ms -> 110 ms`), whereas `count: 2` consumes **`19.0 GB` VRAM** and leaves **`61.0 GB` free**; (b) filtering out `cfg_c8_bs32_slo_viol` (`110.0 ms > 25.0 ms`, `76.0 GB > 40.0 GB`) and dominated `cfg_c4_bs16_dom` yields the Pareto frontier **`["cfg_c2_bs32", "cfg_c2_bs16", "cfg_c1_bs8"]`**, with **`cfg_c2_bs32` (`792.0 RPS` at `18.4 ms` `p99`, `19.0 GB` VRAM)** selected as the optimal configuration.
3. **Exercise 3:** (a) Co-batching a `10`-token query with a `2,048`-token query under request-level dynamic batching traps the short request for **`2,038` padded decode iterations**, driving `p99` ITL to **`420 ms`**, `p99` TTFT to **`14.2 s`**, and SM occupancy to **`18%`**, whereas switching to continuous batching with chunked prefill cuts `p99` ITL to **`19.1 ms`** and increases token throughput by **`3.8x`**; (b) Llama-3-70B consumes **`327,680` bytes/token (`1.31 GB` per `4,096`-token session) in FP16** and **`163,840` bytes/token (`0.65 GB` per session) in FP8**, and switching to `32`-token paged blocks + FP8 KV cache + `0.85` free memory fraction increased max concurrent sessions on `4x A100` GPUs from **`64` (`52%` utilization) to `210` (`91%` utilization)**.
4. **Exercise 4:** (a) Transferring `64` FP32 images (`38,535,168` bytes = `38.54 MB`) takes **`3.21 ms` at `12.0 GB/s` (pageable `malloc`)** versus **`0.66 ms` at `58.5 GB/s` (pinned `/dev/shm`, `4.88x` faster)**, and a `6.2 MB` request fails on a default gRPC channel because it exceeds the **`4.0 MB` (`4,194,304` bytes)** default `max_receive_bytes` limit; (b) from the Prometheus counters, the realized average batch size is **`20.0`** (`1,000 / 50`), mean queue wait is **`2,180.4 us` (`2.18 ms`, `15.27%`)**, GPU execution efficiency is **`76.27%`** (`10,892,000 / 14,280,590`), and GPU VRAM usage is **`24.59 GB` (`22.90 GiB`)**.
