# Claim Ledger: 8.2 Planning and installing BCM

## BCM 11 Installation Manual Claims
- **Hardware Minimums & Appendix B Formulas:** Minimum head node: `2` NICs, `80 GB` disk, `8 GB` RAM recommended (`1 GB` RAM, `1` NIC for regular node). Above `1000` nodes: `24` cores, `128 GB` RAM, `512 GB` SSD. Formulas: Head node RAM = $\text{OS} + 100\text{ MB} + 1.8\text{ MB/node}$ (for up to `100` metrics/checks per device, `+1 MB/device` per extra `100`); Head node disk = $\text{OS} + 5\text{ GB/image} + 100\text{ kB/metric/device}$; Regular node RAM = $\text{OS} + 50\text{ MB} + 10\text{ kB/node}$. Observed table: `1000` nodes (`16 GB` RAM with DB, `2 GB` CMDaemon alone, `10 GB` disk), `2000` nodes (`32 GB`, `4 GB`, `20 GB`), `5000` nodes (`64 GB`, `10 GB`, `50 GB`).
- **Network Topologies (3.3.9), Naming (3.3.11), IP Offset (3.3.15), Disk Layout (3.3.17):** Type 1 (`internalnet` + `externalnet`), Type 2 (`internalnet` behind external router), Type 3 (`internalnet` + `managementnet` across L3 routers requiring DHCP relay). Three-digit naming fits up to `node999` (`999` nodes). IP offset (`0.0.0.20` on `10.141.0.0/16`) shifts BMC IPs to `10.141.0.21..30`. Disk layout switches from single partition to separate `/tmp` and `/var` above `~500 GB`.
- **Licensing (Ch. 4), Burn-In (Ch. 11) & SELinux (Ch. 12):** License bound to head node MAC (`cmsh -c "main licenseinfo"`, `verify-license`); Burn framework uses `<pre-install>` and `<post-install>` alphanumeric phases (`endless="1"` for `mce_check`/`kmon`, status codes `S`, `W`, `F`, `P`, e.g., `disktest (SF,61)`, logs in `/var/spool/burn/<mac>/`); SELinux is disabled by default (`selinuxsettings`, `setfiles` on cloned image).
