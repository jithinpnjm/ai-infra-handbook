## 4. One-Line Expected Exercise Solutions

1. **Exercise 1 (The Git Object Model, Merkle DAG Integrity, and the Three Areas, `NPA` Ch. 11):** Using `git_hash_object()` and `build_git_commit_dag()`, a `blob` hashes only `<type> <size>\0<content>` without the filename (so renaming `main.tf` to `providers.tf` reuses the exact same `blob` SHA while producing new `tree` and `commit` SHAs); branches are 41-byte ref files in `.git/refs/heads/` pointed to by `HEAD`; and `git diff` compares Working Tree vs Index, `git diff --staged` compares Index vs `HEAD`, and `git diff HEAD` compares Working Tree vs `HEAD`.
2. **Exercise 2 (Safe Operational Workflow, `.gitignore` Hygiene, and Remotes `fetch` vs. `pull` & Bare Repos, `NPA` Ch. 5 & 11):** `.gitignore` excludes `*.tfstate*`, `.terraform/`, and secret `*.tfvars` while keeping `.terraform.lock.hcl`, and `git rm --cached` untracks files committed by mistake; `git fetch` updates `origin/main` without modifying local work (unlike `git pull`), and central remotes are initialized with `git clone --bare` because they have no working tree.
3. **Exercise 3 (Branching Strategies, Merge vs. Rebase, Ours/Theirs Inversion, and `--onto`):** Trunk-based development with directory-based environments (`envs/staging`, `envs/prod`) prevents long-lived branch drift; never rebase shared history, remember that during a rebase `--ours` is the upstream base (`origin/main`) and `--theirs` is your replayed commit (regenerate conflicted lock files after taking `--ours`), and use `git rebase --onto main feature-A feature-B` to unstack branches.
4. **Exercise 4 (Undoing Mistakes `restore`/`revert`/`reset`/`reflog` and Automated `git bisect run`):** `git revert <sha>` (`-m 1` for merges) safely undoes published commits with a new inverse commit while local `reset --soft/--mixed/--hard` moves the branch pointer (recoverable via `git reflog`); `simulate_git_bisect_run()` finds commit 27 of 40 in 5 binary-search steps using exit codes `0` (good), `1..127` except `125` (bad), and `125` (skip).
5. **Exercise 5 (Secrets Remediation Order, Pre-Commit Hooks, Branch Protection, and `CODEOWNERS`):** A leaked secret must be (1) revoked and rotated immediately, (2) replaced with a secret-manager reference, (3) purged from history with `git filter-repo`, and (4) blocked by `gitleaks`/`detect-private-key` in both `pre-commit` and required CI checks; in `resolve_codeowners()`, the last matching pattern in `.github/CODEOWNERS` assigns required domain reviewers.
6. **Exercise 6 (Repository Architecture, `git worktree`, `Git LFS`, and Push vs. Pull GitOps):** Combine versioned module/role polyrepos (`?ref=v1.4.2`) with a live environment monorepo, use `git worktree add` for parallel hotfix checkouts, keep large binaries in object storage/registries or Git LFS, and prefer pull-based GitOps (`Argo CD`/`Flux` reconciling inside the cluster) over push-based CI credentials.
