# Claim Ledger: 8.10 Containerization in BCM: Docker, Apptainer and Enroot

## BCM 11 Containerization & Administrator Manual Claims
- **Docker (`cm-docker-setup` & `DockerHost` role, Containerization Manual Ch. 2):** Installs `cm-docker` (`28.0.4`) and optionally `cm-nvidia-container-toolkit`, assigns `DockerHost` (`docker::host`, `Spool = /var/lib/docker`, `overlay2` only, `runc`, `user_namespace.enable=1` for userns remap), and adds `2` health checks (API call and no `dead` containers). Docker Swarm is not supported.
- **Registries (`cm-container-registry-setup`, Containerization Manual Ch. 3):** Installs Docker Registry (`generic::docker-registry`, port `5000`, proxy cache mode) or Harbor (`generic::harbor`, port `9443` on head node, default `admin`/`Harbor12345`, conflicts with Keycloak port `9443`). Registry nodes receive `datanode` protection.
- **Enroot & Pyxis (Administrator Manual §7.3.3) vs Apptainer (`SCL` Ch. 16):** Enroot + Pyxis is integrated via `cm-wlm-setup --with-pyxis` (`00777` $\rightarrow$ `00770` shared cache, `nvcr.io` + `authn.nvidia.com` in `.credentials` mode `0600`). Apptainer/Singularity is not in the BCM manuals and is self-supported on BCM.
