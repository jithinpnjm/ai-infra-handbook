## 4. One-Line Expected Exercise Solutions

1. **Exercise 1 (Containers `community.docker`, Packer Image Baking, and Kubernetes `kubernetes.core`, `AUR` Ch. 13 & 16):** `docker_container` compares desired config against the running container via the Docker API (recreating on change, passing `device_requests` for GPUs); Packer `.pkr.hcl` invokes `provisioner "ansible"` to bake identical hardened roles into VM/cloud/container images; and `kubernetes.core` handles cluster bootstrap and node drains while GitOps (Argo CD/Flux) reconciles ongoing workloads.
2. **Exercise 2 (Cloud Provisioning & Day-2 Ops, Windows `winrm`, and Ansible vs. Terraform, `AUR` Ch. 12 & 17):** Terraform manages stateful cloud resource lifecycles and plans while Ansible handles dynamic inventory (`aws_ec2`, `gcp_compute`), `select_latest_ami()` (`ec2_ami_info` sorted by `creation_date`), `add_host`, and day-2 tasks; Windows hosts are managed agentlessly over WinRM (`win_ping`, `win_chocolatey`, `win_feature`, `win_reboot`, `win_updates`).
3. **Exercise 3 (Network Connection Plugins and Resource Module States, `NPA` Ch. 12):** Network modules run on the control node over `network_cli` (SSH CLI), `httpapi` (eAPI/NX-API/NVUE REST), or `netconf` (XML over SSH); `apply_vlan_resource_module()` demonstrates `merged` (add/update), `replaced` (replace specified items), `overridden` (replace all items of that resource type, pruning extras), `deleted`, `gathered` (read live state), `rendered` (offline CLI generation), and `parsed`.
4. **Exercise 4 (Automating NVIDIA AI Fabrics: `nvidia.nvue`, Quantum InfiniBand / UFM, and BlueField DPUs):** `nvidia.nvue.config` declaratively manages Cumulus/Spectrum-X switches (`mtu: 9216`, BGP unnumbered, PFC/ECN QoS) with atomic apply/confirm; `ansible.builtin.uri` drives the UFM REST API for InfiniBand fabrics; and standard Linux SSH modules + `mlxconfig`/DOCA manage BlueField DPUs.
5. **Exercise 5 (Safe Fabric Change Workflow and LLDP Cabling Verification):** Back up running configs, preview with `--check --diff` / `rendered`, apply with commit-confirm on a single canary leaf (`serial: 1`, never touching both MLAG peers or all spines at once), verify BGP `Established` peers and `verify_lldp_against_cabling_plan()`, roll out in batches, and save config.
6. **Exercise 6 (Comparing Ansible with Python `Nornir` + `NAPALM`, `NPA` Ch. 12, and Security Auditing, `AUR` Ch. 21):** Ansible provides a unified YAML/Jinja DSL and AWX/AAP control plane across servers and switches, whereas Nornir (`InitNornir`) + NAPALM provides a pure-Python multi-threaded framework ideal for complex data processing and `pdb`/`pytest` debugging; `AUR` Ch. 21 pairs `ansible-lockdown` hardening with independent `OpenSCAP` and `ssh-audit` verification.
