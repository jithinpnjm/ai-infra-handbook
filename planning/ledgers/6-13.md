## 4. One-Line Expected Exercise Solutions

1. **Exercise 1 (Enroot & Pyxis Image URI, `#SBATCH` Escaping, and `.sqsh` Naming):** `format_enroot_pyxis_uris("nvcr.io", "nvidia/pytorch", "24.07-py3")` produces `docker://nvcr.io#nvidia/pytorch:24.07-py3` (`#` separates registry from repo), `#SBATCH --container-image nvcr.io\#nvidia/pytorch:24.07-py3` (`\#` prevents shell comment truncation), and `nvidia+pytorch+24.07-py3.sqsh`.
2. **Exercise 2 (Configuring `enroot.conf` Paths for NVMe Compute Nodes):** Point `ENROOT_RUNTIME_PATH`, `ENROOT_DATA_PATH`, and `ENROOT_TEMP_PATH` to `/raid/local/enroot/...` on node-local NVMe so rootfs unpacking avoids NFS metadata storms.
3. **Exercise 3 (Writing a Multi-Node Pyxis Training Script with Mounts):** Pass `--container-image=/shared/images/nvidia+pytorch+24.07-py3.sqsh`, `--container-mounts=/data:/data:ro+rprivate,/scratch/$USER:/scratch,$PWD:/workspace`, and `--container-workdir=/workspace`; use `--container-env=NAME` when a host variable must override a variable baked into the image's `ENV`.
4. **Exercise 4 (Tracing Enroot Hooks for GPUs, InfiniBand, and PMIx):** `98-nvidia.sh` injects host `libcuda.so` and `/dev/nvidia*`, `99-mellanox.sh` injects host MOFED and `/dev/infiniband/*`, `50-slurm-pmi.sh` mounts the PMIx socket, and `50-slurm-pytorch.sh` sets `RANK`/`LOCAL_RANK`/`WORLD_SIZE`/`MASTER_ADDR`; if `NCCL` falls back to `NET/Socket`, inspect `99-mellanox.sh` and `/dev/infiniband`.
5. **Exercise 5 (Quantifying the Registry Thundering-Herd Penalty and Caching Architecture):** `64` nodes pulling `15 GB` over `10 GB/s` takes `96.0 s` vs `1.5 s` for a single central import; `docker-registry-proxy` handles registry auth tokens and caches layer blobs without caching mutable manifests long-term.
6. **Exercise 6 (Comparing Enroot + Pyxis, Singularity / Apptainer, and Charliecloud):** Pyxis integrates via SPANK `--container-*` flags, Singularity/Apptainer runs `.sif` files via `srun singularity run --nv app.sif`, and Charliecloud uses `ch-image`/`ch-build`/`ch-convert`/`ch-run`; passing `docker://` directly to `singularity run` re-downloads, converts, and deletes the temporary `.sif` on every run.
