# Claim Ledger: 7.3 The Redfish protocol: HTTP methods, headers, status codes and query parameters

## DMTF Redfish Specification (DSP0266 v1.21.0) Claims
- **HTTP Methods & Headers (§6.2–6.6, §7.1, §7.4, §8.1–8.2):** Required methods for services are `GET`, `HEAD`, `POST`, `PATCH`, and `DELETE` (`PUT` and `OPTIONS` are optional); unsupported methods return `405 Method Not Allowed` with an `Allow` header (or `501 Not Implemented`). `HEAD` requests with query parameters are rejected with `400 Bad Request` (§7.4). Responses include `OData-Version: 4.0`.
- **ETags & Concurrency (§6.5, §7.2.1, §8.3):** `If-Match` on `PATCH`/`PUT` returns `412 Precondition Failed` when stale; missing required `If-Match` returns `428 Precondition Required`; `If-None-Match` on `GET` returns `304 Not Modified` when unchanged.
- **Query Parameters & Evaluation Order (§7.3.1–7.3.8):** Evaluated in strict order: `1. $filter` $\rightarrow$ `2. $skip` $\rightarrow$ `3. $top` $\rightarrow$ `4. Server paging` $\rightarrow$ `5. $expand` (`.`, `~`, `*`, `$levels=N`) $\rightarrow$ `6. excerpt` $\rightarrow$ `7. $select` (always keeps `@odata.id` and `@odata.type`). Unsupported `$` parameters return `501 Not Implemented`; unknown non-`$` parameters are ignored; invalid values or combining `only` with other options return `400 Bad Request`; `$expand` buffer overflow returns `507 Insufficient Storage`.
- **`PATCH` Partial Success, Array Patching & `OperationApplyTime` (§7.6, §7.7, §7.12):** If at least one property in a `PATCH` succeeds, the service returns `200 OK` with `@Message.ExtendedInfo` listing rejected properties; if all properties fail or the body is `{}`, it returns `400 Bad Request`. Array `PATCH` uses `{}` to keep an element and `null` to remove an element (§7.7). `@Redfish.OperationApplyTime` supports `Immediate`, `OnReset`, `AtMaintenanceWindowStart`, and `InMaintenanceWindowOnReset` (§7.12).
