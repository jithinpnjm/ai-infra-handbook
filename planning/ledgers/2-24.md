## 4. One-Line Expected Exercise Solutions

1. **Exercise 1 (Policy-Based Routing `ip rule`, `fwmark`/`uidrange`, and Linux `VRF`s):** Multi-homed servers fix reply-on-wrong-NIC asymmetric routing by creating per-NIC routing tables (`200 storage` in `/etc/iproute2/rt_tables`) selected by source-IP `ip rule`s (`from 192.168.1.5/32 lookup storage priority 1000`) or `fwmark`/`uidrange` (`nft` `type route hook output` re-evaluates routing after marking), while a Linux **VRF** (`ip link add vrf-blue type vrf table 10`, `ip vrf exec vrf-blue ...`) isolates L3 routing tables across groups of interfaces without the full process/filesystem isolation of a network namespace.
2. **Exercise 2 (End-to-End `MTU` Design, Jumbo Frames, and `RoCEv2` `4096` IB MTU):** Every L2 hop (NICs, bonds, VLANs, bridges, switch ports) must agree on the MTU (`1500` for management/Internet, `9000` for storage and RoCEv2 where the `4096`-byte IB payload + headers fits inside `9000` Ethernet, and `underlay - 50` for VXLAN), verified end-to-end with `ping -M do -s 8972` and `tracepath -n`.
3. **Exercise 3 (The Linux RX/TX Packet Path: Rings, Coalescing, `NAPI`, `RSS`/`RPS`/`RFS`/`XPS`, and `NUMA` IRQ Affinity):** Using `plan_numa_local_rss_and_irq()`: the NIC DMAs frames into the RX ring (`ethtool -G 4096`), fires an MSI-X interrupt per **RSS** queue (`ethtool -L combined 32`), and schedules **NAPI** softirq polling (`netdev_budget = 600`); RSS queues and IRQ `smp_affinity_list` **must be pinned to CPU cores on the NIC's local NUMA node** (stopping `irqbalance` from moving them across sockets), while `RPS`/`RFS` provide software steering for single-queue virtual NICs and `XPS` maps CPUs to TX queues.
4. **Exercise 4 (Hardware Offloads `TSO`, `GSO`, `GRO`, `LRO` and `sendfile` / `MSG_ZEROCOPY`):** Keep **`TSO`**, **`GSO`**, **`GRO`**, scatter-gather, and RX/TX checksum offloads enabled on servers so the kernel processes `64 KiB` super-segments instead of `1500`-byte frames, but **always disable `LRO`** (`ethtool -K eth0 lro off`) on routers, bridges, and hypervisors because LRO lossily merges headers and breaks packet forwarding; `sendfile()` and `MSG_ZEROCOPY` DMA data directly from page/user memory to the NIC without CPU buffer copies.
5. **Exercise 5 (TCP/IP Stack `sysctl` Tuning and `NCCL` Socket/Bootstrap Configuration, `ASP` Chapter 4 & `SP` Chapter 10):** Using `recommend_tcp_max_buffer_bytes()` and `validate_nccl_socket_and_port_config()`: size `rmem_max`/`wmem_max` and `tcp_rmem`/`tcp_wmem` to `>= 2 * BDP` (`16 MiB` for intra-DC, `128 MiB` for WAN) with `default_qdisc = fq` and `tcp_slow_start_after_idle = 0`; for `NCCL` TCP bootstrap and socket transport, set `NCCL_SOCKET_IFNAME` to the fabric/management NIC (never `lo` or `docker0`), configure `net.ipv4.ip_local_port_range` (e.g., `"50000 51000"` or `"10240 65535"`), and ensure **`NCCL_NSOCKS_PERTHREAD * NCCL_SOCKET_NTHREADS <= 64`**.
6. **Exercise 6 (Kernel Bypass `XDP`, `AF_XDP`, `SR-IOV`, `DPDK`, `RDMA` and the Safe Tuning Methodology):** Compare `XDP` (in-driver eBPF before `sk_buff` allocation for line-rate DDoS drop/L4 LB), `AF_XDP` (zero-copy user-space sockets), `SR-IOV` (passing hardware PCIe Virtual Functions to pods/VMs), `DPDK` (user-space poll-mode drivers burning 100% of dedicated cores), and `RDMA` (`RoCEv2`/`InfiniBand` hardware transport offload for GPUs), and apply the 7-step tuning method (*goal -> baseline -> USE bottleneck -> one change -> measure -> persist in config management -> re-validate*).
