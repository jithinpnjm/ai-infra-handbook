## 4. One-Line Expected Exercise Solutions

1. **Exercise 1:** PCIe Gen4 x16 = `~32 GB/s` per direction, PCIe Gen5 x16 = `~64 GB/s` per direction, and H100 HBM3 = `3,350 GB/s`; `PIX` (single PCIe switch) and `PXB` (cascaded PCIe switches) avoid the CPU Root Complex (optimal P2P), `PHB` and `NODE` cross the CPU Root Complex within one NUMA node, and `SYS` crosses the inter-socket `UPI`/`xGMI` link (`~50%` throughput drop).
2. **Exercise 2:** SR-IOV creates Virtual Functions (`VFs`) on the NIC but does not restrict host physical RAM addresses unless the motherboard **IOMMU (`Intel VT-d` / `AMD-Vi`)** is enabled (`intel_iommu=on`); VFIO refuses to open `/dev/vfio/42` until every non-bridge sibling endpoint in Group `42` (including `0000:4b:00.1` audio) is unbound from host drivers (`snd_hda_intel`) and bound to `vfio-pci`.
3. **Exercise 3:** `MSR_WRITE` (`68.90%` of samples) is frequent but fast (`3.25 us`), whereas `HLT` (`19.25%` of samples, `99.63%` of time) represents normal idle vCPU sleep (`4,160.68 us`), and `EPT_VIOLATION` (`[2K, 4K)` ns mode) reflects two-stage page table walks; `vfio-pci` passthrough and SR-IOV bypass the host kernel and `QEMU` I/O proxy, making device I/O invisible to host `iostat`.
4. **Exercise 4:** Container A (`10` shares of `100`) gets `100%` when alone, `10 / (10 + 30) = 25.0%` when only A and B are busy, and `10 / 100 = 10.0%` when all `100` shares are busy (a `10x` bursting drop); setting a `20%` CFS bandwidth cap restricts Container A to `10%–20%` so staging tests match production.
5. **Exercise 5:** Inside a container, `top` (summary), `uptime`, `mpstat`, `vmstat`, `free`, and `iostat` leak host-wide statistics; map guest PID `753` to host PID `4915` via `awk '$1 == "NSpid:" && $3 == 753 { print $2 }' /proc/*/status` and `ls -lh /proc/4915/ns/pid` (`pid:[4026532216]`), check container disk I/O via `/sys/fs/cgroup/blkio/blkio.throttle.io_serviced`, and check CPU throttling via `throttled_time`, `nonvoluntary_ctxt_switches`, host `%idle`, `cpuset` `100%` busy, and neighbor activity (`Figure 11.13`).
6. **Exercise 6:** `QEMU 4.2` has `> 1.4M` LoC, `AWS Firecracker` has `50,000` LoC (`~100 ms` boot, `< 5 MB` RAM), and `Intel Clear / Kata Containers` has `< 45 ms` boot (`48–50 MB` RAM); OS Containers favor **host operators** (shared kernel exposes all guest PIDs to the host while blocking guest kernel tracing), whereas Hardware/Lightweight VMs favor **end users** (dedicated guest kernel enables full guest `perf`/`Ftrace`/BPF while hiding guest internals from the host).
