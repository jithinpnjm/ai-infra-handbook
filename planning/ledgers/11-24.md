## 4. One-Line Expected Exercise Solutions

1. **Exercise 1:** A **GPU Instance (`GI`)** is the hardware partition isolating HBM memory, memory controllers, L2 cache, and crossbar paths, whereas a **Compute Instance (`CI`)** is the SM execution partition created inside a parent `GI`; the `6` validation layers are `Hardware/driver -> MIG configuration -> Container runtime -> Kubernetes -> Application -> Operations/Rollback`, and `docker run --gpus device=gpu:0:0` reports `28C`, `42W / 700W`, and `100MiB / 10000MiB`.
2. **Exercise 2:** `7×(1g.10gb) + 2×(3g.40gb)` requests `13 > 7` compute slices and `150 > 80 GB` memory; `4×(1g.10gb) + 1×(3g.40gb)` uses `4×1 + 1×3 = 7/7` slices and `4×10 + 1×40 = 80/80 GB` (`5.8 GB` headroom for `4.2 GB` Embedding and `29.8 GB` headroom for `10.2 GB` Chat LLM) across `20` shared MIG nodes + `4` reserved whole-GPU nodes = **`24` total H100 nodes**.
3. **Exercise 3:** (a) `7×1g.10gb` = `7/7` slices, `70/80 GB`; (b) `3×2g.20gb + 1×1g.10gb` = `7/7` slices, `70/80 GB`; (c) `1×4g.40gb + 1×2g.20gb + 1×1g.10gb` = `7/7` slices, `70/80 GB` (`~10 GB` is reserved for system/ECC overhead when dividing into `10 GB` slice increments).
4. **Exercise 4:** The `7` fields are `DCGM_FI_DEV_SM_CLOCK`, `DCGM_FI_DEV_MEM_CLOCK`, `DCGM_FI_DEV_GPU_TEMP`, `DCGM_FI_DEV_POWER_USAGE`, `DCGM_FI_PROF_PIPE_TENSOR_ACTIVE`, `DCGM_FI_PROF_NVLINK_TX_BYTES`, and `DCGM_FI_PROF_NVLINK_RX_BYTES`; poll `dcgmi dmon -e 203 -c 1` until `0`, stop `nvidia-dcgm-exporter` and `nvidia-dcgm`, and run `rmmod nvidia_uvm nvidia_drm nvidia_modeset nvidia`.
5. **Exercise 5:** Run `dcgmi diag -r 3` (`DCGM Level 3` hardware stress) and `mpirun -np 8 --bind-to none -x NCCL_DEBUG=INFO /opt/nccl-tests/build/all_reduce_perf -b 1G -e 8G -f 2 -g 1`.
6. **Exercise 6:** (a) `XID 31` on `Node 42` is a user-space CUDA page fault -> kill the offending Pod and debug with `compute-sanitizer`; (b) `XID 48` is an uncorrectable Double-Bit ECC error requiring node drain/RMA if row remapping fails, whereas `XID 94` is a Contained ECC error isolated to a single process; (c) MPS Ghost OOM at `10 GB / 40 GB` is caused by `CUDA_MPS_PINNED_DEVICE_MEM_LIMIT` or a transient neighbor memory spike -> migrate to **MIG** for hardware-isolated memory.
