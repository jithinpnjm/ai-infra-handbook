## 4. One-Line Expected Exercise Solutions

1. **Exercise 1 (The Bottom-Up Tuning Stack, Straggler Math, and Topology Discovery):** (a) Build and verify **bottom-up** (Hardware -> Firmware/BIOS -> Kernel/GRUB -> OS/sysctl -> GPU driver -> Runtime -> Containers/Schedulers) because higher layers cannot fix a broken PCIe `x8` link or BIOS setting, and diagnose symptoms **top-down**; (b) in synchronous distributed training, `1` straggler rank running at `125 ms` while `63` ranks run at `100 ms` forces the entire `64`-GPU job to run at `125 ms/step` (`25.0%` loss across all `64` GPUs).
2. **Exercise 2 (BIOS/UEFI Settings and Contested Kernel Boot Parameters):** Set BIOS to Maximum Performance / HPC profile, limit C-states (`C0`/`C1`), enable NUMA (no socket interleaving), enable Above-4G Decoding / Resizable BAR, and disable PCIe ACS on GPU-NIC switches per vendor GPUDirect RDMA guidance; on the kernel command line, `iommu=pt` keeps the IOMMU active for SR-IOV/VFIO while using identity DMA mapping for host devices, `numa_balancing=disable` stops automatic page migration faults when processes are explicitly pinned, and `transparent_hugepage=madvise` avoids synchronous compaction stalls while allowing opt-in `2 MiB` pages.
3. **Exercise 3 (The 3-Tier `get_gpu_numa_node` Fallback Chain and `DataLoader` Worker Binding):** (a) `resolve_gpu_numa_node()` queries **NVML** first (`nvmlDeviceGetNUMANodeId` or CPU affinity bitmask), falls back to **sysfs** (`/sys/bus/pci/devices/<bdf>/numa_node`, normalizing `-1` to `0`), and then to **CLI** (`nvidia-smi topo -m` / `numactl --show`); (b) because `spawn`/`exec` workers and thread pools do not reliably inherit `numactl`, pass `worker_init_fn` to PyTorch `DataLoader` to pin each worker's CPU affinity (`parse_sysfs_cpulist()`) and `libnuma` policy (without calling CUDA APIs inside `worker_init_fn`), alongside `pin_memory=True` (`2x–3x` faster H2D via `bandwidthTest --memory=pinned`) and `persistent_workers=True`.
4. **Exercise 4 (GPU Driver Daemons, Clock Locking, Allocators, and Scheduler Integration):** Enable `nvidia-persistenced` (`1–2 s` cold init saved) and `nvidia-fabricmanager` *before* starting `slurmd` or `kubelet`; use `nvidia-smi -lgc` / `-ac` for benchmark determinism; set `PYTORCH_ALLOC_CONF=expandable_segments:True,max_split_size_mb:128` (or `TF_FORCE_GPU_ALLOW_GROWTH=true`) and preload `jemalloc` (`MALLOC_CONF="narenas:8,background_thread:true,dirty_decay_ms:10000"`); in Kubernetes use `Guaranteed` QoS + `cpuManagerPolicy: static` + `topologyManagerPolicy: single-numa-node`, and in Slurm use `--gpu-bind=closest --cpu-bind=cores --mem-bind=local`.
5. **Exercise 5 (`node_audit.sh` Verification Suite, Golden Images, and Canary Rollouts):** `evaluate_node_audit()` checks kernel cmdline (`iommu=pt`, `numa_balancing=disable`), sysctls (`swappiness=1`, `max_map_count=1048576`, `numa_balancing=0`), THP (`madvise`), `ulimit -l` (`unlimited`), CPU governor (`performance`), GPU count, persistence mode, PCIe link gen/width == max, `0` uncorrected ECC errors, active `nvidia-fabricmanager`, and `0` recent Xid errors—failing closed (keeping the node drained) on any mismatch.
6. **Exercise 6 (Gregg's Chapter 16 Case Study: *The Unexplained 3 to 4x Win*):** Comparing the `48`-CPU VM (`3–4 s`/req) and `64`-CPU container host (`1 s`/req) simultaneously revealed three quantified factors: (1) the container host had **no neighbors** (`78%` idle vs `2%` idle on the saturated VM at load `85`, where `85/48 - 1 = 77%` CPU wait time), (2) the container host had a larger LLC (`45 MB` vs `33 MB`) and smaller working set, yielding **`90%` vs `30%` LLC hit ratio** and **`1.52` vs `0.57` IPC (`2.6x`)**, and (3) the saturated VM suffered **`2,000,000` vs `1,000` context switches/s** (`< 10 µs` vs `2–4 ms` on-CPU slices in `cpudist`), thrashing its caches.
