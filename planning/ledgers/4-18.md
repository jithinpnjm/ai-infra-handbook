## 4. One-Line Expected Exercise Solutions

1. **Exercise 1 (The Five IaC Categories, Six Trade-Off Axes, and Procedural vs. Declarative Scaling `count = 10 -> 15 -> 5`, `TUR` Ch. 1):** Server templating (`Packer`/`Docker`) + provisioning (`Terraform`/`OpenTofu`) manage immutable infrastructure lifecycles while configuration management (`Ansible`) configures software on running hosts and orchestrators (`Kubernetes`) schedule workloads; because Terraform tracks resource IDs in `terraform.tfstate`, changing `count` from `10` to `15` adds 5 instances and `15` to `5` destroys 10 instances deterministically.
2. **Exercise 2 (Terraform Architecture, `.terraform.lock.hcl`, `~>` Constraints, and Dependency DAG Waves, `TUR` Ch. 1 & 2):** Terraform Core builds the resource DAG and talks to provider plugins over local gRPC while `.terraform.lock.hcl` pins exact provider versions and SHA-256 hashes; `matches_pessimistic_constraint()` shows `~> 5.30` allows `< 6.0.0` while `~> 5.30.1` allows `< 5.31.0`; and `build_dependency_execution_waves()` groups independent resources into parallel waves.
3. **Exercise 3 (HCL Essentials: Variables, Precedence, `sensitive = true`, `locals`, `data` Sources, and `dynamic` Blocks, `TUR` Ch. 2):** Variable precedence runs `default < TF_VAR_* < terraform.tfvars < *.auto.tfvars < -var/-var-file`; `sensitive = true` redacts terminal output but still writes plaintext to `terraform.tfstate`; and GCP GPU VMs require `scheduling { on_host_maintenance = "TERMINATE" }`.
4. **Exercise 4 (Reading `terraform plan` Symbols and `create_before_destroy` on ASGs, `TUR` Ch. 2):** Using `compute_terraform_plan_actions()`, `+` creates, `~` updates in place, `-/+` destroys then creates, `+/-` creates then destroys (`create_before_destroy = true`, required when replacing an `aws_launch_configuration` referenced by an `aws_autoscaling_group`), and `-` destroys; `terraform plan -out=tfplan` + `terraform apply tfplan` guarantees no unreviewed changes execute.
5. **Exercise 5 (Handling Drift `-refresh-only`, Declarative `import {}` Blocks, and Safe Refactoring `moved {}` / `removed {}`):** `plan -refresh-only` inspects real-world drift against state; `import { to = ..., id = "..." }` with `-generate-config-out` adopts unmanaged resources in PR-reviewed code; and `moved { from = ..., to = ... }` rebinds state addresses across renames/module extractions without destroying infrastructure.
6. **Exercise 6 (Workspaces vs. Directories, Terraform OSS vs. HCP vs. OpenTofu, and Rendering Ansible Inventories):** CLI workspaces share one backend and credential set (making directory-per-environment safer for prod/staging isolation); OpenTofu (MPL 2.0) adds native state encryption while HCP Terraform provides managed runs/policy; and `local_file` + `templatefile()` renders Terraform resource attributes directly into an Ansible `inventory.ini`.
