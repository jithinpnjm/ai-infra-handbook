## 4. One-Line Expected Exercise Solutions

1. **Exercise 1 (The 5-Layer Ansible Test Pyramid and Static Analysis `yamllint`/`ansible-lint`/`ansible-later`, `AUR` Ch. 14):** Static linters catch syntax/style/anti-patterns, `--syntax-check`/`--check` catch structural errors, container Molecule catches user-space logic and idempotency bugs, VM Molecule tests kernel/systemd/reboot behavior, and hardware-in-the-loop runners test physical GPUs; `check_ansible_lint_rules()` flags missing names, non-FQCN calls, `command-instead-of-module`, `no-changed-when`, `risky-shell-pipe`, `risky-file-permissions`, and `package-latest`.
2. **Exercise 2 (Molecule Architecture, `molecule.yml`, and `molecule test` Lifecycle, `AUR` Ch. 14 & 22):** Using `run_molecule_lifecycle()`, `molecule test` runs `create -> prepare -> converge -> idempotence -> side_effect -> converge -> verify -> destroy`, while `molecule converge`, `molecule verify`, and `molecule login` (`--destroy never`) provide fast iterative development loops.
3. **Exercise 3 (Comparing Molecule Verifiers: Ansible-Native `verify.yml`, `Testinfra`, and `Goss`, `AUR` Ch. 14):** `verify.yml` uses standard Ansible `assert`/`slurp`/`command` tasks without extra dependencies, `Testinfra` writes Python `pytest` assertions on the `host` fixture, and `evaluate_goss_sshd_spec()` models `Goss` declarative YAML assertions (`test_sshd.yml`) producing TAP output.
4. **Exercise 4 (Multi-Host Scenarios `docker_networks`, `desired_state`, Drift `side_effect.yml`, and Upgrade Testing, `AUR` Ch. 14):** `docker_networks:` (`10.16.0.0/24`) and `groups:` wire multi-container clusters (`redis1..3`), `side_effect.yml` deletes files or stops services to test drift repair, `prepare.yml` installs version $N-1$ to test upgrades, and `desired_state: absent` tests clean uninstallation.
5. **Exercise 5 (Container Limits vs. VMs vs. Hardware-in-the-Loop GPU Runners `gpu_hw`):** Containers share the host kernel and lack physical PCIe/GPU hardware (testing templates and validation logic via a stub `nvidia-smi`), VMs test kernel modules and reboots, and `[self-hosted, gpu]` runners run `molecule test -s gpu_hw` nightly or on `test-gpu` PR labels.
6. **Exercise 6 (CI Pipeline Design for Roles and Collections: GitHub Actions, `Jenkinsfile`, and `ansible-test`, `AUR` Ch. 22):** GitHub Actions runs `lint -> molecule matrix (role x distro) -> gpu-hw` (and `AUR` Ch. 22's `Jenkinsfile` runs `Syntax -> Linting -> Playbook -> Verification -> Idempotency`), while Collections run `ansible-test sanity`, `ansible-test units`, and `ansible-test integration`.
