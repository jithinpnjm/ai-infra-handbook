## 4. One-Line Expected Exercise Solutions

1. **Exercise 1 (DNS Hierarchy, Zone vs. Domain, Delegation + Glue, and Iterative vs. Recursive Lookup):** A **domain** is any subtree of the DNS namespace while a **zone** is an administratively delegated slice served by authoritative nameservers (`NS` records + parent **glue** `A`/`AAAA` records when the nameserver sits inside the delegated zone); a client's **stub resolver** sends one recursive query (`RD` bit) to a **recursive resolver**, which performs iterative queries following referrals from `.` (root) -> TLD -> authoritative server (`aa` flag) and caches answers for their `TTL`.
2. **Exercise 2 (Resource Records, the `CNAME` Apex Rule, and Reverse `PTR` Lookups):** Using `validate_cname_placement()` and `ipv4_to_in_addr_arpa()`: a `CNAME` record cannot be placed at the zone apex (`@`) or coexist with any other record (`SOA`, `NS`, `MX`, `A`, `TXT`), and `10.20.0.45` maps to `45.0.20.10.in-addr.arpa.` (missing `PTR` records cause multi-second stalls in `sshd` `UseDNS`, NFS, Slurm, and Kerberos).
3. **Exercise 3 (`dig` vs. `getent hosts` vs. `resolvectl` and the Linux Host Resolution Path):** `dig` and `nslookup` query a DNS server directly over UDP/TCP port 53 and **bypass `/etc/nsswitch.conf`, `/etc/hosts`, and libc search-path expansion**, whereas `getent hosts` calls `getaddrinfo()` just like real applications (checking `files` `/etc/hosts` before `resolve`/`dns` at `127.0.0.53`).
4. **Exercise 4 (Search Domains, `ndots:5` Query Multiplication, and Trailing Dots):** Using `expand_dns_search_candidates()`: in a Kubernetes Pod (`ndots:5`, 4 `search` domains), looking up `api.example.com` (`2` dots `< 5`) triggers 4 search-suffixed `NXDOMAIN` queries (x2 for `A` and `AAAA` = 8 wasted queries) before querying `api.example.com.`, whereas passing a trailing dot (`api.example.com.`) or setting `ndots: 2` queries `api.example.com.` immediately on the first try.
5. **Exercise 5 (The 5-Second DNS Delay Case Study, Conntrack UDP Races, and `NodeLocal DNSCache`):** In Section 11, parallel `A` and `AAAA` UDP queries from the same socket source port raced in `nf_conntrack` DNAT for the `kube-dns` ClusterIP (`10.96.0.10`), dropping one packet and triggering glibc's `5 s` retry timeout (`compute_resolver_failover_delay_sec()`); fix with **NodeLocal DNSCache** (per-node link-local cache avoiding conntrack), `single-request-reopen` / `use-vc`, lower `ndots`, and kernel upgrades.
6. **Exercise 6 (Designing Cluster DNS for 1,000 Multi-NIC GPU Nodes and DNSSEC / Split-Horizon):** Create deterministic forward and reverse (`in-addr.arpa` / `ip6.arpa`) records for every interface (`gpu01` / `gpu01-mgmt`, `gpu01-ib0..7`, `gpu01-stor`), point Slurm `NodeAddr` and `NCCL_SOCKET_IFNAME` to the intended fabric interface (never leaving `127.0.1.1 hostname` in `/etc/hosts`), and lower `TTL` at least one old-TTL interval before any IP migration.
