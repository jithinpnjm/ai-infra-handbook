## 4. One-Line Expected Exercise Solutions

1. **Exercise 1:** (a) The unchunked `12,288`-token prefill stalls `45` decode streams for `320.0 ms` and spikes `p99 ITL` from `18.0 ms` to **`340.0 ms` (`18.89x` spike)**, whereas `max_num_batched_tokens = 2048` restores `p99 ITL` to **`21.4 ms`** (`< 30.0 ms` SLA); (b) under `P90 TTFT <= 400 ms` and `P90 TPOT <= 40 ms`, colocated Goodput is **`min(3.0, 1.6) = 1.6 RPS/GPU`**, whereas the `2P1D` cluster achieves **`min(2 * 5.6, 10.0) = 10.0 RPS` total** across `3` GPUs, or **`10.0 / 3 = 3.33 RPS/GPU` (`~3.3 RPS/GPU`, `2.08x` per-GPU Goodput gain)**.
2. **Exercise 2:** (a) The RAG workload (`10 RPS, L_in = 8,192, L_out = 128`) demands `81,920` prefill tok/s and `1,280` decode tok/s, yielding **`(N_P = 3, N_D = 1)` (`3:1` ratio)**, while enterprise chat (`16 RPS, L_in = 2,048, L_out = 512`) demands `32,768` prefill tok/s and `8,192` decode tok/s, yielding **`(N_P = 4, N_D = 8)` (`4:8 = 1:2` ratio)**; (b) for Chain-of-Thought reasoning (`8 RPS`, `1,024` prompt tokens with `50%` cache hit -> **`L_in = 512`**, `L_out = 4,096`), demand shifts to `4,096` prefill tok/s and `32,768` decode tok/s, yielding **`(N_P = 1, N_D = 4)` (`1:4` ratio)**, which Arrow (`up to 5.6x` request rate) or Dynamo GPU Planner (`scale_up` decode at `kv_cache_usage >= 75%`) satisfies by scaling or flipping workers from prefill to decode.
3. **Exercise 3:** (a) At `4,096` tokens, Llama-13B (`L=40, d=128`) requires **`819,200 B/tok` (`3.36 GB` FP16 / `1.68 GB` FP8) for MHA (`H_kv=40`), `163,840 B/tok` (`0.671 GB` FP16 / `0.336 GB` FP8, `5.0x` smaller) for GQA-8 (`H_kv=8`), and `20,480 B/tok` (`0.084 GB` FP16, `40.0x` smaller) for MQA-1 (`H_kv=1`)**; (b) at `4,096` tokens, Llama-3-70B GQA-8 (`L=80, H_kv=8, d=128`) requires **`327,680 B/tok` (`1.342 GB` / `1.25 GiB` FP16, `0.671 GB` / `0.625 GiB` FP8)** whereas DeepSeek-V3/R1 MLA (`L=61, d_c=512, d_r=64`) requires **`70,272 B/tok` (`0.288 GB` FP16, `0.144 GB` FP8)**, which is **`4.66x` smaller than 70B GQA-8 and `37.3x` smaller than 70B 64-head MHA (`10.74 GB`)**.
4. **Exercise 4:** (a) Transferring `1.34217728 GB` takes **`134.22 ms` (`314.22 ms` TTFT, violating `250 ms` SLO) on `10 GB/s` non-RDMA PCIe/TCP, `26.84 ms` (`206.84 ms` TTFT) on `50 GB/s` 400G NDR IB, `13.42 ms` on `100 GB/s` 800G ConnectX-8, `3.36 ms` on `400 GB/s` 8-rail NDR, `1.49 ms` on `900 GB/s` NVLink 4, and `0.75 ms` on `1,800 GB/s` NVLink 5**; (b) layer-by-layer overlap across `80` layers on `50 GB/s` NDR exposes only the final layer's **`0.34 ms` (`0.19% < 1%` of `180 ms` prefill, `180.34 ms` total TTFT)**, and collating `7,500` tokens from `16`-token pages to `128`-token slabs cuts RDMA writes from **`469` (`~470`) WQEs to `59` WQEs** and transfer time from **`20.0 ms` to `8.0 ms` (`2.5x` speedup)**.
5. **Exercise 5:** (a) Request 1 (`eff_len = 768 >= 256, Q_p = 4 < 10`) returns **`should_offload = True` (`yaml_score = 1.0 > 0.5`)**, Request 2 (`eff_len = 44 < 64, active_d = 4 < 8`) returns **`should_offload = False` (`yaml_score = 0.3 <= 0.5`)**, and at `Q_p = 12, Q_d = 12`, `QoSController` computes **`est_ttft = 12*35 + 12*20 = 660.0 ms > 500 ms`** and **rejects (`False`)** low-priority traffic; (b) `H200` provides **`1.76x` HBM (`141/80`) and `1.43x` bandwidth (`4.8/3.35`)** over `H100`, `B300` provides **`1.60x` HBM (`288/180`) and `1.98x` post-70B-weight KV capacity (`218 GB` vs `110 GB` / `122 GB` reported)** over `B200`, and moving from `TP_p = 2, PP_p = 2` (`40` layers, `4` KV heads/rank) to `TP_d = 4, PP_d = 1` (`80` layers, `2` KV heads/rank) requires an on-the-fly **NIXL KV layout transpose**.
