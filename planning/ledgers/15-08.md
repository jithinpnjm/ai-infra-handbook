## 4. One-Line Expected Exercise Solutions

1. **Exercise 1:** (a) Colocated goodput is **`1.6 RPS/GPU`** (`min(3.0, 1.6)`), whereas the `2P1D` pool achieves `2 * 5.6 = 11.2 RPS` prefill and `10.0 RPS` decode for an aggregate cluster goodput of **`10.0 RPS` (`min(11.2, 10.0)`)**, or **`3.33 RPS/GPU` (`3.3 RPS/GPU` across `3` GPUs, a `2.08x` per-GPU speedup)**; (b) MLPerf v5.0 p99 SLOs are **`450 ms` TTFT / `40 ms` TPOT for `Llama-2-70B`** and **`6,000 ms` (`6 s`) TTFT / `175 ms` TPOT for `Llama-3.1-405B`**, and loading `140 GB` of FP16 weights on an H100 (`3,350 GB/s`) takes **`41.79 ms` (`~41.7 ms`, capping single-stream decode at `23.93 tok/s` / `~24 tok/s`)**.
2. **Exercise 2:** (a) Request A (`eff_len = 768 >= 256, queue = 4 < 10`) returns **`True` (`remote_prefill_score = 1.0 > 0.5`, offload to remote prefill)**, Request B (`eff_len = 124 < 256, active = 4 < 8`) returns **`False` (`remote_prefill_score = 0.3 <= 0.5`, run locally on decode worker to exploit cached prefix)**, and Request C (`eff_len = 2048 >= 256, queue = 12 >= 10`) returns **`False` (shed load back to local prefill because global prefill queue is saturated)**; (b) the simple 2-term cost picks **`worker-0-cold` (`1.3` vs `2.3`)**, whereas the 5-factor KV-aware composite `latency_cost` picks **`worker-1-warm` (`0.0` vs `6.0`)** because the `-10.0` exact prefix match bonus and `-1.0` recent-use bonus outweigh its slightly higher occupancy.
3. **Exercise 3:** (a) Dynamo GPU Planner triggers **`scale_up` on prefill (`4 -> 5` replicas, since `queue=9 >= 8` and `util=85% >= 80%`)** and **`scale_up` on decode (`8 -> 9` replicas, since `queue=18 >= 16` and `kv=78% >= 75%`)**; (b) `QoSController` computes **`est_ttft = 9 * 35 + 18 * 20 = 675.0 ms` (`> 500 ms` SLO)**, **rejecting `"low"` priority requests (`False`) while admitting `"high"` priority requests (`True`)**, and across `20` workers reserves **`2` workers (`10%`) for `premium` (`priority=100`), `6` workers (`30%`) for `standard` (`priority=50`), and `12` workers (`60%`) for `free` (`priority=10`)**.
4. **Exercise 4:** (a) A `7,500`-token prompt requires **`469` (`~470`) transfers (`20.0 ms`) with `16`-token blocks versus `59` transfers (`8.0 ms`) with `128`-token collated slabs (`2.5x` speedup)**; `250,000` tokens on the `70B` MHA model (`1,310,720 B/tok`) consume **`327.7 GB` (`~328 GB`) in FP16 and `163.8 GB` in FP8**, and `16 RPS * 1.5 GB = 24.0 GB/s` (`~25 GB/s`) fits on NVLink 4 (`900 GB/s`) and NDR InfiniBand (`50 GB/s`) but saturates non-RDMA PCIe/TCP (`10 GB/s`); (b) prefill ranks (`TP_p=2, PP_p=2`) hold **`40` layers and `4` KV heads/rank** while decode ranks (`TP_d=4, PP_d=1`) expect **`80` layers and `2` KV heads/rank** (requiring an on-the-fly NIXL KV layout transpose), and `llm-d` EPP (`port 9002`, `FailClose`) selects **`vllm-llama3-8b-pod-1` (`port 8000`, score `42.0` vs `-24.0`)** due to its prefix and LoRA hits.
