## 4. One-Line Expected Exercise Solutions

1. **Exercise 1 (4-Layer Evidence Ladder & Table 13-1):** (a) `DCGM` / Prometheus ("The Thermometer"); (b) `Nsight Systems` (`nsys`, "The Traffic Camera / X-Ray"); (c) `Nsight Compute` (`ncu`, "The Microscope"); (d) Meta's `Holistic Trace Analysis` (`HTA`) and `Perfetto` (replacing the deprecated TensorBoard profiler plugin).
2. **Exercise 2 (Tables 13-2 & 13-3 reconciliation):** (a) `aten::matmul` (`43.00 ms`, `128` calls) + `aten::linear` (`35.50 ms`, `64` calls) = `78.50 ms` (`56.9%`), and `dispatch` (`18.70 ms`, `2` calls) + `combine` (`12.10 ms`, `2` calls) = `30.80 ms` (`22.3%`); (b) `60.5 + 58.3 + 19.2 = 138.0 ms` (`train_step` Child GPU time, `0.0 ms` Self GPU time); (c) `nsys` uses `CUPTI` to project all `64` asynchronous `aten::add_` kernels launched between the host's single `optimizer_step` push/pop pair onto that `1` NVTX instance.
3. **Exercise 3 (Table 13-4 `ncu` Roofline & Grace `perf`):** Table 13-4 shifts from `50%` FLOPS / `70%` mem BW / `60%` occ (memory-bound) to `85%` FLOPS / `40%` mem BW / `80%` occ (compute-bound); `1.58` IPC is far below the `8.0` max IPC of an ARM Neoverse V2 Grace core; the 5 `perf report` hotspots are `45.0%` `py::forward` (`torch.compile`), `20.5%` `aten::matmul` (compile/fuse GEMMs), `10.2%` `dataloader_iter_next` (`num_workers=4`/GPU + `persistent_workers=True`), `8.7%` `ncclAllReduce` (tune `25 MB` DDP buckets / overlap / 8-bit compression), and `5.3%` `read` (`pin_memory=True`, `non_blocking=True`, `prefetch_factor=4` or `8`, WebDataset/Arrow/Parquet shards, DALI/Magnum IO).
4. **Exercise 4 (`PYTORCH_ALLOC_CONF` & FireworksAI shared graph pool):** With `512:2`, the `512 MB` span in `[512 MB, 1,024 MB]` is split into `2` sub-buckets (`256 MB` step: `[512, 768, 1024]`), rounding `600 MB` up to `768 MB`; FireworksAI captures shared-pool graphs in decreasing batch order (`8 -> 4 -> 2 -> 1`) so batch `8` allocates the maximum `PagedAttention` buffer first and smaller batch variants (`4, 2, 1`) reuse that memory without extra VRAM allocation.
5. **Exercise 5 (`SimpleFSDP`, `GraceAdam`, `NCCL` `MemPool`, `UCX`):** `SimpleFSDP` cuts memory by up to `~28%` and raises throughput by up to `~69%` vs eager `FSDP2`; `GraceAdam` uses ARM `SVE`'s `32` vector registers and `16` predicate registers; Blackwell `NVLink 5` provides `1.8 TB/s` bidirectional (`900 GB/s` unidirectional) bandwidth per GPU; cross-rack `NCCL-UCX` sets `NCCL_NET=UCX`, `NCCL_PLUGIN_P2P=ucx`, and `UCX_TLS=rc,self,gdr_copy,cuda_copy`.
6. **Exercise 6 (Table 13-6 `MLPerf` breakdown & CI gate):** Total step time is `24.0 ms` (`100%`): `forward = 10.5 ms` (`43.8%`), `backward = 9.0 ms` (`37.5%`, total compute = `19.5 ms` = `81.3%`), `allreduce = 4.0 ms` (`16.7%` = `1/6` of step), `other = 0.5 ms` (`2.1%`); `PyTorch HUD` / `TorchBench` CI flags a regression at `>= 5.0%` slowdown sustained across `3` runs.
