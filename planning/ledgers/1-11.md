## 4. One-Line Expected Exercise Solutions

1. **Exercise 1 (From `execve()` to `main()` and `PT_INTERP`):** The 7 stages are: (1) `fork()` + `execve()`, (2) kernel permission/format check (`\x7fELF` vs `#!`), (3) ELF loader maps `LOAD` segments + stack/auxv/heap, (4) kernel maps the dynamic linker named in `PT_INTERP` (`/lib64/ld-linux-x86-64.so.2`) and jumps to it, (5) `ld.so` maps `DT_NEEDED` libraries, performs relocations (with PLT/GOT lazy binding unless `LD_BIND_NOW=1`), and runs constructors, (6) `_start` -> `__libc_start_main` -> `main()`, and (7) `exit_group()` + parent `wait4()`; if `PT_INTERP` is missing (such as a glibc binary in a musl Alpine container), `execve()` fails immediately with `No such file or directory`.
2. **Exercise 2 (Shared Library Naming and `GLIBC` Symbol Versioning):** (a) `classify_library_names("libfoo.so.1.2.3")` gives `linker_name = "libfoo.so"` (used by `ld -lfoo`), `soname = "libfoo.so.1"` (stored in the binary's `DT_NEEDED`), and `real_name = "libfoo.so.1.2.3"`; (b) a binary requiring `GLIBC_2.34` fails on a host with `GLIBC_2.31` because glibc symbol versioning is forward-compatible only (always build on the oldest supported distribution).
3. **Exercise 3 (Demand Paging: `VIRT` vs `RSS` and `262,144` Minor Faults):** Calling `mmap()` for `1 GiB` (`1,073,741,824` bytes) sets `VIRT = 1 GiB` and `RSS = 0` (`0` page faults); touching `1` byte every `4,096` bytes triggers `262,144` minor page faults and raises `RSS` to `1 GiB`.
4. **Exercise 4 (`strace` Overhead and Diagnosing Hung Processes):** Because `ptrace` stops the traced process on every syscall entry and exit, tracing a `dd` copy of `1 KiB` blocks can slow execution by `~70x`; a thread blocked in `futex(..., FUTEX_WAIT...)` is waiting on a user-space lock/condition variable, in `epoll_wait` is waiting for network/descriptor I/O, and in `ioctl` on `/dev/nvidia0` is inside the NVIDIA GPU driver.
5. **Exercise 5 (USE Method for Software Resources and Flame Graphs):** A thread pool with `16/16` busy threads, `45` queued requests, and `2` rejected requests has `utilization = 100.0%`, `saturation = 45`, and `errors = 2`; in a CPU flame graph (`perf record -F 99 -g`), the y-axis is call stack depth, the x-axis width is proportional to sample count (alphabetical, not time), and a wide top-edge plateau identifies the function consuming the most on-CPU time.
6. **Exercise 6 (Fixing `[unknown]` Symbols and Broken Stack Traces):** `[unknown]` frames come from stripped binaries (fix with `-g` / `debuginfo` packages) or JIT code (fix with `/tmp/perf-<PID>.map`), while truncated/broken stacks happen when code was compiled with `-fomit-frame-pointer` (fix with `-fno-omit-frame-pointer`, `-XX:+PreserveFramePointer`, or `perf --call-graph dwarf`).
