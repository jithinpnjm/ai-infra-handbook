## 4. One-Line Expected Exercise Solutions

1. **Exercise 1 (`torch.compile` 4-stage pipeline):** (a) `TorchDynamo` uses CPython `PEP 523`; (b) `PrimTorch IR` decomposes `> 2,000` ATen operators into `~250` primitives (`8.0x` reduction) and functionalizes `x.add_(y)` into `%z = aten::add(x, y)` + `%copy = aten::copy_(x, %z)`; (c) `TorchInductor` lowers its Python `Pointwise` loop IR into OpenAI Triton code, which compiles to NVIDIA PTX via LLVM NVPTX without invoking `nvcc`.
2. **Exercise 2 (`dynamo.explain(toy_example)`):** Reports `Graph Count: 3, Graph Break Count: 2, Op Count: 5` (`builtin: print` and `generic_jump TensorVariable()`); guard `print` with `if not torch._dynamo.is_compiling():` and replace `if b.sum() < 0:` with `b = torch.where(b.sum() < 0, -b, b)` (`model_where`) or `b = torch.cond(b.sum() < 0, lambda b: -b, lambda b: b.clone(), (b,))` (`model_cond`) to achieve `Graph Count: 1` (`0` breaks).
3. **Exercise 3 (Dynamic shapes & debugging flags):** `dynamic=True` forces all dimensions symbolic and disables CUDA Graph capture (prefer `mark_dynamic(tensor, dim)` or bucket padding when lengths vary by `±10%–20%`); use `TORCH_LOGS="perf_hints"` to catch missed CUDA Graphs, `TORCHDYNAMO_REPRO_AFTER="aot"` + `TORCHDYNAMO_REPRO_LEVEL=4` to isolate post-AOT numerical discrepancies, and `CUBLAS_WORKSPACE_CONFIG=:4096:8` (or `:16:8`) with `torch.use_deterministic_algorithms(True)` for deterministic `cuBLAS`.
4. **Exercise 4 (Triton `SPMD` sizing & `@triton_op`):** (a) `cdiv(10000, 1024) = 10` programs; (b) `num_warps = 4` launches `128` threads/block (`8.0` elements/thread), scaling to `num_warps = 8` (`256` threads) at `BLOCK_SIZE = 2,048` and `num_warps = 16` (`512` threads) at `BLOCK_SIZE = 4,096`; (c) `@torch.library.triton_op` + `wrap_triton` + `register_autograd` register the kernel so `torch.compile` can inline and fuse it without a graph break.
5. **Exercise 5 (Triton TMA descriptors, `TMEM` & pipelining rule):** (a) `tl.make_tensor_descriptor` requires leading strides to be multiples of `16 bytes` and the innermost dimension to be contiguous; (b) on Blackwell (`sm_100`), `tl.dot` lowers to `tcgen05` UMMA with FP32 accumulators in `256 KB`/SM `TMEM`; (c) overwriting `a_cur` before `tl.dot(a_cur, b_cur)` lets the compiler reorder/sink next-iteration loads past current uses, collapsing overlap—always follow `prefetch-next -> compute-current -> swap`.
6. **Exercise 6 (`matmul_kernel_persistent`, `Proton` & `OpenXLA`):** `MT = 64, NT = 64, TILE_COUNT = 4,096, K_tiles = 8`; in `Proton`, `matmul_kernel_persistent` (`159.352 ms`, `4,312.421`) beats `matmul_kernel` (`165.349 ms`, `4,156.033`), `torch` (`174.671 ms`, `3,934.214`), and `cublas` (`174.920 ms`, `3,928.623`); `OpenXLA` (`backend="openxla"`) compiles whole static graphs ahead of time and triggers an expensive whole-program recompilation on every unseen shape, requiring static bucket padding.
