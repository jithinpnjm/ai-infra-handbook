## 4. One-Line Expected Exercise Solutions

1. **Exercise 1:** (a) Each `400 Gbps` NDR InfiniBand NIC delivers **`50.0 GB/s` per GPU** (`400 * 0.125 GB/s`) and **`400.0 GB/s` aggregate across all `8` GPUs** in the node, which is **`18.0x` slower per GPU** than `900.0 GB/s` intra-node `NVLink 4`; (b) allowing `TP` to cross the node boundary hits this `18.0x` bandwidth cliff on every layer's synchronous `AllReduce` (causing a **`16.7x` step-time slowdown**), and `all_reduce_perf` converts `algbw = 514.3 GB/s` on `N = 8` GPUs into **`busbw = 514.3 * 2 * (7 / 8) = 900.0 GB/s`**.
2. **Exercise 2:** (a) Using `RANK = NODE_RANK * 8 + LOCAL_RANK`, `(node_rank=2, local_rank=5)` maps to **`RANK = 21`**, and `RANK = 29` inverts to **`(node_rank=3, local_rank=5)`** (`29 // 8 = 3`, `29 % 8 = 5`); (b) under Pattern A (`--ntasks-per-node=1` + `torchrun --nproc_per_node=8`), `SLURM_NTASKS = 4`, `SLURM_PROCID = 0..3`, and `SLURM_LOCALID = 0`, whereas under Pattern B (`--ntasks-per-node=8` + `srun python`), `SLURM_NTASKS = 32`, `SLURM_PROCID = 0..31`, and `SLURM_LOCALID = 0..7`; combining `--ntasks-per-node=8` with `torchrun --nproc_per_node=8` spawns **`64` processes per node (`256` total across `4` nodes, `8x` GPU oversubscription)**.
3. **Exercise 3:** (a) Under standard `tp-cp-pp-dp` ordering on `32` GPUs (`DP=2, PP=2, CP=1, TP=8`), the `4` `TP` groups are **`[0..7]`, `[8..15]`, `[16..23]`, and `[24..31]`** (each confined to a single `8`-GPU `NVLink` node), the first `2` `PP` groups are **`[0, 8]` and `[1, 9]`** (both on Rail `0` and Rail `1`), and the first `2` `DP` groups are **`[0, 16]` and `[1, 17]`** (also on Rail `0` and Rail `1`); (b) reversing to `dp-pp-cp-tp` makes `TP` group `0` equal to **`[0, 4, 8, 12, 16, 20, 24, 28]`**, spanning **all `4` physical nodes** over InfiniBand.
4. **Exercise 4:** (a) For `28.0 GB` of `FP32` gradients, an `8`-GPU Ring moves **`49.0 GB`** (`2 * 7/8 * 28.0 GB`) in **`54.4 ms` (`~54 ms`)** over `900 GB/s` `NVLink` (`8` hops), whereas a `512`-GPU Ring moves **`55.89 GB` (`~55.9 GB`)** in **`2.24 s` (`~2.2 s`)** over `25.0 GB/s` InfiniBand and requires **`512` sequential hops** compared to **`9` hops (`log2 512`)** for a Binary Tree; (b) in `compute_multinode_scaling_curve()`, scaling from `16` GPUs (`2` nodes, `1` tree hop, `0.0894 s` exposed comm) to `16,384` GPUs (`2,048` nodes, `11` tree hops, `0.2367 s` exposed comm) shifts scaling efficiency from **`97.81%` to `94.41%`**.
5. **Exercise 5:** (a) On a `128`-core, `8`-GPU dual-socket node, `LOCAL_RANK = 0` (`cuda:0`) binds to **`NUMA 0`, CPU cores `0–15`, and `mlx5_0` (`PIX`)**, while `LOCAL_RANK = 4` (`cuda:4`) binds to **`NUMA 1`, CPU cores `64–79`, and `mlx5_4` (`PIX`)**; (b) when `GPU 0` uses `NIC 3` (`PXB/NODE`) or `mlx5_7` (`SYS` across the inter-socket `QPI`/`UPI` bus), GPUDirect RDMA loses direct `PIX` switch locality and `nccl-tests` `busbw` drops from **`300.0 GB/s` to `40.0 GB/s` (`7.5x` reduction)**, which is prevented by `NCCL_NET_GDR_LEVEL=5`, `NCCL_CROSS_NIC=0`, and `srun --cpu-bind=numa`.
6. **Exercise 6:** (a) The `8.03B` Megatron-LM model has a theoretical checkpoint size of **`80.30 GB`** (`16.06 GB` `BF16` weights + `64.24 GB` `FP32` `Adam` states) and an actual disk footprint of **`108.0 GB`** (`4 x 27.0 GB` `.distcp` shards), which writes in **`4.32 seconds`** at `25.0 GB/s`—well within SLURM's **`90`-second (`#SBATCH --signal=SIGUSR1@90`)** preemption window; (b) for `LEARNING_RATES=(1e-4, 3e-4, 1e-3, 3e-3)` and `BATCH_SIZES=(16, 32, 64)`, `SLURM_ARRAY_TASK_ID = 5` (`5 % 4 = 1`, `5 // 4 = 1`) runs **`(LR = 3e-4, BS = 32)`**, and `SLURM_ARRAY_TASK_ID = 11` (`11 % 4 = 3`, `11 // 4 = 2`) runs **`(LR = 3e-3, BS = 64)`**.
