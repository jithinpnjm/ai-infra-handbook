## 4. One-Line Expected Exercise Solutions

1. **Exercise 1 (MDS Saturation & Sharding):** (a) At `150,000 KB/s` and `220 KB`/file, each worker opens `~680` files/s (`128 * 680 = 87,040` opens/s total), overloading the `50,000` ops/s `MDS` by `74.1%` (`~75%`); (b) With `10 MB` (`10,000 KB`) shards, each worker opens `15` files/s (`128 * 15 = 1,920` opens/s total, `3.8%` of `MDS` ceiling), allowing the `48` `OSTs` (`38.4 GB/s` raw) to easily deliver the required `19.2 GB/s`.
2. **Exercise 2 (Bounce-Buffer vs GDS):** (a) Unpinned POSIX uses `4` copies (`2` PCIe traversals, `2` CPU `memcpy`s, `60.0 GB` host DRAM traffic per `10 GB`), pinned `pin_memory=True` uses `3` copies (`2` PCIe traversals, `1` CPU `memcpy`, `40.0 GB` host DRAM traffic), and `GDS` uses `1` direct `P2P DMA` copy (`1` PCIe traversal, `0` CPU payload copies, `0.0 GB` host DRAM payload traffic); (b) `GDS` (`9.6 GB/s`, `1.00 ms`) improves throughput by `+20.0%` over CPU mode (`8.0 GB/s`) and reduces latency by `-20.0%` (`1.25 ms -> 1.00 ms`).
3. **Exercise 3 (Bandwidth & Checkpoint Scaling):** (a) At `200 MB/s` per GPU: `8`-GPU node = `1.6 GB/s`, `72`-GPU `NVL72` rack = `14.4 GB/s` (`14–20 GB/s`), `1,024`-GPU cluster = `204.8 GB/s`; (b) `2,000 GB / 60 s = 33.33 GB/s` minimum write bandwidth, requiring `ceil(33.33 / 0.8) = 42` `OSTs` at `800 MB/s` each.
4. **Exercise 4 (45s Checkpoint Stall):** Default `4`-OST striping caps throughput at `4 * 0.8 = 3.2 GB/s`; increasing stripe width (`lfs setstripe -c`) to `25` `OSTs` yields `20.0 GB/s` (`25.0 s` for `500 GB`) and `32` `OSTs` yields `25.6 GB/s` (`19.5 s`).
5. **Exercise 5 (NUMA & PCIe Locality):** Aligned `NUMA 0` (`PIX`) has `55.0 ns` DRAM latency, `GDS` `P2P` enabled, and `10.0 GB/s` (`100%`) throughput; misaligned cross-socket `SYS` + remote `NUMA 1` doubles DRAM latency to `110.0 ns`, disables optimal `GDS` `P2P`, and reduces throughput by `0.72 * 0.80 = 0.576` to `5.76 GB/s` (`57.6%` retention).
6. **Exercise 6 (Page Cache vs `O_DIRECT`):** (a) `120 GB` dataset on `256 GB` free RAM ($120 \le 0.85 \times 256 = 217.6\text{ GB}$) fits in RAM (`~95%` cache hit rate on Epoch 2+, keep buffered page cache); (b) `4,000 GB` shuffled dataset on `512 GB` RAM ($4000 > 435.2\text{ GB}$) thrashes the page cache (`~4%` hit rate, `15%` CPU `iowait`), so enable `O_DIRECT` / `GDS`.
