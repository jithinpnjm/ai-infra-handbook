# Claim Ledger: 7.6 The Redfish schema: reading CSDL, JSON Schema and the Resource Guide

## DMTF Redfish Specification (DSP0266 v1.21.0), Data Model (DSP0268) & Resource Guide (DSP2046) Claims
- **Three Schema Formats (§11.1–11.4):** CSDL XML (`*_v1.xml`), JSON Schema (`*.json`), and OpenAPI YAML (`openapi.yaml`, protocol v1.6.0+). Unversioned JSON Schema files (`ComputerSystem.json`) hold `uris` and capabilities (`insertable`, `updatable`, `deletable`), while versioned files (`ComputerSystem.v1_17_0.json`) hold properties, types, `readonly`, `required`, and `Actions`.
- **Versioning & Deprecation (§9.13, §9.14):** `@odata.type` uses `#<Namespace>.v<Major>_<Minor>_<Errata>.<ResourceType>`. Minor versions are strictly additive; a `v1_0_0` payload cannot carry properties added in later minor versions. Deprecated properties (e.g., `Chassis/{id}/Power` and `Thermal`, replaced by `PowerSubsystem`, `ThermalSubsystem`, `Sensors`) remain valid until the next major version.
- **Registries (§9.12):** Message Registries (`Base.1.24.0.json` has `125` messages), Attribute Registries (BIOS settings), and Privilege Registries. `MessageId` format is `<RegistryPrefix>.<major>.<minor>.<MessageName>`.
