## 4. One-Line Expected Exercise Solutions

1. **Exercise 1 (The GPU Node Bring-Up Dependency DAG):** Using `validate_bringup_role_order()`, `mofed` and its reboot must precede `nvidia_driver` so `nvidia_peermem` binds to the RDMA stack symbols; `nvidia-fabricmanager` must match the exact driver version on NVSwitch systems before CUDA workloads run; and `gpu_validate` must pass before `slurm_client` or `kubelet` exposes the node to users.
2. **Exercise 2 (Pre-Flight Hardware Discovery `gpu_facts` and Host OS / NUMA / CPU Tuning, `ASP` Ch. 3):** `gpu_facts` counts `10de:` GPUs/NVSwitches and `15b3:` NICs via `lspci` into `/etc/ansible/facts.d/gpu.fact` and halts on missing GPUs; `ASP` Ch. 3 locks the `performance` CPU governor and disables deep C-states to eliminate CPU wakeup GPU bubbles, enforces NUMA affinity (`--topology-manager-policy=single-numa-node`), and tunes `vm.swappiness=1` and `vm.dirty_ratio`.
3. **Exercise 3 (Non-Interactive Driver & OFED Installation and Reboot Handling):** `DEBIAN_FRONTEND: noninteractive`, `dpkg_options: "force-confold,force-confdef"`, `lock_timeout: 300`, `dpkg_selections: hold`, and disabling `unattended-upgrades` prevent `dpkg` prompt hangs and kernel/DKMS mismatches; `reboot_timeout: 1800` accommodates 10–15 minute enterprise GPU server POST times.
4. **Exercise 4 (GPU Tuning and DCGM Telemetry, `ASP` Ch. 3):** `nvidia-persistenced` keeps driver state initialized, `nvidia_peermem` enables GPUDirect RDMA, ECC (`-e 1`) prevents silent bit-flip corruption, `-lgc` locks clocks for deterministic benchmarks, MIG slices GPUs for small-model inference, and `dcgmi diag -r 1/2/3` provides seconds/minutes/30-min hardware diagnostics.
5. **Exercise 5 (The 7-Stage Node Validation & Burn-In Ladder and `nccl-tests`):** `gpu_validate` checks PCIe/NVLink/ECC sanity, `dcgmi diag`, 30-minute `gpu-burn` (inspecting `journalctl -k` for XID errors), `nvbandwidth`, RDMA `perftest`, and multi-node `all_reduce_perf` (`parse_and_gate_nccl_busbw()` asserting `Avg bus bandwidth >= expected_busbw_gbps`).
6. **Exercise 6 (Day-2 Drain/Patch/Validate/Resume Workflows and Fleet Health-Sweep Triage):** `evaluate_gpu_health_sweep()` parses read-only `nvidia-smi --query-gpu=...` CSV rows across the fleet to flag missing GPUs, uncorrected ECC, thermal throttling, or PCIe `Gen4x8` link downgrades; maintenance drains nodes (`scontrol State=DRAIN` / `k8s_drain`), applies changes in `block`/`rescue` (leaving failed nodes drained), and resumes only after validation passes.
