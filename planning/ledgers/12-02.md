## 4. One-Line Expected Exercise Solutions

1. **Exercise 1:** `mlx5_0` reports `fw_ver="28.39.2048"`, `vendor_id_hex="0x02c9"`, `vendor_part_id=4129`, `max_qp=262144`, `max_qp_wr=32768`, `max_sge=30`, `max_cq=16777216`, `max_cqe=4194303`, `max_mr=16777216`, `active_mtu=4096`; `rc_pingpong` fails `INIT -> RTR` with `EINVAL` (`Failed to modify QP to RTR`) because `requested_path_mtu` (`4096`) exceeds the peer port's `local_active_mtu` (`2048`).
2. **Exercise 2:** (a) `65,536` B on `4,096` B pages pins `16` pages (`128` B MTT); (b) `1 GiB` (`1,073,741,824` B) on `4,096` B pages pins `262,144` pages (`2,097,152` B = `2 MiB` MTT); (c) `1 GiB` on `2 MiB` (`2,097,152` B) hugepages pins `512` pages (`4,096` B = `4 KiB` MTT, `512x` smaller); registering `131,072` B when `ulimit -l` is `65,536` B fails with `IBV_REG_MR_ENOMEM_MEMLOCK`, fixed by `* soft memlock unlimited` and `* hard memlock unlimited` in `/etc/security/limits.conf`.
3. **Exercise 3:** `wr_id=1043` (`IBV_WC_RETRY_EXC_ERR`, `opcode="RDMA_WRITE"`, `vendor_err="0x81"`, fault domain `TRANSPORT_ACK_TIMEOUT_PEER_OR_PATH`) is the root cause that transitioned the QP to `ERR` and flushed `wr_id=[1044, 1045, 1046]` with `IBV_WC_WR_FLUSH_ERR`; `RNR_RETRY_EXC_ERR` means remote Receive Queue starvation, `LOC_PROT_ERR` means local PD/lkey/bounds violation, and `REM_ACCESS_ERR` means remote rkey/permission/bounds violation.
4. **Exercise 4:** Both sessions start with a `3`-step CM Handshake (`Connect request with client QPN`, `Connect reply with server QPN`, `Ready to use`) and end with a `4`-step CM Terminate (`2` disconnect request/reply pairs); `RDMA_WRITE` has `6` transfer steps (`Steps 4..9`: transfer size/addr + ACK, MR info + ACK, Data + ACK = `13` total) whereas `RDMA_READ` (`20.0.0.2 -> 60.0.0.2`) combines the read request metadata into `Step 4` (`Steps 4..7`: Read request + ACK, Server Data + Client ACK = `11` total).
5. **Exercise 5:** (a) `RDMA READ Request` (`opcode 12`): `12` B `BTH` (`P_Key 0xffff`, `Dest QP 0x000fe1`, `AckReq=True`, `PSN 16548361`) + `16` B `RETH` (`VA 0x00007ff9de5f4000`, `rkey 0x00207100`, `len 65536`) + `4` B `ICRC` (`0xb87e1cbc`) = `32` B; (b) `RDMA READ Response Middle` (`opcode 14`, `Dest QP 0x00007b`, `PSN 16543980`): `12` B `BTH` + `1,024` B payload + `4` B `ICRC` (`0x5b522360`) = `1,040` B; (c) `RC Acknowledge` (`opcode 17`, `Dest QP 0x000123`, `PSN 2592248`): `12` B `BTH` + `4` B `AETH` (`Syndrome 0 Ack`, `MSN 1`) + `4` B `ICRC` (`0x33e6e2af`) = `20` B.
6. **Exercise 6:** `128 × 8 = 1,024` total ranks require `1,023` `RC` QPs/rank, `8,184` `RC` QPs/node, and `1,047,552` cluster-wide `RC` QPs (`DC` reduces initiator QPs to `O(1)` while retaining reliability and RDMA Read/Write/Atomics); `ib_write_bw` at `23,450.5 MB/s` on `200 Gbps` HDR (`25,000 MB/s` line rate) achieves `93.8%` line-rate utilization (`0.357826 Mpps` / `0.375208 Mpps` peak).
