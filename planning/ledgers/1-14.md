## 4. One-Line Expected Exercise Solutions

1. **Exercise 1 (MBR 512-Byte Layout vs UEFI ESP and Secure Boot):** (a) The 512-byte MBR consists of `446` bytes of boot code (`440`/`441` bytes before the 4-byte disk ID), `64` bytes for `4` primary partition entries (`16` bytes each), and the `2`-byte `0x55AA` magic signature, forcing BIOS boot loaders to load `core.img` from the post-MBR gap (or a `BIOS boot` partition on GPT); (b) under UEFI Secure Boot, firmware verifies Microsoft-signed `shimx64.efi`, which verifies `grubx64.efi` and the kernel, and a locked-down kernel refuses unsigned DKMS modules (`nvidia.ko`) with `Required key not available` unless signed with an enrolled MOK.
2. **Exercise 2 (GRUB `root` vs Kernel `root=` and Primary `console=`):** (a) In GRUB's `set root=(hd0,gpt2)`, `root` is the filesystem where GRUB itself looks for `/boot/vmlinuz-*` and `/boot/initrd.img-*`, whereas `root=UUID=...` on the `linux` line tells the Linux kernel which filesystem to mount as `/`; (b) in `console=tty0 console=ttyS0,115200n8`, kernel messages go to both consoles, and the **last** one listed (`ttyS0,115200n8`) becomes `/dev/console` (primary).
3. **Exercise 3 (`initramfs` Lifecycle, Host-Only vs Generic, and Rebuilds):** (a) The `initramfs` is a cpio archive unpacked into a temporary RAM rootfs whose `/init` loads storage/RAID/LVM/LUKS/network modules, mounts the real root filesystem read-only, and calls `switch_root` to exec `/sbin/init` (`systemd`, PID 1); (b) `dracut`'s default host-only mode bundles only the build host's drivers, so a cluster golden image must be built with `dracut --no-hostonly` (or `MODULES=most` in `initramfs-tools`).
4. **Exercise 4 (Localizing Boot Failures Across the 7 Stages):** (a) `No bootable device` / `PXE-E53` = Stage 1 (`stage_1_firmware_or_pxe_rom`); (b) `grub rescue>` = Stage 2 (`stage_2_bootloader_grub`); (c) `VFS: Unable to mount root fs` or `(initramfs)` = Stage 4 (`stage_4_initramfs_root_mount`); (d) `A start job is running for dev-disk-by-uuid... (1min 30s)` followed by emergency mode = Stage 6 (`stage_6_systemd_fstab_mount`, fixed by correcting the UUID or adding `nofail`).
5. **Exercise 5 (PXE Network Boot, RFC 4578 Architecture Matching, and SNMP MAC Discovery):** (a) `PXEClient:Arch:00000` (BIOS) receives `pxelinux.0`, `00007` (UEFI x64) receives `grubnetx64.efi`, and `00009` receives `ipxe.efi`; (b) to map node MACs to switch ports without powering nodes one by one, query the switch's bridge forwarding table via `snmpwalk -c public -v2c <swaddr> iso.org.dod.internet.mgmt.mib-2.dot1dBridge.dot1dTp.dot1dTpFdbTable.dot1dTpFdbEntry.1` (MACs) and `.2` (port numbers).
6. **Exercise 6 (NFS-Root Writable Overlays and Staggering Cluster Boots):** (a) On a shared read-only NFS-root image, mount `tmpfs` (with `size=` caps) on `/tmp`, `/var/run`, `/var/lock`, `/var/cache`, and `/var/tmp`, send logs to a remote syslog server, and obtain hostnames via DHCP; (b) stagger cluster node power-on by at least `1 to 2 seconds` (or per-rack delays) to prevent electrical inrush current spikes and UDP TFTP/DHCP packet loss (`boot storms`).
