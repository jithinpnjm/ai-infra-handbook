## 4. One-Line Expected Exercise Solutions

1. **Exercise 1 (DHCPv4 `DORA`, Lease Timers `T1`/`T2`, Relays `giaddr`, and Option `82`):** (a) In `DORA` (UDP `68 -> 67`), `DISCOVER` and `REQUEST` are broadcast (`255.255.255.255`) because the client starts at `0.0.0.0` and must notify all offering servers which offer it accepted; (b) for a `12h` (`43,200 s`) lease (`compute_dhcp_lease_timers_sec()`), the client unicasts a renewal at `T1 = 50%` (`21,600 s`) and broadcasts a rebind to any server at `T2 = 87.5%` (`37,800 s`), while a router **DHCP relay** (`ip helper-address`) stamps its interface IP into `giaddr` (and switch port into Option `82`) and unicasts to the central DHCP server.
2. **Exercise 2 (Bare-Metal GPU Node PXE / UEFI HTTP Boot and DHCP Snooping):** During PXE boot, NIC firmware sends `DISCOVER` with Option `60` (`PXEClient`) and Option `93` (`7` for UEFI x86-64); the DHCP server replies with an IP plus Option `66` (`next-server`) and Option `67` (`ipxe.efi` or an HTTP URL), and **DHCP snooping** on the top-of-rack switch blocks rogue DHCP servers on untrusted ports.
3. **Exercise 3 (DHCPv6 vs. SLAAC and Why DHCPv6 Never Carries the Default Gateway):** In IPv6, **Router Advertisements** (`ICMPv6 Type 134`) always provide the **default gateway** (`fe80::...`) and indicate via flags whether hosts should form addresses via **SLAAC** (`A` flag), request stateful addresses from **DHCPv6** (`M` flag, UDP `546`/`547` using a `DUID`), or fetch only stateless options like DNS from DHCPv6 (`O` flag).
4. **Exercise 4 (NAT Types `SNAT`, `DNAT`, `MASQUERADE`, `PAT`, and Reading `conntrack -L`):** Using `parse_conntrack_nat_entry()`: `DNAT` rewrites the destination in `PREROUTING` (before routing, for inbound port forwarding and Kubernetes `ClusterIP` Services), `SNAT`/`MASQUERADE` rewrites the source IP and port (`PAT`) in `POSTROUTING` (after routing, for outbound Internet access), and `conntrack -L` shows the mapping by comparing the original tuple (`src=10.0.0.5 sport=51000`) with the expected reply tuple (`dst=203.0.113.9 dport=40001`).
5. **Exercise 5 (Hairpin NAT Loopback and NAT Gateway Port Exhaustion):** (a) When an inside client (`10.0.0.5`) connects to an inside server (`10.0.0.20`) via the NAT gateway's public IP (`check_hairpin_nat_flow()`), `DNAT` rewrites the destination to `10.0.0.20` while leaving the source as `10.0.0.5`, so the server replies **directly on the L2 LAN** and the client resets the unexpected source—fix with split DNS or a hairpin `MASQUERADE` rule; (b) `evaluate_nat_port_exhaustion()` shows that a single NAT IP has `~64,000` ephemeral ports per remote `(dst_ip, dst_port)` tuple, so `80,000` concurrent connections to one container registry require multiple NAT IPs, connection pooling, or a VPC endpoint / local mirror.
6. **Exercise 6 (Why We Never NAT Inside InfiniBand / RoCEv2 AI Fabrics):** RDMA Queue Pair (`QP`) bring-up exchanges true endpoint IP/GID addresses and QP numbers inside the control payload, and NIC hardware transport requires end-to-end address transparency and zero stateful middlebox delay; therefore AI back-end fabrics use non-overlapping routed/L2 private addressing without NAT.
