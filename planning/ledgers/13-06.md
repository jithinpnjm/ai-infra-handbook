## 4. One-Line Expected Exercise Solutions

1. **Exercise 1:** (a) Metadata/syscall time is **`4.0 ms`/file**, CPU time is **`15.0 ms`/file**, total time is **`19.0 ms`/file**, serial batch time is **`4,864.0 ms`**, `8`-worker batch time is **`608.0 ms`**, and ideal wire time is **`10.88 ms` (`11 ms`)**; (b) per-batch overhead is **`597.0 ms`**, wasting **`2,798.74 s` (`46.65` / `~47 minutes`)** across `4,688` batches; (c) the loader is **`6.0x` slower** than the `100 ms` GPU compute pass, leaving the GPU **idle `85.71%` (`~86%`)** of each `700 ms` step.
2. **Exercise 2:** (a) Open rate is **`125,000.0` opens/sec** (`8.0 usecs/call`), overloading a `50,000` ops/sec `MDS` by **`2.5x`**; (b) metadata syscalls consume **`99.19%`** of kernel time (`85.12%` `stat` + `10.05%` `openat` + `4.02%` `close`) vs **`0.81%`** in `read`, array utilization is **`1.25%`** (`5 / 400 GB/s`), and repackaging into `50,000`-file `1 GB` shards requires **`280` shards** (`50,000x` `stat` reduction); (c) `mdtest -b 10 -z 3 -L -I 100000` creates **`1,000` leaf directories** and **`100,000,000` (`100M`) items** per iteration.
3. **Exercise 3:** (a) `10,000`-file `.tar` shards require **`120` opens** (`10,000.0x` reduction) and cut batch wait from `600 ms` to `50 ms` (**`12.0x` speedup**, **`91.7%` Lab 04 wait reduction**), while `1,000`-file `WebDataset` shards require **`1,200` opens** (`1,000.0x` reduction) and cut `256`-GPU batch wait from `30,000 ms` to `20 ms` (**`1,500.0x` speedup**); (b) the `HDF5` dataset occupies **`180.63 GB`** for `images`, **`9.63 MB`** per `(64, 224, 224, 3)` chunk, and **`4.80 MB`** for `int32` `labels`; (c) `1 MiB` sequential reads reduce syscalls by **`256x`** (`262,144 -> 1,024`) vs `4 KB` random reads, and `read_ahead_kb` `128 KB -> 4,096 KB` is a **`32x` multiplier**.
4. **Exercise 4:** (a) Each sample is **`602,112` B** and each `32`-sample batch is **`18.375 MiB`** (`19,267,584` B); at `prefetch_factor=2`, each rank queues **`16` batches (`294.0 MiB`/rank, `2,352.0 MiB` across `8` GPUs)**, while at `prefetch_factor=4`, each rank queues **`32` batches (`588.0 MiB`/rank, `4,704.0 MiB` = `4.59375 GiB` across `8` GPUs)**; (b) `prefetch_factor=4` **does not fit** inside Docker's `64 MiB` `/dev/shm` (`False`) and **does fit** inside Kubernetes's `400 GiB` `emptyDir: Memory` (`True`).
5. **Exercise 5:** (a) Reducing GPU I/O wait from `30%` to `5%` gives a **`6.0x` I/O wait reduction**, recovers **`25.0` percentage points** of GPU time, and yields up to a **`6.0x` step-rate speedup**; `8` GPUs at `5.0x` speedup have **`62.5%` scaling efficiency**, while `8` GPUs need **`1.6 GB/s`** and `72` GPUs (`NVL72`) need **`14.4 GB/s`** at `200 MB/s` per GPU; (b) `DALI` drops active CPU cores from **`8.0` to `2.0`** (**`4.0x` reduction**, **`75.0%` CPU savings**), and the fused GPU `DALI` pipeline (**`8.0 ms`**) outperforms CPU-only (**`92.0 ms`**, **`11.5x` speedup**) and ping-pong `DALI` (**`67.5 ms`**, **`8.44x` speedup**).
6. **Exercise 6:** (a) The `3`-document `uint16` `.bin` payload is **`38` bytes** total, and Document `2` is stored at **`byte_offset = 22, token_length = 8`**; (b) `1B` `uint16` tokens across `500,000` documents produce a **`2.0 GB` `.bin`** file and a **`6.0 MB` `.idx`** file (**`0.3%` index overhead**, **`2.006 GB`** per copy), requiring **`8.024 GB`** for `4` offline pre-shuffled epoch copies.
