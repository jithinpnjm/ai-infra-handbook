## 4. One-Line Expected Exercise Solutions

1. **Exercise 1 (Multi-Tenancy Models `Soft` vs. `Hard`, Trust Boundaries, and the 9 Isolation Layers, `PK` Ch. 12):** Soft multi-tenancy shares control plane and nodes across cooperative internal teams using `Namespace` + `RBAC` + `ResourceQuota`/`LimitRange` + `PSA` + `NetworkPolicy`, whereas hard multi-tenancy adds dedicated node pools + `Kata`/`gVisor` + `vCluster` or separate clusters per tenant across all 9 isolation layers.
2. **Exercise 2 (`ResourceQuota`, `LimitRange`, `scopeSelector`, and Sub-GPU Sharing):** `evaluate_resource_quota_and_limitrange()` injects `LimitRange` defaults before checking `ResourceQuota` (`requests.nvidia.com/gpu`, `count/pods`, `scopeSelector` on `PriorityClass`); hardware `MIG` slices provide memory/fault isolation for multi-tenant sub-GPU sharing whereas `Time-slicing` and `MPS` do not.
3. **Exercise 3 (Delegated Administration `Capsule`/`HNC` vs. Virtual Clusters `vCluster`):** `Capsule` groups multiple namespaces under a `Tenant` CRD with aggregate quotas so team leads can self-create namespaces, while `vCluster` runs an isolated virtual API server inside a host namespace so tenants can install conflicting CRDs/operators.
4. **Exercise 4 (Building a Self-Service `AcmeNamespace` / `Team` Onboarding Operator, `PK` Ch. 11 & 16):** `reconcile_acme_namespace_operator()` inspects the Informer cache for every child object (`Namespace`, `Role`, `RoleBinding`, `ResourceQuota`, `NetworkPolicy`) on every pass rather than trusting `status.phase == "Created"`, and uses a cluster-scoped parent CRD so `ownerReferences` can own cluster-scoped `Namespace`s.
5. **Exercise 5 (The 4-Stage Spectrum of Platform Abstractions `PK` Ch. 16 and Platform-as-a-Product):** Progresses from Stage 1 (`kubectl`/`kubectx`/`Lens`) -> Stage 2 (`Helm` + `Kustomize`) -> Stage 3 (custom workload CRDs like `PinterestService` with break-glass access) -> Stage 4 (full PaaS/portals like `Backstage`/`Waypoint`), measured by onboarding time, GPU efficiency, queue wait `p95`, and developer CSAT.
6. **Exercise 6 (Multi-Tenant GPU Cost Attribution, PromQL Showback, and Idle-GPU Reclamation):** `compute_tenant_gpu_cost_and_waste()` bills teams for requested GPU-hours plus proportional shared platform overhead while reporting `idle_gpu_hours` and `idle_wasted_usd` to drive notebook idle-culling and data-loader optimization.
