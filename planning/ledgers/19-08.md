## 4. Contradictions found

- AI Systems Performance Engineering ch. 3 says NCCL is not supported with MIG. The current MIG guide (Application Considerations) says NCCL 2.31+ gives experimental support with conditions. Chapter follows the guide and notes the book is older.
- nvidia-devops V24 ch. 06 says a layout is valid when slices sum to at most 7 and memory fits. The planner shows this is necessary and not sufficient (start positions). It also contains TFLOPS-per-profile estimates that NVIDIA does not publish and an inconsistent example allocation (see also ledger 19-01). Not reused.
- MIG guide tables: H100 1g.20gb shows memory 1/4 and L2 1/8; copy engines 7 for A100 7g.40gb and 8 for H100 7g.80gb. Kept as printed.
- Handbook 11.24 says "7 x 1g.10gb ... roughly ten gigabytes go to system and ECC overhead". The slice geometry explains the 10 GB gap (one memory slice is unusable with seven 1g instances), so that explanation in 11.24 looks wrong. Not edited here.
- Handbook 11.24 and 18.5 cross-reference numbering: the draft of 19.8 used 11.25 for MIG and 11.17 for time-slicing. Correct numbers are 11.24 and 11.25.
- GKE's H100 partition list has no 4g.40gb, while NVIDIA's table does.
