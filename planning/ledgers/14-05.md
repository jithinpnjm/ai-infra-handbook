## 4. One-Line Expected Exercise Solutions

1. **Exercise 1:** (a) For the `7B` model on `N = 8` GPUs, under the `12 * Psi` (`84.0 GB`) convention: `NO_SHARD` = **`84.0 GB`**, `SHARD_GRAD_OP` = **`22.75 GB`** (`14 + 70 / 8`), `FULL_SHARD` = **`10.5 GB`** (`84 / 8`); under the `16 * Psi` (`112.0 GB`) convention: `NO_SHARD` = **`112.0 GB`**, `SHARD_GRAD_OP` = **`26.25 GB`** (`14 + 98 / 8`), `FULL_SHARD` = **`14.0 GB`** (`112 / 8`); (b) for the `70B` model (`840.0 GB` state), on `N = 8` GPUs: Stage 1 (`ZeRO-1`) = **`350.0 GB`**, Stage 2 (`SHARD_GRAD_OP`) = **`227.5 GB` (`~228 GB`)**, Stage 3 (`FULL_SHARD`) = **`105.0 GB`**, and on `N = 16` GPUs under `FULL_SHARD` = **`52.5 GB`**, leaving **`27.5 GB`** of headroom on an `80 GB` `H100`.
2. **Exercise 2:** (a) Monolithic root wrapping materializes all **`140.0 GB`** of weights at once for a peak state memory of **`192.5 GB`** (`52.5 + 140.0 GB`), whereas `80`-block wrapping (`1.75 GB`/layer) with `2` inflight units (`limit_all_gathers=True`) materializes **`3.5 GB`** for a peak state memory of **`56.0 GB`** (`52.5 + 3.5 GB`); (b) with `limit_all_gathers=False` and `15` queued `AllGather` units (`16` total x `1.75 GB`), transient buffers lock **`28.0 GB`** and push peak state memory to **`80.5 GB`** (`52.5 + 28.0 GB > 80.0 GB`), causing an immediate `CUDA OOM` even before activations.
3. **Exercise 3:** (a) For a `70B` `FP16` model (`M = 140.0 GB`) on `N = 8` GPUs, `DDP` (`NO_SHARD`) and `FSDP` `SHARD_GRAD_OP` (`reshard_after_forward=False`) both transfer **`280.0 GB` asymptotically (`2 * M`)** and **`245.0 GB` exact (`2 * 7/8 * 140.0 GB`)** per step, whereas `FSDP` `FULL_SHARD` (`reshard_after_forward=True`) transfers **`420.0 GB` asymptotically (`3 * M`)** and **`367.5 GB` exact (`3 * 7/8 * 140.0 GB`)** per step; (b) `FSDP` `FULL_SHARD` moves **`1.5x` (`50%` more)** collective traffic per step than `DDP`.
4. **Exercise 4:** (a) Under `HSDP` (`(4, 8)`) on `32` GPUs (`4` nodes x `8` GPUs/node), steady-state memory is **`105.0 GB` per GPU** (`840 / 8`), intra-node `NVLink` collective volume is **`367.5 GB` per step** (`3 * 7/8 * 140.0 GB`), and inter-node InfiniBand `AllReduce` volume on the `17.5 GB` (`140 / 8`) gradient shards is **`26.25 GB` per step** (`2 * 3/4 * 17.5 GB`); (b) compared to **`406.875 GB`** (`3 * 31/32 * 140.0 GB`) under flat `32`-GPU `FULL_SHARD`, `HSDP` reduces cross-node InfiniBand traffic by **`15.5x`**.
5. **Exercise 5:** (a) The `7B` Transformer's raw activation memory (`32 x 8 x 2048 x 4096 x 2 x 12`) is **`51.54 GB` (`~52 GB`)** per GPU, which drops by `75%` to **`12.88 GB`** with activation checkpointing; (b) saving a `70B` checkpoint on `16` GPUs with `FULL_STATE_DICT` gathers **`280.0 GB` (`FP32`)** on rank `0` (crashing an `80 GB` GPU), whereas `DCP` (`full_state_dict=False`) writes **`8.75 GB` (`FP16`)** (`4.375 GB` per `70 GB`) locally per rank.
6. **Exercise 6:** (a) Sharding a `(4096, 1024)` weight tensor across `4` GPUs with `FSDP2` `DTensor(Shard(0))` produces four local shards of shape **`(1024, 1024)`** without `FSDP1` `FlatParameter` concatenation, and TorchTitan's `SimpleFSDP` + `torch.compile` achieved up to **`28%` memory reduction** and **`69%` throughput improvement** over eager `FSDP2`; (b) `PCIe Gen4` `CPUOffload` slows `70B` step time by **`3.96x` (`~4x`, `12.3 s -> 48.7 s`, `18%` GPU util)** because `3 TB/s` `HBM` is **`~93.75x` (`~100x`) faster** than `32 GB/s` `PCIe Gen4`, whereas Grace-Blackwell `SuperOffload` uses `900 GB/s` coherent `NVLink-C2C`, Speculation-Then-Validation (`STV`), and ARM `SVE` `GraceAdam` (`32` vector / `16` predicate registers).
