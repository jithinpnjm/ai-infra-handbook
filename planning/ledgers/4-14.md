## 4. One-Line Expected Exercise Solutions

1. **Exercise 1 (Wall-Clock Performance Model, `forks`, `ControlPersist`, and `pipelining`, `AUR` Ch. 20):** Using `estimate_play_wall_clock_seconds()`, `ControlPersist` drops SSH connection setup from `0.319s` to `0.010s` (`ssh -O check`/`exit`, using `%C` in `control_path` so long EC2 hostnames stay under the 104-byte Unix socket limit), `pipelining = True` cuts SSH trips per task from 3 to 1 (once `!requiretty` is validated via `cat /etc/sudoers /etc/sudoers.d/* %s | visudo -cf-`), and raising `forks` parallelizes waves.
2. **Exercise 2 (Fact Caching, Quadratic $O(N^2)$ Templating, and `delegate_to: localhost` Bottlenecks):** Rendering a per-host template that loops over `groups['all']` across $N$ hosts is $O(N^2)$ on the controller CPU (fixed to $O(N)$ by rendering once with `run_once: true` + `copy`); fact caching (`jsonfile`, `redis`, `memcached`) with `gathering = smart` avoids running `setup` on every play.
3. **Exercise 3 (Execution Strategies `linear` vs. `free` vs. `host_pinned` and Failure-Containment Batching):** Under `linear`, every task wave waits for the slowest straggler host in the batch, whereas `free` (and `host_pinned`) lets fast hosts proceed through independent tasks without waiting (`6.718s` vs `10.718s`); `free` is unsafe when later tasks depend on all hosts having completed an earlier task.
4. **Exercise 4 (Overlapping Long-Running Tasks with `async` and `poll: 0` + `async_status`, `AUR` Ch. 20):** Setting `async: 3600` and `poll: 0` launches a long task (`git clone` or firmware flash) in the background and immediately proceeds to subsequent tasks (`apt` installs), later joining via `async_status: { jid: "{{ job.ansible_job_id }}" }` with `until: res.finished`.
5. **Exercise 5 (Large-Fleet Architectures: Sharded Controllers, AAP Job Slicing & Mesh, and `ansible-pull` Rings):** Scale push mode with sharded inventories, AWX/AAP Job Slicing, and Automation Mesh execution nodes near target racks; scale pull mode with `ansible-pull --only-if-changed --sleep 120` promoting signed commits through canary and stable rings.
6. **Exercise 6 (Callback Plugins `stdout` vs. `notification`, `profile_tasks`, `junit`, `ARA`, and `jsonl_audit.py`, `AUR` Ch. 18):** Only one `stdout_callback` can be active whereas multiple notification plugins (`callbacks_enabled = timer, profile_tasks, junit, jsonl_audit`) run simultaneously; `format_jsonl_audit_event()` strips `msg` whenever `result._task.no_log` is `True`.
