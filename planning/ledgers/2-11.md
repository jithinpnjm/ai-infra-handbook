## 4. One-Line Expected Exercise Solutions

1. **Exercise 1 (The Four Internal Packet-Movement Steps, Three Forwarding Paths, and Crossbar VOQs):** (a) Every switch/router moves packets in 4 steps: (1) media -> memory (`RX ring`, passing buffer pointers to avoid copying), (2) processing (lookup/ACL/NAT/header rewrite), (3) switching across the internal fabric (shared memory, bus, or crossbar with **Virtual Output Queues `VOQ`s** to prevent Head-of-Line blocking), and (4) memory -> media (`TX ring` + QoS output queues); (b) the 3 forwarding paths are **process switching** (punted to CPU software—slow, protected by CoPP), **interrupt-context fast switching** (NAPI softirq / DPDK / XDP), and **ASIC/NPU hardware forwarding** (line-rate TCAM/SRAM pipeline); a `9000`-byte frame takes `72,000 / 10e9 = 7.2 µs` to serialize at `10 Gb/s`.
2. **Exercise 2 (IEEE 802.1Q Tag Anatomy, Access vs. Trunk vs. Native VLAN, and Linux `bridge vlan`):** An `802.1Q` tag adds `4` bytes (`TPID 0x8100` + `3`-bit `PCP` + `1`-bit `DEI` + `12`-bit `VID` `1..4094`, verified via `encode_decode_8021q_tci()`); access ports carry 1 untagged VLAN to hosts, trunk ports carry multiple tagged VLANs between switches/hypervisors, and mismatched **native (untagged) VLANs** on a trunk leak frames across VLANs; on Linux, use `ip link add link eth0 name eth0.100 type vlan id 100` or a VLAN-filtering bridge (`ip link add br0 type bridge vlan_filtering 1` + `bridge vlan add`).
3. **Exercise 3 (Spanning Tree `STP` vs. `RSTP`/`MSTP` and Port Protection Features):** Because Ethernet has no `TTL`, an L2 loop causes an immediate broadcast storm and MAC flapping; STP (`802.1D`) elects the **Root Bridge** with the lowest Bridge ID (`priority + MAC`, default priority `32768`, `elect_stp_root_bridge()`), selects one **Root Port** per non-root switch and one **Designated Port** per segment, and blocks remaining ports (`30–50 s` convergence vs **`~1 s` in RSTP `802.1w`** via proposal/agreement); protect host edge ports with **PortFast + BPDU Guard** (err-disabling any port that receives a BPDU) and **Root Guard**.
4. **Exercise 4 (Why Modern Data Centers and AI Fabrics Avoid Spanning Tree):** STP blocks half of redundant uplinks and suffers disruptive topology-change reconvergence; modern data centers restrict VLANs to a single rack/leaf pair (using **MLAG/vPC** for dual-homed L2 hosts) and route **L3 all the way to the leaf** with **ECMP** (and **EVPN-VXLAN** if L2 must span racks).
5. **Exercise 5 (Control-Plane Topology Discovery, Two-Way Connectivity, and Reactive vs. Proactive Learning, `CN` Chapter 11):** Using `check_two_way_hello_adjacency()`: protocols detect neighbors via explicit multicast **hellos** (`OSPF`, `IS-IS`, `LLDP`) and prove **two-way connectivity** by listing heard neighbor IDs inside each hello (so Router A declares 2-Way only when it sees its own ID in Router B's hello, and verifies matching interface **MTU**); **proactive** control planes (OSPF/IS-IS/BGP) pre-compute all paths before traffic arrives, whereas **reactive** systems (ARP, MAC learning) build state on demand when data packets arrive.
6. **Exercise 6 (`LLDP` Automated Cabling Verification and `BFD` Sub-Second Failure Detection):** Run `lldpd` (`lldpcli show neighbors`) on every GPU server to programmatically verify `(server, NIC) <-> (leaf switch, port)` against the rack wiring plan, and pair routing protocols (`BGP`/`OSPF`) with **BFD (`RFC 5880`, `50–300 ms` probes)** so link failures shift ECMP traffic in milliseconds instead of waiting for multi-second routing hold timers.
