## 4. One-Line Expected Exercise Solutions

1. **Exercise 1:** The H100 is already holding `72,000–72,100 MiB` out of `81,559 MiB` (`88.4%` VRAM) and needs burst headroom for `1-in-20` (`5%`) request overlaps that spike SM to `85%`; admitting a second tenant caused `p99` to jump `4.29x` from `42 ms` to `180 ms`, memory from `48 GB` to `76 GB`, and peak SM from `35%` to `92%`.
2. **Exercise 2:** The 7 states are `Eligible`, `Attached`, `Enumerated`, `DriverReady`, `Entitled`, `ApplicationReady`, and `Drained`; (a) missing profile in `virsh dumpxml` stops at `Eligible` (`Hypervisor` layer), (b) mismatched host `535.161.05` and guest `550.54.14` stops at `Enumerated` (`Guest` matrix violation), and (c) unreachable `NLS` stops at `DriverReady` (`License path`).
3. **Exercise 3:** On the host, `nvidia-smi` and `nvidia-smi vgpu` show physical GPUs and active VMs, `-s` lists supported profiles, and `-c` lists currently creatable profiles; inside the guest, `nvidia-smi` shows only the virtual profile (`NVIDIA GRID A100-20Q`, `45C`, `18W / 400W`, `2000MiB / 20000MiB`), `--query-gpu=gpu_uuid` returns a distinct virtual UUID, and `nvidia-smi -q` reports `vGPU Software Licensed Product`.
4. **Exercise 4:** **Time-Sliced vGPU** gives each VM a dedicated framebuffer allocation while multiplexing SMs and memory paths via the Virtual GPU Manager; **MIG-Backed vGPU** places vGPUs on top of hardware-isolated MIG GPU Instances (`GIs`) with dedicated SMs, L2 cache, and memory controllers, which is chosen when VMs require both a guest-kernel boundary and hardware QoS isolation.
5. **Exercise 5:** Lab 01 lists `0: 1g.10gb` (`7`), `1: 1g.20gb` (`4`), `2: 2g.20gb` (`3`), `3: 3g.40gb` (`2`), `4: 4g.40gb` (`1`), and `5: 7g.80gb` (`1`); `-dci` must precede `-dgi` because active Compute Instances block deleting their parent GPU Instance; and `ClusterPolicy` must be restored before deleting `time-slicing-lab-config` so `nvidia-device-plugin` never references a deleted ConfigMap.
6. **Exercise 6:** `Discovery` maps to short-term measurement pools (no SLO), `Best effort` maps to `Time-Slicing` / `MPS` for trusted dev notebooks, `Bounded service` maps to validated `MIG` or `vGPU` profiles with admission caps, and `Reserved` maps to dedicated `Whole GPU` or protected `MIG`/`vGPU` pools with failover reserve across the `6` intake fields (`Workload class`, `Memory envelope`, `Performance objective`, `Tenant trust`, `Recovery behavior`, `Placement scope`).
