## 4. One-Line Expected Exercise Solutions

1. **Exercise 1 (NumPy Memory Layout, Views vs. Copies, Broadcasting, and BLAS Thread Oversubscription):** Using `compute_ndarray_strides()` and `broadcast_shapes()`, a `(3, 4)` `float32` array has C-contiguous strides `(16, 4)` while `a.T` is a zero-copy view with strides `(4, 16)`; right-aligned broadcasting stretches `(1000, 1) + (1, 64)` to `(1000, 64)` (whereas `(N,) + (N, 1)` accidentally produces `(N, N)`); and setting `OMP_NUM_THREADS=1` prevents `num_workers x BLAS threads` CPU oversubscription.
2. **Exercise 2 (Tabular Data at Scale: `pandas` Memory Diet, Row-Major CSV vs. Columnar Parquet/Arrow, and Data Leakage, `DMLS` Ch. 3):** Narrow dtypes (`int8`, `float32`, `category`, `string[pyarrow]`) and `usecols` reduce DataFrame memory 2x–5x; `compare_row_vs_columnar_io()` shows reading 3 of 50 columns across 1M rows scans 400 MB in row-major CSV versus 6 MB in 4x-compressed Parquet (`66.67x` reduction); and splitting time-series data by timestamp cutoff before fitting scalers/windows prevents look-ahead leakage.
3. **Exercise 3 (PyTorch Tensors, Asynchronous CUDA Execution, Pinned Memory, and Autograd Leaks):** CUDA kernel launches are asynchronous (requiring `torch.cuda.synchronize()` for accurate timing and avoiding per-step `loss.item()` stalls); `pin_memory=True` + `to(dev, non_blocking=True)` enables asynchronous DMA over PCIe; and appending `loss.item()` instead of `loss` avoids retaining the entire forward autograd graph across steps.
4. **Exercise 4 (Training & Inference Memory Accounting `16 B/param`, Caching Allocator, and AMP `bf16` vs. `fp16`, `AIE` Ch. 2, 7, 9):** Using `estimate_adam_mixed_precision_memory_gb(7.0)`, a 7B model requires `14 GB` (`bf16` weights) + `14 GB` (`bf16` grads) + `84 GB` (`fp32` master weights, momentum $m$, and variance $v$) = `112 GB` static memory before activations; `memory_reserved()` includes cached blocks in PyTorch's allocator (`expandable_segments:True`); and `bfloat16` shares `float32`'s 8-bit exponent range so it does not need `GradScaler`.
5. **Exercise 5 (DataLoader Starvation Diagnosis, `/dev/shm` Bus Errors, and Fork Copy-on-Access):** Using `diagnose_dataloader_vs_gpu_bottleneck()`, a 20 ms per-sample decode at `batch_size=64` takes `1280 ms` at `num_workers=0` (`7.8%` GPU util on a 100 ms step) versus `80 ms` at `num_workers=16` (`100%` GPU util); containers need `--shm-size` / memory `emptyDir` on `/dev/shm` to avoid `SIGBUS`; and Dataset metadata should use NumPy/Arrow arrays rather than Python lists to avoid reference-count copy-on-write page faults across forked workers.
6. **Exercise 6 (Atomic Checkpointing, `weights_only=True` vs. `safetensors`, Reproducibility, and `torch.profiler`):** Checkpoints must be written to a temp file and atomically renamed (`os.replace`) and loaded with `weights_only=True` or `safetensors` (`mmap`) to prevent `pickle` code execution; `seed_everything(1234)`, `use_deterministic_algorithms(True)`, `cudnn.benchmark = False`, and `CUBLAS_WORKSPACE_CONFIG=:4096:8` enforce determinism; and `torch.profiler` (`schedule(wait=1, warmup=1, active=3)`) reveals DataLoader gaps, launch overhead, and NCCL stragglers.
