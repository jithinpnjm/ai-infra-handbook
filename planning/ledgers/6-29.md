## 4. One-Line Expected Exercise Solutions

1. **Exercise 1 (Linting Apptainer Definition Files and Dockerfiles for Reproducibility):** `container_lint.py` rejects `From: ubuntu:latest` and `curl ... | sh` as `ERROR`s, warns on `apt-get upgrade` (build-date drift) and unpinned `pip`/`git`/`curl` steps, and uses word-boundary `\b(ba)?sh\b` so `| sha256sum -c -` passes cleanly.
2. **Exercise 2 (Writing a Digest-Pinned Apptainer Definition File):** Pin `From: nvcr.io/nvidia/pytorch@sha256:...`, install from `requirements.lock` with `--no-cache-dir --require-hashes`, record provenance in `%labels`, validate in `%test`, build unprivileged with `apptainer build --fakeroot`, and sign/verify with `apptainer sign` / `verify`.
3. **Exercise 3 (Comparing the Hybrid MPI Model and Bind MPI Model in Apptainer):** In the hybrid model, the container ships its own PMIx-compatible MPI talking to host `slurmstepd` (`srun --mpi=pmix apptainer exec --nv --cleanenv ...`); in the bind model, host MPI libraries are bind-mounted into an MPI-less container.
4. **Exercise 4 (Diagnosing `--nv` `glibc` Mismatches and Host Environment Leakage):** `--nv` bind-mounts host `libcuda.so` linked against the host's newer `glibc`, breaking containers with a much older `glibc`; `$HOME` bind-mounting leaks `~/.local` Python packages unless `--no-home`, `--containall`, or `PYTHONNOUSERSITE=1` is set.
5. **Exercise 5 (Configuring Apptainer and Enroot Cache Paths):** Export `APPTAINER_CACHEDIR=/tmp/$USER/apptainer` and `APPTAINER_TMPDIR=/tmp/$USER/tmp` on node-local NVMe to avoid NFS `$HOME` quota exhaustion (`sudo -E` preserves them across root builds).
6. **Exercise 6 (Runtime Comparison Matrix):** Apptainer uses signable `.sif` files (`srun apptainer exec --nv`), Charliecloud uses `.sqsh`/dir trees (`ch-run`), Enroot + Pyxis uses `.sqsh` unpacked to `ENROOT_DATA_PATH` via Slurm SPANK `--container-image`, and rootless Podman uses layered OCI stores.
