## 5. One-Line Expected Exercise Solutions

1. **Exercise 1 (`libcuda.so` vs `libcudart.so`):** `libcuda.so.1` is the User-Mode Driver owned by the host NVIDIA driver package (`/usr/lib/x86_64-linux-gnu/`), whereas `libcudart.so.12` is the CUDA Runtime library owned by the container's CUDA Toolkit (`/usr/local/cuda-12.4/lib64/`); the NVIDIA Container Toolkit / CDI layer failed to bind-mount `libcuda.so.1` from the host into the container.
2. **Exercise 2 (`no kernel image is available`):** Run `cuobjdump --list-elf ./binary | grep -i sm_` (shows only `sm_80`/`sm_86`) and `cuobjdump --list-ptx ./binary` (empty); rebuild with `nvcc -gencode arch=compute_80,code=sm_80 -gencode arch=compute_86,code=sm_86 -gencode arch=compute_90,code=sm_90 -gencode arch=compute_90,code=compute_90`.
3. **Exercise 3 (PTX JIT slowdown & RAM storm):** (a) `2,340.6 ms / 12.8 ms = 182.86x` (`~190x`) slower on Request 1; (b) `10 pods * 5 GB/pod = 50.0 GB` of host CPU RAM consumed simultaneously by `libnvidia-ptxjitcompiler.so`.
4. **Exercise 4 (Driver compatibility matrix):** (a) Succeeds via driver backward compatibility (`535.154.05 >= 450` for CUDA 11.4); (b) Fails (`HOST_DRIVER_TOO_OLD`, `450 < 525` required for CUDA 12.2 without forward-compat); (c) Succeeds via `CUDA_FORWARD_COMPATIBILITY` (`/usr/local/cuda/compat` supplies `libcuda.so.535.104.05` on `LD_LIBRARY_PATH`).
5. **Exercise 5 (`NVRM: API mismatch` & `rmmod`):** Run `sudo lsof /dev/nvidia*` to kill processes holding device files open, then unload dependent modules in order (`sudo rmmod nvidia_drm nvidia_modeset nvidia_uvm nvidia_peermem` followed by `sudo rmmod nvidia`) or reboot the drained node.
6. **Exercise 6 (Character device audit):** `/dev/nvidia-uvm` and kernel module `nvidia-uvm.ko` (`nvidia_uvm`) are missing; if `nvidia-peermem.ko` is also absent, intra-node NVLink works but inter-node GPUDirect RDMA over InfiniBand/RoCE silently falls back to host CPU RAM staging.

## 6. Self-Assessment (What I Am Least Sure About)

1. **Dynamic major number for `/dev/nvidia-uvm`:** `V3 Lab 01` shows major `234` while `VL4 Ch 2` shows major `238`; because `nvidia-uvm` registers a dynamic character device major via `alloc_chrdev_region`, both values occur in production and both are noted in the chapter.
2. **Early-2025 Python libraries (`cuTile` and `cuPyNumeric`):** Taken directly from *AI Systems Performance Engineering* Chapter 3 (pp. 60–61); APIs in these newer Python packages evolve rapidly across minor releases.
3. **CUDA Forward Compatibility branch matrix:** While `/usr/local/cuda/compat` bridges newer CUDA toolkits onto older enterprise driver branches, exact supported cross-branch pairs depend on NVIDIA's per-release compatibility table.
