## 4. One-Line Expected Exercise Solutions

1. **Exercise 1 (Fast Block-Size Subnetting `/27`, `/21`, `/18`, and Same-Subnet Membership):** (a) `192.168.10.77/27` (`255.255.255.224`, block `32`) has network `192.168.10.64`, broadcast `192.168.10.95`, usable range `.65–.94` (`30` hosts), and wildcard `0.0.0.31`; (b) `172.20.133.9/21` (`255.255.248.0`, 3rd-octet block `8`) has network `172.20.128.0`, broadcast `172.20.135.255`, and `2,046` usable hosts; (c) `10.20.37.130` is inside `10.20.36.0/22` (`10.20.36.0–10.20.39.255`), whereas `10.20.40.5` is in the next `/22` block (`10.20.40.0/22`).
2. **Exercise 2 (VLSM Allocation and Route Summarization / Alignment):** (a) Allocating `[400, 200, 100, 50, 2, 2]` hosts from `10.50.0.0/22` largest-first yields `10.50.0.0/23`, `10.50.2.0/24`, `10.50.3.0/25`, `10.50.3.128/26`, `10.50.3.192/31`, and `10.50.3.194/31` (`allocate_vlsm_subnets()`); (b) `172.16.8.0/24` through `172.16.15.0/24` (8 contiguous `/24`s aligned on a multiple of 8) summarize cleanly to `172.16.8.0/21`, whereas `192.168.5.0/24 + 192.168.6.0/24` cannot be summarized to a `/23` because `5` is odd (not aligned on a multiple of 2).
3. **Exercise 3 (Special-Purpose IPv4 Ranges and Avoiding Enterprise/Cloud Overlaps):** `10/8`, `172.16/12`, and `192.168/16` are RFC 1918 private space; `100.64.0.0/10` is RFC 6598 CGNAT shared space (often used for Kubernetes Pod CIDRs when RFC 1918 is exhausted); `127.0.0.0/8` is loopback (`127.0.0.53` `systemd-resolved`); and `169.254.0.0/16` is link-local APIPA (`169.254.169.254` cloud metadata server).
4. **Exercise 4 (IPv6 Notation, Prefix Types, `/64` Convention, and EUI-64):** Compress `2001:0db8:0000:0000:0000:ff00:0042:8329` to `2001:db8::ff00:42:8329`; `2000::/3` is global unicast, `fd00::/8` (`fc00::/7`) is Unique Local (`ULA`), `fe80::/10` is link-local, and `ff00::/8` is multicast; a `/48` site prefix provides `65,536` `/64` subnets (`16` subnet bits), and MAC `00:1a:2b:3c:4d:5e` forms EUI-64 link-local `fe80::21a:2bff:fe3c:4d5e`.
5. **Exercise 5 (IPv4 vs. IPv6 Header Fields, Fragmentation, and Path MTU Discovery):** IPv4 has a variable `20–60` B header with a per-hop recomputed header checksum and in-network router fragmentation fields (`ID`, `DF`/`MF`, `Fragment Offset`), whereas IPv6 has a fixed `40` B header with no header checksum, a `20`-bit `Flow Label` for ECMP hashing, and **source-only** fragmentation via an extension header; `ping -M do -s 1472` (`1472 + 8 + 20 = 1500` IPv4) and `ping -6 -M do -s 1452` (`1452 + 8 + 40 = 1500` IPv6) test Path MTU Discovery (`ICMP 3/4` / `ICMPv6 Type 2`).
6. **Exercise 6 (Designing a Non-Overlapping Address Plan for a 1,024-GPU Cluster and Kubernetes):** Separate OOB (`10.10.0.0/20`), in-band management (`10.20.0.0/20`), storage (`10.30.0.0/20`), per-rail compute fabrics (`10.100.<rail>.0/21` so IP encodes `<rail>.<node>`), BGP loopbacks (`10.255.0.0/24` `/32`s), and leaf-spine `/31` links (`10.250.0.0/16`); for Kubernetes with `maxPods=110` (`/24` = `256` IPs per node), `500` nodes require at least `500 * 256 = 128,000` IPs (`size_kubernetes_pod_cidr()` -> `/15` = `131,072` IPs, or `/14` = `262,144` IPs for `1,024` nodes).
