## 4. One-Line Expected Exercise Solutions

1. **Exercise 1 (Where Secrets Leak in Terraform and the 7-Tier Mitigation Hierarchy, `TUR` Ch. 6):** Secrets leak in `terraform.tfstate`, saved `tfplan` files, CLI `-var` args, `.tfvars` files, `outputs`/`terraform_remote_state`, provisioners, and `TF_LOG=DEBUG`; `classify_secret_state_exposure()` shows `sensitive = true` and secret-manager `data` sources still write plaintext to state when passed to normal attributes, whereas workload identity, `manage_master_user_password = true`, empty secret containers, and `ephemeral` + write-only (`password_wo`) attributes keep secrets out of state.
2. **Exercise 2 (Authenticating Providers Without Static Keys: `aws-vault`, EC2 `IMDS`, and GitHub Actions OIDC, `TUR` Ch. 6):** Humans use `aws-vault` to store keys in OS Keychain and inject short-lived STS env vars; EC2/GKE runners use IAM Instance Profiles (`169.254.169.254` IMDS) / Workload Identity; and `verify_github_oidc_assume_role()` checks `sts:AssumeRoleWithWebIdentity` conditioned on `token.actions.githubusercontent.com:sub == "repo:<ORG>/<REPO>:ref:refs/heads/main"`.
3. **Exercise 3 (Multi-Region Provider Aliases, Regional `data "aws_ami"`, and RDS Primary + Read Replica, `TUR` Ch. 7):** Define `provider "aws" { alias = "usw2"; region = "us-west-2" }`, query `data "aws_ami"` per region (`provider = aws.usw2`) because AMI IDs are regional, and pass `replicate_source_db = module.mysql_primary.arn` with `providers = { aws = aws.region_2 }` for cross-region read replicas.
4. **Exercise 4 (Multi-Account Isolation `assume_role` and `configuration_aliases`, `TUR` Ch. 7):** Using `validate_child_module_provider_wiring()`, child modules declare `configuration_aliases = [aws.parent, aws.child]` in `versions.tf` without internal `provider` blocks, while the root module defines aliased `assume_role` providers and passes `providers = { aws.parent = aws.mgmt, aws.child = aws.prod }`.
5. **Exercise 5 (The \"Provider Depends on Resource\" Problem: Cluster + `kubernetes`/`helm` Providers, `TUR` Ch. 7):** Because providers initialize before resources are planned, split cluster creation (Layer 1) and `kubernetes`/`helm` add-ons (Layer 2) into separate states and use an `exec` credential plugin (`gke-gcloud-auth-plugin` / `aws eks get-token`) so short-lived cluster tokens are not written into `terraform.tfstate`.
6. **Exercise 6 (Provider Locking, Air-Gapped Mirrors `provider_installation`, and Supply-Chain Security):** Run `terraform providers lock -platform=linux_amd64 -platform=darwin_arm64` to record multi-OS SHA-256 hashes in `.terraform.lock.hcl`, configure `filesystem_mirror` / `network_mirror` in `~/.terraformrc` with `direct { exclude }`, and enforce Conftest Rego rules blocking `aws_iam_access_key` and `google_service_account_key` creation.
