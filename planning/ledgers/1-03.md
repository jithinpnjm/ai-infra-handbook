## 4. One-Line Expected Exercise Solutions

1. **Exercise 1 (FHS Directory Placement):** (a) `/etc`, (b) `/usr/include`, (c) `/usr/local` (`/usr/local/bin`, `/usr/local/cuda`), (d) `/usr/share`, (e) `/lib/modules/<kernel-version>/`, (f) `/run`.
2. **Exercise 2 (Directory Link Count `2 + N`):** `ls -ld /data/Checkpoints` displays a link count of **`7`** (`2` for the directory's own entry in `/data` plus `.`, and `+5` from the `..` entries inside each of the `5` subdirectories; the `20` regular `.pt` files do not contain `..` entries pointing back to the directory).
3. **Exercise 3 (Hard Links, `EXDEV`, and VFAT):** (a) `ln a.txt b.txt` increments `inode 7401`'s `link_count` from `1` to `2` and updates `ctime` while leaving `mtime` unchanged, and `rm a.txt` decrements `link_count` back to `1` without freeing any of the `200 MiB` data blocks; (b) `ln a.txt /dev/shm/c.txt` fails with `EXDEV` because inode numbers are local to a single filesystem (`device 2049 != 2050`), and `ln` fails on `vfat` because VFAT embeds file metadata inside directory entries without a Unix inode table.
4. **Exercise 4 (Deleted-but-Open Files `lsof +L1`):** Immediately after `rm /tmp/big`, `link_count` is `0` and `open_fd_count` is `1`; the `200 MiB` data blocks are **not** freed until the process closes the descriptor or exits, and `sudo lsof +L1` locates the unlinked open file.
5. **Exercise 5 (Timestamps):** (a) Appending bytes updates both `mtime` and `ctime`; (b) `chmod 600` updates only `ctime`, leaving `mtime` unchanged.
6. **Exercise 6 (Atomic Symlink Swap & `ENOSPC`):** (a) `ln -sfn checkpoints/step_001000 latest.tmp && mv -T latest.tmp latest`; (b) `touch /mnt/t/f201` fails with `ENOSPC` because all `200` inodes (`nr_inodes=200`) are exhausted (`df -i` shows `100%` `IUse%` even though `df -h` shows `10 MiB` of free data blocks).
