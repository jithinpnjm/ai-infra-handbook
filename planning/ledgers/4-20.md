## 4. One-Line Expected Exercise Solutions

1. **Exercise 1 (Root vs. Child Modules, Interface Design, and the Two Module Gotchas, `TUR` Ch. 4):** `variables.tf` defines overridable public inputs, `locals.tf` defines internal constants, and `outputs.tf` exposes attributes via `module.<NAME>.<OUTPUT>`; child modules must prefix internal file paths with `${path.module}/...` and use standalone `aws_security_group_rule` (`aws_route`) resources rather than inline `ingress {}` blocks (`detect_inline_vs_separate_sg_conflict()`).
2. **Exercise 2 (Provider Inheritance, `configuration_aliases`, and No `provider` Blocks in Child Modules):** Defining `provider` blocks inside child modules breaks `count`, `for_each`, and module removal; child modules declare `required_providers` (and `configuration_aliases`) in `versions.tf` while the root module passes `providers = { google = google.eu }`.
3. **Exercise 3 (Module Composition Patterns: Dependency Inversion, Data-Driven `yamldecode` + `for_each`, and Facade Modules):** Passing `subnet_id = module.network.subnet_ids["compute"]` into `module.gpu_pool` decouples the child module from network lookup logic, and `for_each = yamldecode(file("gpu-pools.yaml"))` turns adding/resizing GPU pools into a declarative YAML data change.
4. **Exercise 4 (Module Sources `//`, Semantic Versioning `?ref=v2.3.1`, and `moved` Blocks, `TUR` Ch. 4):** Using `parse_git_module_source()`, `//` selects a subdirectory inside a Git repo and `?ref=<tag>` pins an immutable version so `stage` can test `v0.0.2` while `prod` stays on `v0.0.1`; embedding `moved {}` blocks inside a module preserves consumer state across internal resource renames.
5. **Exercise 5 (Testing Terraform Modules: `terraform test` `.tftest.hcl` and `Terratest`):** `tests/validation.tftest.hcl` runs fast plan-mode unit tests (`command = plan`) with `assert` and `expect_failures = [var.gpu_count]` (modeled in `validate_gke_gpu_pool_inputs()`), while `Terratest` runs apply-and-destroy integration tests in an ephemeral sandbox.
6. **Exercise 6 (Auditing Module Anti-Patterns):** Avoid 150-variable God modules, zero-value pass-through wrappers, and hardcoded `if var.env == "prod"` branches; build focused modules like `checkpoint-bucket` that bake in encryption, versioning, `public_access_prevention = "enforced"`, and `prevent_destroy = true`.
