## 4. One-Line Expected Exercise Solutions

1. **Exercise 1 (Checkpoint Bandwidth and Stall-Overhead Arithmetic):** At `14` bytes/parameter, a `70B` checkpoint is `0.98 TB` (`16 GB/s` for 60s; `98s` = `2.7%` hourly stall at `10 GB/s`) and a `405B` checkpoint is `5.67 TB` (`94 GB/s` for 60s; `567s` = `15.8%` hourly stall at `10 GB/s`).
2. **Exercise 2 (Characterizing Metadata vs Data Paths with `iomix.py`):** `iomix.py` shows that cached reads (`11,562 MB/s`) reflect RAM rather than disk (`633 MB/s` `fsync`'d write) and that file `create` (`4,585/s`) is $\sim 80\times$ slower than cached `stat` (`378,127/s`); defeat page caching with `O_DIRECT`, cache drops, or files larger than RAM.
3. **Exercise 3 (Configuring an HPC NFS Server and Client Mounts):** Export `/home` with `rw,sync,no_subtree_check,root_squash`, apply with `exportfs -ra`, verify with `showmount -e/-d/-a`, and mount on clients with `vers=4.2,hard,noatime,nodiratime,rsize=1048576,wsize=1048576,nconnect=8`.
4. **Exercise 4 (Hardening Cluster Time Synchronization):** Configure `/etc/ntpd.conf` with `restrict default kod nomodify notrap nopeer noquery`, step-sync large boot offsets via `ntpdate` or `chrony` `iburst`/`makestep` before mounting parallel filesystems, and inspect `systemd-timesyncd` with `timedatectl show-timesync --all`.
5. **Exercise 5 (Dataset Streaming Bandwidth — Text vs Vision):** Pre-tokenized LLM text for `4,096` GPUs requires only `49 MB/s`, whereas `500` nodes streaming `2,000` `150 KB` images/s requires `150 GB/s`; packing small images into WebDataset `.tar` shards eliminates metadata bottlenecks.
6. **Exercise 6 (Designing a 4-Tier Storage Architecture for a 2,048-GPU AI Cluster):** Use HA NFS/NAS for `/home` and `/opt` (with `.sqsh` containers), an RDMA parallel filesystem (Lustre/GPFS/WEKA/VAST) for `/scratch` and active datasets, node-local NVMe for `ENROOT_DATA_PATH` and async checkpoint staging, and S3 object storage for cold archives.
