## 4. One-Line Expected Exercise Solutions

1. **Exercise 1 (Warp sector & cache-line math):** (a) `stride = 1` aligned (`offset 0`) touches `1` cache line (`128 B`) and `4.0` sectors (`100.0%` efficiency); (b) `stride = 1` misaligned (`offset +4 B`) touches `2` cache lines and `5.0` sectors (`128 / 160 = 80.0%` efficiency); (c) `stride = 2` touches `2` cache lines and `8.0` sectors (`128 / 256 = 50.0%` theoretical / `23%` measured in Table 7-1); (d) `stride = 8` touches `8` cache lines and `32.0` sectors (`128 / 1,024 = 12.5%` efficiency).
2. **Exercise 2 (`float4` vs `float8` vectorized loads):** (a) `float4` (`16 B`/thread, `ld.global.v4.f32`) moves `512 B`/warp = `4 × 128 B` lines = `16` sectors (`4.0` sectors/line, `4x` fewer load instructions), while Blackwell `alignas(32) float8` (`32 B`/thread, `ld.global.v8.f32`) moves `1,024 B`/warp = `8 × 128 B` lines = `32` sectors (`8x` fewer load instructions); (b) `d_ptr + 25` is offset by `25 × 4 = 100` bytes (`100 % 16 = 4 != 0`), breaking 16-byte alignment and forfeiting vectorization.
3. **Exercise 3 (`32 × 32` vs `64 × 64` tiling & register budget):** (a) `32 × 32` tiling cuts global load sectors `9,800 → 1,200` (`~8.17x`), lifts arithmetic intensity `1.5 → 8.0 FLOPs/B`, and boosts throughput `15 → 170 GFLOPS` (`~11.3x`); (b) a `64 × 64` tile uses `16,384 B` (`16 KB`) per matrix (`32 KB` for `sA + sB`), and on a `1,024`-thread block uses `12 × 1,024 = 12,288` regs/block (`5` blocks by regs, capped at `2` blocks = `2,048` threads by SM thread limit) or `22 × 1,024 = 22,528` regs/block (`2` blocks = `45,056 <= 65,536` regs).
4. **Exercise 4 (Bank conflict modulo proof):** With `row_stride = 32` (`tile[32][32]`), Lane `i` reading column `0` hits bank `(i * 32 + 0) % 32 == 0` for all `i in 0..31` (`32`-way conflict on `Bank 0`); with `row_stride = 33` (`tile[32][33]`), Lane `i` hits bank `(i * 33 + 0) % 32 == i % 32 == i`, mapping all 32 lanes to 32 distinct banks (`0` conflicts) with `1 / 32 = 3.125%` (`~3%`) memory overhead.
5. **Exercise 5 (`__shfl_down_sync` trace):** Across the 5 steps (`offset = 16, 8, 4, 2, 1`), Lane `0` accumulates the sum of all 32 lanes (`1 + 2 + ... + 32 = 528.0`) directly in registers (`0` SMEM, `0` bank conflicts); it cannot reduce across two warps because shuffle hardware only connects the 32 lanes inside a single warp.
6. **Exercise 6 (`const __restrict__` & `TMA` pipeline):** `const __restrict__` cuts runtime `2.5 → 1.0 ms` (`2.5x`, DRAM `600 → 200 GB/s`, Table 7-6) and `TMA` cuts runtime `18 → 7 ms` (`~2.6x`, Load Eff `23% → 99%`, Table 7-7) using the 4-step loop `pipe.consumer_wait(); processTile(tiles[(t-1)&1]); pipe.consumer_release(); pipe.producer_acquire(); cuda::memcpy_async(tiles[t&1], ..., pipe); pipe.producer_commit();`.

## 5. Self-Assessment (What I Am Least Sure About)

1. **Theoretical vs measured `stride = 2` Load Efficiency (`50%` vs `23%` in Table 7-1):** Purely from sector geometry, a 128-byte warp load spread across `8` sectors (`256 B`) has `128 / 256 = 50%` byte utilization; in *ASP* Ch 7 Table 7-1 (p. 220), Nsight Compute reports `23%` Global Memory Load Efficiency due to boundary straddling and cache effects. Both numbers are explained in Section 1.
2. **Illustrative benchmark note in *ASP* Ch 7:** As noted on p. 220 of *AI Systems Performance Engineering*, the numeric values in Tables 7-1 through 7-7 are illustrative profiles from the book's benchmark suite to demonstrate relative improvements (`3.7x`, `3.5x`, `11x`, `3x`, `2.5x`, `2.6x`).
3. **Blackwell 32-byte vector load (`ld.global.v8.f32`) compiler requirements:** Requires `sm_100` (Blackwell) and CUDA 13+ with provable 32-byte alignment (`alignas(32)`); on Hopper (`sm_90`), `nvcc` splits a 32-byte struct into two `16-byte` `ld.global.v4.f32` instructions (*ASP* Ch 7 pp. 223–226).
