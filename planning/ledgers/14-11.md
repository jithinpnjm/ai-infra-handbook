## 4. One-Line Expected Exercise Solutions

1. **Exercise 1:** (a) At `16 bytes/param`, the `70B` checkpoint is **`1,120.0 GB` (`~1.09 TB`)** total and **`8.75 GB` per GPU** across `128` GPUs; omitting `2 B` BF16 gradients (`14 bytes/param`) yields **`980.0 GB`** total, **`15.3125 GB` (`~15 GB`) per GPU** across `64` GPUs, and **`122.5 GB` (`~122 GB`) per 8-GPU node**; (b) naive rank-0 gather takes `44.8 s` (`1,120 / 25`) + `224.0 s` (`1,120 / 5`) = **`268.8 seconds` (`~269 s` / `4.5 minutes`)**, whereas parallel sharded writes (`640 GB/s` demand capped at `400 GB/s` Lustre ceiling = `3.125 GB/s` per GPU) complete in **`2.80 seconds` (`8.75 / 3.125`)**, a **`96.0x` speedup**.
2. **Exercise 2:** (a) At `99.9%` (`0.999`) daily GPU reliability across `100,000` GPUs, the 24-hour survival probability is **`0.999^100,000 ≈ 3.7 * 10^-44`**, with **`100.0` expected failures/day** and a fleet MTBF of **`14.4 minutes` (`864 seconds`)**; (b) Daly's formula `T_opt = sqrt(2 * M * T_c) - T_c` yields **`3,040 seconds` (`~50.7 minutes`)** for `M = 28,800 s, T_c = 180 s` (`sqrt(10,368,000) - 180 ≈ 3,220 - 180`) and **`2,980 seconds` (`~49.7 minutes`)** for `M = 21,600 s, T_c = 240 s` (`3,220 - 240`), which engineers round down to **`30–40 minutes`** because real hardware failures cluster rather than arriving as an idealized Poisson process.
3. **Exercise 3:** (a) Copying `100.0 GB` to host RAM at `55.0 GB/s` blocks GPUs for **`1.82 seconds` (`< 2 s`)** while flushing to storage at `5.0 GB/s` takes **`20.0 seconds`** in background CPU threads, reducing GPU pause time by **`12.0x`** (`21.82 s / 1.82 s`); (b) overlapping `2` in-flight `100.0 GB` buffers (`200.0 GB`) exceeds the **`132.0 GB`** of free host RAM (`512 - 380 GB`) and triggers the Linux OOM killer (**`[Node 3] dmesg: Out of memory: Killed process 1234 (python)`**), which is prevented by awaiting the prior save handle (`future.wait()`) or provisioning a **`100 GB` swap file** (`sudo fallocate -l 100G /swapfile && sudo chmod 600 /swapfile && sudo mkswap /swapfile && sudo swapon /swapfile`).
4. **Exercise 4:** (a) A naive topology-coupled loader fails on a `64 -> 48` GPU resize with **`RuntimeError: Number of shards in checkpoint (64) does not match world size (48)`**, whereas PyTorch DCP (`FileSystemReader`) dynamically reshards the `1,120.0 GB` payload from **`64 x 17.50 GB` shards to `48 x 23.3333 GB` shards**; (b) omitting `optimizer_state_dict` causes an immediate **epoch-4 loss spike** (`1.9500` vs `0.9800` control), omitting `rng_state` causes **silent trajectory divergence** (`1.0125` vs `0.9800` control), and omitting `dist.barrier()` / `.tmp` atomic rename risks **corrupted truncated files (`size mismatch`)** if killed mid-write.
5. **Exercise 5:** (a) Launch with `torchrun --nnodes=2:4 --nproc_per_node=8 --max_restarts=3 --rdzv_id=job_1411 --rdzv_backend=c10d --rdzv_endpoint=$MASTER_ADDR:29400 train.py`; when shrinking from `32` GPUs (`3` accum steps) to `24` GPUs (`micro_batch = 2`), increase `gradient_accumulation_steps` to **`4`** (`24 * 2 * 4 = 192`), and under the square-root rule (`base_lr = 1e-4` at batch `32`), scaling to `64 * 128 = 8,192` scales LR by **`16.0x` (`sqrt(256)`) to `1.6e-3`**; (b) crashing at step `5,243` with a `500`-step checkpoint interval loads **step `5,000`**, resumes at **step `5,001`**, and loses **`243` steps**, while a `2.0 s` heartbeat detector (`4` missed = **`8.0 s`**) detects dead ranks **`225.0x` faster** than the `1,800.0 s` (`30-minute`) default NCCL timeout.
