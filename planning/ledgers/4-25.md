## 4. One-Line Expected Exercise Solutions

1. **Exercise 1 (The 5-Layer Kubernetes Platform Stack and Single-Owner Boundary):** Terraform owns Layers 1–3 (Cloud Foundation, Cluster/Node Pools, Platform Operator/GitOps Bootstrap) while GitOps (Argo CD / Flux) owns Layer 5 (Workloads); `check_cluster_and_ownership_safety()` flags any resource managed simultaneously by both Terraform and Argo CD (`selfHeal` tug-of-war).
2. **Exercise 2 (Configuring `kubernetes`, `helm`, and `kubectl` Providers and Preventing Wrong-Cluster Disasters):** Separate cluster creation (Layer 2) from `kubernetes`/`helm` provider configuration (Layer 3), use `exec` auth plugins so short-lived tokens are not stored in state, never leave `host` empty (which falls back to `~/.kube/config`), and assert `kube-system` Namespace `uid` in a `check`/`precondition`.
3. **Exercise 3 (Installing the NVIDIA GPU Operator and Platform Add-Ons with `helm_release`):** Label the `gpu-operator` namespace `pod-security.kubernetes.io/enforce = "privileged"`, set `atomic = true`, `wait = true`, `cleanup_on_fail = true`, pass typed `yamlencode({...})` values (`driver.enabled = false` when pre-installed on host images), and manage CRD upgrades explicitly since Helm ignores `crds/` on upgrade.
4. **Exercise 4 (Solving the CRD Plan-Time Schema Problem):** `evaluate_crd_manifest_plan()` shows `kubernetes_manifest` queries the API server OpenAPI schema during `terraform plan` (failing if the CRD is installed in the same apply), which is solved by two-stack layering, `kubectl_manifest` (`alekc/kubectl`) with `depends_on`, pre-installing CRDs, or delegating CRs to GitOps.
5. **Exercise 5 (Data-Driven Multi-Tenant GPU Quotas, RBAC, and Default-Deny NetworkPolicies):** `generate_team_tenancy_objects()` flattens `var.teams` into per-namespace `kubernetes_namespace` (`baseline` PSA), `kubernetes_resource_quota` (`requests.nvidia.com/gpu`), `kubernetes_role_binding` (`edit`), and `kubernetes_network_policy` (`default-deny-ingress`) resources.
6. **Exercise 6 (Bootstrapping GitOps, Teardown Ordering, and OpenTofu Features):** Install `helm_release.argocd` and a single root `Application` (`App-of-Apps`) to hand off cluster management to Git; destroy in-cluster `LoadBalancer` Services and `PersistentVolumeClaim`s before destroying the cluster so cloud LBs/disks are not orphaned; and leverage OpenTofu for client-side state encryption, dynamic provider `for_each`, and early variable evaluation.
