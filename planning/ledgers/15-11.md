## 4. One-Line Expected Exercise Solutions

1. **Exercise 1:** (a) At `B = 1, H_kv = 8, S_kv = 4,096` on a `132`-SM H100, standard `FlashAttention-2` launches **`8` CTAs (`6.06%` single-wave SM occupancy)** whereas `FlashDecoding` with `C_split = 256` (`16` splits) launches **`128` CTAs (`96.97%` SM occupancy, up to `8x` speedup)**, and `XQA` packs **`8` query heads per KV head tile** (`64 / 8`); (b) with `45` active decode streams and `MaxTokensPerIter = 2,048`, available prefill budget is **`2,003` tokens/step** (`7` steps for `12,288` tokens, cutting `p99` ITL from `340 ms` to `21.4 ms`), whereas setting `max_num_batched_tokens = 512` (`8 ms` chunk + `2 ms` decode) triggers **`450` scheduler context switches/sec** and under-fills Tensor Core tiles, degrading `p99` ITL from `28 ms` to `45 ms` and `TTFT` from `180 ms` to `320 ms`.
2. **Exercise 2:** (a) A `70B` MHA model (`L=80, H=32, D_head=128`) uses **`1,310,720` bytes (`1.31 MB/token`) and `327.68 GB` (`~328 GB`) at `250,000` tokens in FP16** (`163.84 GB` in FP8), whereas Llama-3-70B GQA (`H_kv=8`) uses **`327,680` B (`320 KiB/tok`) in FP16 (`1.25 GiB` at `4K`, `39.06 GiB` at `128K` vs `312.5 GiB` MHA), `163,840` B (`160 KiB/tok`, `0.625 GiB` at `4K`) in FP8, and `81,920` B (`80 KiB/tok`) in INT4**; (b) for a `129`-token sequence, reducing `tokens_per_block` from `128` to `32` cuts internal fragmentation from **`49.61%` (`127/256`) to `19.38%` (`31/160`)**, HQQ `INT4` with `residual_length = 128` in BF16 at `S = 4,096` achieves a **`3.66x` compression ratio**, and `StreamingLLM` (`4` sinks + `4,092` window = `4,096` active tokens) reduces a `128,000`-token KV cache by **`31.25x`**.
3. **Exercise 3:** (a) An `8B` model serving `10,240`-token prompts (`1.5 GB` KV/req) at `16 RPS` requires **`24.0 GB/s` (`~25 GB/s`)** transfer bandwidth, collating `7,500` tokens from `16`-token pages (`469` transfers, `20.0 ms`) to `128`-token slabs (`59` transfers) cuts RDMA latency to **`8.0 ms` (`2.5x` faster, `60.0%` reduction)**, and `7,500` FP8 tokens on Llama-3-70B (`1,228,800,000` B) rounds up to **`1,280 MiB` (`1.25 GiB`)** on a `256 MB` boundary; (b) Long-Context CAG (`500` uncached tokens) cuts TTFT **`10.0x` (`5.0 s -> 0.5 s`)** at **`$0.013`/req vs `$0.007`/req** for RAG (`5,500` uncached tokens), while `CacheBlend` (`15%` selective recomputation) saves **`85.0%` of prefill compute (`6.67x` reduction)**.
4. **Exercise 4:** (a) `should_offload_prefill` returns **`True` for Request A** (`eff_len = 512 >= 256, queue = 4 < 10`), **`False` for Request B** (`eff_len = 124 < 256, decode = 3 < 8`), **`False` for Request C** (`queue = 12 >= 10, decode = 3 < 8`), and **`True` for Request D** (`decode = 9 >= 8, eff_len = 100 >= 64`), while `latency_cost` evaluates to **`-3.95` for the warm cached worker** versus **`+3.00` for the idle cold worker** (selecting the cached worker); (b) `est_ttft = 6 * 65.0 + 8 * 20.0 = 550.0 ms > 500.0 ms`, so Mooncake's `QoSController` **rejects (`False`, `HTTP 503`) the `"low"` priority request** and **admits (`True`) the `"high"` priority request**.
