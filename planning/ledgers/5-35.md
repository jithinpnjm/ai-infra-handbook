## 4. One-Line Expected Exercise Solutions

1. **Exercise 1 (Single Cluster vs. Multi-Cluster Trade-Offs, Replicated Silo Overhead, and Global Traffic Routing, `KUR` Ch. 21):** Start with one cluster per environment per region per hardware fabric domain (keeping each synchronous `NCCL` job inside one cluster); `audit_fleet_cidrs_and_silo_overhead()` shows how the Replicated Silo pattern's 3-replica HA floor across 8 regions requires 24 replicas, and Anycast HTTP(S) load balancing avoids GeoDNS TTL caching and ISP skew.
2. **Exercise 2 (The 6 Layers of Fleet Management, Per-Cluster Terraform State, and `Cluster API`):** Isolate each cluster in its own Terraform state file to bound blast radius and state lock contention, and use `Cluster API` (`Cluster`, `MachineDeployment`, `MachinePool`) on an HA management cluster to manage workload cluster lifecycles.
3. **Exercise 3 (GitOps Fleet Delivery: Push vs. Pull Argo CD, `ApplicationSet` Generators, and Progressive Rollout Rings):** `plan_applicationset_ring_rollout()` filters clusters by inventory labels (`gpu: "true"`) and promotes changes across `canary -> staging -> prod-ring-1 -> prod-ring-2` rings with automated health checks and soak gates.
4. **Exercise 4 (Cross-Cluster AI Job Dispatch with Kueue `MultiKueue`):** `simulate_multikueue_dispatch()` contrasts `AllAtOnce` (nominating all workers simultaneously) against `Incremental` (nominating batches of 3 every 5 minutes in `MultiKueueConfig.spec.clusters` priority order, e.g., on-prem DGX first then cloud spill-over), with worker credentials stored in least-privilege `Secret`s or `ClusterProfile`s.
5. **Exercise 5 (Comparing Multi-Cluster Orchestrators and Cross-Cluster Networking):** `MultiKueue` dispatches batch/AI jobs, `Karmada` federates arbitrary Kubernetes resources via `PropagationPolicy`, and `OCM` uses pull-based `ManifestWork` agents; `audit_fleet_cidrs_and_silo_overhead()` verifies non-overlapping Pod/Service CIDRs required for `Cilium ClusterMesh` and `Submariner`.
6. **Exercise 6 (Fleet-Wide Identity, Observability, Upgrade Runbooks, and Failure-Domain Design):** Attach `externalLabels: { cluster: "..." }` to Prometheus remote-write streams, protect central management-plane credentials with least-privilege RBAC and pull-based agents, and verify that workload clusters continue running independently if the management plane is unreachable.
