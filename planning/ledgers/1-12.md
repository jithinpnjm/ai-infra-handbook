## 4. One-Line Expected Exercise Solutions

1. **Exercise 1 (Flash Partition Alignment `2048` vs `1953126`):** For `4,096`-byte flash pages (`8` sectors of `512` bytes per page), starting at sector `2048` (`1 MiB`) gives `2048 / 8 = 256` with remainder `0` (`aligned = True`), whereas `/sys/block/sdf/sdf2/start = 1953126` (`HLW` Ch. 4.1.6) gives `1953126 / 8 = 244140.75` with remainder `6` (`aligned = False`, causing single logical reads/writes to straddle two physical flash pages).
2. **Exercise 2 (`ext4` Reserved Blocks and the Five Meanings of `ENOSPC`):** On a `100,000`-block `ext4` volume with `40,000` used blocks and the default `5%` root reservation (`5,000` blocks), non-root `Available` is `55,000` blocks (`Used + Available = 95,000 < 100,000`); the five distinct causes of `ENOSPC` / write failure are (1) data blocks full (`df -h`), (2) inodes exhausted (`df -i`), (3) read-only error remount (`mount | grep ' ro,'`, `dmesg`), (4) user/group/project quota hit (`repquota -a`, `xfs_quota`), and (5) deleted files held open (`sudo lsof +L1`) or writing into an unmounted mount point (`findmnt -T`).
3. **Exercise 3 (`O_DIRECT` Alignment Rules and GPUDirect Storage vs Page Cache):** (a) `O_DIRECT` requires the memory buffer address, file byte offset, and transfer length to be exact integer multiples of the device's logical block size (`512` or `4,096` bytes), returning `EINVAL` if any of the three is misaligned; (b) `O_DIRECT` bypasses only the kernel page cache (still DMAing into host CPU RAM before `cudaMemcpy`), whereas GPUDirect Storage (`GDS` / `cuFile`) DMAs directly between NVMe/NIC and GPU `HBM` over PCIe (unless it silently falls back to POSIX compatibility mode).
4. **Exercise 4 (Interpreting `iostat -xz` on NVMe SSDs):** On a parallel NVMe SSD rated at `7,000 MB/s`, `%util = 99%` with `aqu-sz = 1.0` and `250 MB/s` means a single synchronous application thread is issuing one request at a time (`app_single_thread_sync_limited_not_drive_saturated`), whereas `aqu-sz = 64.0` and `await = 8.2 ms` indicates genuine `drive_queue_saturated`.
5. **Exercise 5 (Filesystem Transaction Cost and 64-Node Checkpoint Storms):** (a) When `180 ms` of a `200 ms` operation is blocked in filesystem I/O (`90%`), eliminating that I/O latency yields up to `200 / (200 - 180) = 10.0x` speedup (versus `1.01x` when only `2 ms` is spent in I/O); (b) when `64` nodes write checkpoints simultaneously to a shared parallel filesystem, per-node `iostat` is idle because the shared **metadata servers (MDS)** saturate on concurrent `open`/`create`/`fsync`/`close` RPCs.
6. **Exercise 6 (6-Step Linux Quota Setup and `e2fsck` Backup Superblock Recovery):** (a) Edit `/etc/fstab` (`usrquota`), remount `ro` (`mount -o remount,ro`), run `quotacheck -vugc`, remount `rw`, run `quotaon -va`, and set limits with `edquota`/`setquota` (plus `rpc.rquotad` on NFS servers); (b) unmount the corrupt `ext4` volume, find backup superblock offsets with `sudo mke2fs -n /dev/sdb1` (never omit `-n`), and repair with `sudo e2fsck -b 32768 /dev/sdb1`.
