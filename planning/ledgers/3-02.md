## 4. One-Line Expected Exercise Solutions

1. **Exercise 1 (3-Step Import Pipeline, 5-Component Search Path, and `.pyc` Validation, `LP` Chapter 22):** On first import, Python checks `sys.modules` (and `sys.builtin_module_names`/frozen modules), then (1) finds the file across the 5-component `sys.path` (script home dir, `PYTHONPATH`, stdlib, `site-packages`, `.pth` files), (2) compiles to `__pycache__/name.cpython-312.pyc` unless a `.pyc` with a matching magic number, timestamp+size (or `--check-hash-based-pycs` hash), and interpreter tag exists, and (3) executes top-level statements; top-level scripts do not write `.pyc` files unless `python3 -m compileall -b -l .` is used.
2. **Exercise 2 (`import` vs. `from` Reference Semantics, Lexical Scoping, Downward Qualification, and `reload()`, `LP` Chapter 23):** Using `simulate_import_vs_from_and_reload()`, `from share import x, y` copies object references into local variables so `x = 'hack'` rebinds only the importer's `x` (`share.x == 1`) while `y[0] = 'hack'` mutates the shared list in place (`share.y == ['hack', 2]`); `importlib.reload(share)` updates `share.__dict__` in place so `share.x` sees the new value while `copied_x` remains stale; and `lex1.f()` in `lex2.py` prints `11 99` because a function's global scope is always its defining module file.
3. **Exercise 3 (Packages, `__init__.py` & `__main__.py` Modes, Relative vs. Absolute Imports, and 4-Step Search, `LP` Chapter 24):** `python3 dir1` runs `dir1/__main__.py` directly without `dir1/__init__.py` (so `import mod` works and `from . import mod` fails), whereas `python3 -m dir1` runs `dir1/__init__.py` first in package context (so `from . import mod` works and `import mod` fails, while `import dir1.mod` with `PYTHONPATH=.` works in both); using `resolve_four_step_import_search()`, Step 1 (`d/name/__init__.py` regular package) and Step 2 (`d/name.py` simple module) return immediately while Step 3 (`d/name` bare directory) only records candidates for a PEP 420 namespace package if the entire `sys.path` scan finishes without hitting Step 1 or Step 2.
4. **Exercise 4 (Data Hiding, Dynamic String Imports, and Transitive Reloaders, `LP` Chapter 25):** Using `filter_from_star_exports()`, `__all__ = ['a', '_c']` takes precedence over `_X` in `from alls import *`; `build_dynamic_getattr_module()` routes undefined external attribute fetches (`gamod.test -> 'testtest'`) to `__getattr__`; `compare_dunder_import_vs_import_module('email.message')` shows `__import__` returns `'email'` (leftmost) while `importlib.import_module` returns `'email.message'` (rightmost); and `transitive_reload_recursive()` (`reloadall2.py`) and `transitive_reload_stack()` (`reloadall3.py`) traverse `module.__dict__.values()` with a `visited` set to reload nested modules that `importlib.reload(ra)` skips.
5. **Exercise 5 (Virtual Environments, PEP 668, Lockfiles, `pyproject.toml`, and Entry Points):** `python3 -m venv .venv` isolates `site-packages` (`sys.prefix != sys.base_prefix`), systemd/cron jobs call `/path/to/.venv/bin/python` directly, and PEP 668 protects OS-managed Python (`externally-managed-environment`); libraries declare ranges (`requests>=2.31,<3`) in `pyproject.toml` while applications lock exact versions and SHA-256 digests (`pip-compile --generate-hashes` + `pip-sync` or `uv lock`); and `[project.scripts]` / `[project.entry-points]` expose CLI launchers and `importlib.metadata.entry_points` plugins.
6. **Exercise 6 (Wheels, Dependency Confusion, and GPU / Container Packaging):** `numpy-1.26.4-cp311-cp311-manylinux_2_17_x86_64.whl` targets CPython 3.11 ABI on x86_64 Linux with `glibc >= 2.17` (`+cu121` marks CUDA 12.1 local builds); `--extra-index-url` risks dependency confusion if an attacker publishes a higher version of an internal package name on public PyPI (use `--index-url` to a private mirror); and GPU containers avoid `CUDA driver version is insufficient` and NumPy 1.x/2.x ABI breakage via driver forward compatibility, NGC constraint files (`pip freeze > constraints.txt`), and multi-stage `-slim` Docker builds.
