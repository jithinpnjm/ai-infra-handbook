## 4. One-Line Expected Exercise Solutions

1. **Exercise 1 (Kernel `netdev` Abstraction, `ip` Command Family, and `UP` vs. `LOWER_UP`):** A Linux network interface (`netdev`) decouples physical drivers/NICs from L3 IP protocols (`lo` is index `1`); in `ip addr` / `ip link`, `UP` means the interface is administratively enabled by software (`ip link set dev up`), whereas `LOWER_UP` means the physical layer detected a carrier signal (`NO-CARRIER` means the cable is unplugged or the switch port is down), and `ethtool` / `ethtool -m` inspects negotiated speed, FEC, and optical transceiver DOM power.
2. **Exercise 2 (Persistent Network Managers: `Netplan`, `NetworkManager`, `systemd-networkd`, and `optional: true`):** Manual `ip addr`/`ip route` commands modify only volatile kernel state and are wiped on reboot or overwritten by active network daemons; on servers, assign **one** manager per interface, set `ipv4.never-default yes` (or `unmanaged`) on secondary storage/fabric NICs, and set `optional: true` in Netplan so `systemd-networkd-wait-online` does not hang the boot sequence if a fabric switch is down.
3. **Exercise 3 (Sockets, Listening vs. Connected `Recv-Q`/`Send-Q`, and Unix Domain Sockets):** A TCP server creates a **listening socket** (`bind -> listen`) whose `accept()` call returns a new **per-connection socket**; on a `LISTEN` socket `Recv-Q` is the current accept queue occupancy and `Send-Q` is the max backlog limit (`min(backlog, somaxconn)`), whereas on an `ESTAB` socket `Recv-Q` is unread bytes in the kernel receive buffer (slow app) and `Send-Q` is unsent/unacknowledged bytes; **Unix domain sockets** (`AF_UNIX`, e.g., `/var/run/docker.sock`, inspected via `ss -xlp`) bypass the TCP/IP stack for fast local IPC and enforce access via filesystem permissions.
4. **Exercise 4 (Tracing Packet Drops Across the 7 Kernel Layers: `ethtool -S`, `/proc/net/softnet_stat`, and `nstat`):** Using `parse_softnet_stat_line()`: physical bit corruptions show up as `rx_crc_errors` in `ethtool -S`; NIC ring exhaustion before the kernel can DMA shows up as `rx_missed_errors` / `rx_no_buffer` (fix with `ethtool -G` and RSS `ethtool -L`); per-CPU NAPI softirq starvation shows up in `/proc/net/softnet_stat` column 2 (`dropped`) and column 3 (`time_squeeze`); and L3/L4 protocol drops show up in `nstat -az` (`IpInAddrErrors`, `TcpExtListenOverflows`, `TcpRetransSegs`, `UdpRcvbufErrors`).
5. **Exercise 5 (Gregg's `USE` Method, PCIe Gen4 vs. Gen5 Bus Bottlenecks, and `ss -ti` Limiter Flags, `SP` Chapter 10):** Using `evaluate_interface_and_pcie_use()`, a `400 Gb/s` NIC plugged into a **PCIe Gen4 x16** slot (`~252 Gb/s` usable bandwidth) hits `100%` PCIe bus saturation at only **`63.0%` link utilization** (requiring **PCIe Gen5 x16** `~504 Gb/s`); using `classify_ss_ti_bottleneck()`, `ss -ti` distinguishes `rwnd_limited` (receiver window), `sndbuf_limited` (sender socket buffer), `cwnd_limited` (network congestion/loss), and `app_limited`.
6. **Exercise 6 (eBPF Network Observability with `BCC` / `bpftrace`: `tcplife`, `tcpretrans`, `tcpconnlat`, `tcpdrop`, and `kfree_skb`):** Standard SNMP counters (`nstat`) tell you *that* retransmits or drops occurred system-wide, whereas eBPF tools (`tcplife`, `tcptop`, `tcpretrans`, `tcpconnlat`, and `tcpdrop` / `tracepoint:skb:kfree_skb`) attribute every connection, retransmit, and kernel packet drop to the **exact PID, process name (`comm`), socket 4-tuple, and kernel call stack** with negligible overhead.
