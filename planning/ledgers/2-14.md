## 4. One-Line Expected Exercise Solutions

1. **Exercise 1 (Spanning Tree, RIP, and EIGRP as Distance-Vector Control Planes, `CN` Chapter 15):** (a) Spanning Tree acts like a single-destination Bellman-Ford protocol toward the Root Bridge while learning host MAC reachability **reactively** in the data plane; (b) **RIP** (`UDP 520`, `224.0.0.9`) broadcasts its full table every `30 s` with hop-count infinity `16`, whereas **EIGRP** (`IP proto 88`, `224.0.0.10`) sends incremental updates over Reliable Transport (`RTP`), computes a composite bandwidth+delay metric (`compute_eigrp_classic_metric()`), and uses **DUAL** (`RD < FD`) for loop-free instant failover.
2. **Exercise 2 (IS-IS Architecture, `NET` Addressing, TLV Marshaling, and Reliable Flooding, `CN` Chapter 16):** IS-IS runs directly over Layer 2 (`CLNS`), separating router identity from IP prefixes; in `NET = 49.0001.1921.6800.1001.00` (`parse_isis_net()`), `49.0001` is the AFI+Area, `1921.6800.1001` is the 6-byte System ID derived from `192.168.1.1` (`ipv4_to_isis_system_id()`), and `00` is the N-selector; each router originates one logical TLV-encoded LSP (using `metric-style wide` `24/32`-bit metrics instead of legacy `6`-bit `max 63` narrow metrics) synchronized via padded **IIH** hellos, **CSNPs**, **PSNPs**, and **SRM** flags.
3. **Exercise 3 (OSPF LSA Types `1`–`7`, Packet Types `1`–`5`, and the Neighbor State Machine):** OSPF (`IP proto 89`, `224.0.0.5`/`.6`) uses 5 packets (`Hello`, `DBD`, `LSR`, `LSU`, `LSAck`) to flood LSA Types `1` (Router), `2` (Network from DR), `3` (Summary from ABR), `4` (ASBR Summary), `5` (External from ASBR), and `7` (NSSA); in `diagnose_ospf_neighbor_state()`, mismatched hello/area parameters stick in `Down`, one-way links stick in `Init`, non-DR broadcast peers stay in `2-Way`, and **MTU mismatches** stick in **`ExStart` / `Exchange`** when exchanging `DBD` packets.
4. **Exercise 4 (Multi-Access `DR`/`BDR` vs. `DIS`, Point-to-Point Fabric Links, and the Reference-Bandwidth Trap):** On broadcast segments, OSPF elects a non-preemptive `DR` and `BDR` (while IS-IS elects a preemptive `DIS` with no backup) to reduce `n(n-1)/2` adjacencies to `O(n)` via a pseudo-node, whereas data-center fabric links are point-to-point and should always set `ip ospf network point-to-point` / `isis network point-to-point` to skip elections; using `compute_ospf_interface_cost()`, OSPF's default `100 Mb/s` reference bandwidth makes `1G`, `10G`, `100G`, and `400G` links all cost `1`—fix by setting `auto-cost reference-bandwidth 400000` on every router (`400G = 1`, `100G = 4`, `10G = 40`).
5. **Exercise 5 (OSPF Areas vs. IS-IS Levels, Overload Bit / Max-Metric Drain, and Protocol Selection):** OSPF partitions routers into **Area 0** (backbone) and non-backbone areas connected via **ABRs** (with `stub`, `totally stubby`, and `NSSA` areas), whereas IS-IS places area boundaries on **links** using `Level 1`, `Level 2`, and `L1/L2` routers (often run as flat `level-2-only` in data centers) and carries both IPv4 and IPv6 in a single process; before rebooting a switch for maintenance, set the IS-IS **overload bit** or OSPF **`max-metric router-lsa`** so peers route transit traffic around the switch gracefully.
6. **Exercise 6 (Configuring and Troubleshooting OSPF and IS-IS Underlays in FRR):** Configure FRR (`ospfd` / `isisd` + `bfdd`) with explicit loopback `router-id` / `net`, `passive-interface default`, `network point-to-point` on fabric uplinks, `bfd` (`100 ms x 3`), `maximum-paths 64`, and `metric-style wide` / `auto-cost reference-bandwidth 400000`, and verify identical LSDBs across switches with `show ip ospf database` / `show isis database detail`.
