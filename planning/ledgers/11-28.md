## 4. One-Line Expected Exercise Solutions

1. **Exercise 1:** `swp14 up 100G` on the leaf switch only proves Layer 3 (DPU-to-switch physical link), while `enp1s0f0np0 DOWN` on the host only shows Layer 1 symptom; checking `systemctl status openvswitch-policy-load.service` on the DPU's Arm subsystem (Layer 2) isolated the failed policy-load service (`PID 812`, `status=1`) that left the embedded switch without host-facing rules.
2. **Exercise 2:** During a rollout, `node09`'s `dpu-agent` image pull timed out and abandoned reconciliation after `5` retries, leaving `node09` online and forwarding traffic under stale `dpu-image-24.07-prod-1` policy while fabric-wide link counters stayed green.
3. **Exercise 3:** With host-resident `iptables`, a host `root` attacker runs `systemctl stop iptables` (**Shared Fate**) and launches lateral/DDoS attacks; with a **BlueField DPU**, firewall rules (`DOCA Flow`) and encryption keys reside in the isolated DPU Arm domain and DPU RAM, containing the compromised x86 host.
4. **Exercise 4:** **BlueField DPU SKUs** default to **DPU (`ECPF`) mode** (where the embedded Arm subsystem owns NIC resources and the embedded switch), whereas **BlueField SuperNIC SKUs** default to **NIC mode**; in DPU mode, the first packet of a flow punts via a representor to the Arm slow path to validate policy and program a hardware rule into the embedded switch, after which subsequent packets traverse the ConnectX ASIC fast path at line rate.
5. **Exercise 5:** **Supported DOCA service** is preferred for production when it fits the use case; **DOCA reference sample** is for evaluation/learning only; **Custom DOCA application** requires a dedicated engineering team to own testing, CVE patching, and on-call support; and **Host/fabric-native** is chosen when a DPU adds no measurable value or lacks an operational owner.
6. **Exercise 6:** The `6` change steps are `1. Qualify release set` -> `2. Capture baseline & rollback artifacts` -> `3. Canary group` -> `4. Verify DPU, host function, uplink, policy & app traffic separately` -> `5. Expand in batches` -> `6. Preserve OOB recovery procedure` across the `5` observability layers (`Host`, `DPU control plane`, `DPU data plane`, `Fabric`, and `Platform`).
