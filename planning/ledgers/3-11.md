## 4. One-Line Expected Exercise Solutions

1. **Exercise 1 (Closures, Late Binding, Function vs. Class Decorators `@tracer`, and `@rangetest`, `LP` Ch. 39):** `rangetest()` inspects `func.__code__.co_varnames[:func.__code__.co_argcount]` to map positional and keyword arguments to parameter names while `@functools.wraps` and `ParamSpec` preserve signatures; a class-based `@tracer` with only `__call__` fails on methods because it lacks `__get__` to bind `self`, whereas a nested function closure with `nonlocal` (or implementing `__get__`) works on both functions and methods.
2. **Exercise 2 (Dynamic Attributes `FrozenJSON`, `@property`, `cached_property`, and `CardHolder` 4 Ways, `FP` Ch. 22 & `LP` Ch. 38):** `FrozenJSON.__new__` returns a `FrozenJSON` on mappings, a list comprehension on sequences, and the scalar itself otherwise, while `__init__` appends `'_'` to Python keywords (`keyword.iskeyword`); in `CardHolder`, storing attribute values on the shared descriptor (`self.name` in `validate_descriptors1.py`) causes `sue` to overwrite `bob`, whereas storing values on `instance` (`validate_descriptors2.py`) isolates instances.
3. **Exercise 3 (The Descriptor Protocol: Data vs. Non-Data Descriptors, `__set_name__`, and Bound Methods, `FP` Ch. 23):** `object.__getattribute__` checks (1) data descriptors (`__set__`/`__delete__`) on `type(obj).__mro__`, (2) `obj.__dict__`, (3) non-data descriptors (only `__get__`, such as functions and `cached_property`) or class attributes on `type(obj).__mro__`, and (4) `__getattr__`; thus `Quantity` (`Validated` with `__set_name__`) overrides `obj.__dict__` on every access while `cached_property` runs once and is shadowed by `obj.__dict__`.
4. **Exercise 4 (Class Creation Mechanics: `type()`, `record_factory`, `__init_subclass__`, Class Decorators, and Metaclasses, `FP` Ch. 24 & `LP` Ch. 40):** Evaluating `class Sub(Base, metaclass=TraceMeta):` runs `(1) __prepare__ -> (2) class body -> (3) __new__ -> (4) __set_name__ -> (5) Base.__init_subclass__ -> (6) __init__`; `I.attr` searches only `I.__dict__` + `C.__mro__`, `C.attr` searches `C.__mro__` + `M.__mro__`, and implicit built-ins (`str(X)`, `X[0]`) start lookup at `type(X)` (skipping `I.__dict__` for instances and `C.__dict__` for classes).
5. **Exercise 5 (How Frameworks Work Under the Hood: `FastAPI`, `pytest`, `@dataclass`, and PyTorch `nn.Module`):** `ToyModule.__setattr__` intercepts assignments of `ToyParameter` and `ToyModule` instances to register them in `_parameters` and `_modules` (so layers inside a plain Python `list` are missed unless wrapped in `nn.ModuleList`); `FastAPI` and `pytest` inspect `inspect.signature(fn)` and `typing.get_type_hints(fn)` to wire parameters and fixtures by name.
6. **Exercise 6 (Introspection, `dis`, `ast.literal_eval` vs. `eval`, Import Hooks `sys.meta_path`, and Entry Points):** `eval`/`exec` and `pickle` execute arbitrary code on untrusted inputs whereas `ast.literal_eval()` safely parses literals and `ast.parse()` builds syntax trees for static analysis; custom `sys.meta_path` finders/loaders let `pytest` rewrite `assert` AST nodes on import, and `importlib.metadata.entry_points` discovers installed third-party plugins.
