## 4. One-Line Expected Exercise Solutions

1. **Exercise 1 (Navigating the Kubernetes REST API and Storage Version Conversion, `KPG` Ch. 2):** Core objects live under `/api/v1` while named groups live under `/apis/<group>/<version>`; a `Kind` (`Deployment`) is the schema type whereas a `resource` (`deployments`) is the URL collection noun; and while multiple versions (`v1alpha1`, `v1beta1`, `v1`) can be served, only a single **storage version** is persisted in `etcd`.
2. **Exercise 2 (The `kube-apiserver` Request Pipeline and Admission Webhooks vs. CEL, `KUR` Ch. 17):** Requests pass through AuthN -> AuthZ -> APF -> Mutating Admission (returning base64 `JSONPatch`) -> OpenAPI Schema Validation -> Validating Admission -> `etcd` persistence & KMS v2 encryption -> Watch fan-out; in-process `ValidatingAdmissionPolicy` (CEL) avoids webhook network latency and cluster-deadlock failure modes.
3. **Exercise 3 (`resourceVersion`, Optimistic Concurrency `409`, Watch `410 Gone` & `BOOKMARK`, and `LIST` Modes):** `EtcdMVCCSimulator` shows `resourceVersion` tracks `etcd`'s MVCC revision, rejecting stale `PUT`s with `409 Conflict` and watches older than `compacted_revision` with `410 Gone`; `allowWatchBookmarks=true` advances quiet watch bookmarks, and `resourceVersion="0"` serves `LIST`s from the watch cache without hitting `etcd`.
4. **Exercise 4 (Writing Objects: `PUT` vs. `PATCH` vs. Server-Side Apply `managedFields`):** `evaluate_ssa_field_ownership()` demonstrates how Server-Side Apply tracks per-field ownership in `metadata.managedFields`, raising a 409 conflict if Argo CD tries to overwrite `/spec/replicas` owned by an HPA unless the field is omitted or `--force-conflicts` is used.
5. **Exercise 5 (API Priority and Fairness `APF`: `FlowSchema` and `PriorityLevelConfiguration`):** `compute_apf_concurrency_limit()` allocates server concurrency across `PriorityLevelConfiguration`s by `nominalConcurrencyShares`, while Shuffle Sharding (`queues: 64, handSize: 6`) isolates noisy flows; client-side throttling (`QPS=5, Burst=10`) is fixed by raising `--kube-api-qps`/`--kube-api-burst`.
6. **Exercise 6 (`etcd` Internals, `NOSPACE` Recovery, Safe Member Replacement, and 5,000-Node Scaling):** Compaction frees logical MVCC revisions while `etcdctl defrag` reclaims physical disk space (followed by `etcdctl alarm disarm` to clear `NOSPACE`); dead members must be **removed before adding** a replacement to avoid raising quorum while a node is down; and 5,000-node GPU clusters isolate `etcd` on NVMe with a separate `etcd-events` cluster.
