## 4. One-Line Expected Exercise Solutions

1. **Exercise 1 (Non-Cumulative Permission Evaluation):** `alice` (`UID 1042`) matches the `user_owner` class first (`---` = `0`) and is **denied** read access even though she belongs to `projx` (`2001`), whereas `bob` (`UID 1043`) does not match `user_owner`, falls through to the `group` class (`rwx` = `7`), and is **granted** read access.
2. **Exercise 2 (`umask` Creation Modes):** Under `umask 022`: file = `0644` (`rw-r--r--`), dir = `0755` (`rwxr-xr-x`); under `umask 077`: file = `0600` (`rw-------`), dir = `0700` (`rwx------`); under `umask 002`: file = `0664` (`rw-rw-r--`), dir = `0775` (`rwxrwxr-x`).
3. **Exercise 3 (Special Bits `4000`, `2000`, `1000`):** (a) Running `/usr/bin/passwd` (`4755` owned by `root`) sets `ruid = 1042`, `euid = 0`, and `saved_uid = 0`; (b) `2770` (`setgid`) ensures new files inside `/data/projx` inherit group `projx` rather than the creator's primary group, and `1777` (`sticky`) on `/tmp` prevents non-owners from deleting or renaming other users' files.
4. **Exercise 4 (POSIX ACL Mask Capping):** Running `chmod 640` sets the ACL `mask::r--` (`04`), which caps `u:alice:rw-` (`06`) to `#effective:r--` (`04`), shown as `user:alice:rw-   #effective:r--` in `getfacl mydir`.
5. **Exercise 5 (`/usr/sbin/master-sync` and `ALRM` Watchdog):** (a) Pulling from the destination compute node at boot ensures any node that was powered off or replaced automatically synchronizes `/etc/passwd`, `/etc/shadow`, and `/etc/group` when it starts; (b) across `100` nodes at `0.1` s stagger, the delay is `10.0` seconds, while `-o connecttimeout=3` (`CT=3`) and `(sleep 600 && kill -ALRM "$$") &` with `trap 'exit' ALRM` prevent a hung node from blocking forever.
6. **Exercise 6 (NIS/NIS+ `yp` vs. LDAP):** (a) Sun named NIS *Yellow Pages* (`yp`) in `1985` before a trademark lawsuit forced the rename; a single NIS+ server struggles above `30–40` clients, and its three daemons are `ypserv` (lookup server), `yppasswdd` (password changes), and `ypxfrd` (slave map sync); (b) a 500-node job launch causes all 500 nodes to query LDAP simultaneously ("explosive" burst access), dropping requests unless cached locally by `SSSD` or a replica hierarchy.
