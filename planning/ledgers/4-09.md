## 4. One-Line Expected Exercise Solutions

1. **Exercise 1 (Development vs. Production Architecture and Multi-Play Decomposition `site.yml`, `AUR` Ch. 6 & 7):** Production replaces foreground `runserver` + SQLite with NGINX (TLS, static files, rate limits) -> Gunicorn/Uvicorn (managed by systemd/Supervisor) -> PostgreSQL + Memcached; `site.yml` composes `baseline.yml`, `database.yml`, `app.yml`, `web.yml`, and `verify.yml` via `import_playbook` so tiers can be run together or individually by tag/limit.
2. **Exercise 2 (PostgreSQL Provisioning, `become_user: postgres`, `pg_hba.conf`, and UFW Filtering, `AUR` Ch. 7):** `become_user: postgres` requires `acl` (`setfacl`) so the unprivileged `postgres` user can read temporary module files without `0777` permissions; setting custom `UTF8` locales on `postgresql_db` requires `template: template0`; and `listen_addresses`, `pg_hba.conf` (`scram-sha-256`), and `ufw` lock port `5432` to `groups['app']` IPs.
3. **Exercise 3 (Versioned Release Directories, Atomic `current` Symlink Swaps, and Instant Rollback):** Using `validate_pinned_version()` and `AtomicReleaseDeployer`, pinning `app_version` to a tag/SHA and installing each release in `/opt/fleetapp/releases/<version>/{src,venv}` lets `file: state=link` switch `/opt/fleetapp/current` atomically, retain `N=5` releases, and roll back in seconds without rebuilding.
4. **Exercise 4 (Zero-Downtime Rolling Updates `serial: 1`, Expand/Contract Migrations, and `systemd` Hardening):** `alembic upgrade head` runs with `run_once: true` using backward-compatible expand/contract schema changes; `meta: flush_handlers` restarts `fleetapp` before `/readyz` polling and load-balancer undraining; and `NoNewPrivileges=yes`, `ProtectSystem=strict`, `ProtectHome=yes`, and `PrivateTmp=yes` harden the systemd unit.
5. **Exercise 5 (NGINX Reverse Proxy `upstream`, TLS, `proxy_buffering off`, `nip.io`, and `verify.yml`, `AUR` Ch. 7):** `nginx-site.conf.j2` generates `upstream` servers from `groups['app']` with `proxy_buffering off` for SSE streaming, `192.168.33.10.nip.io` provides wildcard DNS for `ALLOWED_HOSTS`, and `verify.yml` runs end-to-end `uri` + `assert` checks to prove the deployed version is answering over HTTPS.
6. **Exercise 6 (Host Virtualenv vs. Container Deployment `community.docker.docker_container` Pinned by Digest):** Host virtualenvs require OS `-dev` compilers and per-host wheel installs, whereas `docker_container` deploys an immutable image built once in CI and pinned by `@sha256:...` with `read_only: true`, `cap_drop: [ALL]`, and `no-new-privileges:true` (scaling to Kubernetes for multi-node container orchestration).
