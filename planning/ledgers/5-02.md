## 4. One-Line Expected Exercise Solutions

1. **Exercise 1 (The Kubernetes Runtime Stack `kubelet -> CRI -> containerd/CRI-O -> shim -> OCI runtime`, `PK` Ch. 3):** `CRIRuntimeSimulator` traces `RunPodSandbox` (creating the `pause` container and invoking CNI) followed by `PullImage`, `CreateContainer`, and `StartContainer`; `dockershim` was removed in 1.24 because `containerd` implements CRI natively, and per-pod `containerd-shim-runc-v2` processes keep containers running across `containerd` daemon restarts.
2. **Exercise 2 (Configuring `containerd` `/etc/containerd/config.toml`, `SystemdCgroup = true`, and `CRI-O`):** `validate_cgroup_and_runtime_class()` checks that `kubelet` (`cgroupDriver: systemd`) and `containerd` (`SystemdCgroup = true`) share a single cgroup manager; Kubernetes objects live in the `k8s.io` containerd namespace (`ctr -n k8s.io`).
3. **Exercise 3 (Comparing OCI Runtimes `runc`, `crun`, `gVisor`, `Kata`, `CoCo` and `RuntimeClass`, `PK` Ch. 3):** `runc`/`crun` isolate via host kernel namespaces/cgroups, `gVisor` (`runsc`) intercepts syscalls in a user-space kernel, and `Kata Containers` boots a lightweight KVM/QEMU microVM per Pod; `RuntimeClass` maps `handler` to `config.toml` `runtimes.<name>` and adds `overhead.podFixed` to scheduling requests.
4. **Exercise 4 (Integrating the NVIDIA Container Toolkit with `containerd`):** Either register the `nvidia-container-runtime` wrapper under `runtimes.nvidia` (selected via `runtimeClassName: nvidia`) or enable native `CDI` (`nvidia-ctk cdi generate` writing `/var/run/cdi/nvidia.yaml`) so `containerd` injects `/dev/nvidia*` and `libcuda.so` directly into `runc`/`crun`.
5. **Exercise 5 (Node-Level Debugging with `crictl`, `ctr -n k8s.io`, `nerdctl`, and `runc`):** Use `crictl pods`, `crictl inspectp <pod-id>`, `crictl ps -a`, `crictl inspect <ctr-id>`, `crictl logs`, and `ctr -n k8s.io plugins ls` / `tasks ls` to diagnose CNI failures, OOM kills, and OCI create errors.
6. **Exercise 6 (Day-2 Runtime Operations: Image GC, Dedicated NVMe Storage, and `PLEG is not healthy`):** Mount `/var/lib/containerd` on dedicated fast NVMe storage so 25 GB ML images do not trigger root `DiskPressure` or constant `imageGCHighThresholdPercent` (85%) eviction loops, and monitor containerd I/O and shim counts to prevent 3-minute PLEG timeouts.
