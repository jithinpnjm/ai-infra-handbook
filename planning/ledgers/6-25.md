## 4. One-Line Expected Exercise Solutions

1. **Exercise 1 (Auditing and Hardening `sshd_config` on Bastion and Login Nodes):** `sshd_audit.py` flags `PermitRootLogin=yes`, `PasswordAuthentication=yes`, `PermitEmptyPasswords=yes`, and `PermitUserEnvironment=yes` as hard `ERROR`s, uses `cfg.setdefault()` to model OpenSSH's "first occurrence wins" rule, and delegates `Match`-block evaluation to `sshd -T -C user=...,host=...,addr=...`.
2. **Exercise 2 (Designing `ProxyJump` Client Configs and SSH Certificate + MFA Authentication):** Use `ProxyJump bastion` (`ssh -J`) so private keys never leave the user's laptop (avoiding `ForwardAgent` socket hijacking), and configure `TrustedUserCAKeys` + `AuthenticationMethods publickey,keyboard-interactive` for short-lived CA certificates + MFA.
3. **Exercise 3 (Configuring Open OnDemand for a Slurm GPU Cluster):** Name `/etc/ood/config/clusters.d/<ClusterName>.yml` to match `slurm.conf` `ClusterName`; Apache authenticates the user and reverse-proxies to their Per-User NGINX (`PUN`), and because OOD submits with `sbatch --export=NONE`, batch-connect scripts invoking `srun` must `export SLURM_EXPORT_ENV=ALL`.
4. **Exercise 4 (Comparing Remote Graphical Access `X11`, `Xming`, `TigerVNC`, `x2go`, and OOD Batch-Connect):** In X11 the `X server` runs on the user's workstation (`:0`) and the `X client` runs on the cluster authenticated via `xauth` (never `xhost +`); over WAN links, `TigerVNC`, `x2go`, or OOD browser desktops outperform raw `ssh -X`.
5. **Exercise 5 (Preventing Dotfile Pollution and Login-Node Abuse):** Keep `conda activate` and `module load` out of `~/.bashrc` so `sbatch --export=ALL` jobs stay clean; protect login nodes with `systemd` `user-.slice` caps, `pam_slurm_adopt` on compute nodes, and dedicated DTNs for bulk transfers.
6. **Exercise 6 (Implementing User Support, Ticketing, and Annual Account "Actualization"):** Route `cluster-support` via `/etc/aliases` + `newaliases` into `RT`/`OTRS`/`Trac`/`OpenProject`, run `Mailman` in moderated mode, and hold an annual 2–3 week re-registration ("actualization") window that blocks—rather than deletes—unconfirmed accounts until the next cycle.
