## 4. One-Line Expected Exercise Solutions

1. **Exercise 1 (MAC Address Anatomy `I/G` & `U/L` Bits, Ethernet Frame Format, and CSMA/CD vs. Full Duplex):** (a) In a 48-bit MAC (`decode_mac_address()`), bit 0 (LSB) of the first octet is `I/G` (`0` = unicast, `1` = multicast/broadcast `ff:ff:ff:ff:ff:ff`) and bit 1 is `U/L` (`0` = IEEE globally unique OUI, `1` = locally administered such as `52:54:00:12:34:56`); (b) the 64-byte minimum Ethernet frame (`14`B header + `46`B payload + `4`B FCS) originally ensured a station on shared half-duplex coax was still transmitting when a collision reached it (CSMA/CD), whereas modern switched full-duplex point-to-point links have separate TX/RX paths and zero collisions.
2. **Exercise 2 (Reading Optics/Transceiver Names, `NRZ` vs. `PAM4`, `RS-FEC`, and `ethtool -m` / `mlxlink`):** `400GBASE-DR4` is `400 Gb/s` over `4` parallel single-mode fiber (`SMF`) lanes of `100 Gb/s` `PAM4` each (`500 m` reach, `QSFP-DD` or `OSFP`), whereas `100GBASE-CR4` is `4 x 25G` `NRZ` twinax copper `DAC`; because `50G`/`100G`-per-lane `PAM4` uses 4 amplitude levels (`2` bits/symbol) with tighter SNR margins, it requires **Reed-Solomon FEC (`RS-FEC`)**, and link health is verified via `ethtool -m` (DOM optical power/temp), `ethtool --show-fec`, and `ethtool -S` (`rx_crc_errors`, uncorrected FEC, `carrier_changes`).
3. **Exercise 3 (Switch MAC Learning, Flooding, L2 Loops, and Internal Switch Fabric VOQs/iSLIP):** (a) On receiving a frame (`simulate_switch_frame_action()`), a switch learns `src_mac -> ingress_port` in its FDB, forwards known unicast to its target port, filters same-port frames, and floods unknown unicast/broadcast/multicast out all other ports in the VLAN (which causes infinite broadcast storms in an L2 loop because Ethernet has no `TTL`); (b) inside a switch ASIC, **Virtual Output Queues (`VOQ`s)** (one input queue per destination port) paired with an **iSLIP** crossbar scheduler prevent head-of-line blocking when one output port is congested by incast.
4. **Exercise 4 (IPv4 ARP, Gratuitous ARP, and Multi-NIC AI Server `arp_ignore` / `arp_announce` Tuning):** An ARP request is broadcast (`ff:ff:ff:ff:ff:ff`) and answered unicast; **gratuitous ARP** (`sender IP == target IP`) updates peer caches/switch FDBs on failover and detects duplicate IPs (`arping -D`); on multi-NIC GPU servers, Linux's default weak-host model answers ARP for any local IP on any NIC, so you must set `arp_ignore=1`, `arp_announce=2`, and `rp_filter=2` (plus per-NIC policy routing) so each rail NIC answers only for its own IP.
5. **Exercise 5 (IPv6 Neighbor Discovery `NDP`, Solicited-Node Multicast, `EUI-64`, `DAD`, and `SLAAC`):** IPv6 replaces broadcast ARP with ICMPv6 **Neighbor Solicitation (`135`)** and **Neighbor Advertisement (`136`)** sent to the **solicited-node multicast address** `ff02::1:ffXX:XXXX` (Ethernet MAC `33:33:ff:XX:XX:XX`, disturbing only hosts sharing the low 24 bits); from MAC `01:23:45:67:89:ab`, flipping the U/L bit and inserting `ff:fe` yields `fe80::323:45ff:fe67:89ab` (`mac_to_ipv6_eui64_link_local()`), verified via **DAD** before forming global addresses from **Router Advertisements (`134`)** via **SLAAC**.
6. **Exercise 6 (Serialization Delay, Store-and-Forward vs. Cut-Through, and 802.11 Wi-Fi CSMA/CA):** A `1500`-byte frame (`12,000` bits) takes `120.0 ns` to serialize at `100 Gb/s` versus `12,000.0 ns` (`12 µs`) at `1 Gb/s` (`compute_serialization_delay_ns()`); cut-through switches forward after the first `14–24` bytes (`~300 ns–1 µs`) whereas store-and-forward waits for the full frame and FCS check; 802.11 Wi-Fi uses **CSMA/CA** with explicit ACKs (and optional `RTS/CTS` for hidden nodes) because a radio transmitter cannot listen for collisions while transmitting.
