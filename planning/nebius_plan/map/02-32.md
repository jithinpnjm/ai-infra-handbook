# 2.32 Cloud networking: VPC design, connectivity, load balancers and GCP specifics for AI
Words: ~9,900 | Read time: ~66 min | File: docs/part-02-networking/32-cloud-networking-vpc-peering-load-balancers-and-gcp-specifics.md
One-line purpose: Teaches how to design and troubleshoot cloud networks on GCP (global VPC, NAT, peering, hybrid links, load balancers, GKE alias IPs, GPU VM networking), with AWS and Azure equivalents and the cost traps.
Beginner friendly: partly. Needs 2.4 (subnets, CIDR), 2.5 and 2.15 (routing, BGP), 2.8 and 2.9 (NAT, DNS), 2.20 (load balancing) and 2.25 (container networking) first. Read section 2 (business trade-offs) quickly; it is plain prose.
Nebius rounds served: R1 (cloud networking basics, NAT and routing), R2 (GKE and Kubernetes networking, troubleshooting with connectivity tests and flow logs), R3 (system design: multi-region, hybrid, data gravity, availability), R4 (own-project cloud design).
Chapter verdict: READ-SECTIONS (sections 2 trade-offs, 3 challenges, 5 GCP VPC model, NAT, connecting networks, load-balancer table, 6 GKE, 7 design guidance, 9, 10; then skim the AWS/Azure table and the lab). Nebius is a GPU cloud, so the GCP specifics matter mainly as the reference model for the design and GKE questions. The checkpoint Q&A repeats the body, so skim it.

Hands-on to do:
- `python3 code/part02/cloud_vpc_gke_networking_lab.py` (the chapter's free self-check lab; confirm the file exists in the repo first).
- Arithmetic without a cloud account: a `/14` pod range split into `/24` per node gives `2^(24-14) = 1,024` nodes (exercise 5).
- Create a custom-mode VPC and a subnet with a secondary range in a billing-enabled lab project: `gcloud compute networks create lab-vpc --subnet-mode=custom`, then `gcloud compute networks subnets create ... --secondary-range=pods=...,services=...`. Delete everything afterwards.
- Run `gcloud network-management connectivity-tests create` between two VMs, then `describe` it to see which firewall or route blocks the test.
- Check MTU with `ping -M do -s N <vm-ip>` between two VMs, and compare the VPC MTU (1460 default) with the attachment MTU.
