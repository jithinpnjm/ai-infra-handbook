# 1.6 Users, groups, permissions, ACLs, sudo and user environments
Words: 14629 | Read time: 98 | File: /Users/jithinpjoseph/Documents/GitHub/ai-infra-handbook/docs/part-01-linux/06-users-groups-permissions-acls-sudo-and-user-environments.md
One-line purpose: Explains how Linux decides who you are (numeric UIDs and GIDs, passwd/shadow/group) and what you may do (mode bits, umask, special bits, ACLs, sudo, limits), plus how identity stays consistent across cluster nodes.
Beginner friendly: partly. Sections 1, 3 and 5 are beginner-friendly and step through each idea. Section 8 (NIS and NIS+ history, LDAP) assumes familiarity with directory services and can be skipped. Read chapter 1.5 section 2 alongside the StrictModes parts.
Nebius rounds served: R1, R2, R4
Chapter verdict: READ-SECTIONS (1 intro, 2, 3 all subsections, 4 mask only, 5 sudo and the three-identity distinction, 6 startup pitfalls, 7 limits, 8.1, 8.5, 9, How it fails 1, 2, 4, 5, 7). These cover the permission and identity questions that come up in R1 and R2 and the UID-consistency points that matter for Slurm and shared filesystems. Skip the NIS history and the csh and zsh startup examples.

Hands-on to do:
- `id`, `groups`, `getent passwd $USER` and `grep $USER /etc/passwd`, then compare them.
- Permission truth table: make a file with mode 070 owned by you and try to read it; then remove x from a directory and try `cd`, `ls` and `cat dir/file`.
- umask table: run `umask 022`, `umask 077` and `umask 002`, create a file and a directory under each, and record the modes.
- Shared-directory recipe: `chmod 2770` on a test directory, create a file as one user and edit it as another; check the group with `ls -l`.
- Sudo: `sudo -l`, `export FOO=1; sudo env | grep FOO` (empty), then `sudo -E`, and `echo x | sudo tee /root/f >/dev/null`.

Likely interview questions from this chapter:
1. A file looks readable with `ls -l` but `cat` says Permission denied. Walk me through the causes in order.
2. Explain umask 022 versus umask 002 and build a shared project directory for a team.
3. What does `x` mean on a directory, and why can you delete a read-only file in a writable directory?
4. Authentication, identification and authorization: what is the difference?
5. A container wrote root-owned files into your project directory. How do you stop it, and how do you fix the files?
6. The same user has different UIDs on two nodes. What breaks, how do you detect it, and how do you fix it?
7. Why does `sudo echo x > /root/file` fail, and why does `sudo` drop my exported environment variable?
