# 10.21 GPU health: DCGM, ECC, row remapping and Xid

One-line purpose: Gives the operating model for GPU fleet health: DCGM telemetry, ECC and row-remapper counters, the three-tier Xid triage policy, GPU sharing isolation, safe node draining and cluster SLO error budgets.
Beginner friendly: no for the first read. It assumes you know what a GPU driver, HBM memory and NVLink are, and it uses GPU-specific terms (MIG, MPS, NVML, SM) without much explanation. Read 10.8 (nvidia-smi, driver stack, topology) and 10.9 (NVIDIA software stack) first, then the 10.20 profiling overview if you want the tools landscape. The Xid triage (section 3) and the SLO ledger (section 4.2) are readable with only the basic GPU background.
Nebius rounds served: R2, R3, R4

Hands-on to do:
- If a GPU node is available: `dcgmi discovery --list --all`, `dcgmi dmon --field-id 100,101,203 --count 10`, `dcgmi diag --run 1` (section 5).
- Read the ECC and row-remapper state: `nvidia-smi -i 0 -q -d ECC,PAGE_RETIREMENT,ROW_REMAPPER` (section 2.1 and 2.3).
- Pull the kernel Xid log: `dmesg -T | grep -B5 -A5 "Xid" | tail -n 60` and classify each code with the tier table (section 3.1).
- Run the chapter's lab with no GPU: `python3 code/part10/gpu_health_dcgm_xid_lab.py` (expect 25 passed) (section 7).
- Work the error budget by hand: (1 - 0.99) x 730 = 7.3 hours; 6.0 used leaves 1.3 (section 4.2).
