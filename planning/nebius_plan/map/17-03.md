# 17.3 Logging with Loki and tracing with OpenTelemetry
Words: 10700 | Read time: 69 | File: /Users/jithinpjoseph/Documents/GitHub/ai-infra-handbook/docs/part-17-operations/03-logging-with-loki-and-tracing-with-opentelemetry.md
One-line purpose: Covers how logs leave containers (node agents, structured JSON, low-cardinality Loki labels) and how traces flow through the OpenTelemetry Collector with tail sampling, plus the trace-to-log join that makes an incident debuggable.
Beginner friendly: partly. The log-shipping and trace-ID ideas are clear, but sections 1.5-1.6 (Fluentd, audit policy) and 2.5-2.6 (OpenTracing history, Zipkin/Jaeger component list) are dense and partly legacy. Read 17.1 first, and read the Kubernetes "Logging" and "Events" ideas in the Part 4 or Part 11 material before 1.5.
Nebius rounds served: R2, R3, R4
Chapter verdict: READ-SECTIONS (1.1-1.4, 1.8, 2.1-2.4, 3.2, 4.3, 5, 6 with 6.9), because log labels versus fields, trace propagation, tail sampling and the trace-to-log join are the parts an SRE is asked about; skim the rest, and skip the audit-policy YAML and OpenTracing history.

Hands-on to do:
- Put a trace ID into a log line (section 3.2 code), then pull that ID with a LogQL line filter (`{namespace="mlops"} |= "<trace_id>"`) and confirm the lines come back.
- Run the section 1.3 LogQL error-rate query and then deliberately misspell one label to see the silent empty result.
- Run `kubectl describe pod <name>` and `kubectl get events -n <ns>` on a pod that fails to start; note the one-hour Event window (section 1.7).
- Send a parent and a child span with the section 6.7 snippet, then search for them in Tempo or Grafana (section 6.8).
