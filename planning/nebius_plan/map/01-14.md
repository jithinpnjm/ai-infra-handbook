# 1.14 Boot: firmware, GRUB, kernel, initramfs
Words: ~14,900 | Read time: ~99 min | File: /Users/jithinpjoseph/Documents/GitHub/ai-infra-handbook/docs/part-01-linux/14-boot-firmware-grub-kernel-initramfs.md

One-line purpose: Walks the boot chain from firmware to `init` so you can find which stage failed on a node that will not boot, repair GRUB and initramfs, and set up PXE and NFS-root for diskless GPU fleets.
Beginner friendly: partly. Section 1 (the seven stages) and section 7 (the symptom table) are readable cold. The GRUB internals, MBR byte layout, PXE config and SysV init are intermediate or historical. Read 1.12 (partitions, GPT, ESP, fstab) first, and 1.10 for kernel modules.
Nebius rounds served: R1 (boot and console troubleshooting, GRUB, kernel parameters, initramfs shell, lost-password drill), R2 (GPU node boot failures: driver missing after kernel update, Secure Boot and DKMS, fleet kernel policy, PXE for node provisioning), R3 (fleet provisioning and boot storms as a design topic), R4 (how you built or ran your own node images)

Read in full: section 1 (the stages), section 2 "Secure Boot" and "Hardware/firmware settings", section 4 "Kernel parameters" table, section 5 (initramfs and "Dropped to an initramfs shell"), section 7 (the symptom table and the "How it fails" recovery routine), section 10 "Boot storms" and the PXE "Debugging" bullet, and section 11 (GPU node patterns). Hands-on to do:
- `[ -d /sys/firmware/efi ] && echo UEFI || echo BIOS; efibootmgr -v; cat /proc/cmdline; uname -r`. Note the boot mode, the boot entries and the kernel parameters.
- `journalctl -k | grep -E 'Command line|Run /init|mounted filesystem'` and `systemd-analyze blame | head`. Explain each milestone in your own words.
- In a disposable VM: `lsinitramfs /boot/initrd.img-$(uname -r) | grep -E 'nvme|virtio|dm-|raid'`, then rebuild with `update-initramfs -u` (Ubuntu) or `dracut -f` (RHEL).
- Add `console=ttyS0,115200n8` through `/etc/default/grub`, run `update-grub`, reboot, then confirm with `cat /proc/cmdline` (lab step C). Undo it afterwards.
