# 1.2 The command line: shells, commands, pipes and redirection

One-line purpose: Teaches how a shell turns a typed line into a running program (split, expand, redirect, find, run), plus the exit-code, environment, and error-message rules that explain most "works in my shell, fails in the job" incidents.
Beginner friendly: yes, it starts from zero and uses concrete examples. It is dense in places (the command forms in section 3.1 and startup files in section 8.2), so read those in pieces. Read chapter 1.1 first for processes and syscalls.
Nebius rounds served: R1, R2
Chapter verdict: READ-SECTIONS (2, 2.1, 2.2, 3.1, 3.2, 5, 6, 7, 7.1, 8, 10, How it fails) because R1 tests shell and console skills directly and the rest is reference. Skip the trivia and the rest of the reference tables once you can predict expansions.

Hands-on to do:
- `file="my report.txt"; printf '<%s>\n' $file; printf '<%s>\n' "$file"` and predict the output before running.
- `ls /tmp /nope > both.txt 2>&1`, then compare with `ls /nope 2>&1 > out.txt`, and explain by the left-to-right rule.
- `false | cat; echo $?`, then `set -o pipefail; false | cat; echo $?`, then `echo ${PIPESTATUS[@]}` after a pipeline.
- `bash -c 'kill -9 $$'; echo $?` (expect 137) and `sleep 100` interrupted with Ctrl-C then `echo $?` (expect 130).
- `type -a python3; command -v python3; echo "$PATH" | tr ':' '\n'`, and `set -o noclobber` followed by `sort f > f` to see the safety net.

Likely interview questions from this chapter:
1. Walk me through what the shell does between you pressing Enter and a program starting.
2. A filename has a space in it and `cp $src /backup` fails. Why, and how do you fix it?
3. What is the difference between `cmd > out.txt 2>&1` and `cmd 2>&1 > out.txt`?
4. A batch job reports success but a middle stage failed. How would you make the script catch it?
5. A Kubernetes pod exited with code 137. What happened and what do you check first?
6. A command works in my terminal but fails inside the Slurm job. What would you check, and why?
