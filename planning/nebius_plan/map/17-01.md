# 17.1 Observability foundations: metrics, logs and traces
Words: 9200 | Read time: 61 | File: /Users/jithinpjoseph/Documents/GitHub/ai-infra-handbook/docs/part-17-operations/01-observability-foundations-metrics-logs-and-traces.md
One-line purpose: Sets the three pillars (metrics, logs, traces), the RED and USE methods, the cardinality budget, and the failure patterns that every later observability and alerting chapter builds on.
Beginner friendly: partly. The ideas are plain and the analogies help, but it assumes you know what Prometheus, a pod and an SLO are. Read 17.2 (Prometheus and Grafana) alongside it, or first skim a Prometheus glossary, because the examples are PromQL-heavy. It also points to Chapters 1.23, 16.10 and 16.14 as prerequisites; 1.23 (USE method) is the one to read first if you can.
Nebius rounds served: R2, R3, R4
Chapter verdict: READ-SECTIONS (1, 2, 4.1-4.2, 6), because the three pillars, RED/USE, cardinality and failure modes are the core SRE vocabulary; section 3 and 5 can be skimmed for recall, and the lab is optional for this interview.

Hands-on to do:
- Count cardinality by hand: for a metric with labels method (10), status (10), path (100), confirm 10,000 series; then decide which label to drop (section 2.1-2.2).
- Exercise 1 of the chapter: add a label with 10,000 values to a counter, then watch `prometheus_tsdb_head_series` in Prometheus, and remove the label.
- Run the section 7.6 queries: `curl http://prometheus.monitoring:9090/api/v1/query?query=up | jq .` and the Loki curl (`curl -G .../loki/api/v1/query --data-urlencode 'query={job=...}'`); if you have no cluster, run the Prometheus query against a local Prometheus.
- Install kube-prometheus-stack with the section 7.2 Helm command on a scratch cluster and check that Grafana loads (note the lab is untested per the chapter).
