# 1.7 Packages, repositories and software installation

One-line purpose: Explains how packages, repositories, signatures, shared-library lookup and source builds work, and why package drift breaks GPU nodes.
Beginner friendly: partly. It assumes shell (1.2), directory layout (1.3) and users/sudo (1.6). Read 1.2, 1.3 and 1.6 first.
Nebius rounds served: R1, R2 (R4 only if your own project involves node builds)
Chapter verdict: READ-SECTIONS. The package layer, shared-library lookup, the GPU version-pinning section and the troubleshooting list are interview material. The scripting-language survey, InfiniBand/OFED and the cluster-hardware details are not.

Hands-on to do:
- On Ubuntu: `dpkg -S /usr/bin/ssh`, `apt policy openssh-client`, `sudo apt install -s tree`, then remove and purge `tree` and note `rc` in `dpkg -l tree`.
- `sudo debsums -s` (or `sudo dpkg --verify openssh-server`), then `apt-file search zlib.h` and build a `z.c` that includes `<zlib.h>` before and after `zlib1g-dev`.
- Build GNU hello into `$HOME/opt/hello-2.12.1` with `./configure --prefix`, `make -n install`, `make install`, then `ldd` it.
- Shared-library drill: make `libgreet.so`, see `cannot open shared object file`, then fix it with `LD_LIBRARY_PATH=.` once and with `-Wl,-rpath='$ORIGIN'` permanently (check with `readelf -d`).
- Makefile drill: run `make` twice, `touch greet.c && make`, then replace a tab with spaces and read the `missing separator` error.
