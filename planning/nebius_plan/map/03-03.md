# 3.3 Idiomatic Python: the data model, comprehensions, generators
Words: ~14,100 | Read time: ~94 min (about 45 min if you read only the READ-SECTIONS rows) | File: docs/part-03-python/03-idiomatic-python-the-data-model-comprehensions-generators.md
One-line purpose: Teaches the Python data model (special methods), sequence, mapping and set types, references and copies, first-class functions, comprehensions and the iterator and generator protocol, using streaming and pagination examples that matter for log and API work.
Beginner friendly: partly. Read 3.1 (names, mutability, collections) and 3.2 (imports) first. The chapter assumes you already know what a list and a dict are.
Nebius rounds served: R1 (Python scripting: streaming large logs in constant memory, comprehensions, dict and set choices, copy semantics), R2 (DevOps tooling: paginated APIs, batching, context managers for cordon and drain), R4 (reviewing your own code for idioms and bugs).
Chapter verdict: READ-SECTIONS (context managers, mappings and sets, text vs bytes, references and copies, comprehensions, the iterator protocol, generator functions, pipelines, EAFP, the infrastructure examples, 12 and 13). These are the parts a scripting round tests and that you will use to read other people's code. The data-model table, the NodeInventory and Vector walkthroughs, the scramble/permute and Strategy-pattern sections, and most of the lab are optional depth.

Hands-on to do:
- `python3 code/part03/python_idiomatic_data_model_lab.py` (the chapter's self-check lab; confirm the file exists in the repo first).
- Single-pass generator: `g = (c * 4 for c in 'hack'); print(list(g), list(g))` shows the second list is empty.
- Tuple puzzle: `python3 -c "t=(1,2,[30,40])
try: t[2]+=[50,60]
except TypeError as e: print(e)
print(t)"` (write it as a file if your shell mangles the newlines), then check the bytecode with `python3 -m dis` on `s[a] += b`.
- Shallow vs deep copy on a class holding a list: `copy.copy` and `copy.deepcopy`, then `drain` on the original and inspect each copy.
- Pipeline test: generate a few gzip log files, then run the `files`, `lines`, `parse`, `errors` generators and a `Counter`. Measure memory with `/usr/bin/time -v` (on macOS use `/usr/bin/time -l`).
- `python3 -m timeit -s 'xs=list(range(10**5))' '99999 in xs'` against the same test on a `set`, to see the O(n) vs O(1) gap.
