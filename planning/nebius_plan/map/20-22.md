One-line purpose: Explains what each serving tool is for (engine, server or orchestrator), the memory and latency knobs an SRE must defend, the start-up phases, what health endpoints prove, upgrade risks and which engine metrics to read during an incident.
Beginner friendly: partly. The first sections are readable, but the memory arithmetic and parallelism need GPU and model basics. Read first: Part 15 chapter 01 (anatomy of an inference request) and 02 (batching, KV cache and quantisation), Part 15 chapter 03 (vLLM in depth) and 06 (Triton), Part 5 chapter 07 (Deployments and rolling updates) and 09 (kubelet, probes and eviction), and Part 11 chapter 06 (GPU scheduling, as cited). Then 20.12 for the KV-per-token formula used in section 3 and 20.18 for the failure modes these knobs cause.
Nebius rounds served: R2 (primary: Kubernetes troubleshooting and the "pod OOMs at start" and probe-kill cases), R3 (engine choice and capacity in design), R4 (project deep dive on the engine you ran), R1 (only the nvidia-smi and log-reading habits)
Chapter verdict: READ-SECTIONS. Read sections 1, 3, 7, 8, 10, the "How to answer out loud" block, Scenario B and the drills in full; read sections 2, 4, 5, 6, 9 and 11 once each and Scenarios A and C quickly; read the Deployment YAML probes section once; skim the reviewer code (read its rule names and the test list only); skip sources and the verification log.

Hands-on to do:
1. `python3 -m pytest -q code/part20/test_c22_vllm_config_review.py` (expect 19 passed).
2. `python3 code/part20/c22_vllm_config_review.py --gpus-per-node 1 --gpu-arch hopper --kv-cache-tokens 389100 -- vllm serve m --max-model-len=16384 --max-num-seqs=128 --max-num-batched-tokens=8192 --gpu-memory-utilization=0.90`. Read the "max-num-seqs=128 is above 23.75" finding and explain it.
3. Run the same reviewer on a command with `--tensor-parallel-size 16 --no-enable-chunked-prefill --max-num-batched-tokens 4096 --max-model-len 32768 --quantization fp8 --prefix-caching-hash-algo xxhash` and read every finding (two errors, three warnings).
4. `kubeconform -strict -summary -kubernetes-version 1.31.0 code/part20/c22_vllm_deployment.yaml`. Then change `failureThreshold: 90` to a string and read the error message.
5. Only on a GPU host: start the pinned vLLM image, read the start-up log for "GPU KV cache size" and "Maximum concurrency", and check `curl -i localhost:8000/health`.
