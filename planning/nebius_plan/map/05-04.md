# 5.4 Bare-metal Kubernetes from scratch with kubeadm (lab)
Words: 15,200 | Read time: 101 | File: docs/part-05-kubernetes/04-bare-metal-kubernetes-from-scratch-with-kubeadm-lab.md
One-line purpose: A step-by-step kubeadm build of a multi-node cluster (node prep, containerd with SystemdCgroup, kubeadm init phases, CNI, worker join with TLS bootstrap, HA with kube-vip, GPU worker, troubleshooting table), with a lab checklist.
Beginner friendly: partly. The reader must already know the Linux basics (swap, modules, sysctl, systemd services) and 5.1 to 5.3. Sections 2 and 3 are concrete but dense; section 8 onward (cloud and laptop options, operator-based add-ons) is the weakest part for a beginner. A Mac user needs Linux VMs (Multipass, Lima or UTM) or a kind cluster for the hands-on, because kubeadm runs on Linux only.
Nebius rounds served: R2 (kubeadm and node troubleshooting table, kubelet and cgroup mismatches, CSR and TLS errors, reset procedure), R3 (control-plane topology, etcd member replacement, why an odd count), R1 (Linux node preparation: sysctls, br_netfilter, swap, time sync, cgroup v2 check), R4 (bare-metal GPU cluster build and rationale for own project)
Chapter verdict: READ-SECTIONS. Read sections 2, 3, 5, 7 (members and quorum part), 9 (GPU worker) and 11 (troubleshooting) in full, since they are the R1 and R2 material. Read section 1 (bare metal vs virtualized, compute and network planning) once for R3 capacity answers. Skim sections 4, 6 and 10 for commands. Skip section 8's cloud and laptop walkthroughs, the editor and GUI tools, and the Raspberry Pi note.

Hands-on to do:
- On a Linux VM (a Mac user needs Multipass, Lima or UTM; kubeadm does not run natively on macOS): run the section 2 preflight. Check with `stat -fc %T /sys/fs/cgroup` (expect `cgroup2fs`), `swapon --show` (expect nothing), `lsmod | grep br_netfilter`, and `sysctl net.bridge.bridge-nf-call-iptables`.
- Run `sudo kubeadm init --config kubeadm-config.yaml`, then `ls /etc/kubernetes /etc/kubernetes/manifests /etc/kubernetes/pki` and `sudo kubeadm certs check-expiration`. Name each file you see.
- Join a second VM with `kubeadm token create --print-join-command` and `kubectl get nodes`. Then run `kubectl get csr` and approve any pending serving request with `kubectl certificate approve <name>`, followed by `kubectl logs` on a test pod.
- Break it on purpose: set `SystemdCgroup = false` in containerd and watch the kubelet behave, then restore it. Run `sudo kubeadm reset -f` on the lab node only, then read the cleanup list in section 11.
- Optional GPU check if a GPU VM exists: `kubectl get nodes -o json | jq '.items[] | {name:.metadata.name, gpu:.status.allocatable["nvidia.com/gpu"]}'`.

Notes for the reader (verify before relying on them):
- The chapter uses kubeadm config API `v1beta4` with Kubernetes `v1.30.4`. Check that your kubeadm version supports that API version.
- The kind example uses `kind get kubeconfig-path`, which is an old command. Current kind docs may differ.
- Checkpoint 13 says kubeadm detects `systemd-resolved` automatically. The chapter does not show that, so verify it.
