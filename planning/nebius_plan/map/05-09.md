Hands-on to do:
- Read the live node config: `kubectl get --raw "/api/v1/nodes/<node>/proxy/configz" | jq .kubeletconfig`, then `kubectl describe node <node> | grep -A8 -E 'Capacity|Allocatable'` and compare allocatable with capacity minus reservations.
- Find the cgroup tree on a worker: `systemd-cgls` and `systemd-cgtop`, then `cat /sys/fs/cgroup/kubepods.slice/memory.max` and check a pod's `cpu.weight` against its requests.
- Make an OOM and read it: a pod with `limits.memory: 100Mi` running a memory hog; then `kubectl describe pod <name>` (Last State: OOMKilled, exit 137) and `dmesg -T | grep -i oom` on the node.
- Follow the node's health signals: `journalctl -u kubelet -f` during a test, and `kubectl get csr` to spot serving CSRs waiting for approval.
- Offline: `python3 code/part05/kubelet_node_managers_lab.py` (CPU manager static, topology hint intersection, memory eviction victim ranking).
