# 5.3 Kubernetes architecture overview: components and what talks to what
Words: 13,500 | Read time: 90 | File: docs/part-05-kubernetes/03-kubernetes-architecture-overview-components-and-what-talks-to-what.md
One-line purpose: Gives the whole-cluster map: control-plane and node components, the two rules (only the API server touches etcd; components coordinate through watched objects), the kubectl-to-container relay, HA and failure timelines, and extension points.
Beginner friendly: partly. Read 5.1 and 5.2 first (the chapter itself assumes them). After that the big-picture diagram, the component list and section 6 (the relay) are readable for a beginner; section 7 (HA timelines) and section 10 (GPU cluster design) need more practice.
Nebius rounds served: R2 (control-plane and node failure diagnosis, the spec-versus-status method, taints and evictions), R3 (HA topologies, etcd quorum, control-plane scaling for bursts, 5,000-node limits), R4 (cluster architecture for own project), R1 (what runs on a node, which ports, which tool)
Chapter verdict: READ-SECTIONS. Sections 1, 2, 3 (Capacity/Allocatable and Conditions only), 5, 6, 7 and 14 are must-reads for R2 and R3. Section 4 (ports) is a recall table. Sections 8 and 9 are skim-for-recall. Section 10 is the GPU design answer and should be read once before R3. Skip the historical and Borg material in section 1 except the five benefits.

Hands-on to do:
- On a kind cluster: `kubectl get pods -n kube-system -o wide`, then `kubectl get --raw='/readyz?verbose' | head -30` to see the API server's etcd check.
- Watch the relay: run `kubectl get events -w` in one terminal and `kubectl create deployment web --image=nginx --replicas=3` in another, then match each event to a component (ReplicaSet, scheduler, kubelet).
- Spec versus status: `kubectl scale deploy web --replicas=5`, then `kubectl get deploy web -o jsonpath='{.spec.replicas} {.status.readyReplicas}'`. Delete one pod with `kubectl delete pod <name>` and watch the ReplicaSet recreate it.
- Find leader election: `kubectl get lease -n kube-system` and read `holderIdentity` for `kube-scheduler` and `kube-controller-manager`.
- Read the node: `kubectl describe node <node>` and compare Capacity with Allocatable. Work out the reserved amount.
