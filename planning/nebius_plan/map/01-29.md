# 1.29 Remote administration reference: SSH server and client options, host-based authentication, parallel shells, screen and tmux, IPMI and console managers
Words: 10896 | Read time: ~73 | File: docs/part-01-linux/29-remote-administration-reference-ssh-server-and-client-options-host-bas.md

One-line purpose: A reference for administering many machines remotely: how SSH authenticates and encrypts, how to configure the client and server safely, how to run commands on hundreds of nodes, keep sessions alive in screen or tmux, and reach a dead machine through its BMC (IPMI, SOL, conman, iKVM).

Beginner friendly: partly. The SSH login sequence and the key basics are readable by a beginner, but the reader should first work through 1.5 (SSH keys, ~/.ssh/config, tmux basics) and 1.6 (permissions), which the chapter itself requires. The sshd Match, host-based authentication and IPMI user-setup sections are intermediate.

Nebius rounds served: R1, R2

Chapter verdict: READ-SECTIONS (§1 out-of-band prep; §2 SSH session sequence and host keys; §3 key permissions and the append rule; §4 client options and Host blocks (lookup only); §6 sshd_config essentials and the lock-out warning; §7 restricting a key with from= and command=; §8 pdsh and clush fan-out; §9 screen/tmux start-or-attach only; §10 ipmitool basics and security; "How it fails" section in full), because lock-out-safe sshd changes, fan-out limits and BMC access are the day-to-day SRE skills for R1 and R2; host-based authentication, the full screen/tmux key tables, the iKVM section and the exercise and checkpoint blocks are skim-only.

Hands-on to do:
1. Read the SSH handshake yourself: `ssh -vvv <host> true` and find the key exchange, host-key check, offered auth methods, and the accepted key. Then `ssh-keygen -lf ~/.ssh/id_ed25519.pub` for the fingerprint (Part A, steps 1-2). A local `localhost` login works if Remote Login is on.
2. Harden sshd safely: copy `/etc/ssh/sshd_config` to a scratch file, edit `PasswordAuthentication no`, `PermitRootLogin no`, and an `AllowGroups` line, then `sshd -t -f <copy>`. Apply on a throwaway VM only, with a second session open, and test a key login before closing the old session (Part B, step 4).
3. Fan out safely: `pdsh -w node-[01-03] -f 1 'sleep 2; uptime'` versus `-f 10`, then `| dshbak -c`. Add one unreachable host and show the effect of `ConnectTimeout` (Part D, steps 9 and 11).
4. Keep a session alive: `tmux new -A -s 0`, run a long command, detach with `Ctrl-b d`, reattach with the same command from a new SSH connection (Part E, step 12).
