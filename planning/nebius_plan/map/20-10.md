# 20.10 Complexity, latency numbers and measuring your own code
Words: 8759 | Read time: 58 | File: docs/part-20-nebius-sre-interview/10-complexity-latency-numbers-and-measuring-your-own-code.md
One-line purpose: Teaches how to state Big-O with named variables, quote measured Python costs, use the latency ladder and fan-out tail arithmetic, and measure code with timeit and cProfile instead of guessing.
Beginner friendly: partly. Big-O and the latency ladder are explained from first principles; the Python cost table and cProfile output assume the Python from 20.8. Read first: 20.8 (coding round process) and Part 3 `12-objects-types-and-data-structures-in-depth.md`. For the availability and error-budget arithmetic, read 20.19 first. For the tail-latency section, read 20.21 (hedging) after.
Nebius rounds served: R1 (complexity follow-up in the coding round), R3 (estimation, availability arithmetic, fan-out tail), R2 (profiling and measuring a slow service)
Chapter verdict: READ-SECTIONS (1, 2, 4, 5, 6, 8, 10, "How to answer out loud", Scenarios A and B, Drill questions). SKIM 3, 7 and 9 for recall. SKIP the Sources and Verification log. Reason: the complexity follow-up and the fan-out tail are the two ideas most likely to be asked; the rest is supporting measurement.
