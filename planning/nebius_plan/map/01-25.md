# 1.25 Benchmarking correctly
Words: 13156 | Read time: ~88 | File: docs/part-01-linux/25-benchmarking-correctly.md

One-line purpose: Teaches how to tell a trustworthy performance number from a misleading one (active benchmarking, sanity checks, six-question checklist, load-test method), then applies it to CPU, memory, storage, network, GPU, NCCL, training and LLM inference.

Beginner friendly: partly. The ideas (sanity arithmetic, "why not double?", p99 vs mean) are learnable by a beginner; the tool sections assume Linux perf tools and GPU/NCCL basics. Read 1.23 (methodology/USE) and 1.24 (observability: iostat, perf, bpftrace) first. Read the chapter's 1.12-1.14 storage basics before the fio section.

Nebius rounds served: R1, R2, R3, R4

Chapter verdict: READ-SECTIONS (§1, §2 table, §4 active/ramp/checklist/questions, §5 procedure, §6.3 fio rules, §6.5-6.8 GPU/NCCL/inference trap lists, §7 sanity arithmetic and statistics, §8 worked examples, §11) because the reader needs the method and the traps for R1 and R3 numbers, but not every tool's flag list; §6.1, §6.2, §6.4, §6.9, §6.10 and the checkpoint/exercise blocks are skim-only.

Hands-on to do:
1. Write an env dump script (uname -a, lscpu, numactl -H, lspci -vv, cat /proc/cmdline, nvidia-smi -q if a GPU) and run it before every benchmark (step 1).
2. Make a 2 GiB file and run `fio --rw=read --bs=1M` with and without `--direct=1`; compare with `iostat -x 1` to see the page cache effect (step 2).
3. Run a steady-state check of the bundled arithmetic: 50,000 IOPS x 8 KiB against 1 GbE (section 7a) by hand, then in the chapter's Python lab (`python3 code/part01/benchmarking_correctly_lab.py`, path inside the book repo, not checked here).
4. Interleave two runs of the same tool 10 times each and compute median and MAD (step 14).
