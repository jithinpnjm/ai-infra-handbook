# 1.3 Files and the directory hierarchy: paths, links, inodes

One-line purpose: Explains how Linux names, stores and links files (paths, FHS layout, inodes, hard and symbolic links, timestamps, find, tar) and the filesystem failures that look like something else, such as "disk full" with free space.
Beginner friendly: yes, mostly. It builds from paths to inodes step by step. Read chapter 1.2 first for the shell side. The inode and link sections need careful reading, and the labs are easier if you already run `ls -l` comfortably.

Hands-on to do:
- `echo hello > a.txt; ln a.txt b.txt; ls -li a.txt b.txt; rm a.txt; cat b.txt` (same inode, then the data survives).
- `stat f1`, then `chmod 600 f1`, then `stat f1` again, and confirm that only ctime moved.
- `sudo mount -t tmpfs -o size=10m,nr_inodes=200 tmpfs /mnt/t` and fill it with `touch`; compare `df -h /mnt/t` with `df -i /mnt/t` (needs sudo; clean up with umount).
- `sudo dd if=/dev/zero of=/tmp/big bs=1M count=200; sleep 600 < /tmp/big & rm /tmp/big; sudo lsof +L1 | grep big`, then `kill %1` and watch space return.
- `tar -czf a.tar.gz dir; tar -tzf a.tar.gz; tar -xzf a.tar.gz -C /tmp/out; diff -r dir /tmp/out/dir`.
