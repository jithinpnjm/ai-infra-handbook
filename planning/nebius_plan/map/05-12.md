# 5.12 Ingress, load balancers and the Gateway API
Words: 14,600 | Read time: 97 | File: docs/part-05-kubernetes/12-ingress-load-balancers-and-the-gateway-api.md
One-line purpose: How traffic gets into a cluster: L4 versus L7 balancing, Ingress and its controllers, the Gateway API (GatewayClass, Gateway, HTTPRoute, ReferenceGrant), cert-manager TLS, bare-metal load balancers, and the edge settings an LLM streaming endpoint needs.
Beginner friendly: partly. Read 5.10 (Services) and 2.10 and 2.20 (HTTP and TLS) first. The layers section and the Gateway API roles table are readable after that. The Contour install, sample Services and host and path walk-throughs are reference material.

Hands-on to do:
- List and inspect the edge objects: `kubectl get ingressclass,ingress -A`, `kubectl describe ingress llm-api -n serving`, `kubectl get gatewayclass,gateway,httproute -A`, and `kubectl describe httproute chat -n serving | sed -n '/Status/,$p'` (look at `Accepted` and `ResolvedRefs`).
- Test a route before DNS: `curl -vk --resolve llm.example.com:443:<LB-IP> https://llm.example.com/v1/models`. Then check streaming without buffering: `curl -N -H 'Accept: text/event-stream' https://llm.example.com/v1/chat`.
- Check the certificate: `openssl s_client -connect <LB-IP>:443 -servername llm.example.com </dev/null | openssl x509 -noout -dates -subject -issuer`, then `kubectl get certificate,certificaterequest,order,challenge -A` and `kubectl describe challenge <name>` if issuance is stuck.
- Read the controller's view: `kubectl -n ingress-nginx logs deploy/ingress-nginx-controller --tail=100` (or the equivalent for your controller). Check for 502 and 504 patterns against the status table in section 7.
- Offline: `python3 code/part05/gateway_llm_router_lab.py` (HTTPRoute precedence and ReferenceGrant, streaming config validator, endpoint picker).
