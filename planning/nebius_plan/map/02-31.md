# 2.31 Network monitoring and telemetry for AI data centers
Words: ~9,100 | Read time: ~61 min | File: docs/part-02-networking/31-network-monitoring-and-telemetry.md
One-line purpose: Explains which network signals to collect (SNMP, gNMI, probes, flows, IFA), how to build a Prometheus-based stack, which AI-fabric signals and alerts matter, and how to run the monitoring system itself without pager fatigue.
Beginner friendly: partly. Read 2.22 (ip, ss, counters) and 2.19 (ECN, PFC) first. Prometheus basics (scrape, labels, counter vs gauge) are assumed, so read Section 3 "Prometheus model" slowly.
Nebius rounds served: R1 (network monitoring basics), R2 (Prometheus, PromQL, alerting, SRE practice), R3 (SLOs, failure domains, monitoring not sharing fate with the system), R4 (own-project observability).
Chapter verdict: READ-SECTIONS (sections 1, 2 table, 3 "Prometheus model", 4 signals table and alert design, 6 "Correlating switch and server telemetry", 7 cardinality and retention, sections 9 and 10, then skim section 5 IFA and the rest). For an SRE interview, the signal table, PromQL pattern and alert design carry the answers; IFA is niche. The checkpoint Q&A repeats the body, so skim it.

Hands-on to do:
- `python3 code/part02/network_monitoring_telemetry_lab.py` (the chapter's self-check lab; confirm the file exists in the repo before you rely on it).
- Run `node_exporter --collector.netdev --collector.netstat --collector.softnet` locally, then `curl -s localhost:9100/metrics | grep node_network_receive_bytes_total` to see the raw counter.
- In Prometheus, query `rate(node_network_receive_bytes_total{device=~"ens.*"}[1m]) * 8 / 1e9` and `rate(node_network_receive_errs_total[5m]) > 0`.
- On a lab VM, add loss with `tc qdisc add dev eth0 root netem loss 3%`, run `iperf3`, and watch the drop and retransmit counters respond. Remove it with `tc qdisc del dev eth0 root`.
- Write and test a `Watchdog` (always-firing) alert and a `LinkFlapping` alert with `changes(...[10m]) > 2` and `for: 1m`.

Likely interview questions from this chapter:
- How would you monitor a 4,000-GPU RoCE fabric? Which metrics matter, and at what resolution?
- SNMP polling or streaming telemetry: what are the differences, and when do you use each?
- How do you detect a slow rail or a failing optic before it takes a job down?
- How would you design alerts for PFC storms and ECN/CNP anomalies?
- How do you avoid alert fatigue, and how do you make sure the monitoring system itself is reliable?
- Explain cardinality in Prometheus and how you control it.
