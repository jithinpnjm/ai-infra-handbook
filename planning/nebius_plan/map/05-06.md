# 5.6 Controllers and the reconcile loop: how Kubernetes thinks

Hands-on to do:
- Trace the ReplicaSet chain: `kubectl create deployment web --image=nginx:1.27 --replicas=3`, then `kubectl get rs -l app=web -o jsonpath='{range .items[*]}{.metadata.name}{" owner="}{.metadata.ownerReferences[0].name}{"\n"}{end}'`.
- Watch self-healing: in a second terminal run `kubectl get pods -l app=web -w`, then `kubectl delete pod -l app=web --wait=false`.
- Quarantine a pod without losing capacity: pick one pod, run `kubectl label pod <name> app-`, then check that a replacement appears and the old pod keeps running. Remove the orphan when done.
- Rollout and rollback: `kubectl set image deploy/web nginx=nginx:1.27.1`, `kubectl rollout status deploy/web`, `kubectl rollout history deploy/web`, `kubectl rollout undo deploy/web`.
- Leader check: `kubectl get lease -n kube-system` and read `holderIdentity` for `kube-controller-manager`. On a kubeadm control plane, you can stop the leader's static pod and watch the holder change.
- For a stuck namespace (in a lab only): `kubectl get ns <name> -o json | jq .status.conditions` and `kubectl get apiservices` to look for `AVAILABLE=False`.

Notes to verify before quoting (the chapter's numbers come from its own text):
- Checkpoint 18 says the kube-controller-manager resync default is 10 hours. Some Kubernetes versions use a different default (about 12 hours). Check your version.
- Checkpoint 17 treats `workqueue_retries_total` as the same thing as `controller_runtime_reconcile_errors_total`. These are different metrics. Check the metric names in your controller framework.
- Checkpoint 9 gives the out-of-service taint with the value `nodeshutdown`. Confirm the taint value in the current docs before you use it in a runbook.
