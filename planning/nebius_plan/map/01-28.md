# 1.28 Putting it together: tuning a Linux node for GPU and HPC work
Words: 14014 | Read time: ~93 | File: docs/part-01-linux/28-putting-it-together-tuning-a-linux-node-for-gpu-and-hpc-work.md

One-line purpose: Capstone of Part 1. A layered playbook (topology, firmware, boot params, sysctl/limits, memory, CPU/IRQ placement, GPU driver, containers/K8s/Slurm, config-as-code, node audit, troubleshooting map) for making a GPU server deliver its hardware capability, proving it, and keeping a fleet uniform.

Beginner friendly: no. This is advanced material that assumes the earlier Part 1 chapters. Read first: 1.17 (virtual memory, NUMA, huge pages), 1.18 (cgroups, CPU scheduling), 1.22 (kernel modules, sysctl), 1.23 to 1.25 (USE method, benchmarking), 1.14 (boot and GRUB), 1.12-1.13 (disks, NVMe), and 1.19 (containers). Skim 1.26-1.27 for virtualisation context only.

Nebius rounds served: R1, R2, R3, R4

Chapter verdict: READ-SECTIONS (§1 stack and principles; §2 topology commands and `nvidia-smi topo -m` codes; §4 boot parameters and their contested items; §5 sysctl/limits/service-order gotchas; §6 pinning and OOM; §7 NUMA/IRQ placement concepts (skip code bodies); §8 GPU driver settings table; §9 K8s and Slurm mechanism tables; §10 provisioning, drift, fleet health; §11 audit script; §12 case study; §13 troubleshooting map), because this is the chapter that maps almost one-to-one to an SRE role on GPU nodes; skip the Python helper bodies, the Grace superchip subsection, storage detail, and the checkpoint and exercise blocks unless time allows.

Hands-on to do:
1. Topology report on a GPU node: `lscpu | egrep 'Model name|Socket|Core|Thread|NUMA'`, `numactl -H`, `nvidia-smi topo -m`, `nvidia-smi --query-gpu=index,pci.bus_id,pcie.link.gen.current,pcie.link.gen.max,pcie.link.width.current,pcie.link.width.max --format=csv`, and `lspci -vv -s <BDF> | egrep 'LnkCap|LnkSta'`. Write the GPU to NUMA to NIC table (step 1).
2. Read the live kernel and service state, then compare with the chapter's expectations: `cat /proc/cmdline`, `sysctl -n vm.max_map_count vm.swappiness kernel.numa_balancing`, `cat /sys/kernel/mm/transparent_hugepage/enabled`, `systemctl is-active nvidia-persistenced nvidia-fabricmanager`.
3. Check limits where a job actually runs, not in your shell: `srun ... bash -c 'ulimit -l -n'` or `kubectl exec ... -- sh -c 'ulimit -l -n'` (section 5 and Q6).
4. Run the section 11 audit script with `exp_gpus` set to your GPU count. Expect some FAILs on a default box; each FAIL is a line you should understand. Then `journalctl -k | grep 'NVRM: Xid'` for the Xid check. Also run `python3 code/part01/tune_gpu_node_lab.py` (path inside the book repo, not checked here).
