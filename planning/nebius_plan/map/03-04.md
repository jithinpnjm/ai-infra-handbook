# 3.4 Classes, dataclasses, typing and protocols
Words: ~16800 | Read time: ~110 min (full read) | File: docs/part-03-python/04-classes-dataclasses-typing-and-protocols.md
One-line purpose: Teaches Python classes as software design (attributes, inheritance and MRO, composition, ABCs and Protocols, dataclass and pydantic record builders, type hints, operator overloading) and ends with design habits for infrastructure code.
Beginner friendly: partly. Assumes 3.1 (functions) and 3.3 (data model, dunder methods). Sections 1 and 2 lean on Learning Python and Fluent Python digests that are dense for a rusty reader; the dataclass, Protocol and design sections are self-contained.
Nebius rounds served: R1 (small typed scripts and classes), R2 (typed API/config clients for DevOps tooling), R4 (own project design, "why composition", config validation)
Chapter verdict: READ-SECTIONS. A rusty Senior SRE can skip most of the book-digest prose and the operator-overloading and variance material; read the inheritance/MRO rules, composition, ABC vs Protocol, the dataclass and pydantic examples, the design habits, common mistakes and interview angles (about 40 min of the 110).

Hands-on to do:
- `python3 code/part03/python_classes_typing_protocols_lab.py` (the chapter's self-checking lab; run it and read any failure).
- Build a dataclass with a list default with no `default_factory`, and confirm dataclasses rejects it; then fix it with `field(default_factory=list)`.
- Write a `NodeSpec` pydantic model with `extra="forbid"`. Load a YAML with a typo (`timout`) and a string `gpus: "8"`, and print `e.errors()`.
