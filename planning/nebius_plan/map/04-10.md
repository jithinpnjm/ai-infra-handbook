# 4.10 Debugging Ansible playbooks
Words: ~11,600 | Read time: 77 min | File: docs/part-04-automation/10-debugging-ansible-playbooks.md
One-line purpose: Gives a layered method for diagnosing a failed run (parse, connection, data, privilege/module, application), with the verbosity levels, debug/assert tools, SSH and sudo failure tables, and a way to reproduce a module by hand on the target.
Beginner friendly: partly. This is the most useful chapter for a Linux-beginner reader because the layered method and the connection/privilege tables are plain troubleshooting. The SSH agent-forwarding and host-key paragraphs assume basic SSH from Part 1. Read 04-03 section 8 (first 30 minutes of connection troubleshooting) first, as a short warm-up.

Hands-on to do:
- `python3 code/part04/ansible_debugging_toolkit_lab.py` from the handbook root (folder exists there). Expect 2 checks to pass.
- Connectivity and interpreter check: `ansible <host> -m ansible.builtin.command -a 'which python3' -vvv`, then read the `SSH: EXEC` line.
- Reproduce `UNREACHABLE` on purpose: set a wrong `ansible_user`, read the message, then run `ssh -vvv user@host` and `nc -vz <host> 22` to isolate the layer.
- Keep the module wrapper: `ANSIBLE_KEEP_REMOTE_FILES=1 ansible <host> -m ansible.builtin.copy -a "src=./x dest=/tmp/x" -vvv`. Log in to the host, run `python3 AnsiballZ_copy.py explode` and then `execute` in that folder. Delete the folder afterwards.
- Break a quote on purpose (`msg: Failed: x`), run `--syntax-check` and `yamllint`, then compare the two messages.
- Triage a failing run: `ansible-playbook site.yml 2>&1 | grep -E "fatal:|FAILED" | sed 's/.*=> //' | sort | uniq -c | sort -rn`.

Likely interview questions from this chapter:
1. A playbook works on most hosts but fails on a few. How do you debug it?
2. What does each verbosity level add? How do you see the SSH command and the module arguments?
3. How do you run a failing module by hand on the target host?
4. A deployment is slow. How do you find out why, and what do you change first?
5. 40 of 500 nodes failed in a fleet run. What do you do first?
6. A `git` task fails with `Permission denied (publickey)` even though agent forwarding is on. Why?
