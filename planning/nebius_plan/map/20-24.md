# 20.24 Terraform for resilient GPU clusters
Words: ~10,160 (about 15% is HCL and the plan fixture) | Read time: 68 | File: /Users/jithinpjoseph/Documents/GitHub/ai-infra-handbook/docs/part-20-nebius-sre-interview/24-terraform-for-resilient-gpu-clusters.md
One-line purpose: Shows how to build Terraform that makes a GPU cluster hard to break: small module inputs, remote locked state, state split by blast radius, prevent_destroy with moved blocks, a plan risk gate, tests, CI approvals, drift checks, and recovery of a lost state.
Beginner friendly: no on first read. It assumes you can read Terraform resource blocks, plans and state. Read first: Part 4 chapter 18 (Terraform refresher: providers, resources and the workflow), chapter 19 (state in depth: backends, locking and drift), chapter 20 (modules), chapter 21 (loops, conditionals, lifecycle and gotchas), chapter 23 (production-grade structure, testing and team workflows) and chapter 24 (Terraform on GCP and Nebius: networks, GPU VMs and GKE). Also Part 5 chapter 19 (cluster deployment models and day-2 operations) and chapter 20 (upgrades, etcd backup and restore), which carry the node-pool upgrade and state-recovery ideas.
Nebius rounds served: R3 (primary: "design the Terraform for a GPU cluster and stop one bad change from taking out production"), R2 (incident: an apply deleted a node pool), R4 (deep-dive follow-ups on IaC you built)

Hands-on to do:
1. From `code/part20/c24_module`: `terraform init -backend=false`, then `terraform validate` and `terraform fmt -check -recursive`. Expect "Success! The configuration is valid."
2. `terraform test`. Expect 4 passed. Read `tests/c24_pools.tftest.hcl` and note how `expect_failures` proves each guard rejects bad input.
3. From `code/part20`: `python3 -m pytest -q test_c24_plan_risk.py` (expect 18 passed), then `python3 c24_plan_risk.py c24_fixtures/c24_plan_delete_nodegroup.json` and check the CRITICAL line and exit code 1.
4. Remove `gpu` from the pools in a scratch copy with a hand-written state, run plan, and read the "Instance cannot be destroyed" error. Then add a `moved` block in the scratch copy and show the destroy disappears.
5. Optional drift check: in a scratch folder with the hashicorp/local provider, run `terraform plan -refresh-only -detailed-exitcode` before and after editing the file by hand (exit 0, then 2). This needs the provider download.
