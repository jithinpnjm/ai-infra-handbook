Beginner friendly: partly. You can read it without cluster access, but the allocation vs step model (section 1) must come first, and 6.7 section 3 (life of a job) helps. The "Simulating a multi-node cluster" and the 2D grid-search material can be skipped on the first pass.

Nebius rounds served: R1 (sbatch/srun/salloc commands, env variables, monitoring commands), R2 (job scripts, srun --overlap, dependency chains, log and job-pending triage), R3 (checkpoint and requeue design for long training), R4 (submission templates and "common mistakes" as team standards).

Hands-on to do:
- Run `python3 code/part06/sbatch_lint_lab.py` (if the code folder is present). Then run `sbatch_lint.py` on your own script and fix every ERROR.
- 2-node rank test: write a script that calls `srun hostname` plus `echo $SLURM_PROCID $SLURM_NODEID`, then run the same echo without srun and compare which variables are empty.
- Submit with `sbatch --test-only`, then check `squeue -j <id> --start` and `scontrol show job <id>`.
- Array test: `sbatch --array=0-5%2 ...`, then `squeue -r` and count how many tasks run at once.
- Dependency test: chain a job that fails with `afterok:<id>`, observe `DependencyNeverSatisfied`, then repeat with `--kill-on-invalid-dep=yes`.
- Interactive overlap: `salloc` then `srun --pty bash`, then a second `srun nvidia-smi` (it blocks), then `srun --overlap --jobid=<id> nvidia-smi`.
