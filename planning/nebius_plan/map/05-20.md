# 5.20 Upgrades, etcd backup and restore, and disaster recovery

One-line purpose: How to upgrade a Kubernetes cluster safely (skew, kubeadm order, GPU stack), back up and restore etcd, and plan DR with RPO and RTO targets.
Beginner friendly: partly. The concepts are explained from zero, but the commands assume you can read a shell and file paths, and that you know what a control-plane node and a static pod are. Read 5.19 first (node lifecycle, drain). Then 5.4 and 5.5. Linux basics (Part 1: files, permissions, systemd) help with the kubeadm and etcd commands.
Nebius rounds served: R2 (upgrade and etcd troubleshooting), R3 (DR design, RPO/RTO, availability), R4 (what you ran and how you recovered)
Chapter verdict: READ-SECTIONS (1 skew policy; 2 checklist and strategy table; 3 kubeadm order and rollback; 4 GPU stack upgrade; 5 etcd backup and restore scenarios A to E; 7 DR tiers; 8 failure table; 10, 11; checkpoints 1, 2, 3, 5, 6, 8, 9, 10, 16, 17, 18). Hands-on to do:
- On a throwaway kubeadm cluster: `sudo kubeadm upgrade plan`, then `kubectl get nodes -o wide` before and after the first control-plane node upgrade.
- `kubectl get --raw /metrics | grep apiserver_requested_deprecated_apis` to see which deprecated APIs are still being called.
- On a control-plane node: `ETCDCTL_API=3 etcdctl snapshot save /backup/test.db` with the cert flags from section 5.1, then `etcdutl snapshot status /backup/test.db -w table`.
- `etcdctl member list -w table` and `etcdctl endpoint health --cluster`, so you can read member IDs before you remove one (Restore scenario A).
- `sudo kubeadm certs check-expiration`, then the chapter's Python lab: `python3 code/part05/k8s_upgrade_dr_planner_lab.py`.
