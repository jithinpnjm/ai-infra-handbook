# 3.9 Testing, quality and CI for Python tooling
Words: ~9230 | Read time: ~62 min (full read) | File: docs/part-03-python/09-testing-quality-and-ci-for-python-tooling.md
One-line purpose: Teaches how to test infrastructure Python without touching real hardware: the test pyramid, pytest (parametrize, fixtures, markers), dependency injection and fakes versus mocks, transport-level HTTP fakes, property-based and contract tests, CLI tests, static gates (ruff, mypy, bandit, pre-commit), and CI pipeline design and hardening.
Beginner friendly: partly. Assumes 3.1 to 3.8. The pytest and fakes-versus-mocks sections are approachable; the Ansible, Terraform and benchmarking material is background that a rusty developer can skip.
Nebius rounds served: R1 (testing a small tool or script, exit codes, testing without hardware), R2 (CI and deploy gates, testing infra changes), R3 (design-for-testability as a system design input), R4 (own project's test strategy and CI)
Chapter verdict: READ-SECTIONS. A rusty Senior SRE can skip the Ansible/Molecule walkthrough, the benchmarking section, the Jinja and golden-file material and the Terraform and Kubernetes tool lists beyond one sentence. Read the test strategy, pytest essentials and fixtures, the fakes-versus-mocks section with dependency injection, the transport fakes, flaky-test policy, the CI skeleton and hardening, the common mistakes and interview lists (about 30 min of the 62).
