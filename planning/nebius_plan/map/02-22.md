# 2.22 Linux networking I: inspecting state with ip, ss, counters and the observability toolkit

One-line purpose: The Linux operator's toolkit for finding out why a host cannot reach or be reached: interfaces (ip, ethtool), persistent config (Netplan, NetworkManager), sockets (ss, lsof), drop counters, a performance method, and eBPF tools.
Beginner friendly: partly. Built for someone who knows processes and systemd (Part 1) and TCP/IP basics (2.4-2.7). Section 2 (ip), section 4 (ss, lsof) and section 8 (checklist) are readable for a beginner who types the commands on a VM. Sections 6-7 (USE method, eBPF) are dense and need the counter ideas from section 5 first.
Nebius rounds served: R1 (Linux console troubleshooting, the main target), R2 (node-level network debugging in Kubernetes), R4 (only if the project involved a host network issue)
Chapter verdict: READ-SECTIONS (intro, 1, 2, 4, 5, 8, 10, 11, checkpoints 2, 3, 8, 11, 12, 20). This is the most practical chapter for R1. Read the commands in sections 2, 4 and 5 by heart, and skim the performance-method sections as recall.

Hands-on to do:
- Inventory a fresh VM: `ip -br addr`, `ip -br link`, `ip route`, `ip neigh`, `ss -tulpn`, `ip -s link`, `nstat -az`. Save the output as a baseline (lab step 1).
- Socket test: `python3 -m http.server 8000`, then `ss -tulpn` and `sudo lsof -i :8000 -nP`. Connect with `nc -zv localhost 8000` and `curl -v --trace-ascii trace.txt http://localhost:8000/`.
- Accept-queue test: a server with `listen(1)` that never calls accept. Open several clients and read Recv-Q in `ss -ltn` and ListenOverflows in `nstat` (lab step 5).
- Loss injection: `sudo tc qdisc add dev lo root netem loss 1%`, run a transfer, watch `nstat -d 1` and `ss -ti`, then remove the qdisc with `sudo tc qdisc del dev lo root` (lab step 6).
- Triage a host: `nstat -az | egrep 'TcpRetransSegs|ListenOverflows|UdpRcvbufErrors'` and `cat /proc/net/softnet_stat`. Read the deltas over 10 seconds, not the totals.
