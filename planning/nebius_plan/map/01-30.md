# 1.30 Network file sharing and remote graphical access: rsync in depth, Samba, SSHFS, NFS clients, cloud storage, X11, VNC and alternatives
Words: 12596 | Read time: ~84 | File: docs/part-01-linux/30-network-file-sharing-and-remote-graphical-access-rsync-in-depth-samba.md

One-line purpose: A reference for choosing and using file-copy and file-sharing tools (rsync in depth, Samba/CIFS, SSHFS, NFS client, cloud FUSE mounts) and for giving users remote access (SSH/SFTP policy, X11 forwarding, VNC/x2go alternatives), with the performance and security limits of network file sharing explained.

Beginner friendly: partly. The tool-choice table and the rsync sections are learnable at beginner level. Read 1.5 (scp, rsync basics) and 1.29 (SSH reference) first, as the chapter requires. The Samba server configuration and the X11 xorg.conf material are intermediate and can be skipped for interview purposes.

Nebius rounds served: R1, R2, R3 (weaker; only the "why network filesystems stall" argument)

Chapter verdict: READ-SECTIONS (§1 tool-choice table; §3 rsync: getting started, exact copies and --delete, trailing slash, quick check and safeguards; §4 why network storage is slow for small files; §5 only the CIFS mount and credentials-file lines; §6 NFS client, sec= flavours and x-systemd.automount; §7 cloud storage behaviour; §8 access policy (SFTP over FTP, no web server on the head node); §9 only the X11 client/server role inversion and the alternatives table; "How it fails" items 1, 4, 6, 7), because rsync safety and NFS hang behaviour are the practical R1 and R2 items, while Samba server setup, xorg.conf, the Windows X servers, and the D-Bus and CUPS paragraphs are skim-only.

Hands-on to do:
1. rsync safety drill (no VM needed, use two scratch directories or localhost): `rsync -nva --delete src/ dst/` to preview, then `rsync -a src dst` vs `rsync -a src/ dst`, and compare the trees (section 3 and steps 2, 4).
2. Verify the quick-check trap: change a file's contents and keep its size and time with `touch -r`, then compare `rsync -av` (no change) against `rsync -avc` (catches it). Use `--backup --suffix=.old` to keep the old copy (step 3).
3. NFS hang and automount: export a directory from one VM, mount it on another with `x-systemd.automount` in `/etc/fstab`, stop the server, and confirm boot and unrelated commands no longer hang. A process in state `D` shows the hang (step 8; `ps -o stat,cmd`).
4. Remote display without X: start a Jupyter or simple HTTP server bound to 127.0.0.1 on the VM, and reach it with `ssh -L 8888:localhost:8888 vm`. Then run `ssh -X vm xclock` and break it on purpose (missing xauth, no DISPLAY after sudo) to see the failure from "How it fails" item 6 (steps 10 and the tunnel pattern in section 9).

Note for reviewer: the chapter recommends `soft` or `intr`-style NFS options in failure 4. `intr` has been a no-op on modern Linux kernels, so do not rely on it. The chapter does not say this.
