# 5.1 Containers from first principles: images, layers, registries
Words: 16,000 | Read time: 107 | File: docs/part-05-kubernetes/01-containers-from-first-principles-images-layers-registries.md
One-line purpose: Explains a container as an ordinary Linux process (namespaces, cgroups, overlayfs), how images are layered and content-addressed, how to build small and secure images, how registries serve nodes, and how GPU containers split work between image and host.
Beginner friendly: partly. It assumes Part 1 namespaces and cgroups (1.19, 1.20) and the process model; read those first if "namespace" or "cgroup" is fuzzy. Section 1 is the key concept and is readable after that.
Nebius rounds served: R1 (container as process, namespaces/cgroups, OOM, signals), R2 (image pull failures, exit codes, OOMKilled, build/cache troubleshooting), R3 (pull storms across 500 nodes, registry placement and HA), R4 (own project's Dockerfile, base image and GPU image choices)
Chapter verdict: READ-SECTIONS. Sections 1, 2, 4, 7 and 8 carry most of the interview value and must be read; the rest can be skimmed for recall, because the Linux parts repeat Part 1 and the history and build-backend material is optional.

Hands-on to do:
- On a Linux VM (not macOS directly): `docker run -d --name demo --memory 256m --cpus 0.5 nginx:1.27`, then `PID=$(docker inspect -f '{{.State.Pid}}' demo)`, `ps -o pid,ppid,cmd -p $PID`, `sudo nsenter -t $PID -m ls /`. Then `docker rm -f demo`.
- Inspect a remote image without pulling: `skopeo inspect --raw docker://docker.io/library/nginx:1.27 | jq .` and `crane manifest nginx:1.27 | jq '.manifests[] | {platform, digest}'`.
- Look at layers: `docker history --no-trunc --format '{{.Size}}\t{{.CreatedBy}}' nginx:1.27 | head`, then `docker save nginx:1.27 -o nginx.tar && tar -tf nginx.tar`.
- Build the chapter's Node.js example twice: change `server.js` only, rebuild, and confirm the `npm install` step shows as cached.
- Run the Python lab from the handbook's code folder: `python3 code/part05/oci_image_layers_lab.py` (no Docker needed).
