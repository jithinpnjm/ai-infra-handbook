# 2.30 Network troubleshooting: method, models and case studies
Words: ~11,900 | Read time: ~80 min | File: docs/part-02-networking/30-network-troubleshooting-method-and-case-studies.md
One-line purpose: Teaches a repeatable troubleshooting method (purpose, models, half-split, manipulation, fix, learning) and applies it to 14 production network failure cases, ending in AI-fabric faults.
Beginner friendly: partly. Read first: 2.2 (layers), 2.7 (ping, traceroute, mtr), 2.22 (ip and ss), 2.26 (tcpdump), 2.19 (PFC, ECN) before the AI-fabric table and Cases 8 and 14. The method sections (1-4) are readable without them.
Nebius rounds served: R1 (practical Linux and network troubleshooting), R2 (troubleshooting in DevOps and Kubernetes), R3 (system design: availability, failure domains), R4 (deep-dive on own incidents).
Chapter verdict: READ-SECTIONS (sections 1-4, 5 for the kit concept, 6 all, Cases 2, 3, 8, 13, 14, sections 9 and 10, then skim the rest). The method is the core of an R1/R2 troubleshooting answer, and the cases are worked examples of it. The checkpoint Q&A repeats the body, so skim it.

Hands-on to do:
- `python3 code/part02/network_troubleshooting_method_lab.py` (chapter's self-check lab; the code folder is referenced in the chapter, check it exists in the repo).
- `ping -M do -s N <host>` to find the largest unfragmented payload, then compare with `mtr -n -r -c 100 <host>` for loss on a single hop (Cases 2, section 5).
- `nstat -az` and `ss -tanpi` before and after you run a fault. Chart `UdpRcvbufErrors` (Case 5). For Case 10, capture with tcpdump and filter for `tcp.analysis.zero_window` in Wireshark/tshark.
- On a disposable VM only: `ip link set eth2 mtu 1400` on one link (fault 1 of the table). Write the symptom, half-split, then fix it, and note the permanent fix.
- Run the `netdiag.sh` script from section 5 on a lab node, then open the tarball and find the conntrack and ethtool output.
