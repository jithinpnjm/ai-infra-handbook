One-line purpose: Explains how Linux filters and translates packets (netfilter hooks, nftables, conntrack, NAT), what Docker and kube-proxy add to the same path, and how to find the one rule or table that drops a packet.
Beginner friendly: no-partly. Written for someone who already knows routing (2.5), TCP (2.6), NAT (2.9) and ss/ip (2.22). Without those, the hook diagrams and conntrack states are hard to follow. Start with the default-deny ruleset in section 1 and the states table in section 2; both are concrete enough for a beginner to type and test.
Nebius rounds served: R1 (host firewall and NAT troubleshooting), R2 (kube-proxy, Docker and conntrack on Kubernetes nodes; conntrack exhaustion incidents), R3 (NAT gateway and SNAT design only if asked)
Chapter verdict: READ-SECTIONS (intro, 1 hook and nftables parts, 2 states and exhaustion, 3 SNAT exhaustion, 4 container hosts, 6 debugging, 9, 10). Priority is the conntrack table-full story and the "which rule dropped it" method. Skip the iptables quick map and section 7 (performance) for recall only.

Hands-on to do:
- Safe rollback first: `sudo nft -c -f <file>` to check syntax, then load a default-deny ruleset with a 60-second rollback timer, and keep a second SSH session open (checkpoint 19).
- Hook counters: add counter rules at prerouting, input, forward, output and postrouting, then ping locally and across a namespace router (lab step 1).
- Trace one packet: `sudo nft monitor trace` after adding a priority -300 chain with `meta nftrace set 1` for one test flow (checkpoint 18).
- Conntrack: `sudo conntrack -L | head`, `sudo conntrack -C`, `sudo conntrack -S`, and read `sysctl net.netfilter.nf_conntrack_max net.netfilter.nf_conntrack_count` (section 2.2).
- Table-full drill: set `nf_conntrack_max` to 2048 in a lab VM, open many connections, watch `dmesg` and `conntrack -S`, then restore the value (lab step 4).
- On a Docker host, run `sudo iptables -t nat -S DOCKER`, publish a port, and read the rule. Do not flush anything.
