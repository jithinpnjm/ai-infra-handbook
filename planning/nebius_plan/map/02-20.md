One-line purpose: Explains how a load balancer spreads work across backends (L4 vs L7, algorithms, health checks, drain, ECMP scale-out) and why LLM streaming traffic breaks web-era assumptions.

Chapter verdict: READ-SECTIONS (sections 0, 1, 2, 3, 4, 7, 8, 9, 10, 12, 13). Load balancing and inference routing are the most likely R3 design topic, and the troubleshooting table is R1 material. Config blocks in 5-6 are OPTIONAL for recall.

Hands-on to do:
- Build the IPVS DR service from section 5 in a disposable VM, then run `sudo ipvsadm -Ln --stats` and `sudo ipvsadm -Lcn` to see distribution (lab step 1).
- Run the HAProxy config from section 6.1 with `check inter 1s fall 2 rise 2`, stop one backend, and time how long detection takes (lab step 3).
- Open one gRPC channel, send many calls, and count which backend gets them. Compare an L4 path with an L7 path (lab step 4; `ghz` or `grpcurl`).
- For the troubleshooting table: `ss -tn` per backend, and `ss -s` to read the connection view (section 10).
- Run the Python lab the chapter names, `python3 code/part02/load_balancing_l4_l7_lab.py`, if that file exists in your copy of the repo. I did not check whether it does.
