One-line purpose: Shows how to write node, partition, cgroup and topology config so that the scheduler's promises (cores, RAM, GPUs) are actually enforced by the kernel, and how to read the node states that tell you why a node is out of service.

Beginner friendly: partly. Needs 6.7 (daemon model) and Part 1 cgroups basics first. The partition table and the advanced PrologFlags/SchedulerParameters material are dense; read the node-state and cgroup parts first.

Hands-on to do:
- On any Slurm node you can reach, run `slurmd -C` and compare with `scontrol show node <name>`. Note CPUs, RealMemory and Gres fields.
- Run `sinfo -R` (reasons) and `sinfo -N -l` on a test cluster; decode each suffix (`*`, `$`, `~`, `#`, `!`, `%`, `@`, `^`) against the table.
- Drain and resume a node: `scontrol update nodename=<node> state=drain reason="badmem"` then `scontrol update nodename=<node> state=resume` (chapter exercise 8.3).
- Run `python3 code/part06/slurmconf_lint_lab.py` (if the code folder is present). Confirm the broken config yields 5 errors and 3 warnings, and the valid config yields 0.
- GPU isolation check (chapter checkpoint 14, needs a GPU node): `srun --gres=gpu:1 --mem=4G -n1 bash -c 'nvidia-smi -L; cat /proc/self/cgroup'`. Expect one GPU listed.

Likely interview questions from this chapter:
- A user requests 1 GPU on an 8-GPU node and sees all 8 in nvidia-smi. Which file and parameter did you miss?
- A new node registers, then goes invalid or drained with "Low RealMemory". What do you check, and what do you change?
- What separates a partition in DOWN from one in DRAIN, and why is PriorityTier different from PriorityJobFactor?
- Why does SelectTypeParameters without _Memory make ConstrainRAMSpace useless?
- What does SwitchAsNodeRank do for a job whose nodes alternate between two leaf switches?
- What do PrologFlags Alloc, Contain and DeferBatch solve on a GPU cluster that uses pam_slurm_adopt?
