# 2.25 Linux networking IV: namespaces, veth, bridges and container networking

One-line purpose: Shows how a container gets its network from kernel primitives (namespace, veth, bridge, NAT), how Docker and CNI package them, how a pod packet crosses nodes, and how GPU pods add RDMA secondary interfaces with Multus.
Beginner friendly: partly. Section 1 (namespaces) and section 2 (hand-built bridge) are approachable if you can type commands. Needs 2.5, 2.11, 2.17, 2.23 and the Part 1 namespace and cgroup chapters (1.18-1.20). Sections 4-6 assume you know what a Kubernetes Pod and Service are; read Part 5 basics first if not.
Nebius rounds served: R2 (pod-to-pod debugging, CNI, Kubernetes networking troubleshooting), R1 (namespaces and nsenter as Linux practical), R3 (GPU pod networking in a system design), R4 (if the candidate's project ran pods with special networking)
Chapter verdict: READ-SECTIONS (1, 2 intro and the first script, 3 modes table, 4 ADD/DEL and model, 5 walkthrough, 6 items 1, 2, 4, 5, 7 debugging section 7, 9, 10). The macvlan/ipvlan and CNI-table details are recall. Section 7 is the most useful R2 drill.

Hands-on to do:
- Build the namespace-plus-veth wiring from section 2 by hand: `sudo ip netns add c1`, a veth pair, one end moved with `ip link set ... netns c1`, then `sudo ip -n c1 addr` and `ping` between c1 and c2 through `br0` (script step 1).
- Inspect a real pod's namespace from a node: `crictl pods --name <pod>`, `crictl inspectp <id> | jq .info.pid`, then `sudo nsenter -t <pid> -n ip -br addr; ip route; ss -tulpn` (section 7).
- Map a pod's eth0 to its host veth: `sudo nsenter -t <pid> -n ethtool -S eth0 | grep peer_ifindex`, then `ip -o link | grep "^<N>:"` (checkpoint 2).
- Inspect Docker's modes on a Docker host: `docker network ls`, `iptables -t nat -S DOCKER`, `bridge link` (section 3).
- On a kind cluster, check `/etc/cni/net.d` and `ip route` in a node container, then trace one cross-node packet with `tcpdump` (lab step 7).

Notes on the source chapter (for your own review):
- Section 6 item 3 and checkpoint 15 describe hostNetwork pods as unable to use NetworkPolicy. That holds for most CNIs, so verify it against your CNI before quoting it.
- Checkpoint 13 says NCCL ignores only `lo` and `docker0` by default. Check the current NCCL documentation before quoting the default.
