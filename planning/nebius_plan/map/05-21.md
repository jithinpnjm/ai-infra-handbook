# 5.21 Certificates, identity, admission control and policy
Words: 20900 | Read time: 140 | File: /Users/jithinpjoseph/Documents/GitHub/ai-infra-handbook/docs/part-05-kubernetes/21-certificates-identity-admission-control-and-policy.md
One-line purpose: How the cluster proves who is talking (PKI, CSRs, OIDC, workload identity), how every request is checked before it is stored (admission chain, webhooks, VAP), and how policy engines and Pod Security enforce guardrails on a shared GPU cluster.
Beginner friendly: partly. The PKI, expiry and "which check runs when" sections are readable from zero. SPIRE, Rego, the Go CSR program and the long YAML are advanced. Read 5.5 (API server, admission basics) and 5.16 (RBAC) first, and skim Part 1 on certificates and TLS if the words "CA" and "SAN" are new.
Nebius rounds served: R2 (certificate-expiry and webhook-outage troubleshooting), R3 (multi-tenant guardrails, failure modes of admission), R4 (security posture you ran and why)
Chapter verdict: READ-SECTIONS (1 PKI tree, "Inspecting and renewing", "Kubelet TLS bootstrapping and CSRs"; 2 OIDC and "Cloud metadata proxies versus IRSA"; 3 whole admission flow and "Webhook failure modes"; 4 PSS table and namespace rollout; 5 Kyverno/Gatekeeper strengths and image admission; 6 guardrail table; 7 troubleshooting table; 9, 10; checkpoints 1, 3, 6, 8, 9, 10, 12, 16, 17, 20). Skip the SPIRE deep dive, the Rego worked example, the Go CSR program, the amicontained output and the platform-identity prose. Those are advanced and rarely asked at this level.

Hands-on to do:
- On a kubeadm control-plane node: `sudo kubeadm certs check-expiration`, then `sudo openssl x509 -in /etc/kubernetes/pki/apiserver.crt -noout -subject -issuer -dates -ext subjectAltName`.
- Preview Pod Security violations without enforcing: `kubectl label --dry-run=server --overwrite ns --all pod-security.kubernetes.io/enforce=baseline`. Then label one test namespace with `warn=restricted` and `audit=restricted` and apply a plain pod to read the warning.
- Run the CSR flow from section 1.3 for a test user with a 24-hour `expirationSeconds`, then `kubectl certificate approve` and `kubectl get csr`. Note that you cannot revoke it.
- Run kube-bench as a Job (the chapter's `kubectl apply` link) and read the FAIL lines and their remediation.
- Apply the `gpu-request-limits` ValidatingAdmissionPolicy with `--dry-run=server`, then run the chapter's lab: `python3 code/part05/pki_admission_policy_eval_lab.py`.
