# 20.11 Coding practice set: 40 problems with tested solutions
Words: 11713 | Read time: 78 | File: docs/part-20-nebius-sre-interview/11-coding-practice-set-40-problems-with-tested-solutions.md
One-line purpose: A timed practice bank of 40 original problems (12 easy, 16 medium, 8 harder, 4 SRE mini-projects), each with hints, the key insight, the common wrong answer and a follow-up, plus tested reference solutions.
Beginner friendly: no. It is a drill bank for someone who already writes Python. Read first: 20.8 (round process and toolkit), 20.9 (patterns), 20.10 (complexity). Then Part 3 `12-objects-types-and-data-structures-in-depth.md` and `14-functions-scopes-and-arguments-in-depth.md`. Do not attempt the harder tier before the medium tier goes clean.
Nebius rounds served: R1 (coding round, all tiers), R2 (P1 log/SLO scripting), R3 (P2 rate limiter and P4 rollout planner lead into distributed follow-ups)
Chapter verdict: READ-SECTIONS to use as a drill bank, not a read-through. Read sections 1 to 3 (run routine, how to use the set, index), "How to answer out loud", Scenarios 1, 2, 3 and 5, Common mistakes. For problems, attempt them cold with the clock, then read only the Insight and Common-wrong-answer lines. SKIM Scenario 4 (sliding median) and the mini-project bodies. SKIP the Sources and Verification log.

Hands-on to do:
1. From the repo root: `python3 -m pytest -q code/part20/c11_solutions` (expect 61 passed).
2. `python3 -I tools/check_code_files.py code/part20/c11_solutions` (expect 0 problems). The tool path is as the chapter gives it.
3. Attempt E1 cold: 15 minutes, no hints, plain editor. Then run `python3 -m pytest -q code/part20/c11_solutions/test_c11_easy.py -k e01`.
4. Deliberate break from the chapter: in `c11_m02_merge_windows.py` replace the `if e > out[-1][1]` block with unconditional `out[-1][1] = e`. Expect `test_m02` to fail with `[(1, 3)] == [(1, 10)]`. Restore the file.
5. Build M11 (token bucket) from memory without the file, then run the chapter's property idea: tokens handed out never exceed `capacity + rate * elapsed`.

Likely interview questions from this chapter:
1. "Given a stream of access-log lines, tell me whether we are burning our error budget too fast. Use any language and talk me through your choices."
2. "Write a token bucket that allows 2 requests a second with bursts up to 4. What happens if the clock goes backwards?"
3. "Merge overlapping maintenance windows. Do `[1,3)` and `[3,5)` overlap? What about `[1,10)` followed by `[2,3)`?"
4. "Simplify `/a//b/./c/../d/`. What breaks with a string-replace approach, and what changes if the path contains symlinks?"
5. "Give me a start order for these services, smallest name first when there is a tie. What should happen if there is a cycle?"
6. "Your sliding median passes the examples but is wrong on `[2,2,2,2]` with k=2. What is wrong, and how would you test for it?"
