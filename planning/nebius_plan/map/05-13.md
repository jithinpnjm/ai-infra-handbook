# 5.13 Pod networking under the hood: veth, bridges, routes and CNI plugins

One-line purpose: Shows how a pod gets its network (namespace, veth, bridge, routes, CNI plugin), how packets cross nodes, where MTU breaks, and how to inspect a pod's network from the node.

Beginner friendly: partly. Needs Linux networking basics first: network namespaces, veth, bridges, routing, MTU (chapters 2.7, 2.11, 2.22-2.25 in Part 2). Read those before section 2 or the hand-built network will not make sense. Read chapter 5.8 (CNI at a high level) and 5.10 (Services) before this one.

Nebius rounds served: R1 (Linux/networking, console troubleshooting), R2 (Kubernetes troubleshooting), R4 (only if your own project touches pod networking)

Chapter verdict: READ-SECTIONS (1, 2, 3, 5, 7, 8, plus section 10-11 for interview answers). Skip the RDMA, SR-IOV and DPU parts of section 6 beyond one-line recall, since Nebius inference work is unlikely to ask about them. The reason: MTU, the node-level inspection flow, and the troubleshooting matrix are the most likely R1/R2 practical tasks.

Hands-on to do:
- Run the section 2 bridge script on a Linux VM as root (`ip netns add pod1`, `ip link add cni0 type bridge`, veth per pod). Confirm that `ip netns exec pod1 ping -c2 10.244.1.12` works, then ping 8.8.8.8 to check the MASQUERADE rule.
- Inspect a live pod: `crictl pods --name <pod> -q`, then `sudo nsenter --net=<netns> ip -br addr` and `ip route`. Match the host veth using `cat /sys/class/net/eth0/iflink` inside the pod and `ifindex` on the host.
- MTU test: `ping -M do -s 1422 <peer-pod-ip>` (succeeds on 1450 MTU) versus `-s 1423` (fails with "Frag needed"). Know that 1422 + 8 + 20 = 1450.
- Exercise 10 from the chapter: break the CNI MTU on purpose, reproduce a stalled large transfer, diagnose it with `ping -M do`, then fix and clean up.
- Run `ls /etc/cni/net.d /opt/cni/bin /var/lib/cni` on a kubeadm node and read the first conflist file.

Likely interview questions from this chapter:
- What is the Kubernetes network model, and what does a CNI plugin actually do?
- Walk me through pod-to-pod traffic across two nodes with VXLAN, and then with BGP routing. Where does the packet change?
- A pod is stuck in ContainerCreating with a CNI error. How do you debug it?
- Pods can ping each other, but `pip install` or a TLS handshake hangs. What is the cause and how do you prove it?
- Build a pod network by hand: which primitives do you need, and which step gives the pod its gateway and egress?
- Why does a GPU training job not run its NCCL traffic over the default pod network?
