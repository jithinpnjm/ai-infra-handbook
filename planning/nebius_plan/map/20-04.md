# 20.4 Files, descriptors, syscalls and permissions
Words: ~10640 | Read time: 71 | File: /Users/jithinpjoseph/Documents/GitHub/ai-infra-handbook/docs/part-20-nebius-sre-interview/04-files-descriptors-syscalls-and-permissions.md
One-line purpose: Teaches the three console errors a Linux SRE meets first (Too many open files, No space left with free space, Permission denied on a 666 file), each traced to its kernel object and checked in a fixed order, with eight runnable broken-box scenarios.
Beginner friendly: partly. Sections 1-2 (descriptors, limits) and 5 (df vs du, deleted-but-open files) are readable from scratch; section 6 (permission layers, ACL mask, mount flags) and section 7 (user namespaces, capabilities) are dense. Read first: 1.3 (inodes, paths, links) and 1.6 (users, groups, mode bits, ACLs) before section 6; 1.8 (processes, ulimit) before section 2; 1.11 (system calls, strace) before section 4; 1.19 (namespaces) and 1.21 (capabilities, SELinux/AppArmor) before section 7; 5.9 (kubelet, cgroups, security context basics) before section 7's Kubernetes part.
Nebius rounds served: R1 (practical Linux console: the file-descriptor and permission questions named in the report), R2 (pod permission and read-only-root questions in section 7), R4 (debugging story: "how did you find a leak").
Chapter verdict: READ-SECTIONS: 1, 2, 3, 4, 5, 6 (the top layers: path, identity, mode class, ACL, mount), How to answer Q1-Q3, Scenarios 1, 2, 3, 6, 8, and the drill questions; SKIM section 6's MAC/userns paragraphs and section 7 (read only the four-question Kubernetes order); skip the Part A/B lab commands unless you can run Linux.

Hands-on to do:
1. Inspect your own shell: `ls -l /proc/$$/fd`, `grep 'Max open files' /proc/$$/limits`, `echo /proc/$$/fd/* | wc -w`. Explain each number aloud.
2. Run the leak triage on any busy process: `pid=$(pidof <name>); ls -l /proc/$pid/fd | awk 'NR>1{print $NF}' | sort | uniq -c | sort -rn | head`.
3. Run `bash ch04_s2_deleted_open.sh` (in `code/part20/`, Linux only, as a normal user) and compare `df` used space before and after the `rm`; then run `bash ch04_s2_deleted_open.sh answer` to read the key first.
4. Run `strace -f -e trace=%file -e status=failed -o trace.txt bash ch04_s6_dir_search.sh`, then `python3 ch04_strace_errors.py < trace.txt`, and find the first `EACCES` line that matters.

Likely interview questions from this chapter:
- A service logs "Too many open files". What do you do, and how do you tell a leak from a low limit?
- `df` says the disk is full but `du` finds almost nothing. Why, and how do you free the space without a restart?
- A file is mode 666 and the service still gets Permission denied. What do you check, in order?
- How would you use strace on a production process, and what does it cost?
- `df -h` shows free space but a create fails with "No space left on device". What is the cause?
- A pod works on a laptop and fails in the cluster with Permission denied or Read-only file system. What do you check?
