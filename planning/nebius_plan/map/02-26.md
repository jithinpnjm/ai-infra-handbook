# 2.26 Packet capture from scratch: tcpdump, tshark, Wireshark and BPF-based tracing

One-line purpose: Teaches packet capture as evidence: how tcpdump and its BPF filters work on Linux, how to read a TCP trace in Wireshark or tshark, how to capture in containers and on RDMA fabrics, and how BCC and bpftrace show what counters cannot.
Beginner friendly: partly. Section 2 (tcpdump commands and filter table) is approachable if you have run `ip` and `ss`. Section 3 (reading TCP) and section 6 (BPF) need the TCP handshake and window ideas from 2.6 and the counter ideas from 2.22. Start with the first capture in section 2 and the lab's step 1.
Nebius rounds served: R1 (tcpdump and filters are a classic live-console task), R2 (capturing inside a pod or on a node, retransmit diagnosis), R3 (not usually asked; use as a note on observability), R4 (only if the project has network-level evidence)

Hands-on to do:
- Healthy baseline: `sudo tcpdump -nni <iface> -s 96 -w /tmp/base.pcap 'host <peer> and tcp port 80'`, run `curl http://<peer>/`, stop it, then read with `sudo tcpdump -nr /tmp/base.pcap`. Label SYN, SYN-ACK, ACK and FIN (lab step 1).
- Filters: test `tcp[tcpflags] & (tcp-syn|tcp-ack) == tcp-syn` for SYN-only, and `sudo tcpdump -d 'tcp port 22'` to see compiled BPF. Write the same logic as a Wireshark display filter (lab step 2).
- Loss and MTU: `sudo tc qdisc add dev <veth> root netem loss 2%` on a lab veth, capture a transfer, then look for `tcp.analysis.retransmission` in `tshark -r file -Y ...` and `tcp.analysis.duplicate_ack` (lab step 3). Remove the qdisc afterwards.
- Container capture: `sudo nsenter -t <pid> -n tcpdump -nni eth0 -s 96 -c 50` on a lab node (section 5.1).
- Ring buffer: `sudo tcpdump -nni <iface> -s 96 -C 10 -W 5 -w /var/tmp/ring.pcap 'not port 22'` (checkpoint 5).
- BPF: `sudo tcpretrans` during a transfer with induced loss, and `sudo tcpdrop` during a drop; compare with the pcap (BCC tools, section 6).
