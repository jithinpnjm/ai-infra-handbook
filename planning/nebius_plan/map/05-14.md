# 5.14 Overlay versus routed pod networking: VXLAN, BGP with Calico, eBPF with Cilium

One-line purpose: Compares the ways pod traffic is carried between nodes (VXLAN/Geneve/IPIP overlays, routed BGP with Calico, eBPF with Cilium) and gives a decision method for a GPU cluster.

Beginner friendly: no. Read 5.13 first (namespaces, veth, MTU, the CNI contract), then Part 2 BGP and VXLAN (2.15-2.17). Cilium's eBPF material assumes the Part 1/2 Linux and eBPF basics. Skim the Cilium sections on first pass; the overlay and routed sections are the ones to understand.

Nebius rounds served: R1 (MTU and overlay trade-offs as practical networking), R2 (CNI and BGP troubleshooting), R3 (capacity: IP and BGP session counts, per-node block sizing), R4 (justifying the CNI choice for your own project)

Chapter verdict: READ-SECTIONS (1, 2, 3 incl. "Calico in BGP mode", 4 "Concepts" and "kube-proxy replacement", 5, 7, 8, 10, 11). Skip the Helm flag details and the Cilium BGP CRD API differences, which change by release. The reason: the decision frame, overlay vs routed trade-offs and the failure-mode reasoning are the likely interview content; the install flags are version-specific and easy to look up.

Hands-on to do:
- Run the 500-node BGP math by hand: full mesh is N(N-1)/2 = 124,750; compare with three route reflectors (about 1,500 sessions) and dual ToRs (about 1,000 sessions). Then run the local planner `python3 code/part05/overlay_bgp_cilium_planner_lab.py`, which is the lab file named in the chapter.
- On a 3-node cluster with Flannel VXLAN or Calico VXLAN: capture VXLAN on the underlay with `tcpdump -ni eth0 udp port 4789`, then run `bridge fdb show` and `ip -d link show flannel.1` to see where each pod's MAC and VTEP sit.
- Check a routed setup: `calicoctl node status` (BGP peers Established), `ip route | grep 'proto bird'`, and `calicoctl ipam show --show-blocks`.
- MTU and throughput check from section 7: `ping -M do -s 8972 <pod-ip-on-other-node>` (8972 + 28 = 9000), then `iperf3 -c <server-pod-ip> -P 8 -t 30` and `mpstat -P ALL 1` to see per-core CPU during the run.
- If Cilium is installed: `cilium status`, `cilium bpf lb list | head`, and `hubble observe --pod <ns/pod> --verdict DROPPED`, which is the drop-reason drill from checkpoint 17.

Likely interview questions from this chapter:
- Overlay vs routed networking: what are the trade-offs, and when would you peer nodes with the ToR over BGP?
- Calico full mesh vs route reflectors vs ToR peering: which one at 500 nodes, and why?
- How does Cilium enforce policy and Services without iptables? What is a security identity, and why does it survive pod churn?
- What is kube-proxy replacement and DSR? What goes wrong with DSR on the MTU or with IP options?
- You have a bare-metal leaf-spine GPU cluster you control. Which CNI would you pick for the primary network, and what stays off it?
- How would you migrate a running cluster from Calico or Flannel to Cilium without a cluster-wide outage?
