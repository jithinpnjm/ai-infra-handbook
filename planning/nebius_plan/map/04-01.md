# 4.1 Git from scratch for infrastructure engineers
Words: 15500 | Read time: 104 | File: /Users/jithinpjoseph/Documents/GitHub/ai-infra-handbook/docs/part-04-automation/01-git-from-scratch-for-infrastructure-engineers.md
One-line purpose: Teaches Git as the evidence trail for infrastructure: object model, daily safe workflow, rebase and recovery (reflog, bisect), repo layout, hooks, secrets remediation, CODEOWNERS and GitOps hand-off.
Beginner friendly: partly. Commands are explained one by one and the analogies help, but the object model (section 2) and rebase rules (section 7) need patience, and section 1's network-lab material (Vagrant, Containerlab) is off-target for this reader. Start with a scratch repo and run the section 2 commands before reading the rest.
Nebius rounds served: R1, R2, R4
Chapter verdict: READ-SECTIONS (2, 3, 5, 7, 8, 10, 11, 12, 14, 16, 17), because Git questions are asked as a practical R1/R2 check and the rebase golden rule, reflog recovery, secrets remediation order and push-versus-pull GitOps are the parts that come up; skim 1 and 4, and skip the Vagrant/Containerlab material in section 1 and most of the lab exercises.

Hands-on to do:
- Run section 2's commands in a scratch repo: `git init demo && cd demo`, add `main.tf`, commit, then `git cat-file -t HEAD`, `git cat-file -p HEAD^{tree}`, `cat .git/HEAD .git/refs/heads/main`.
- Practise the safe workflow in section 3 with `git fetch origin`, `git log main..origin/main`, `git diff --staged --check`, then `git push -u origin <branch>`.
- Find a file committed by mistake: `git rm --cached <file>` then commit, and confirm `git status --ignored` and `git check-ignore -v <path>` explain why.
- Run recovery: `git reset --hard HEAD~1` on a scratch branch, then `git reflog` and `git branch rescue HEAD@{1}` (section 8).
- Run bisect on a scratch history: `git bisect start`, `git bisect bad`, `git bisect good <tag>`, `git bisect run <script>`, `git bisect reset`.

Likely interview questions from this chapter:
- What is a commit physically, and why are branches cheap?
- Explain merge versus rebase. What is the golden rule and what would you do after rebasing a branch you already pushed?
- A secret was pushed to main. Walk me through the remediation, in order.
- I lost commits after a reset. How do I get them back, and what are the limits of the reflog?
- How would you find the commit that halved throughput across 40 commits?
- Push-based CI deployment versus pull-based GitOps: where do cluster credentials live, and why does it matter?
