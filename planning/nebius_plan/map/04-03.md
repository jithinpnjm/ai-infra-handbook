# 4.3 Ansible from zero: what it is, how it works, installation and ad-hoc commands
Words: ~12,500 | Read time: 84 min | File: docs/part-04-automation/03-ansible-from-zero-what-it-is-how-it-works-installation-and-ad-hoc-comm.md
One-line purpose: Builds the Ansible mental model (agentless, push, idempotent), then gets the reader running ad-hoc commands, a first playbook and connection troubleshooting.
Beginner friendly: partly. Analogies are clear, but it assumes SSH and Linux admin (Part 1) and Python basics (Part 3). Read 04-04 (YAML and Jinja2) alongside this chapter, since playbooks are YAML.
Nebius rounds served: R2 (primary: Ansible/DevOps scripting), R1 (SSH keys, sudo, host keys, Linux console checks), R4 (control-node security, team change control)
Chapter verdict: READ-SECTIONS (sections 1, 2, 4, 6, 7, 8, 9, 10, 11, 12, the checkpoint answers 1, 4, 5, 9, 10, 11, 12, 17); the Vagrant subsection and the install details can be skimmed. The reader needs the mental model and the command fluency, not every provisioning detail.

Hands-on to do:
- `ansible all -m ansible.builtin.ping`, then `ansible-config dump --only-changed` and `ansible-inventory --graph` against a 2 to 3 host lab (Vagrant `ubuntu/focal64` or Multipass).
- `ansible gpu -m ansible.builtin.command -a "dmesg | grep -i xid"` and then the same with `shell`, to see the pipe failure yourself.
- Run `site.yml` (chrony baseline) with `--syntax-check`, then `--check --diff`, then apply, then rerun and confirm `changed=0`.
- Break it on purpose: a wrong `remote_user` (publickey error), then a misspelt package name, then read `-v` and `-vvv` output.
- Run `python3 code/part04/ansible_foundations_lab.py` from the handbook root first (the file exists there).

Likely interview questions from this chapter:
1. What does "agentless" mean, and what happens on the target when a task runs?
2. Ansible versus Terraform: why are they not competitors?
3. What is idempotency, and how do you keep a `shell` task idempotent?
4. How would you speed up Ansible across 1,000 hosts?
5. How do you secure the control node and its credentials?
6. How do you do a dry run with `--check`, and where does it give a false answer?
