One-line purpose: A repeatable method (scope, layer, bisect, test) plus kubectl and node-level tools (crictl, nsenter, tcpdump, ip, ss, cgroups, nvidia-smi) and failure playbooks for pods, networks, storage, nodes and GPUs.
Beginner friendly: no, not on its own. The method section is clear, but the node commands assume root on a worker, Linux processes and namespaces, and basic networking. Read Part 1 (processes, /proc, file permissions, systemd and journald) and Part 2 (interfaces, routing, iptables, DNS) first, then 5.8 to 5.10 and 5.13. Do the kind-node exercises once before the interview, so the commands are not new on the day.
Nebius rounds served: R1 (practical Linux console and troubleshooting, the main match), R2 (Kubernetes troubleshooting playbooks), R3 (incident response reasoning), R4 (post-incident review and evidence)

Hands-on to do:
- On a kind cluster, find the node container (`docker exec -it <kind-node> bash`), then run `crictl ps`, `crictl inspect <ctr-id> | jq .info.pid`, and `nsenter -t <pid> -n ss -tnap`.
- Capture traffic from inside a pod's network namespace with no tools in the image: `sudo nsenter -t <pid> -n tcpdump -ni eth0 -c 50 port 8000` (run on the node, as root).
- Create one pod that exits with code 127 and one that exits with 137 (for example, `sh -c 'exit 137'`), then read `kubectl describe pod`, `kubectl logs <pod> --previous` and the `Last State` exit code.
- Run the 4-hop bisection on a test Service: curl a backend pod IP on the same node, a pod IP on another node, the ClusterIP, and the DNS name, from a netshoot pod. Note which hop fails first.
- Practise `kubectl debug -it <pod> --image=nicolaka/netshoot --target=<container> --share-processes` on a running pod with no shell.
- Run the chapter's lab: `python3 code/part05/k8s_node_troubleshooter_lab.py`, then change an exit code in the input and read the classifier output.

Likely interview questions from this chapter:
- A pod is stuck in ContainerCreating. Walk me through diagnosing it.
- A service is intermittently failing. How do you localise whether it is DNS, kube-proxy, CNI or the app?
- How do you capture traffic from inside a pod when the image has no tools? (`nsenter -n` from the node, ephemeral containers.)
- A training job hangs after hours of running. What do you check? (ranks, NCCL, Xid, py-spy, network counters, stragglers.)
- A node goes NotReady intermittently. What are the likely causes, and how do you confirm each one?
- What do exit codes 137, 139 and 143 mean, and how do you tell a container OOM from a host-wide OOM?
- How do you run an incident and a blameless post-incident review?
