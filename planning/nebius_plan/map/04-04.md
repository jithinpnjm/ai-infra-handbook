# 4.4 YAML and Jinja2 for infrastructure code
Words: ~12,000 | Read time: 80 min | File: docs/part-04-automation/04-yaml-and-jinja2-for-infrastructure-code.md
One-line purpose: Teaches the YAML data model and its type-coercion traps, then Jinja2 expressions, filters and whitespace control, and how Ansible, Helm, Terraform and Kustomize differ in templating.
Beginner friendly: partly. It assumes basic scripting and suits a reader who needs a Python and config refresh. The YAML sections (1, "Rules that bite") can be read first, without any Ansible background. Read 04-03 section 7 (first playbook) after this chapter's section 1.
Nebius rounds served: R2 (primary: YAML/Jinja for Ansible, Helm and config), R1 (Python scripting: parsing, templating, `yaml.safe_load`), R4 (review and secrets handling in rendered files)
Chapter verdict: READ-SECTIONS (1 "YAML essentials" incl. "Rules that bite", 2 "Jinja2 essentials" incl. "Filters" and "Whitespace control", 3 "Jinja2 in Ansible", 4 "Templating elsewhere", 5 "Testing and debugging templates", 6 "Security considerations", 8 "Common mistakes", 9 "Interview angles"; checkpoint answers 2, 4, 7, 8, 13, 14, 16, 19, 20). Skip the detailed XML/Protobuf/YANG and Gem-book walkthroughs, since they are network-automation content. The reader does need the quoting rules and the `StrictUndefined` idea.

Hands-on to do:
- `python3 code/part04/yaml_jinja2_templates_lab.py` from the handbook root (the folder exists there). Expect 4 checks to pass.
- Create a file with `no`, `1.10`, `010`, `22:30` and `~`, then run `python3 -c 'import sys,yaml,json; print(json.dumps(yaml.safe_load(sys.stdin), indent=2))' < file.yml` to see each type. Then run `yamllint` with the `truthy` rule.
- Render a Slurm-style template with `jinja2.Environment(undefined=StrictUndefined, trim_blocks=True, lstrip_blocks=True)`. Remove one variable from the data and read the error.
- `ansible localhost -m ansible.builtin.template -a "src=nccl.conf.j2 dest=/tmp/out" -e @vars.yml --diff` (needs Ansible installed, from 04-03).
- Add `validate: "visudo -cf %s"` to a sudoers template task, then break the template on purpose and watch the run reject it.

Likely interview questions from this chapter:
1. What are YAML's gotchas? Name a value that changes type and a value that loses a zero.
2. What is the difference between `|` and `>` in YAML, and when would you use each?
3. Why is `yaml.load` dangerous, and what do you use instead?
4. Why must `msg: "{{ var }}"` be quoted, and why must `when:` not use `{{ }}`?
5. How do you test and validate a template before it reaches a server?
6. How do Helm, Jinja2, Kustomize and Terraform `templatefile()` differ, and when would you choose each?
