# 1.26 KVM, QEMU and libvirt basics
Words: 11865 | Read time: ~79 | File: docs/part-01-linux/26-kvm-qemu-and-libvirt-basics.md

One-line purpose: Explains how a hypervisor virtualises CPU, memory and I/O (VM exits, EPT, IOMMU, virtio, VFIO), how KVM/QEMU/libvirt split the work, and how to tune, observe and troubleshoot a VM, with GPU passthrough as the end goal.

Beginner friendly: partly. The "hypervisor vs emulator" and "what is a VM" sections are beginner-readable; the VM-exit, EPT and VFIO sections are intermediate. Read 1.17 (virtual memory, NUMA, huge pages), 1.18 (cgroups, CPU scheduling), 1.19 (namespaces) and 1.22 (kernel modules) first, as the chapter itself requires.

Nebius rounds served: R1, R2, R3

Chapter verdict: READ-SECTIONS (§1 hypervisor types; §2 CPU virtualisation and VM exits, memory virtualisation, the virtio/VFIO table; §3 KVM/QEMU/libvirt split; §6 host-first tuning checklist; §7 observing VMs and %steal; §8 VFIO steps, GPU/NVLink notes; §11 troubleshooting table), because the reader needs the mental model and the symptom-to-cause table for R1 troubleshooting and VM-based GPU questions, while storage, networking and security detail are only recall material.

Hands-on to do:
1. Preflight on a Linux host: `lscpu | grep -i virt`, `grep -E -c 'vmx|svm' /proc/cpuinfo`, `ls -l /dev/kvm`, `kvm-ok`, `virt-host-validate` (step 1).
2. Create a cloud-image VM with `qemu-img create -f qcow2 -F qcow2 -b ... vm1.qcow2`, a cloud-init seed, and `virt-install`; then `virsh list --all`, `virsh domifaddr vm1`, and `ps -ww -o args -C qemu-system-x86_64` to see the real QEMU command (step 4).
3. While `stress-ng --cpu 2` runs in the guest, run `pidstat -tp <qemu-pid> 1` on the host and map the `CPU n/KVM` threads; then `sudo perf kvm stat record -a -- sleep 10; sudo perf kvm stat report` (step 5).
4. Run `virsh dumpxml vm1` and read the cputune, memoryBacking and hostdev lines; then `virsh destroy` and `virsh undefine --remove-all-storage --nvram` to clean up (steps 12, 4).
