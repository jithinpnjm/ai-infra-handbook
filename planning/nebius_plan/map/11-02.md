# 11.2 Device plugin, container toolkit, CDI and runtime classes

One-line purpose: Traces how a scheduled GPU Pod becomes a working CUDA container: the device plugin gRPC contract (Register, ListAndWatch, Allocate), the NVIDIA Container Toolkit and CDI, RuntimeClass, the Capacity/Allocatable/Allocated fields, and a dependency-ordered triage for missing GPUs.
Beginner friendly: partly. The "three boundaries" framing at the start is clear and the kubectl and node-level commands are concrete. The kernel-module, character-device and CUDA-compat sections (section 1) assume Linux and CUDA basics, so read 11.1 first and the Linux chapter on kernel modules and /dev if you have it. Section 3's gRPC sequence is advanced; you can skim it and keep the `Capacity` versus `Allocatable` table.
Nebius rounds served: R2, R3, R4
Chapter verdict: READ-SECTIONS (intro, 1 Basics ~host kernel/user-space split only, 2 CDI and RuntimeClass table, 3 device plugin handshake and Capacity/Allocatable table and extended-resource rules, "How it fails" table and decision tree, exercise 5 and checkpoints 1, 4, 8, 11-17, 20), because "scheduled is not usable" and the layer-by-layer triage (lspci, host nvidia-smi, plugin, kubelet, container) are the GPU-on-Kubernetes troubleshooting an SRE is asked in R2; skip the PID-namespace detail, the MIG/NVLink and fleet-pool arithmetic beyond the placement idea, and the lab output.

Hands-on to do:
- Run the boundary checks in order on a GPU node: `lspci | grep -i nvidia`, `lsmod | grep '^nvidia'`, `ls -l /dev/nvidia*`, `nvidia-smi -L` (section 4.1).
- Confirm runtime injection with `sudo crictl inspect $(sudo crictl ps -q --name <name>) | grep -A4 '"devices"'` and then `kubectl exec <pod> -- nvidia-smi -L` (section 4.2). Compare the UUIDs.
- Compare Capacity and Allocatable: `kubectl get node <node> -o jsonpath='{.status.capacity.nvidia\.com/gpu}{" capacity\n"}{.status.allocatable.nvidia\.com/gpu}{" allocatable\n"}'` (section 3.2 and the lab runbook).
- Save evidence before any fix: `kubectl get node <node> -o yaml`, `kubectl describe node`, `kubectl get events -A --sort-by=.lastTimestamp` (lab Step 2).
- Run the chapter's self-check: `python3 code/part11/device_plugin_toolkit_cdi_lab.py` (expect 26 passed).
