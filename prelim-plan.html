How Kubernetes runs on a Linux node (memorize this chain)​

StepWhat happensLinux primitive underneath
1kubectl reads kubeconfig, calls the API server over HTTPSTCP + TLS, client cert or token
2API server authenticates, authorizes (RBAC), admits, stores in etcdHTTP, etcd (Raft)
3Scheduler picks a node; kubelet on that node sees the Podwatch on the API server
4kubelet asks containerd (CRI) to create the sandbox and containersgRPC over a unix socket
5containerd + runc start the container processclone with new namespaces (pid, net, mnt, uts, ipc), pivot_root
6image layers become the container root filesystemOverlayFS mount
7CPU/memory limits are enforcedcgroup v2 (cpu.max, memory.max); over memory limit = OOM kill
8CNI plugin gives the pod an IPveth pair, bridge or routes, optional VXLAN/BGP
9Service virtual IP reaches podskube-proxy iptables or IPVS NAT rules + conntrack
10Volumes appear in the podCSI plugin + mount (bind mounts)
11GPUs appear in the poddevice plugin + NVIDIA container toolkit (device files, driver libs)
12Probes and evictionkubelet loop; liveness restarts, memory pressure evicts
