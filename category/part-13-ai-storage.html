Part 13: AI storage

9 chapters. Default priority tier 2.

📄️13.1 The AI data path: from storage to GPU

Why AI storage fails under capacity-only sizing, the 5 AI storage workload phases, the 8-layer data path from media to GPU HBM, bounce-buffer vs GPUDirect Storage DMA, and per-rack bandwidth math.

📄️13.2 Local NVMe and data staging

Local NVMe and data staging on AI compute nodes: 2-tier DGX H100/H200 and GB200/GB300 NVL72 scratch architectures, mdadm RAID 0 chunk and XFS stripe alignment, multi-epoch staging break-even math, asynchronous checkpoint staging, Linux blk-mq and read-ahead tuning, SMART endurance telemetry, and Slurm prolog/epilog lifecycle management, verified by a 28-check Python lab.

📄️13.3 GPUDirect Storage architecture

Eliminate the host CPU bounce buffer on the storage-to-GPU data path using NVIDIA GPUDirect Storage. The cuFile API, nvidia-fs.ko BAR1 peer-to-peer DMA, 4 KiB O_DIRECT alignment, gdsio, Nsight Systems, and Blackwell hardware decompression.

📄️13.4 Lustre for AI

Production Lustre engineering for AI training and inference clusters: SuperPOD High-Performance Storage tiers, Progressive File Layout (PFL) and Data-on-MDT (DoM), Distributed Namespace (DNE Phase 1 and Phase 2) metadata scaling, LNet multi-rail RDMA binding, client RPC bandwidth-delay-product tuning, GPUDirect Storage integration, and N-to-1 vs N-to-N checkpoint striping.

📄️13.5 BeeGFS, Weka, VAST and object storage

Architecture, stripe math, and operational tuning for BeeGFS, WekaFS, VAST Data DASE, DeepSeek 3FS, and S3 object storage dataset pipelines in GPU clusters.

📄️13.6 Data loading, small files and metadata

Quantifying small-file metadata amplification, dataset repackaging into WebDataset/tar/HDF5/Parquet, PyTorch DataLoader pipelining, NVIDIA DALI GPU offload, and NeMo Curator .bin+.idx memory-mapped LLM datasets.

📄️13.7 Checkpoint architecture and recovery

Mathematical sizing, Young-Daly scheduling, two-stage asynchronous staging, PyTorch Distributed Checkpoint DCP N-to-M resharding, atomic recovery, and transparent cuda-checkpoint and CRIU GPU state snapshots.

📄️13.8 Capacity, performance and cost planning

Size AI storage across usable capacity, read and write bandwidth, metadata IOPS, burst headroom, SuperPOD Standard vs Enhanced tiers, erasure coding efficiency, and 3-year GPU-stall TCO economics.

📄️13.9 Storage troubleshooting

Systematic 8-layer production storage troubleshooting for AI clusters: isolating GPU compute vs collective communication vs DataLoader CPU starvation vs metadata storms vs NIC ring-buffer drops vs Lustre OST imbalance vs GPUDirect Storage fallback vs local NVMe thermal/SMART wear.
