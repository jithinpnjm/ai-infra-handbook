Part 20: Nebius Senior SRE (Token Factory) interview preparation

Study volume for the Nebius Senior Site Reliability Engineer, Token Factory (Inference Platform) interview loop.

📄️20.1 The Nebius loop and this volume

What Nebius says about its SRE interview process stage by stage, what is not public, how four candidate reports differ, what the official page says about scoring, a think-aloud script, a plan for being stuck, the setup checklist, the official reading list mapped to this volume and the library, questions for the recruiter, and a map from each stage to the chapters that prepare you for it.

📄️20.2 The role in one page

Every responsibility and requirement of the Senior SRE, Token Factory (Inference Platform) posting, quoted briefly, with what it likely means day to day, the chapters and earlier handbook parts that cover it, a self-assessment template, a tested gap-tracker script that ranks what to study, what Token Factory is from public sources, sister Nebius SRE roles, and an honest gaps list.

📄️20.3 Triage method for a sick Linux box

How to triage a slow or failing Linux server in the first minutes: the 60-second checklist, the USE method, RED and golden signals for the service above it, hypotheses spoken aloud, and a plan for a one-hour console round.

📄️20.4 Files, descriptors, syscalls, permissions

The Linux console round for a Nebius-style SRE interview: file descriptors and their limits, reading strace and lsof output, inodes versus blocks, deleted-but-open files, and why a file can stay unreadable when chmod does not help. Eight broken-box scenarios with scripts.

📄️20.5 CPU, memory, disk and the scheduler

Load average versus utilisation versus saturation, PSI, CPU throttling in containers, steal time, NUMA, page cache, the OOM killer, disk latency, perf, eBPF and pinned memory, with six broken-box scenarios and reproduction scripts.

📄️20.6 Network debugging

How to debug a network problem in the Linux console round: what refused, timeout and reset mean, reading ss states, accept queue and SYN backlog, TIME_WAIT, conntrack, DNS and ndots in Kubernetes, MTU black holes, tcpdump, TLS failures, idle timeouts on streaming connections, and the Service path in Kubernetes.

📄️20.7 The console round: text tools, systemd and everyday operations

Twelve timed Linux console tasks with synthetic fixtures and tested solutions: top talkers, slowest requests, error bursts and percentiles from a 5xx access log, plus journald, systemd units and restart policy, signals and zombies, cron and logrotate gotchas, disk and user audits, tar, rsync, curl, jq, and bash scripts that survive production.

📄️20.8 The coding round

How to handle the coding task in a Nebius SRE interview: the 60-minute structure, thinking aloud, writing code that runs first time in a plain editor, hand testing with edge-case checklists, the Python standard-library tools worth knowing with verified behaviours, Go equivalents, common pitfalls and a four-week practice routine, with a tested harness and edge-case examples.

📄️20.9 Algorithm patterns for SRE problems

Sixteen algorithm patterns that appear in SRE coding rounds, each with the idea in plain words, a tested Python template, its complexity measured where practical, the operations situation it models, the variations an interviewer adds and the bug that sinks candidates.

📄️20.10 Complexity, latency and measuring code

Big-O out loud, measured costs of Python operations, the 2009 latency table with its arithmetic, fan-out tail latency by formula and simulation, locality, timeit, cProfile and loop budgets.

📄️20.11 Coding practice set

Forty original practice problems in four tiers for the Nebius coding round: 12 easy, 16 medium, 8 harder and 4 SRE mini-projects, each with a statement, target complexity, three hidden hints, the key insight, the common wrong answer and an interviewer follow-up. Every reference solution has pytest tests with edge cases and, where cheap, a randomised brute-force cross-check.

📄️20.12 Estimation toolkit for inference capacity

The back-of-envelope maths an inference SRE says aloud: weights memory by precision, KV-cache memory per token and per request, bandwidth-bound decode versus compute-bound prefill, tokens per second per GPU, GPUs per QPS with headroom and N+1, cost per million tokens, goodput, and the sanity checks, with a tested standard-library estimator.

📄️20.13 Design: multi-tenant LLM API

A 45-minute system design walk-through for a multi-tenant LLM inference API: numbers first, gateway, token rate limits, metering, cache-aware routing, prefill and decode pools, autoscaling, isolation, regions, failure handling and rollout, with a tested simulation.

📄️20.14 Dedicated endpoints and rollout

A system design walk-through for dedicated inference endpoints and a custom-weights flow: control plane versus data plane, GPU sizing, weights distribution and cold start, probes, rolling versus blue/green versus canary when GPUs are scarce, quality gates, rollback signals, version skew and scale-to-zero, with a tested rollout simulator.

📄️20.15 Design: observability pipeline

A system design walk-through for the telemetry pipeline behind an inference platform: what to collect, cardinality budgets and forbidden labels, pull versus push, Prometheus sharding and long-term storage, recording rules, log sampling, head versus tail trace sampling, exemplars, per-tenant metering versus operational metrics, backpressure, monitoring the monitoring and cost, with a tested cardinality estimator, label linter and recording rules.

📄️20.16 Design: GPU fleet health

A system design for finding a failing GPU before the customer does: health signals and the Xid catalog, passive and active checks, the node lifecycle from cordon to return, blast-radius limits on automation, spare pool sizing with arithmetic, silent capacity loss, draining inference traffic, a fleet capacity SLO and the vendor RMA flow, with a tested state machine, drain limiter, spare-pool calculator and a promtool-checked rule file.

📄️20.17 Design drill sheet: twelve prompts

A timed drill sheet for the system design round: twelve prompts with clarifying questions, worked sizing arithmetic, a 40-minute outline, an architecture sketch, the trade-offs graders look for, a failure story and curveballs, plus a rubric, a first-five-minutes script, a decision checklist and a tested estimate calculator.

📄️20.18 How LLM serving fails

A failure catalogue for an inference SRE: queue growth, KV-cache exhaustion and preemption, head-of-line blocking, OOM, NCCL hangs and Xid errors, cold start, thundering herd, probe mistakes, retry amplification, quality drift and version skew, each with symptom, confirmation, mitigation and fix, plus a decision tree and a tested failure-signature classifier.

📄️20.19 SLIs, SLOs and alerts

How to choose SLIs for a streaming token API, why averages lie, how a 99.9% target turns into minutes of budget, and how to design multiwindow burn-rate alerts. Includes tested Prometheus rules using real vLLM metric names and a burn-rate calculator.

📄️20.20 Autoscaling GPU inference

Why CPU and GPU-utilisation autoscaling fail for LLM engines, which signals work, the HPA formula with a worked example, stabilization windows and flapping, the anatomy of scale-up latency and how to hide it, minimum replicas and X+1, safe scale-down for streams, cluster autoscaler and GPU node pools, and multi-model placement. Includes a tested autoscaler simulator and validated HPA, KEDA and overprovisioning manifests.

📄️20.21 Routing, retries, overload

Which failures are safe to retry on a streaming LLM API, how timeouts nest, why per-request retries amplify an outage, backoff and jitter maths, retry budgets, hedging cost on GPUs, circuit breakers, load shedding, 429 versus 503, backpressure, cache-aware routing, draining and regional failover, with a tested discrete-event simulation and a schema-validated Istio fragment.

📄️20.22 Operating the engines

What vLLM, Triton, Ray Serve LLM, TensorRT-LLM and SGLang are for and how they differ in operation: the knobs an SRE must understand with cost and risk, start-up sequence, what health endpoints prove, upgrades, reading engine metrics, a comparison table, interview answers, and a tested vLLM config reviewer plus a kubeconform-validated Deployment.

📄️20.23 Kubernetes failure drills

A fixed debugging order for Kubernetes and twelve spoken drills on GPU platforms: Pending GPU pods, image pulls, restarts, NotReady nodes, eviction, PDB, DNS, Services, HPA, device plugins, etcd and webhooks, with a tested kubectl-output triage helper.

📄️20.24 Terraform for resilient GPU clusters

How to write Terraform modules that build resilience into a Kubernetes GPU cluster: module inputs and outputs, remote state and locking, state splitting and blast radius, drift, safe changes with prevent_destroy, moved and import, node pool design, secrets, testing, CI/CD, and recovery of the state itself, with a validated Nebius module and a plan-JSON risk checker.

📄️20.25 PromQL, Grafana, tracing traps

Fifteen PromQL, alerting, dashboard and tracing traps for an inference platform, each with a fix. Rules and unit tests that pass promtool, an Alertmanager config that passes amtool, and a PromQL pitfall linter with pytest.

📄️20.26 The stress interview

Run a 30-minute production-incident drill: take control in two minutes, mitigate before root cause, and practise on ten scripted incidents with a tested drill runner and scorecard.

📄️20.27 Post-mortems and on-call

How to answer behavioural questions about incidents you led, run incident roles and handover, write a blameless post-mortem with measurable action items, measure toil, write runbooks for tired engineers, keep on-call sustainable, and negotiate reliability work with an error budget, with a tested post-mortem linter and timeline builder.

📄️20.28 Project deep dive and final round

How to prepare for the final hour with a Nebius team leader and a possible long deep dive on one project: choosing the project, a one-page dossier template, the questions that probe each part, honest talk about trade-offs and mistakes, why Nebius, why SRE, why inference, questions to ask, logistics, a first-90-days answer and a tested dossier completeness checker.

📄️20.29 Plan, final week, cheat sheet

An 8-week study schedule with hours per week as a parameter, compressed 3-week and 10-day versions, a spaced-repetition drill list built from the volume's drill questions, a mock-interview protocol for the four round types, the final-week and morning-of routine, a one-page cheat sheet with a chapter id on every row, and the after-interview steps. Includes a tested schedule generator and a flashcard extractor.

📄️20.30 AI factory architecture map

Trace Nebius's public AI Cloud and Token Factory surfaces from cloud resources to the inference API, billing, caching and recovery limits, and learn where the public evidence stops.

📄️20.31 AI Cloud foundation

The AI Cloud layers under Token Factory as the public docs describe them: GPU platforms and regions, InfiniBand clusters and topology, VPC, storage, Managed Kubernetes, Soperator, Serverless AI, capacity and cost controls, with every fact tagged by evidence and checked on 2026-11-09.

📄️20.32 Token Factory lifecycle and economics

What Token Factory publishes about Public Serverless and Dedicated Endpoints: lifecycle and readiness, capacity, flavors, cached-token billing, dynamic rate limits, GPU-hour billing, data handling, observability and deprecations, with a tested unit-economics calculator and a verification log.

📄️20.33 AI Factory design, HA and recovery

A solutions-architect guide to composing Nebius AI Cloud, Token Factory and customer-operated inference fleets, with an evidence-tagged account of what Nebius documents about regions, SLAs, capacity, maintenance and backups, and labelled design advice where it is silent.

📄️20.34 Hardware and GPU fleet

The technical failure domains of a GPU fleet as Nebius, NVIDIA reference architectures and the gem books describe them: node, NVLink rack, fabric leaf, power feed, cooling loop, hall. How hardware faults surface, what they do to blast radius and spares, and a tested model.

📄️20.35 Nebius API surface

The technical shape of the public Nebius AI Cloud API read from its protobuf files and SDK source: resources, long-running operations, pagination, errors, idempotency, IAM tokens, quotas, retries, and a tested design for a safe fleet-automation client.

📄️20.36 Managed Kubernetes and Soperator

How Nebius Managed Kubernetes and the open-source Soperator operator work, fail and are operated: control plane, node groups, GPU health repair, upgrades, SlurmCluster and NodeSet resources, and debugging a stuck Slurm job versus a stuck pod.

📄️20.37 Observability and status on Nebius

The technical observability surface of Nebius Token Factory: documented metrics and their limits, the Prometheus federation path, lifecycle and rate-limit signals, what the status page and incident history show, customer-side SLIs built on percentile-only data, and how to write a post-mortem when the provider is the cause.

📄️20.38 Token Factory inference engineering

Every public technical fact about how Nebius serves inference in Token Factory: routing and cache, batching, speculative decoding, quantisation, dedicated versus serverless, with a master table, a labelled reconstruction of the data plane, the signals an SRE watches, and a tested claim register.
