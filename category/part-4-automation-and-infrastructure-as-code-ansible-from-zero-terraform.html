Part 4: Automation and infrastructure as code (Ansible from zero, Terraform)

27 chapters. Default priority tier 0.

📄️4.1 Git from scratch for infrastructure engineers

Git as the evidence trail of infrastructure: the object model, the daily workflow, branching and rebasing, repo layouts, hooks, secrets hygiene, branch protection, recovery with reflog and bisect, LFS and GitOps hand-off

📄️4.2 CI/CD pipelines: concepts and design

CI/CD for infrastructure and cluster configuration: evidence versus mutation, pipeline stages, pull requests as the control plane, OIDC, policy as code, golden images, secrets, canary rollouts and drift detection

📄️4.3 Ansible from zero: what it is, how it works, installation and ad-hoc commands

Ansible architecture and execution model, installation (ansible-core, collections, execution environments), ansible.cfg, SSH and privilege escalation, a first playbook, and ad-hoc commands for fleet operations

📄️4.4 YAML and Jinja2 for infrastructure code

YAML syntax, types, anchors and pitfalls; Jinja2 expressions, filters, tests, control structures, whitespace control and macros; how Ansible, Helm, Kubernetes and Terraform use templating; validation and linting

📄️4.5 Ansible inventory: hosts, groups, dynamic inventory and variables

Static and dynamic Ansible inventory: INI/YAML formats, groups and nesting, host and group variables, patterns and limits, inventory plugins for clouds and Kubernetes, variable precedence, multi-environment layouts and large-fleet design

📄️4.6 Ansible playbooks: tasks, modules, idempotency and check mode

Playbook structure, plays and tasks, the essential module families, idempotency patterns, command/shell guards, check mode and diff, tags, limits, serial, strategies and exit codes for operating fleets safely

📄️4.7 Ansible variables, facts, templates and filters

Defining and using Ansible variables, registered results, facts and custom facts, magic variables, lookups, filters and templates for generating configuration, with worked GPU-cluster examples and precedence debugging

📄️4.8 Ansible handlers, conditionals, loops, blocks and error handling

Control flow in Ansible: handlers and notify semantics, when conditionals, loops, blocks with rescue and always, failure handling, retries, assertions, delegation patterns, imports versus includes and rolling-update orchestration

📄️4.9 A real playbook end to end: deploying an application

Building a complete multi-tier deployment with Ansible: a FastAPI service behind nginx with PostgreSQL, systemd, TLS, firewall and monitoring; layout, variables, templates, handlers, zero-downtime rollout, verification and idempotency testing; plus a Docker-based variant

📄️4.10 Debugging Ansible playbooks

A systematic approach to debugging Ansible: reading errors, verbosity levels, debug and assert, step and start-at-task, the interactive task debugger, connection and privilege problems, variable and template failures, performance profiling and keeping failed module files

📄️4.11 Ansible roles and collections

Reusable Ansible: role structure and conventions, defaults versus vars, argument specs, dependencies, role design for GPU nodes, Galaxy and collections, building and publishing a collection, versioning and repository layout

📄️4.12 Ansible Vault and secrets management

Handling secrets in automation: Ansible Vault (files, strings, vault IDs), keeping secrets out of logs and diffs, HashiCorp Vault and cloud secret managers, SOPS, CI integration, rotation and incident response

📄️4.13 Testing Ansible: ansible-lint, Molecule and CI

A test strategy for Ansible code: static analysis with yamllint and ansible-lint, syntax and check-mode tests, Molecule scenarios with idempotence and verification (testinfra/Ansible verify), containers and VMs, GPU-specific testing limits, CI integration and release gates

📄️4.14 Ansible at scale: performance, strategies and callbacks

Running Ansible on thousands of hosts: SSH and execution tuning, fact caching, strategies, serial and async, pull mode, execution nodes, callbacks and reporting, and the failure-containment patterns that matter more than raw speed

📄️4.15 Custom modules, plug-ins and Ansible Automation Platform

Extending Ansible with custom modules and plugins (filters, lookups, inventory, callbacks, action, connection) and operating it as a platform: AWX/AAP, execution environments, controller architecture, credentials, RBAC, workflows, surveys, and API-driven automation

📄️4.16 Ansible for containers, cloud and network devices

Using Ansible beyond Linux hosts: Docker/Podman and Kubernetes modules, cloud provisioning and inventory (AWS, GCP, Azure), and network device automation with network_cli, NETCONF, httpapi, resource modules, NVUE for NVIDIA switches, config backup and safe change

📄️4.17 Ansible for GPU nodes and clusters

Applying Ansible to GPU fleets: ordered node bring-up (OS, kernel, OFED, NVIDIA driver, Fabric Manager, DCGM, container toolkit, Slurm/Kubernetes agents), role design, reboot handling, validation and burn-in, NCCL tests, drain/patch workflows, and the production incidents that shape the design

📄️4.18 Terraform refresher: why, providers, resources and the workflow

Infrastructure as code with Terraform and OpenTofu: declarative model, architecture (core, providers, state, the dependency graph), HCL language essentials, the init/plan/apply/destroy workflow, the CLI reference, importing and refactoring, workspaces and OSS versus HCP versus OpenTofu

📄️4.19 Terraform state in depth: backends, locking and drift

How Terraform state works and fails: contents and risks, remote backends and locking (S3, GCS, Azure, HCP), state isolation and layout, migration, recovery, surgery, drift handling, secrets in state, and cross-stack data sharing

📄️4.20 Terraform modules and reusable infrastructure

Designing Terraform modules: structure, inputs and outputs, composition, versioning and sources, registries, testing, anti-patterns, and a worked GPU cluster network and node-pool module set

📄️4.21 Terraform loops, conditionals, lifecycle and gotchas

count, for_each, for expressions and dynamic blocks; conditionals; lifecycle rules (prevent_destroy, create_before_destroy, ignore_changes, replace_triggered_by, preconditions); zero-downtime deployment patterns; and the sharp edges of Terraform

📄️4.22 Terraform secrets and multiple providers

Handling secrets safely in Terraform (sensitive values, ephemeral resources, secret managers, workload identity, state exposure) and working with multiple providers: aliases, multi-region and multi-account patterns, provider passing, authentication, versioning and mirrors

📄️4.23 Production-grade Terraform: structure, testing and team workflows

What production-ready Terraform means: repository and environment layout, standards and checklists, testing levels, CI/CD and Atlantis-style workflows, policy and cost guardrails, change management for GPU infrastructure, operating a Terraform estate at team scale

📄️4.24 Terraform on GCP and Nebius: networks, GPU VMs and GKE

Provisioning GPU infrastructure with Terraform: GCP VPCs and subnets, firewall and NAT, GPU VM families and capacity (reservations, DWS, spot), GKE clusters and GPU node pools, storage and IAM, plus the Nebius provider model for GPU clusters, InfiniBand fabrics, Kubernetes and Slurm-style environments

📄️4.25 Terraform with Kubernetes and Helm providers, and OpenTofu

Managing Kubernetes platform layers with Terraform: kubernetes, helm, kubectl/kustomize providers, authentication and layering, installing the GPU Operator and platform add-ons, namespaces/quotas/RBAC as code, limits of Terraform for workloads, and OpenTofu specifics

📄️4.26 GitOps with Argo CD and Flux

GitOps principles and architecture; Argo CD and Flux in depth (applications, ApplicationSets, sync waves, health, multi-cluster, RBAC, secrets, progressive delivery); repository design; GPU platform bootstrap order; operating and troubleshooting a GitOps control plane

📄️4.27 Lab: provision a GPU cluster with Terraform and Ansible

End-to-end lab: Terraform creates a network, storage and a small Slurm-style GPU cluster (with a zero-cost local rehearsal path), exports an Ansible inventory, Ansible configures drivers/monitoring/Slurm and validates the nodes, with pipeline, drift, upgrade and teardown exercises
