Part 16: MLOps and LLMOps tools and platforms

15 chapters. Default priority tier 1.

📄️16.1 MLOps foundations and lifecycle

MLOps foundations and lifecycle: the failure mode MLOps prevents, the end-to-end ML lifecycle, the four pillars (data, model, code, deployment), maturity levels, the move from MLOps to LLMOps, and the infrastructure context for an AI factory.

📄️16.2 Data versioning and experiment tracking

Data versioning and experiment tracking with DVC, MLflow and Weights and Biases: content-addressed storage, the experiment record contract, the registry handoff, multi-run comparison, and the operational pattern that makes both work on a Kubernetes GPU platform.

📄️16.3 Data pipelines and feature stores

Data pipelines and feature stores: ingestion and transformation DAGs, the feature store contract (offline and online parity), Feast, Tecton, the Vertex AI Feature Store, embeddings pipelines for LLMOps, and the integration with the tracking and registry layers from Chapters 16.1 and 16.2.

📄️16.4 Pipeline orchestration

Pipeline orchestration for ML: Argo Workflows, Kubeflow Pipelines, Flyte, Airflow. DAG execution models, retries, caching, artefact passing, GPU pool integration, secret and IAM management, and the operational pattern that ties the orchestrator to the tracker, registry, and feature store.

📄️16.5 Distributed compute for ML

Distributed compute for ML on Kubernetes: Ray and KubeRay for general-purpose distributed Python, Kubeflow Training Operator for TFJob/PyTorchJob/MPIJob/XGBoostJob, Katib for hyperparameter tuning and neural architecture search, plus the gang scheduling, fault tolerance, and GPU pool integration that ties them to the cluster.

📄️16.6 Model registry, CI/CD and GitOps for models

Model registry contract and stages, CI/CD for ML artifacts, GitOps for the registry, image promotion, canary deployment, rollback paths, and the operational pattern that ties training pipelines to serving systems.

📄️16.7 Model serving platforms

Model serving platforms on Kubernetes: KServe, Seldon Core and BentoML. The InferenceService contract, autoscaling, canary, traffic routing, multi-model serving, inference graphs, and the operational patterns that tie a serving platform to the registry from Chapter 16.6.

📄️16.8 LLMOps: RAG, vector databases and agents

LLMOps architectures: Retrieval-Augmented Generation (RAG) pipelines, vector databases and indexes, embedding models, agent loops and orchestration, function calling, and the cost / latency / quality trade-offs that govern LLM-based applications in production.

📄️16.9 LLM evaluation and guardrails

LLM evaluation methodology: automated metrics, LLM-as-judge, human evaluation, eval suites in CI, plus guardrails for safety, factuality, PII, jailbreak resistance, and hallucination detection in production.

📄️16.10 Monitoring, drift and continual learning

Monitoring, drift detection, and continual learning for ML systems in production: feature drift, label drift, concept drift, distribution shift detection (KS test, PSI, learned embeddings), online evaluation, A/B testing, shadow mode, and the retraining triggers that close the feedback loop.

📄️16.11 Cloud MLOps platforms

Cloud MLOps platforms on AWS, Azure and GCP: SageMaker, Azure Machine Learning, and Vertex AI. The managed-stack trade-off (Studio, Pipelines, Feature Store, Registry, Endpoints), when to use managed vs self-hosted, hybrid architectures, and the operational patterns that survive a cloud migration.

📄️16.12 NVIDIA enterprise stack

The NVIDIA AI Enterprise (NVAIE) software stack: NGC containers and models, NIM (NVIDIA Inference Microservice), NeMo framework, RAPIDS for data science, licensing models, and the operational pattern that ties the stack to a Kubernetes GPU cluster.

📄️16.13 Governance, privacy and compliance

Governance, privacy and compliance for ML platforms: regulatory regimes (GDPR, HIPAA, EU AI Act, SOC2, ISO 27001), data lineage and audit trails, model cards and model risk management, fairness and bias, privacy-preserving ML, and the operational pattern that makes compliance auditable.

📄️16.14 Platform design: AI factory

Multi-tenant AI factory platform design: per-team namespaces, GPU quota pools, scheduling tiers, chargeback and FinOps, self-service onboarding, internal developer platform, and the SLO-based design that ties the platform to the business.

📄️16.15 Lab: end-to-end MLOps on GKE

End-to-end MLOps lab on GKE: data versioning, feature store, experiment tracking, pipeline orchestration, training, promotion gate, registry, serving, monitoring, drift detection, retraining trigger, governance. The capstone that ties every chapter in Part 16 together.
