Part 14: Distributed training and fine-tuning

16 chapters. Default priority tier 2.

📄️14.1 ML and deep learning fundamentals for infrastructure engineers

First-principles ML and deep learning systems mechanics for infrastructure engineers: model selection, forward/backward 6PD FLOPs, 16-byte/param AdamW memory anatomy, warmup + cosine schedules, critical batch size, cross-entropy/perplexity, and MFU capacity planning.

📄️14.2 Transformers and LLM architecture

Infrastructure-first analysis of Transformer and Foundation Model architectures: tokenization and vector spaces, MHA vs GQA vs MQA vs DeepSeek MLA attention, SwiGLU and RoPE, KV cache memory math, FlashAttention HBM tiling, Dense vs MoE parameter scaling, Chinchilla compute-optimal scaling, SFT/RLHF/DPO alignment, and FM system customization.

📄️14.3 Training memory and compute anatomy

First-principles GPU memory and compute anatomy for LLM training. Covers static AdamW state, transformer activations, FlashAttention, checkpointing, gradient accumulation, allocator fragmentation, MFU, HFU, and collectives.

📄️14.4 Data parallelism and DDP

How PyTorch DistributedDataParallel scales training across GPUs and nodes. Covers reverse-order gradient bucketing, asynchronous NCCL AllReduce overlap, DistributedSampler, no_sync accumulation, and torchrun.

📄️14.5 FSDP and parameter sharding

Scaling larger-than-GPU-memory models with PyTorch Fully Sharded Data Parallel (FSDP1 and FSDP2 fully_shard), ZeRO sharding stages, AllGather/ReduceScatter communication math, DeviceMesh and Hybrid Sharding (HSDP), DCP checkpointing, prefetching, activation checkpointing, CPU/SuperOffload, and torch.compile integration.

📄️14.6 DeepSpeed and ZeRO

DeepSpeed and the Zero Redundancy Optimizer (ZeRO Stages 1, 2, and 3), ZeRO-Offload (CPU RAM), ZeRO-Infinity (NVMe), Grace-Blackwell SuperOffload (NVLink-C2C and GraceAdam), ZeRO++ (qwZ, hpZ, qgZ), DeepSpeed-Ulysses sequence parallelism, and how state sharding combines with Megatron computation sharding.

📄️14.7 Tensor, pipeline and expert parallelism; Megatron

Scaling beyond state sharding with Megatron Core: Tensor Parallelism, Sequence Parallelism, Context Parallelism, Pipeline Parallelism, Expert Parallelism for MoE, Megatron-FSDP, Distributed Optimizer, FP8 Transformer Engine, and 5D hybrid parallelism across NVLink and InfiniBand.

📄️14.8 PyTorch performance: profiling, tuning and scaling

End-to-end PyTorch performance engineering: multi-level profiling, torch.compile, CUDA Graph Trees, memory allocator tuning, SuperOffload, SimpleFSDP, AsyncTP, and HUD CI regression gates.

📄️14.9 PyTorch compilers and kernels: torch.compile

Inside the PyTorch 2.x training and inference compiler stack: TorchDynamo PEP 523 frame evaluation and guards, AOTAutograd joint forward-backward FX graph capture and min-cut activation checkpointing partitioner, PrimTorch (>2,000 ATen ops to ~250 primitives), TorchInductor Triton/C++ codegen, dynamic shapes (mark_dynamic vs dynamic=True), torch._dynamo.explain() graph break analysis, Table 14-1 TORCH_LOGS flags, @torch.library.triton_op custom Triton kernels with autograd, TMA 16-byte alignment, persistent GEMM, Proton profiling, and OpenXLA.

📄️14.10 Multi-node training architecture

End-to-end multi-node distributed training system architecture: rail-optimized InfiniBand and RoCE v2 fabrics, c10d TCPStore rendezvous, SLURM/Enroot/Pyxis and Kubernetes JobSet/PyTorchJob launch mechanics, 3D/4D process-group rank placement across NVLink and network rails, host CPU/NUMA/PCIe/NIC affinity binding, scaling efficiency from 16 to 16,384 GPUs, and storage/checkpoint/network co-design.

📄️14.11 Checkpointing, fault tolerance and elastic training

Production checkpointing, fault tolerance, and elastic training at scale. Covers 5-component LLM checkpoint anatomy, sharded parallel writes vs rank-0 gather, Young-Daly optimal checkpoint intervals, two-phase asynchronous checkpointing, PyTorch Distributed Checkpoint dynamic resharding, TorchElastic, and Slurm preemption recovery.

📄️14.12 Training performance engineering and troubleshooting

End-to-end distributed training performance engineering and troubleshooting: decoding the nvidia-smi utilization lie, MFU, HFU, and Goodput math, top-down bottleneck isolation across host DataLoader, kernel Roofline, memory allocator, and NCCL collectives, multi-rank straggler detection in Nsight Systems and Holistic Trace Analysis, and production failure triage.

📄️14.13 Fine-tuning: SFT, LoRA and QLoRA, preference alignment

End-to-end post-training and fine-tuning engineering: when to fine-tune versus RAG and prompt engineering, supervised fine-tuning dataset curation and chat templates, parameter-efficient fine-tuning with LoRA and DoRA, QLoRA 4-bit NormalFloat quantization with double quantization and paged optimizers, preference alignment via RLHF, PPO, DPO, GRPO, ORPO, and KTO, model merging, multi-LoRA serving, and Kubernetes Kubeflow Trainer operations.

📄️14.14 Dataset engineering for fine-tuning

End-to-end dataset engineering for LLM fine-tuning and alignment: data curation, domain composition, exact/MinHash-LSH/semantic deduplication, benchmark decontamination, quality filtering, PII redaction, NVIDIA NeMo Curator, synthetic data generation, LLM-as-a-Judge verification, chat templates, and FlashAttention varlen sequence packing.

📄️14.15 Fine-tuning infrastructure and cost

End-to-end fine-tuning infrastructure and FinOps architecture: VRAM sizing across full SFT, LoRA, QLoRA, DPO, GRPO, and PPO, GPU hardware selection across L4, L40S, A100, H100, H200, and B200, the PCIe versus NVLink SXM crossover, token throughput and cost per run, Unsloth/Axolotl/Torchtune/TRL/LLaMA-Factory stacks, and Kubernetes Kubeflow Trainer v2 and Spot operations.

📄️14.16 NeMo framework and customisation

End-to-end NVIDIA NeMo Framework and enterprise model customisation architecture. Covers NeMo 2.0 recipes, Megatron-Core parallelism, Transformer Engine FP8, NeMo Curator, SFT, LoRA, DPO, GRPO, sharded checkpoints, NeMo Evaluator, and NeMo Guardrails.
